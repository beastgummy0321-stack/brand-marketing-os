# Objective
Implement ruling RC-D (2026-09-14): real platform purchases must reach the close-out verdict. Today `ingest_meta` writes
`purchases=0` (`app/ads/outcome.py:142`), `_bucket` drops Meta-sourced rows from the purchase count (`:170-174`) and
`closeout.py:102-103` turns untracked purchases into 0, so every real campaign closes as 看不出.
Write the cause chain first (in the commit body): where the zero is introduced, every caller relying on it, and why removing
it is the root fix rather than a guard at the verdict.
# Done
- A new ads-prefixed migration drops `NOT NULL` and the `DEFAULT` on BOTH `purchases` and `revenue` of `ads_outcome_daily`
  (`supabase/migrations/20260913000001_ads_tables.sql:180-181` created them). Existing rows are NOT rewritten: historic
  zeros stay as they are and are documented as "legacy zero = unknown for Meta-sourced rows written before this migration".
  Do not guess a back-fill.
- A SECOND, separate migration `supabase/migrations/20260920000002_ads_outcome_legacy_meta_unknown.sql` normalises the
  legacy literals that were never an observation — `UPDATE ads_outcome_daily SET purchases = NULL WHERE source = 'meta';`
  and `UPDATE ads_outcome_daily SET revenue = NULL WHERE source = 'meta' AND revenue = 0;`. Never edit the first file's SQL:
  an applied migration is corrected by a new file, not in place. Header comment must state that these values were written
  unconditionally by the pre-F16 ingest and never recorded an observation, that the statement reproduces the pre-change
  reading semantics exactly, and that it must sort before any migration or ingest that writes real Meta purchases (F16-I05).
  Record before/after row counts as evidence (expect 708 rows for `purchases` on the current local dev DB).
  Reason this is needed: once `_bucket` keys on `IS NOT NULL` instead of `source != "meta"`, a legacy `0` would start
  reading as a real counted zero — the exact "unknown becomes zero" this feature removes.
- Purchases are nullable end to end: untracked = NULL, tracked zero = 0; the Meta filter in `_bucket` is removed.
  `ingest_meta` writes NULL when the platform gave no purchase action / no ROAS, and 0 only for a tracked zero; the
  `revenue != 0` sentinel in `_bucket` is removed together with the Meta filter.
- `repository._outcome_totals` returns NULL (not 0) when every row is unknown; the trailing-30 path
  (`repository.py:455-500`) and the `purchases > 0` sample filter treat NULL days as unknown — excluded, never counted as
  zero. `experiments.py` sums skip NULL, and the comparison returns 看不出 with a reason when the known sample is below
  the gate.
- The verdict uses real purchases; sample bucket 低 still yields 看不出; tests cover tracked-zero vs untracked vs real counts.
  Two further tests are required: a legacy-shaped Meta row (after normalisation) reads as unknown in `_outcome_totals` and
  in campaign detail; and a regression test for the trailing-30 path in `repository.budget_history` proving a NULL day is
  excluded from the daily-CPA median and from the `purchases > 0` sample-ads count rather than counted as zero.
- Remove the three stale promises of an unattended close: `app/ads/routes.py:819` docstring, `app/ads/judgment.py:109-112`,
