# Objective

The learning ledger carries two tracks on the column it already has and can expire one row, so visual
learnings (F07-I11 writes and downgrades, F07-I04 reads) never leak into the strategy prompt
(ARCHITECTURE.md §3 "Two tracks, one ledger"). This extends the storage facade's read/write surface for
its own table only; no capability moves into legacy. Never delete or overwrite anything under `data/`.

# Done

1. `app/brand_intelligence/repository.py::record_learning` gains keyword `source_track: str = "ads"` and
   writes it into `learning_ledger.source_track` (existing column, `NOT NULL DEFAULT 'ads'`): add it to
   the INSERT column list and to the returned/audited row. Existing callers are unchanged.
2. `list_learnings` gains keyword `source_track: str | None = None`; when given it adds
   `AND source_track = %s`. `None` returns every track, exactly as today.
3. New `expire_learning(conn, brand_id, learning_id, *, actor) -> dict | None`: `UPDATE learning_ledger
   SET expired = true WHERE brand_id = %s AND id = %s`, `write_audit(... action="update", before,
   after)` in the same style as `record_learning`, commit, return the updated row (`None` when no row
   matched). Expiring an expired row is a no-op that still returns the row.
4. `app/ads/strategy.py::_learnings_section` calls `list_learnings(conn, brand_id,
   limit=_MAX_LEARNINGS, source_track="ads")`.
5. Tests:
   - `test_ads_learning_ledger.py`: a row recorded with `source_track="visual"` is returned by
     `list_learnings(..., source_track="visual")` and by `source_track=None`, and not by `"ads"`; a row
     recorded without the argument reads back `source_track == "ads"`; after `expire_learning` the row
     is absent from `list_learnings` and present with `include_expired=True` and `expired is True`;
     a wrong brand id returns `None` and changes nothing.
   - `test_ads_strategy.py`: with one `ads` and one `visual` learning on the brand, the strategy
     prompt's 【過去的學習】 contains the first text and not the second (follow the file's existing
     prompt-capture pattern).

# Verify

`uv run python -m pytest app/tests/test_ads_learning_ledger.py app/tests/test_ads_strategy.py -q`

# Blocked if

- A migration puts a CHECK on `learning_ledger.source_track` that rejects `'visual'`
  (`grep -rn "source_track" supabase/migrations/`); a migration is a planner decision.
- Another caller of `list_learnings` besides `strategy.py` and tests feeds a prompt. Report it; do not
  change it.
