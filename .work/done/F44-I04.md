# Objective
A refused slot keeps its reason and the slots read says it (feature outcome 4, Contract D). Today `slots._confirm_if_ready` drops
the refusal and the slot reads `in_progress` forever.

# Done
1. Migration: `ALTER TABLE ads_asset_placement ADD COLUMN blocked_reasons jsonb NOT NULL DEFAULT '[]'::jsonb;` (list of Contract C
   details).
2. `_confirm_if_ready`: a refusal with any detail whose kind is not `wait` writes those details to the placement's current
   revision; a refusal with only `wait` writes nothing. `_apply_confirmation` resets the column to `[]`. A new revision starts
   empty (column default).
3. `_planned_slot`: a pending placement with stored details, or whose original failed processing (the failure status
   `user_assets` writes, with its `error`) → `state: "blocked"`, the copy half as today, and
   `blocked = {"text", "terms", "fix", "more"}` from the first detail (`fix`: `copy` → `"copy"`, `file` → `"file"`, else `null`;
   a failed original: kind `file`, text 「這個檔案處理失敗：〈error〉」). Every other slot carries `blocked: null`.
4. Every slot carries `offer_label` (the planned ad's offer coordinate label; `null` when the ad has none and on imported
   campaigns).
5. `slots.recheck(conn, org, brand, campaign_id, ad_id, actor)` + `POST …/campaigns/{c}/slots/{ad_id}/recheck`: same write guard as
   `choose_copy` (`_slot_ad_for_write`), `slot_no_file` when the slot has no unconfirmed placement, then `_confirm_if_ready` +
   `settle`, returns `{"slots": read(…)}`. Errors map like the `/copy` route.
6. Tests: refusal stored and read back as `blocked` with `fix: "copy"`; `choose_copy` with a clean version clears it and the slot is
   ready; `recheck` after the cause is removed (the ad's offer coordinate changed to match) makes the slot ready and, with the
   cause still there, returns the same reason; a not-ready preview stays `in_progress`; a failed original reads `fix: "file"`;
   `offer_label` present; route guard covers the new route.

## Lead note 2026-10-01 (from F44-I03 as built)
- `confirm_manual` returns `pending_details` on refusal: `[{"kind": "copy"|"file"|"campaign"|"wait", "text", "terms"}]`
  (`asset_suggestions._refused`). The offer label is already resolved by `asset_suggestions._judged_against` — reuse it for
  `offer_label`, do not write a second resolver.
- `confirm_manual` raises `ValueError` when the campaign's sell-way was deleted (`validate_claims`: 「找不到此品牌商品。」).
  `_confirm_if_ready` catches a `ValueError` from it and stores one detail `{"kind": "campaign", "text": <the message>, "terms": []}`
  so the slot reads blocked instead of the upload failing after the placement is stored.
