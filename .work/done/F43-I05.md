# Objective
The product-onboarding HTTP contract for `#/p1`–`#/p5`, `#/plist`, `#/bundle` and the `#/home` product block of
`.harness/scratch/prototype/f41-onboarding/index.html`. Every number/label those screens show comes from here, computed by the
program (break-even, derived list price/cost, offer labels, 食安法 flags). No LLM call (prefill and 自訂 blocks are F43-I06).

# Done
1. Router `routes_product_api.py` (mounted in `routes_api.py`), logic `product_onboarding.py`; tenant checks as the brand routes;
   all writes through the facade (F43-I01). Each GET field carries `source` ∈ saved|ai|none and `note` like the brand steps.
   - `GET /api/intake/brands/{b}/products` → `{products: [{id, name, thumbnail_url, state: "ready"|"draft", step, summary
     (「2 群顧客・證據 2・說法 3」 / 「建到一半：還沒確認顧客」), sell_ways: [{id, name, price, break_even, offer_labels}]}], bundles:
     [{id, name, thumbnails[], price, break_even, offer_labels}], suggestions: [{name, url}]}` (suggestions = F42 prefill products
     not yet created).
   - `POST …/products` `{name, page_url?}` → `{product_id}` with `onboarding_step = 1`.
   - `GET …/products/{p}/onboarding` → `{step, completed, prefill_status, prefill_error}`.
   - `GET|PUT …/onboarding/what` → `{name, page_url, photos: [{id, url}], intro, mechanism, difference}` (photos via the existing
     official-asset upload with `product_id`).
   - `GET|PUT …/onboarding/who` → `{groups: [{id|null, who, pain_keys[1–2], quote, when_used, source, note}], pain_options: PAIN_KINDS}`
     (≤3).
   - `GET|PUT …/onboarding/evidence` → `{proof: [{id|null, fact_key, text, source, note}], claims: [{id|null, text, from_note,
     verdict: "ok"|"no"|null, statutory: {term, sentence}|null}]}`; a claim with a statutory hit (`app.workbench.validate_claims(...)["statutory_hits"]`, the public
     entry; brand regime) is `no` and not editable; PUT refuses a claim with `verdict` null (「還有 N 句沒選」).
   - `GET|PUT …/onboarding/sell-ways` → `{sell_ways: [{id|null, name, components: [{product_id, name, qty}], price, list_price,
     list_price_derived, cost, cost_derived, shipping, close_rate (lead/booking brands only), break_even, cap_per_sale,
     landing_url, landing_is_default, offer_labels}], show_close_rate, assumptions}`; break-even through `ads.budget.breakeven_cpa`
     semantics (reuse the facade/ads public entry, do not re-implement); cap NULL shown as break-even; F05 「不知道 → 參考值」 flags kept.
   - `POST …/onboarding/complete` → `onboarding_step = NULL`; refused while a step is unsaved or no sell-way exists.
   - `GET|PUT /api/intake/brands/{b}/bundles/{id}` and `POST …/bundles` → `{name, components, price, list_price (derived, 「兩盒單價相加」),
     cost (derived), shipping, break_even, cap_per_sale, landing_url, offer_labels, reused: {groups[], proof[]}}` (the 「廣告會用到的」 card).
   - The four step PUTs advance `onboarding_step`; re-entry on a finished product edits in place.
2. `frontend/src/lib/intakeProductApi.ts` (owned by `intake` in the manifest since carve): typed clients and types for all of it.
3. Tests `app/tests/test_intake_product_api.py` (new): list shape with a draft, a ready product, a bundle and a suggestion; each step
   GET (none / ai / saved) and PUT validation (4 groups, 3 pain keys, unknown key, unset claim verdict, negative price, component of
   another brand, statutory claim forced to `no`); sell-way numbers (break-even, derived list price, offer labels 組合價／免運 with a
   F42 滿額免運 policy); complete refused without a sell-way; cross-brand refusal.
