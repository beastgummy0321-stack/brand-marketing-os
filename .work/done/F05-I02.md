# Objective

F05-I01 建好了層級與解析器，但**沒有任何讀者用它**。不接上的話：使用者選了「薑黃錠 · 3 入組」，
文案提示詞讀不到薑黃錠的任何事實、圖片提示詞找不到薑黃錠的商品照、策略頁看不到這個產品有幾種賣法
——每個賣法都會變成一個沒有知識的孤兒。

這張票只做一件事：**知識往上找母產品，金額往下找賣法**（`ARCHITECTURE.md` §8 第 1 條）。

# Done

## 1. 事實：`app/llm/context_compiler.py`

`compile(conn, brand_id, product_id)` 讀產品事實之前，先
`product_id = bi_repo.knowledge_product_id(conn, brand_id, product_id)`。一處改完，所有靠它組 prompt 的
呼叫端（素材工作檯、品牌報告…）一起對。**這是修根因的那一行，不要在每個呼叫端各補一次。**

## 2. 商品照：`app/workbench/jobs.py::_product_line`（`:192-205`）

判斷「有沒有參考商品照」時，先把 `product_id` 過一次解析器再跟 `list_official_assets()` 的
`product_id` 比對。賣法沒有自己的照片，用母產品的。

## 3. 策略：`app/ads/strategy.py::_products_section`（`:66-96`）

現在是「一個 product_id 一行」。改成**先按母產品分組**：

```
【商品】
- 薑黃錠｜事實：<母產品的事實，沿用既有的 fact 讀法與 cap>
  賣法：單品 NT$1,200／3 入組 NT$3,200／5 入組 NT$5,000
```

- 分組鍵＝`knowledge_product_id()`。母產品的名稱取母列的 `name`；賣法那一行印子列的 `name`
  （已經是「<母> · <賣法>」，印的時候可以只取「 · 」後半段，找不到分隔就整個印）。
- **賣法清單要有上限**（§1 每個進 prompt 的清單都要 cap）：一個母產品最多印 8 個賣法，
  多的印「另有 N 種賣法沒有列出」。
- `basis` 照舊一個賣法一筆（`product_id`／`price`／`effective_from`／`stale`），畫面的
  「查看策略依據」才對得起來。沒有價格資料的賣法仍然印「沒有價格資料」。

## 4. 預算：`app/ads/budget.py::_economics_for`（`:57-65`）

Campaign 選到的 `product_id` 如果是**母產品**（它自己沒有 economics、但有子），就取它的**第一個賣法**
（`list_products` 的既有順序，精靈先寫「單品」所以第一個就是單品）算 breakeven，
並在 `basis` 的 `product_id` 記下**實際用的那個賣法的 id**——依據要說得出是用哪個賣法算的。

## 5. 測試

- `test_product_hierarchy.py`：**只**放 `context_compiler` 的案例（母有事實、子沒有 → `compile(子)` 的文字裡有母的事實）。
  這個檔不屬於任何受管模組，所以**不准** import `app.ads.*` 或 `app.workbench.*` 內部（checker 會紅）。
- `test_workbench_product_line.py`（新檔，落在 workbench 擁有的 `test_workbench*.py` 樣式）：母有商品照 →
  `_product_line(子)` 說得出「有參考商品照」。
- `test_ads_strategy.py`：一個母產品＋三個賣法 → `_products_section` 只出現一個事實區塊、三行賣法價格；
  九個賣法 → 只印 8 行＋「另有 1 種賣法沒有列出」。
- `test_ads_strategy.py`：Campaign 指到母產品 → 預算算得出數字，`basis.product_id` 是第一個賣法。
