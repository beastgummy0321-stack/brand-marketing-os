# Objective

同工作區的既有活動與自帶素材完整介面。

將 I01–I05 接到新建與 Campaign 工作區，依 §6.9.5 完成可操作而非只有後端的流程。

# Done

1. 沿用 docs/design-system.md 與現有 ads patterns，不另建導航／模式。列表加入既有活動：快取／loading／分頁／錯誤／選取後納入；匯入後直接工作區，不重走產生策略。
2. Campaign detail 顯示來源、平台狀態、最近成功時間及部分缺漏；進階展開原生結構／預算。不要讓 groups=[] 觸發舊無廣告空畫面或 nextStep 引導強制產圖。
3. NewCampaignPage 與 AssetsTab 可批次上傳品牌素材並掛入 Campaign；未提交或中斷仍可找回品牌暫存。圖片／影片預覽、逐檔進度與重試、去重回饋、原文編輯、必用安排一覽。
4. 建議 → 核對缺项 → 分批確認 → 手動交接 → 選平台候選／重新讀回；處理狀態按 revision 更新，重開仍一致。三種『廣告存在／素材版本／成效是否可歸屬』分開白話呈現。
5. 不支持寫入的操作由 capability 控制並說原因；internal 舊流程／F07 workbench 入口維持。平台資訊、unknown 及 labels 由 backend 產生，前端不另猜規則。
6. 元件測試涵蓋正常、empty/loading/error/heavy、重試、超過10檔、必用有pending、失效確認、imported 無內部 groups、廣告存在但版本待核對。1024/1920 真實截圖與 I07 合作驗證，不以 DOM 斷言代替視覺檢查。

必要 manifest 維護：兩支新增 adsExternalApi.ts／adsUserAssetsApi.ts 依既有 adsApi 模式列入 ARCHITECTURE.md 的 ads owns，不改模組方向。

已完成 API 補充：建議批次清單 GET 可找回未確認／失敗／執行中的批次；confirm 的 batch_id=null 支援純手動文案檢查，不需模型成功才能繼續。原文 copy_fields 可能有額外欄位，編輯三個標準欄位時保留其他原文。媒體 URL 需 apiFetch 帶租戶授權後轉 Blob，妥善取消請求及撤銷 object URL；不把權杖放 URL。上傳進度使用逐檔階段／完成數，不造假傳輸百分比。
