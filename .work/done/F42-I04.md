# Objective
The brand-onboarding HTTP contract the seven screens use (`#/b1`–`#/b7` of `.harness/scratch/prototype/f41-onboarding/index.html`).
Every field a screen shows comes from here; every save writes the final store named in the feature Decisions through the facade.
No LLM call in this issue (scan prefill and 自訂 are F42-I05; this issue only reads `intake_draft.prefill_json` if present).

# Done
1. Draft steps become 1 基本 · 2 AI 讀網站 · 3 品牌是誰 · 4 證據與政策 · 5 素材 · 6 接工具 · 7 完成 (`state.py`; a brand created
   without URLs and photos skips 2). Every step route below works for an open draft **and** for a completed brand (re-entry:
   reads/writes the stores directly; a PUT on an open draft advances `current_step` to at least step+1). A brand that never had a draft (e.g. the seed brand) reads
   as completed (re-entry mode), never 404. `brand_web`-style tenant
   checks (`require_brand`) on all.
2. `POST /api/intake/brands` (form) additionally accepts `photo_kinds` (parallel to `photo_tokens`; logo|store|team|brand_image|other,
   default other), `market_region`, `regulatory_regime` (`food_tw` or empty), up to 5 `urls`; each photo becomes an
   `official_asset` (`product_id` NULL). The history choice keeps its current field and behaviour.
3. New router `routes_onboarding_api.py` (mounted in `routes_api.py`), logic in `onboarding.py`, all under
   `/api/intake/brands/{brand_id}/onboarding`. Each GET returns `{…, "source"}` per prefilled field where `source` ∈ `"saved"` (a
   confirmed store value), `"ai"` (from `prefill_json`, with `note` e.g. 「about 頁」), `"none"` (網站上沒找到):
   - `GET ""` → `{step, completed, skipped_scan, prefill_status: none|running|done|failed, prefill_error}`.
   - `GET|PUT /basics` → `{name, urls[], photos: [{id, kind, url}], market_region, regulatory_regime, advertising_history,
     client_name, description}` (PUT = re-entry edit; photo add/remove through the existing upload + `photo_tokens`).
   - `GET|PUT /identity` → `{positioning: {value, source, note}, tone: {values[], options: TONES + saved custom tones, source,
     note}, visual: {value, source, note, photo_urls[]}}`; PUT `{positioning, tone: [1–2], visual}` writes the three brand facts
     (confirmed, replacing the previous confirmed row of each type).
   - `GET|PUT /evidence` → `{proof: [{id|null, fact_key, text, source, note}], proof_kinds, policies: [{key, label, group, params,
     offer_key, offer_label, sentence, source}], policy_types: POLICY_TYPES (+ offer_label), cooling_off: {applies, disclosure},
     forbidden: [{id|null, text}], regime_label}`; PUT `{proof: [{id?, fact_key, text}], policies: [...], cooling_off, forbidden:
     [text]}` — full-list semantics per list (proof via the brand-fact functions, policies via `save_brand_policies`, forbidden via
     `rule` `forbidden_word` rows with `product_id` NULL). Empty lists are valid (「沒有也沒關係」).
   - `GET|PUT /media` → `{media: "photo"|"photo_video"|null}` (`set_media_capability`).
   - `GET /tools` → `{connectors: [{key, group, label, icon, reads, state: "connected"|"available"|"seat", note}], conversion_goal,
     conversion_goal_options}` from `connector_catalogue.json` (same idea as `app/schedule/channel_catalogue.json`: data file, one
     row per connector — meta, google, tiktok, ga4, gsc, shop, csv, mcp, api with the prototype's groups/labels/「接上後系統能讀」
     text; `live` flag per row). Meta `connected` + note 「已接上：〈account name〉」 from the bound account; csv `available` (links the
     existing orders import); every other row `seat` (「即將開放」).
   - `POST /complete` → marks the draft completed; idempotent; returns `GET ""`.
4. `routes_tools_api.py::conversion_goal_post` works on a completed brand (no open draft → no step bump, no 404).
5. `frontend/src/lib/intakeOnboardingApi.ts` (new; owned by `intake` in the ARCHITECTURE.md manifest since carve): typed GET/PUT/POST clients and response types for every route above; `intakeApi.ts`
   `createBrand` sends the new form fields. No component changes here.
6. Tests `app/tests/test_intake_onboarding_api.py` (new): per step GET shape with no prefill / with a stored prefill (`source="ai"`) /
   after PUT (`"saved"`); PUT validation (tone count, unknown policy key, disclosure length, proof key) → 400 with a Chinese message;
   re-entry on a completed brand; cross-brand refusal; tools list states with and without a bound Meta account. Existing intake API
   tests updated for the new step numbering.
