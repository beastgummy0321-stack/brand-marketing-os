# Objective
Contract T in `.work/features/F35.md`: the slots read shows each planned ad's copy half and the two new states, a file
uploaded into a slot carries the ad's selected workbench copy, fills the purpose, confirms and assigns in one call, and a
slot with a file but no copy can take one of the brand's workbench copy versions. The launch rule
(`change_control_launch.ready_material`) and `assets.readiness` are not touched.

# Done
1. `slots.py` — the ad→set map, once per read: `_ad_sets(conn, org, brand, campaign) -> dict[ad_id, brief]` from
   `workbench.briefs_for_source(conn, org, brand, assets.PACK_SOURCE_KIND, {"ads_campaign_id": campaign})` (same walk as
   `routes._enriched_campaign`; the latest brief per `source_ref.ads_ad_id` wins). `_workbench_copy(conn, org, brand, brief)
   -> dict | None`: `out = workbench.adopted_output(conn, org, brand, brief["id"], "copy")`; `None` unless `out` and
   `out["is_adopted"]`; else `workbench.material_source(conn, org, brand, brief["id"], out["id"])["copy_fields"]` with
   `label = f"工作檯第 {out['version_index']} 版"`. `workbench_href = workbench.set_action_url(conn, org, brand, brief["id"])`.
2. `_slot(...)` gains `copy` and `workbench_href` (both `None` for platform／imported slots and the reserved seat). `_planned_slot`
   order, first match wins:
   - launched (entity) → `ready`, copy from the material's `effective_copy` (source `placement`, label 「已確認」) if any;
   - `launch.ready_material(material)` → `ready`, copy = `{"source": "placement", "label": "已確認", **bindings.effective_copy(placement)}`
     (read the placement through `user_assets.placement(conn, org, brand, campaign, material["placement_id"], material["placement_revision"])`);
   - pending placement whose effective copy has neither `headline` nor `body` (blank／whitespace) → `image_only`, thumbnail of
     the pending asset, `copy: None`;
   - pending placement otherwise, or a stale material, or `readiness == "in_progress"` → `in_progress` (copy from the
     pending／stale placement, source `placement`, label 「待確認」);
   - no placement and `_workbench_copy` is not None → `copy_only`, `copy = {"source": "workbench", "label", headline, body, description}`;
   - else `missing`.
   `confirmed` stays `state == "ready"`; `read()`'s `ready`／`total` unchanged.
3. `user_assets_repository.attach(..., copy_fields, actor, *, purpose=None)` inserts `purpose` when given (column exists;
   `revise` already validates the 4000 limit — apply the same check). `attach_selected(conn, org, brand, campaign, body, actor,
   *, purpose=None)` passes it through; the request-body key set is unchanged (purpose is never a request field).
4. `slots.upload`: after the existing guards, `ad_copy = _workbench_copy(...)` for this ad; when the body has no
   `copy_fields` and `ad_copy` is not None, use `ad_copy`'s three fields as the placement copy; call `attach_selected(...,
   purpose=ad["name"])`. Then, when the placement is not yet confirmed and its `asset_status`／`status` is ready:
   `asset_suggestions.confirm_manual(conn, org, brand, campaign_id, placement["id"], placement["revision"], actor)` (import
   lazily inside the function, the way `settle` is called from the routes) — a returned `pending_reasons` result is not an
   error (the slot stays waiting: `image_only` or `in_progress`). Then `settle` as today. Response shape unchanged. An
   already-confirmed placement (dedup path) is untouched.
5. `slots.copy_options(conn, org, brand, campaign_id) -> {"options": [...]}` = `workbench.material_options(conn, org, brand, part="copy")`
   after `ads_repo.require_internal_campaign`. `slots.choose_copy(conn, org, brand, campaign_id, ad_id, body, actor)`: body
   exactly `{set_id, version_id}` (strings) else `ValueError("文案選項無效。")`; the ad must be a planned ad with a
   `slot_placement_id` whose current revision is unconfirmed, else `ValueError("slot_no_file")`; frozen → the same message as
   `upload`; `fields = workbench.material_source(...)["copy_fields"]` (a `ValueError` from it → 「找不到這個文案版本。」);
   `user_assets.revise(conn, org, brand, campaign_id, placement_id, current["revision"], {"copy_fields": fields, "purpose": current["purpose"] or ad["name"]}, actor)`;
   then `confirm_manual` on the new revision, then `settle`; return `{"placement": ..., "slots": read(...)}`.
6. `user_assets_routes.py`: `GET /brands/{brand_id}/campaigns/{campaign_id}/slots/copy-options` and
   `POST /brands/{brand_id}/campaigns/{campaign_id}/slots/{ad_id}/copy`, wired like `campaign_slots`／the upload route
   (same actor／brand checks and error mapping); map `slot_no_file` to 409 `{"code": "slot_no_file", "message": "這一格還沒有圖，先上傳圖再選文案。"}`
   using the file's existing error-mapping style.
7. Tests, `test_ads_slots.py` (extend the `env` fixture with a helper that dispatches the campaign pack, writes a copy
   output for the ad's set and adopts it — see `test_workbench_pack_api.py` for the output／adopt helpers, and
   `test_pack_being_worked_is_in_progress_but_never_counts_as_ready` for how this file already makes a pack):
   - selected copy, no file → `copy_only` with the three fields, the label 「工作檯第 1 版」 and a `workbench_href`; `ready` count 0;
   - upload into that slot → response `placement.confirmed_at` set, `placement.purpose == ad name`, copy equals the workbench
     copy, slot `ready`, `ads_ad.material_placement_id` set (no second call needed);
   - upload with an explicit `copy_fields` keeps the given copy (no override);
   - upload into an ad with no set → `image_only`, `copy: None`; `POST …/copy` with the brand's version → `ready`, placement copy
     = that version's fields; `POST …/copy` on a slot with no file → `slot_no_file`; bad body → 400;
   - `GET …/slots/copy-options` lists the adopted version with `copy_fields`;
   - a pending placement with copy but zero campaign budget stays `in_progress` (confirmation refused by `pending_reasons`),
     never `ready`;
   - every existing test in the file still passes unchanged in intent (update fixtures only for the two new keys).
   `test_ads_user_assets.py`: one case that `attach(..., purpose="x")` stores the purpose and the placement route still
   rejects `purpose` in a request body (unchanged behaviour, now asserted).
