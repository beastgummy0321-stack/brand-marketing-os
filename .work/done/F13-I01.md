# Objective

原生來源契約、資料保存與工作區生命週期。

建立 §6.9.1 的來源紀錄與 nullable 契約，讓外部活動能掛入同一工作區且不被舊生命週期誤結案。

# Done

1. 新增 ads_campaign.origin 及 imported 必要的 nullable 欄位；success_target 已 nullable 不重複改。內部建立 API 仍要求原本條件，來源未知不得用 0／假目標／今天補齊。
2. 新增 ads_external_entity／ads_external_daily，識別鍵、父層同帳號、欄位可用性、預算與指標 provenance 按 §6.9.1；數值不強制零，錯誤與覆蓋區間可持久保存。分頁缺列不刪舊節點。
3. 公開 API contract：既有 CampaignDetail 新增 origin、external_view（entities、observations、coverage、sync）與 capabilities。origin=internal 的舊欄位語意不變；imported 的 groups 可空，budget_total 不冒充原生 lifetime 預算。
4. 為 imported 新增明確可用操作集合，所有策略 adopt／budget／pack／publish／simulate／close 入口及排程檢查，回可理解的原因；不僅前端防護。保留查看、同步、加素材、內部安排及確認。
5. 品牌刪除計數／清理與 RLS 涵蓋新表，帳號隔離與 FK 驗證；ARCHITECTURE resource manifest 登記新表歸 ads，禁止跨模組 SQL。僅更新本票新增 ownership，不改全域規則。
6. 測試：舊 internal 行為、imported 無目標、活動層 lifetime、第三種非固定階層 fixture、多幣別、跨品牌 FK／API、日期已過仍可查看、直接打禁止入口被拒。
