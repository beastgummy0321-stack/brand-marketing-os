# Objective

`DiagnosisPanel.tsx`）在 `app/schedule/jobs.py:690-704` 連打三次模型，三次的**前四段完全一樣**
（methodology ＋ compressed ＋ reminders ＋ budget_section，實測約 16k tokens），只有最後一段
`role_text(lens)` 不同。這是全站唯一一個「同樣的 bytes 在幾秒內故意送三次」的地方，也就是
Anthropic prompt caching 唯一真的會命中的地方：第一次寫入 1.25 倍、第二三次讀取 0.1 倍。

`round_id` 三列的寫法，風險遠大於省下的錢。§0 連結：**learning**（判讀是學習的上游）。

# Done

## 1. 共同前綴標上 `cache_control`

`for lens in diagnosis_mod.LENSES:` 這個迴圈裡，把 `messages` 從一段字串改成兩個 text block：

```python
shared_prefix = "\n\n".join(
    section for section in (methodology_result.text, compressed, reminders, budget_section)
    if section
)
```
（**在迴圈外**算一次，本來每一圈重算一次同樣的字串）

```python
messages=[{"role": "user", "content": [
    {"type": "text", "text": shared_prefix,
     "cache_control": {"type": "ephemeral"}},
    {"type": "text", "text": diagnosis_mod.role_text(lens)},
]}]
```

- 段落順序與內容一個字都不能變（ADR 0068 §6／T8b：指令的位置會決定它會不會被照做；
  `role_text` 還是最後一段）。兩個 block 之間 Anthropic 會用換行接起來——如果你不確定，
  把 `shared_prefix` 的尾端保留原本的 `"\n\n"` 語意（第二個 block 的 text 前面補 `"\n\n"`），
  讓拼起來的字串跟今天**逐字相同**。
- 一行註解：為什麼只有這裡加快取（只有這裡在幾秒內重送同樣的前綴；其他呼叫點每次的 prompt 都
  不同，加快取只會多付 25% 的寫入費——ARCHITECTURE.md §1）。
