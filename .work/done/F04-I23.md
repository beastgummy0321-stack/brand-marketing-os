# Objective

投放中的 Campaign 現在**沒有任何提前結案的路**。使用者裁決（2026-09-12 第 13 條）是
「結束後 7 天自動結案並寫學習，**可提前手動**」——但畫面上的結案卡片只在
`c.status === "ended"` 時出現（`frontend/src/components/ads/PerformanceTab.tsx:220`），
而 **`ended` 這個狀態今天沒有任何程式會寫**（整個 `app/ads` 只有讀它的地方：
`jobs.py` 的自動結案條件、`judgment.py:106` 的分支、`routes.py:62` 的計數；沒有一支
UPDATE 會把 `live` 變成 `ended`）。自動結案的排程是把 `live` 的 Campaign 在 `end_date + 7 天`
之後直接變 `closed`。結論：結案卡片挂在一個永遠不會發生的狀態上，等於不存在。

**規劃師已經查過，工人不要再找也不要順手修**：

- 後端 `POST …/close` 不必改。`app/ads/closeout.py::close()` 只擋 `status == 'closed'`
  （原樣回傳、不重寫學習），`live` 進去照判照寫。
- 資料不足也不會出錯：`closeout._judge()` 在 `success_target` 沒設、指標未追蹤、
  或樣本 `低` 時一律寫「看不出」，不會硬判達成／未達成。
- `ended` 該不該有人寫（每日排程把過了 `end_date` 的 `live` 變 `ended`），或這個字乾脆
  從 judgment／計數裡拿掉——那是 **F05** 的決定，已記在 `.work/features/F04.md` 的
  Open notes 第 13 條。**這張票不碰後端、不碰狀態機**，只把已經存在的動作接給看得到的狀態。

# Done

只改 `PerformanceTab.tsx` 一個檔（外加它的新測試檔）。

1. **結案卡片對 `live` 也顯示**：`c.status === "ended"` 的條件改成
   `c.status === "live" || c.status === "ended"`。按鈕字**不變**，還是「立即結案」。
   卡片裡那句說明依狀態分兩種：
   - `ended`：維持現在這句，一個字都不改——
     「投放已結束，7 天後系統會自動結案，也可以現在提前手動結案。」
   - `live`：「提前結案會用到目前為止的成效判定，判定後這個 Campaign 不再更新成效」

2. **還沒到 `end_date` 時多一行小字**：`live` 且 `c.end_date` 還在未來（`end_date` 是
   `YYYY-MM-DD` 字串，可能是 `null`）時，在上面那句下面加一行
   「投放期間到 {end_date}，現在結案等於提前結束」（用既有的
   `text-xs text-muted-foreground` 密度，不加新的 token／樣式）。
   `end_date` 是 `null` 或已經過去 → 不顯示這行。
   比今天的寫法用本地日期，一行就好：
   `const today = new Date().toLocaleDateString("sv-SE");`（sv-SE 的日期格式就是
   `YYYY-MM-DD`），然後 `c.end_date > today` 直接字串比。**不要**為了這件事引新套件、
   不要動 `frontend/src/lib/format.ts`（在 `do_not_touch`）。

3. **確認對話框重複同一句**：`live` 時，`DialogDescription` 在現有那句
   （「結案後會對照成功條件寫下判定…不能再改。」）之外，補上第 1 點那句
   「提前結案會用到目前為止的成效判定，判定後這個 Campaign 不再更新成效」。
   `ended` 時對話框內容維持原樣。同一個字串只寫一次（宣告成一個 const 在元件裡，
   卡片與對話框共用）——不要抽成新元件、新檔案、新 `patterns/`。

4. **其餘一律不動**。數字來源的規矩照舊：這頁所有數字只認 `getPerformance`／
   `ingestOutcome`，不准讀 `campaign.outcome`。不動 `published` 判斷、不動
   `VerdictCard`、不動 `handleClose`、不改 `closeCampaign` 的呼叫形狀、不加
   `reason` 參數。
