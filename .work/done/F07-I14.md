# Objective

自由創作 no longer asks how many images to make. An image round is always 10 prompts (F07 Decisions 9, 25,
28), so a count field for 圖片 and an `image_prompt_count` in the payload are leftovers that mislead: today the
number only changes how many versions must be selected. Copy and video script counts stay exactly as they are.
Both halves live in the `workbench` module (the frontend `components/workbench/` folder is owned by it), so the
browser and the one backend default that re-adds the key change together.
Never delete or overwrite anything under `data/`.

# Done

1. **Precise control** (`FreeJobPage.tsx:466-475`): the 「產出數量」 field renders only when `control.part` is not
   `image_prompt`. For 文案 and 腳本 it is unchanged (number input, 1–30).
2. **`specToCreateBody`** (`FreeJobPage.tsx:110-143`): for an `image_prompt` output, `required_outputs.image_prompt`
   is `1` whatever count the parse returned, and `request` carries no `image_prompt_count` key. For `copy` and
   `video_script` nothing changes: `required_outputs[part] = count ?? 1` and `request[`${part}_count`] = count`.
   Rewrite the doc comment above it: the 2026-09-12 「五張」 ruling still holds for copy and scripts; images are one
   round of 10 with one version to select (F07 Decision 28).
3. **Preview and AI 解析結果** (`FreeJobPage.tsx:243-259`, `:507-513`): the preview pack card counts an
   `image_prompt` output as `required: 1`, and its 需要產出 badge reads exactly 「圖片（一輪 10 張）」. Other parts
   keep 「{label} {count} 份」.
4. **Backend default** (`app/workbench/repository.py::create_free_pack`, `:1082-1084` docstring and `:1096-1097`):
   delete the `request.setdefault("image_prompt_count", …)` line and the docstring's image half. The
   `video_script_count` default stays. A payload that still sends `image_prompt_count` is still accepted and ignored
   (`submit_brief`, `:67-69`, unchanged; Decision 25).

     The copy case (`:43-50`) stays.

     choose 文案 → 「產出數量」 is shown.

     and no 「5 份」.
