# Objective

Two new routes answer **422 before they answer 401/404**, because their Pydantic models have
required fields and FastAPI validates the body before `require_actor` runs:

- `POST /api/workbench/brands/{b}/packs/{p}/completion` — `CompletionRequest` (`routes.py:109-111`),
  required `key`, `checked`
- `POST /api/workbench/brands/{b}/parse` — `ParseFreeTextRequest` (`routes.py:161-163`), required
  `free_text`

That is the other 2 of the 9 failures: `test_identity_auth.py::NoAuthorizationSweepTest`
(no Authorization must be a 401 envelope) and
`test_identity_tenant_routes.py::RouteTableTenantTest` (another org's brand must be 404). Both
sweeps send `json={}`. The repo's convention is already written down one screen above the bug —
`NewFreePackRequest` (`routes.py:77-86`): every field optional with a default, real validation in
the repository or the handler, **after** auth and tenant.

# Done

- `CompletionRequest` → `key: str | None = None`, `checked: bool | None = None`, with the same
  two-line comment `NewFreePackRequest` carries (租戶界線先於欄位驗證). In `set_pack_completion`,
  after `require_actor`/`require_brand`: `body.checked is None` →
  `web.ApiError(400, "checked_invalid", "請指定要勾選或取消。")`; pass `body.key or ""` through to
  `repository.set_pack_completion`, whose existing `key_unknown` → 400 already covers a missing or
  unknown key (`repository.py:834`). Nothing about the repository changes.
- `ParseFreeTextRequest` → `free_text: str | None = None` (`defaults: dict = {}` is already fine).
  The handler already does `free_text = body.free_text or ""` and raises 400 `free_text_invalid`
  (`routes.py:172-175`), so a missing field now lands there — no handler change needed for this one;
  read it and confirm rather than adding a second check.
- Nothing else in the file gains optional fields: `RunProductRequest.count` is already optional and
  every other route takes no body.
- **Do not touch the tests.** In particular do not add these routes to `_MINIMAL_BODIES` or
  `_SWEEP_SKIP` in `app/tests/test_identity_auth.py` — the escape hatch would hide exactly the
  invariant this issue restores.

# Verify

The command above: the two sweeps go green and the five endpoint tests that send full bodies
(`test_workbench_approve.py:60`, `test_workbench_pack_api.py:205`,
`test_schedule_creative_pack_signal.py:66`, plus the parse tests) stay green. Then
`uv run ruff check app` and `uv run python -m pyright`.
