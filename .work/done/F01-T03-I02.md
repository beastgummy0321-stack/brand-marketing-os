# Objective

The three renderers, their validation and the job that wires them - one change, because the symbols
this deletes (`render_image_prompt`, `check_image_prompts`, `fixed_block_chars`, `FIXED_KEYS`,
`VARIABLE_KEYS`, `PROMPT_MIN`, `PROMPT_MAX`, `SUBJECT_PREFIX`) are called from `jobs.py` and
`validate.py` today; splitting it would leave the repository red between two issues.

Line order and wording are settled in ARCHITECTURE.md §5.6-§5.8. Every line is omitted entirely when
its content is empty - a missing promotion note means no 可用字句 line, not an empty one.

# Done — renderers (`prompts.py`, pure functions, everything passed in as arguments)

- `render_hero_prompt(fields, *, style_block, product_line, audience_line, appeal_line,
  quotable_lines, output_line) -> str` renders, in this order:
  `【風格】` / `【商品】` / `【受眾】` / `【這則的訴求】` / `【可用字句（逐字，不得改）】` /
  `【畫面】<scene>／<person>／<subject_position>` /
  `【圖上文字】大標：「<headline>」；副標：「<subhead>」；文字純色填滿，數字獨立成行` / `【輸出】`.
  The 副標 clause is dropped when `subhead` is empty. There is no 禁止 line and no 保留 line.
- `render_variant_prompt(*, count, appeal_sentence, quotable_lines, output_line, style_block) -> str`
  is a constant with slots, no model fields:
  「以附上的這張圖為基底，分別生成 <N> 個完全不同風格排版與人物的圖片，主要訴求保持不變。一次一張。」 then
  「不變：訴求「<appeal_sentence>」、可用字句「<quotable_lines joined by ／>」（數字逐字）、商品外型與 Logo、<output_line>。」 then
  「可變：場景、人物、構圖、文字排版位置、配色。」 then `【風格】<style_block>`.
  The 可用字句 clause is dropped when `quotable_lines` is empty; the `<output_line>` clause is dropped
  when `output_line` is empty (always in 探索模式). `appeal_sentence` is the node's 切角 (angle)
  label in 變體模式, and 「以這張圖原本的主訴求為準」 in 探索模式 or when the node has no angle label.
- `render_exploration_prompt(angles, *, style_block, product_line, purpose_line, quotable_lines,
  count) -> str`: `【風格】` / `【商品】` / `【目的與對象】` / `【可用字句（逐字，不得改）】` /
  `【任務】分別給我 <N> 張圖，每張一個不同的說服切角，排版與風格彼此差異要大：` followed by one line per
  angle `<i>. <name>｜<brief>｜圖上文字：「<on_image_line>」` (`<i>` counts from 1) /
  `【圖上文字】每張圖只出現它自己那一行字；文字純色填滿，數字獨立成行`. There is no 【輸出】 line: a
  manual brief has no format coordinate, and 「一張」 would contradict 「分別給我 <N> 張圖」.
- In prompts ① and ③ the `【可用字句（逐字，不得改）】` line joins `quotable_lines` with 「／」.
- These exact skeletons are transcribed in `app/methodology/image-prompt-template.md` §2-§4
  (F01-T03-I01, asserted by `ImagePromptMethodologyShapeTest`); the renderers must match them.
- `render_image_prompt` and `SUBJECT_PREFIX` are deleted.

# Done — validation (`validate.py`)

- `check_image_prompt(data, *, mode, count, quotable_text) -> list` replaces `check_image_prompts`:
  - `mode == "variant"`: `hero` must be an object whose `scene`, `person`, `subject_position` and
    `headline` are non-empty strings and whose `subhead` is a string or `null`.
  - `mode == "exploration"`: `angles` must be a list of exactly `count` objects, each with non-empty
    `name`, `brief`, `on_image_line`.
  - number rule, both modes: every digit run (regex `\d[\d,.]*`) inside an on-image string
    (`headline`, `subhead`, each `on_image_line`) must appear inside `quotable_text`; otherwise that
    item fails. When `quotable_text` is empty, any number fails - that is the intended behaviour
    ("no quotable text, no numbers on the image").
  - the failing item's `message` is exactly `數字「<n>」未出現在可用字句或品牌資料` (`<n>` = the first
    offending digit run). `quotable_text` is promotion-note lines **plus** brand context, and this
    message is fed verbatim to the model in the fix round (`jobs._fix_call` 「問題：」 line) and shown as
    the ❌ line - 「未出現在可用字句」 alone would tell the model the wrong search scope.
  - items keep the `{"path", "ok", "message"}` shape; paths are `hero.headline`, `hero.subhead`,
    `angles[3].on_image_line`.
- `fixed_block_chars`, `FIXED_KEYS`, `VARIABLE_KEYS`, `PROMPT_MIN`, `PROMPT_MAX` are deleted.

# Done — job wiring (`jobs.py`)

- Mode comes from the brief: `source_kind == "schedule_node"` -> `"variant"`, otherwise
  `"exploration"`. Nothing else decides it.
- Line sources, all read inside `jobs._run` and passed to `prompts.*`:
  - `style_block`: `repository.get_style(brief["style_key"])["style_block"]`.
  - `product_line`: the read is `bi_repo.list_official_assets(conn, brand_id)` (verified 2026-09-10:
    it is `SELECT * FROM official_asset WHERE brand_id = %s`, so every row carries `product_id`,
    `asset_kind` and `status`). There is no per-product, per-kind read and **you do not add one**.
    Decide with exactly this rule, invent nothing:
    「this brief has a reference photo」 == the brief's `product_id` is not null **and** at least one
    returned row has `asset_kind == "product_photo"` **and** `row["product_id"] == brief product_id`
    (`app/core/vocab.py:72-77`: the other kinds are logo / packaging / other and are not a product
    photo; a brand-level row has `product_id` NULL and never counts). Then the line is
    `見參考商品照：<product name>。不重述外觀。`; in every other case (no `product_id` on the brief, or no
    matching row) it is `無參考商品照，畫面以情境與人物為主，不畫商品特寫。` - never claim a photo the
    model cannot see.
    The rule lives in `jobs._product_line(conn, brand_id: str, product_id: str | None,
    product: dict | None) -> str` (module-level, this exact name and signature - `ProductLineTest`
    calls it directly).
    **The read is not wrapped in `try`/`except` of any kind.** The job runs on one connection
    (`app/core/db.py` `connection()`); a failed statement aborts the Postgres transaction, so every
    later statement fails anyway and a swallowed error only hides the first real cause. `Conn` has no
    savepoint API and `conn._pg` is off-limits, so no savepoint either: a read error propagates to
    `_run`'s existing failure path (`brief.status='failed'` + `last_error`), which also never claims a
    photo. The `_product_line` docstring must not mention a "read error -> no photo" branch.
  - `audience_line` (variant): `<audience label>；痛點：<pain label>` from `coordinates_snapshot_json`,
    dropped when both are empty.
  - `appeal_line` (variant): `切角：<angle label>——<說明>；標題公式：<hook label>——<說明>`, where 說明 is that
    label's `situation` text in `repository.list_coordinate_vocabulary()` (the read the copy part
    already uses); a label with no description renders as the label alone.
  - `quotable_lines`: the non-empty lines of `request_json.promotion_note`. `quotable_text` for
    validation is those lines plus the compiled brand context string this job already builds.
  - `output_line` (variant): `<format label>（<format 的 situation 文字>），一張` from the same vocabulary
    read; with no format coordinate it is `一張`. In 探索模式 it is empty.
  - `appeal_sentence` (prompt ②): as in the `render_variant_prompt` bullet above.
  - `purpose_line` (exploration): `request_json.free_text` or 「未指定」.
  - `count`: the `count` argument the job already receives (`image_prompt_count`).
- The model-facing worksheet: `prompts.image_prompt_prompt(department_text, methodology_text,
  brief_section, brand_context, *, mode, count, quotable_lines, headline_hint)` keeps today's join
  order (department text · methodology · worksheet · brand context). The worksheet is
  `brief_section` followed by these lines, in this order, each left out when its content is empty.
  They replace today's 「這張工單要幾則圖片提示詞…」 and 「已採用的標題（圖上文字只能從這裡逐字取用…）」
  lines:
  - `模式：變體模式` or `模式：探索模式；角度數：<N>`
  - `可用字句（逐字，不得改）：<quotable_lines joined by ／>`
  - `可用的大標（可用可不用）：「<headline_hint>」`. `headline_hint` is the first headline of the
    brief's adopted copy output when one exists, else `None`. It is an optional hint, never a
    constraint, and never appears in a rendered prompt.
  `app/departments/workbench/image_prompt.md` (F01-T03-I01) names these three labels; do not reword
  them. The pre-call `RuntimeError("沒有圖上文字可用…")` is already gone (`F01-T01-I03`); do not go
  looking for it.
- `body_json` for the part becomes `{"mode", "fields", "rendered": {"hero"|"exploration": str,
  "variant": str}, "validation": [...]}`.
