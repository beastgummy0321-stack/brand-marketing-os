# Objective
Background progress reads the real queue (Feature Contract G): the existing `/api/jobs/active` endpoint and its top-bar panel switch from running `llm_task` rows to the procrastinate queue, with position N of M, and the worker runs 3 jobs at once.

# Done
1. `app.background.queue_snapshot()` (facade, next to `is_active`): todo + doing jobs of the current queue schema in pick order (running first), `done_today`/`failed_today` per org from the queue's own records; no write. `routes_jobs_api.py` keeps its path and tenant filter (`org_id` from job args, brand re-checked), adds the Contract G fields and a label for every `background.ads_*` task plus the existing kinds (task names, not `llm_task` types). Other tenants' jobs only add to `other_count`.
2. `worker.py`: `run_worker(..., concurrency=3)`. Before changing it, measure on the dev stack and record in the report: `SHOW max_connections`, `pg_stat_activity` count with web + worker idle, and with 3 jobs running. Keep 3 unless the running count leaves under 20 free connections; then stop and report. List each `ads_*` task whose writes could race when two run at once and whether a procrastinate `lock` already serialises it.
3. Top-bar panel (`ActiveJobsBell.tsx`): prototype `topRight()`/`renderJobs()`, demos `jobs:ok` and `jobs:fail`: pill 「正在同步成效・還有 N 件排隊」, panel rows with position, 「前面還有 N 件」, today's done/failed line, and a read-failure state with 重試 (never 「沒有進行中的背景工作」 on a failed read). Escape closes, focus returns to the pill. Built from `components/layout/ui` primitives (layout may not import ads kit pieces). Side-by-side on `home` for both demos, port 8736.
4. Tests: position with two tenants' jobs, a job without `brand_id` in args (excluded from items, counted), concurrency argument passed to the worker, failed read in the panel.
