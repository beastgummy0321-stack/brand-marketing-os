# Objective
A new bundle shows the server's numbers while it is being built, as the prototype `#/bundle` does (found by F43-I13: before
「建立組合」 there is no unit price/cost per row, no summed 原價／成本, no 打平線, no offers, no 「廣告會用到的」 card, no 成交率 column).

# Done
1. `POST /api/intake/brands/{b}/bundles/preview`: same body as `POST /bundles`, same response shape as `GET /bundles/{id}` (id null),
   computed through the same facade path as a saved bundle (effective economics, offers, reused groups/proof, show_close_rate,
   benchmarks), **writes nothing** (a transaction that is rolled back, or a pure read path — prove no row is created). Refusals match
   create (fewer than 2 finished products, foreign product) as 400.
2. `BundlePage.tsx`: while the bundle is new, call preview on blur of a valid form (and after a component is added/removed) and show
   its values exactly as the edit mode shows GET values; no money arithmetic on the page.
3. Tests: preview returns derived list price / cost / break-even / offers for a two-product bundle and creates no product / component /
   economics row; the page shows preview numbers before create.
