# Objective
Test fixtures stop choosing their own clock (third failure from the same class this run). Between 00:00 and 08:00 Taiwan time on a
month's first day, fixtures that date rows with the UTC date (`db.now_utc()`, `datetime.now(UTC).date()`) land in the previous month
while the product reads the org's month (`coresettings.today_for_org`), so 7 tests went red on 2026-10-01 on master too. Test bugs only;
the product is consistent.

# Done
1. New helper `app/tests/org_clock.py`: `org_today(conn, org_id) -> date` and `org_month(conn, org_id) -> "YYYY-MM"`, both through
   `coresettings.today_for_org` (the product's own clock).
2. Use it where a fixture's date feeds an org-clock path:
   - `test_ads_change_control.py:52` (`self.month`) and `:1209`;
   - `test_meta_daily_spend.py:814, :828, :854` (rows read back through the month-window route);
   - `test_ads_copy_variants.py:226`, `test_ads_learning_flow.py:41`, `test_ads_recovery.py:79` (same latent pattern);
   - `test_schedule.py` BindTreeApiContractTest fixture (already fixed inline in F43-I03) switches to the helper.
   Leave UTC timestamps that are event times (`settled_at`, created/updated) alone.
3. No product code changes.
