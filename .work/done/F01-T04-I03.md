# Objective

The image-prompt card shows the round's failing validation lines again. `F01-T04-I02` replaced the
old per-prompt `failLine(validation, "prompts[i]")` display and dropped it; the backend still renders
a prompt whose checks failed and records the reason only in `body_json.validation`
(`app/workbench/jobs.py` `_render_image_prompt` docstring, lines 245-248). That list is the one
place the number rule of `F01-T03` (a number on the image must be verbatim from the quotable text)
reaches the user. Without it the user copies a prompt carrying an unsupported price.

# Done

- In `ImagePromptPartCard` (`BriefDetail.tsx`, today around line 240), read `body.validation` and
  keep every entry that is a string starting with `"❌ "`. Shape reference: `failLine` in the same
  file (lines 36-43) - `body_json.validation` is a string array `"✅ path：message"` /
  `"❌ path：message"`.
- Render those lines, each as `<p className="text-xs text-danger">` (the class the copy card uses at
  line 175), inside the ① 主圖提示詞 box in `variant` mode and inside the ③ 探索提示詞 box in
  `exploration` mode, below the prompt text. Every image-prompt check (`hero.*`, `angles`,
  `angles[i].*`, `_root`, `hero` in `app/workbench/validate.py::check_image_prompt`) concerns the
  model data that builds ① or ③; ② 變體提示詞 is built from the quotable text and gets no lines.
- Show the line text as stored (it already names the path and, for the number rule, the number).
  No new copy string, no new helper file; `✅` lines are not shown.
- Nothing else in the card changes: button order, 席位保留 button, `WarningsList`, count field.
