# Done
1. `claims.missing_offer(value, rows, offer_key) -> list[str]`: `offer_key` is `None`, `"none"`, or a key with no row in `rows` →
   `[]`; otherwise the registered sentences of the rows with that `offer_key` when none of them appears in any string of `value`
   (`_strings` walk; compare with all whitespace removed on both sides). One sentence present → `[]`.
2. Facade `validate_claims` returns `missing_offer` (from the same narrowed `sources(..., offer_key)`); existing keys unchanged.
   Document it in the docstring's public shape.
3. Backing rule: a RISK offer word is backed only when that exact matched term occurs inside the text of one of the available
   offer rows (`rows` with `offer_key`, already narrowed by the caller's `offer_key`). This replaces the family-wide backing of
   `_offer_backed` (F42) including 「優惠」; proof and endorsement words keep the exact-sentence rule. Update the module docstring.
4. `RISK` widened with: 第二件半價、半價、特價、特惠、下殺、限時、原價、早鳥價、加購價、組合價、現折、滿額、滿[數字]送、滿[數字]折（incl. 滿千送百）、
   再送、加送、送[數字]、回饋、點數、抽獎. A bare 「送」 is not a RISK word (送禮、送貨、贈送 stay clean); 「優惠價」 keeps matching via 優惠.
   `_OFFER_FAMILIES` keeps mapping terms to offer keys only where a key exists in `app/core/vocab.py` (read it, do not add keys);
   terms with no key stay exact-sentence.
5. The version list (`repository.py` near `claims.warning`): when the brief has an offer key and `missing_offer` is non-empty,
   `claim_warning` carries 「這組文案沒有寫這則廣告要帶的優惠：「〈sentence〉」。」 (merged with an existing unsupported-term warning
   into one message; same `href`).
6. Tests: the sell-way sentence 「三盒組優惠價 NT$999（原價 NT$1,500）」 under `offer_key="bundle"` → present → `[]`; absent → that
