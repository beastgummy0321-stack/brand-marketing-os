# Objective

The dispatch payload carries the node's length and the period's verbatim offer text, and the
schedule reads back one length - and keeps reading the image-prompt round correctly when the
workbench changes the shape of `rendered`.

# Done

- The `workbench.submit_brief` call in `jobs.schedule_tree` already sends `parts: ["copy"]` and no
  `kind` (`F01-T01-I01` moved that with the contract). This issue adds the two remaining keys, so the
  request becomes
  `{"use_brand_knowledge": True, "product_ids": product_ids, "parts": ["copy"],
  "copy_length": leaf.get("copy_length") or "short", "promotion_note": <promotion_note>}`.
  The promotion note is the one already frozen on the plan task row that this expansion came from
  (`plan_scope`; `schedule_plan` puts it into `context_scope`); send `None` when it is absent.
  Everything else in the payload
  (`source_kind`, `source_ref`, `product_id`, `coordinates`, `style_key`) is unchanged, and so is the
  per-node try/except.
- `state._copy_summary` returns `{"is_adopted", "generation_round", "copy_length", "bodies",
  "headlines", "descriptions", "visual_tone", "visual_concept", "validation", "warnings"}`:
  `copy_length` is `body_json["copy_length"]` falling back to `"short"`, `bodies` is
  `body_json[copy_length]` falling back to `[]`. The `short` / `medium` / `long` keys disappear from
  the shape the API returns.
- `state._image_prompt_summary` returns `{"generation_round"}` only. The `count` field goes: the
  workbench is about to write `body_json.rendered` as an object (主圖／變體 or 探索／變體), not a list of
  N prompts, so a count of prompt texts stops meaning "how many images". This issue owns that change
  and it is safe in either merge order - the new function never looks inside `rendered` at all.
- `_sync_creative_candidate` keeps working: wherever it read one of the three band lists it reads
  `bodies`.
- Assertions in `app/tests/test_schedule.py` that expect three band keys, that seed three-band
  outputs, or that assert an image-prompt `count`, move to the new shape - that is why this issue is
  a `legacy_migration`.

- **No new test file in this issue.** The assertions stay in `app/tests/test_schedule.py`, which the manifest lists as
  `legacy` - the container checker skips it, which is the only reason it may import both sides of the
  schedule/workbench line. A new `app/tests/test_schedule*.py` would be **schedule** code under
  ARCHITECTURE.md §2 and could not carry those imports; if you think one is needed, stop and report.

# Verify

`uv run python -m pytest app/tests/test_schedule.py -q -k "brief or copy"` - red before (the response still
carries three band keys and an image-prompt count), green after.
