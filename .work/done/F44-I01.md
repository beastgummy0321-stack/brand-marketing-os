# Objective
The brief's offer coordinate decides which offer the copy may write (feature outcome 2, Contract B). Today the copy step lists every
offer the sell-way has, whatever the coordinate says: drill 9 had 4 ads with coordinate `none` and copy 「優惠價 999（原價 1,500）」.

# Done
1. `claims.sources(conn, brand_id, product_id, offer_key=None)`: `None` = today's rows; `"none"` = no offer rows; another key = only
   the offer rows whose `offer_key` equals it. Rows without `offer_key` are never filtered.
2. `claims.policy(rows, offer_key=None)` adds one instruction line when `offer_key` is given: for `"none"` (or a key with no row
   left) 「這則廣告的優惠座標是無優惠：不寫任何優惠、優惠價或原價（售價可以寫）。」; for a key with a row 「這則廣告要帶下面
   [offer:…] 這個優惠：每一組文案都把它的原字句寫進標題或內文。」. Without `offer_key` the text is unchanged.
3. `jobs._run`: the offer key is `_resolve_coordinate(rows, "offer", snapshot["offer"])` of the brief's
   `coordinates_snapshot_json` (a snapshot may carry a key or a label); a brief without an offer coordinate passes `None`. It feeds
   both `claims.sources` and `claims.policy`, for every part that reads `claim_sources`.
4. The version reader (`repository.py` near `claims.warning`) narrows with the same brief offer key, so an offer word on an
   `offer=none` set shows the existing `claim_warning`.
5. Facade: `validate_claims(conn, org_id, brand_id, product_id, value, *, offer_key=None)` passes `offer_key` to `claims.sources`.
   Existing positional callers keep working.
6. `copy.md`: one sentence in its own style — the 優惠 part of the copy follows the 優惠來源 block; no source there, no offer.
7. Tests: `sources` for `None` / `"none"` / `bundle` on a sell-way with a list-price offer and a free-shipping policy; `policy` lines;
   `validate_claims(..., offer_key="none")` reports 「優惠」 for the sell-way's own price sentence and `offer_key="bundle"` does not;
   a set whose brief has `offer=none` gets a `claim_warning` on an offer version.
