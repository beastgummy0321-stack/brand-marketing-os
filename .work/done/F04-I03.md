# Objective

ARCHITECTURE.md §1 第 1 條在 `ads` 自己組的三段清單上：`app/ads/strategy.py` 把**全部**品牌事實
（還附 `updated_at`，:39-45）、**全部**學習（`list_learnings` 預設 limit=50，:87）送進 prompt；
`app/ads/brief.py::_products_context`（:61-90）把品牌**每一個**商品連同售價／單位成本／運費全部
送進去。同時 `app/departments/ads/strategy.md:25` 叫模型回一個固定三選一角色的中文 `label`——
那張對照表是程式的（`strategy.py:130-140` 只是收下它），叫模型填是花錢買一個我們已經知道的答案。

§0 連結：**strategy**（這一步要的是判斷，不是資料庫傾印）。一張票、一個模組、兩個檔案、
同一組測試。`app/ads/plan.py` 的座標詞彙**不在範圍內**：`key` 是英文 slug、`label` 才是意思，
拿掉會讓模型用猜的（F04.md Decisions 5）。

# Done

## 1. `strategy.py::_brand_facts_section`

- 取用上限：**讀 `rule_cards.get_value(conn, brand_id, "rule_prompt_cap", "max_active_rules")`**
  （預設 20）——跟 `app/llm/context_compiler.py` 同一張卡、同一個數字，不要在 `ads` 裡另立
  `_MAX_FACTS` 常數（一個上限只有一個出處；`app/core/rule_cards.py` 是 legacy facade，可以 import）。
  依 `confirmed_at`（沒有就 `created_at`，兩者都沒有就維持原順序）新到舊取前 N 筆；
  截斷時最後補一行 `（另有 N 筆較舊的品牌事實沒有列出）`。
- **`basis` 只列真的進 prompt 的那幾筆**（跟下面學習那一段同一條規則：「依據」要等於模型真的
  看過的東西，否則查看策略依據是假的）。
- prompt 的每一行**拿掉** `（更新於 {updated_at}）`——畫面上的「更新於」是從 `basis` 讀的
  （`StrategyTab.tsx:284`），`basis` 那一半**照舊帶 `updated_at`，一個字不動**。
- `strategy.md` 裡「品牌已知的事實（附更新時間）」那句話跟著改成「品牌已知的事實」。

## 2. `strategy.py::_learnings_section`

`bi_repo.list_learnings(conn, brand_id)` 的預設 limit 是 50。這裡明確傳 `limit=10`
（模組層 `_MAX_LEARNINGS = 10`），拿最新的 10 條；`basis` 也只收這 10 條（畫面上的「用到的學習」
必須跟真的進 prompt 的那些一致，不然「依據」是假的）。**不要**改
`app/brand_intelligence/repository.py` 的預設值（那是別的呼叫端的事）。

## 3. `brief.py::_products_context`

- 上限 **20** 個商品（`_MAX_PRODUCTS = 20`），順序照 `bi_repo.list_products` 現有順序取前 20；
  截斷時補一行 `（這個品牌另有 N 個商品沒有列出）`。
- 回傳的第三個值（`brand_product_ids`，用來過濾模型瞎掰的 `product_ids`）**仍然是全部商品的 id**
  ——那是驗證用的白名單，不是 prompt 內容，截了會讓合法的商品被當成瞎掰。這一點寫成一行註解。
- `get_product_economics` 的 N+1 照舊（20 次查詢不是成本問題，改成批次查是另一張票）。

## 4. `strategy.md` 不再要 `label`

- 交付內容裡刪掉 `label` 那一項與回覆範例裡的 `"label"` 鍵；`allocation` 變成
  `{"role", "pct", "rationale"}`。
- `strategy.py::_validate_reply`：不再要求 `label`，改由程式對照
  `_ROLE_LABELS = {"new": "新客", "retarget": "再行銷", "explore": "探索"}` 填進
  `validated_allocation` 的 `label` 欄位——**存進 `budget_basis_json` 的形狀一個鍵都不變**
  （前端 `StrategyTab.tsx:136` 讀 `item.label`，不能因此變 undefined）。
- 舊資料相容：模型回了 `label` 也不報錯，直接忽略（以程式的對照表為準）。
