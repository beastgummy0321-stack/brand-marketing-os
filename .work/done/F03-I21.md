# Objective

The demo CLI stops importing the assembly root. §0: it serves the acceptance walk (a full loop with
no platform); its input is a command line; its output is unchanged; its trace is
`app/tests/test_no_branch_imports_app_main.py` going green; it is pluggable.

`app/ads/demo.py:70-72` does `import app.main` inside its `__main__` block to trigger
`_load_dotenv()`. The AST gate scans **every** node under `app/ads`, `app/orders` and `app/intake`
including function-local and `__main__` imports — that is the exact evasion it was built to catch
(修憲落地 A4, no `app.main` ← branch import, ever). `app/meta/daily_pull.py` does the same thing
legally only because `app/meta` is not in `CHECKED_PACKAGES`; it is **not** a pattern to copy here.

# Done

- **Delete the `import app.main` line and its comment** from `app/ads/demo.py`'s `__main__` block.
  Nothing else in that block moves: `settings()` is still called first and the
  `brand_os_env == "production"` refusal still guards the script (it writes a whole simulated
  campaign — it must stay impossible to run in production).
- **`.env` comes from `uv`, not from importing the app**: the CLI line in the module docstring (`:6`)
  and the `argparse` `prog`/`description` become
  `uv run --env-file .env python -m app.ads.demo --org <org> --brand <brand> [--days 14]`.
  One sentence of comment says why (the A4 gate forbids `import app.main` under `app/ads/`;
  `--env-file` is `uv`'s own loader, uv 0.12 is what this repo runs). Do **not** re-implement a
  dotenv parser in `app/ads/`, do **not** add a dependency, and do **not** move
  `_load_dotenv` out of `app/main.py` — that would drag two legacy facades and
  `app/tests/test_main_dotenv.py` into a one-line fix.
- **The failure mode stays loud, and that is the point**: run without `--env-file`, `BRAND_OS_ENV`
  is unset → `production` → `settings()` raises its usual RuntimeError listing what is missing, or
  the script exits with its own production refusal. It never silently runs against the wrong
  database.
- Nothing else in `app/ads/demo.py` changes — not `run()`, not the campaign shape, not the
  coordinates.

# Verify

`test_no_branch_imports_app_main.py` (the gate that failed) plus
`test_ads_publish_simulated.py` (the simulated adapter this CLI drives — proof the module still
imports and its callees are untouched). No frontend gate, no e2e.

Optional manual smoke, not a gate and not required to finish (it needs `supabase start`):
`uv run --env-file .env python -m app.ads.demo --org org_bughunt --brand brd_bughunt`.

# Blocked if

The docstring change is not enough because something else in the `__main__` block genuinely needs
the full app assembly (a procrastinate task registration, a router import). Report what needs it and
why; do not solve it by importing `app.main` from anywhere under `app/ads/`, and do not add
`app/ads` to an exception list in the gate.
