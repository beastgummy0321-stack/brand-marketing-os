# Objective
Two material-path root causes (drill-8 #4 and the advanced-assignment copy). Backend only; no screen changes.
(a) A slot whose original finishes previewing in the worker stays 處理中 forever, because nothing calls the confirmation after
`process_preview` commits `ready`. (b) 「將成品指派給計畫中的廣告」 ships the library upload's old copy instead of the ad's workbench copy.

# Done
1. `app/ads/slots.py` gains one module function, e.g. `settle_ready_asset(conn, org, brand, asset_id) -> int`: for every current,
   unconfirmed placement of that asset that an `ads_ad` points at through `slot_placement_id`, run the same two calls the upload
   runs — `_confirm_if_ready(...)` then `settle(...)` — with actor = the placement's `created_by`, else `"system:preview"`.
   Returns how many slots it settled. Library placements (no ad points at them) are left for the user. Docstring names the reader.
2. `app/ads/user_assets.py::process_preview`: after the `status='ready'` commit, call it through a lazy import (the way `slots.py`
   imports `asset_suggestions`). A failure inside it is logged and swallowed — the asset stays `ready`, the slot keeps waiting and
   manual confirmation still works; it never flips the asset to `error`/`retryable`.
3. Advanced assignment: the route behind `POST …/handoff/assignments` (`handoff_routes.py` ~203) calls a new
   `handoff_assignment.assign_with_ad_copy(...)` (same signature/return as `assign`). When the ad has an adopted workbench copy
   (`slots._workbench_copy` for the ad's set) whose three fields differ from the chosen placement's `bindings.effective_copy`, it
   places the same asset for that ad through the slot-upload path (`slots.upload(..., {"asset_id": <placement asset>}, actor)`,
   which writes the workbench copy, confirms and settles) and returns `workspace(...)`; otherwise it calls `assign` unchanged.
   Clearing an assignment (`placement_id=None`) is unchanged. `slots.settle` keeps calling plain `assign` (no recursion).
4. Tests: `test_ads_user_assets.py` — upload into a slot while the original is `pending`; run `process_preview`; the slot's
   placement is confirmed and the ad's `material_placement_id` set, with no extra call; a library placement of another asset stays
   unconfirmed; a raising settle leaves the asset `ready`. `test_ads_handoff.py` — ad with adopted workbench copy + library
   placement with different copy → after the assignment route the ad's material snapshot `copy_fields` equal the workbench copy;
   ad without adopted copy → the library copy as before.
