# Objective
Root cause found by F27-I13 on real data: `copy_variants` is written only when the adapter parses a creative during sync (F27-I02), so every creative stored before that (all of brd_bughunt's dynamic ads — their `asset_feed_spec` has `titles`/`bodies`) reads as having NO copy until the next daily sync, and a review created meanwhile freezes empty copy. Make the variants a read-time derivation.
# Done
1. Adapter layer: a platform dispatch `copy_variants(platform, creative) -> {titles, bodies} | None` (Meta: parse `fields.asset_feed_spec.titles[].text` / `bodies[].text`, the same parser `creative_summary` uses — share it, do not duplicate).
2. `change_control_data.copy_fields` / `copy_editable`: when a dynamic creative lacks `fields.copy_variants`, derive it through that dispatch (entity carries `platform`); a stored `copy_variants` still wins.
3. Tests: an old-shape stored dynamic creative (asset_feed_spec with titles/bodies, no copy_variants) now yields the variants in copy_fields and `copy_editable.mode == "variants"`; catalog-only still refused.
# Verify
Issue verify plus manifest gates.
# Blocked if
`copy_fields` callers do not have the entity's platform — stop and report.
