# Objective
One original photo may back several ads, each with its own copy (drill-7 #6; user ruling 2026-09-29). Today the partial unique index
`ads_asset_placement_current (org_id, brand_id, campaign_id, asset_id) WHERE is_current` and `attach`'s lookup by `asset_id` force
one current placement per (campaign, asset), so the second slot upload of the same file with different copy hits
`PlacementConflict` (`user_assets_repository.py:257`, route 409 `placement_copy_conflict`).

# Done
1. Migration `supabase/migrations/20260929000011_ads_asset_placement_per_ad.sql`: `ALTER TABLE ads_asset_placement ADD COLUMN ad_id text
   REFERENCES ads_ad(id) ON DELETE SET NULL;` drop index `ads_asset_placement_current`; recreate it as a partial unique index on
   `(org_id, brand_id, campaign_id, asset_id, ad_id) WHERE is_current` (NULL `ad_id` rows are library attaches and stay distinct per
   Postgres NULL semantics — say so in the header comment). Header names F40-I02 and the reader (`attach`, `slots.py` upload).
   The lead applies it to the dev DB before merge; do not run it yourself.
2. `app/ads/user_assets_repository.py::attach` gains keyword `ad_id: str | None = None`; the "existing" lookup (lines ~250-254) filters
   on `ad_id IS NOT DISTINCT FROM %s` as well; insert writes `ad_id`. `PlacementConflict` keeps its meaning for the same ad with
   different copy. Module docstring sentence: 「one current placement per (campaign, asset, ad)」.
3. `app/ads/slots.py` upload path (~line 381) passes `ad_id=ad["id"]`. `app/ads/user_assets_routes.py` library attach passes nothing
   (NULL) — unchanged behaviour for the library.
4. Tests: `test_ads_user_assets.py:138` (the conflict assertion) becomes two cases — same ad + different copy → still 409; two ads +
   same asset + different copy → two current placements, no conflict. `test_ads_slots.py` — uploading the same file into two slots
   yields two `slot_placement_id`s and both slots read the same `thumbnail_url`.
