# Objective
The slot read tells every stored state as it is, with one chip and one sentence per state, and a stuck hand-off can be retried
(feature Contract T; audit W10; slots #1–#4, #11, #12; drill-11 R2 B5／P4). Today a failed preview reads 處理中 for ~15 minutes, a
failed copy generation reads 「等你：到工作檯選定一版文案」, a refused assignment leaves a confirmed slot saying 「等你：確認這版文案」
with 重新檢查 answering 「還沒有圖」, the structure tab paints one 缺素材 for six states, and a failed enqueue disables the material
task button forever.

# Done
1. `slots.STATE_TEXT` (Contract T) and every slot serving `state`, `state_label`, `state_text` (with `retry_at` on `retrying`, the
   brief's `last_error` on `failed`). `retrying` = original `retryable` (`error`, `next_attempt_at` read from the asset row the slot
   already loads); `in_progress` only for `pending`／`processing`; `failed` = the slot's workbench brief `failed` (status and
   `last_error` from the existing `workbench.briefs_for_source` read), exit = `workbench_href`.
2. Assignment refusal: `slots.settle` stores a refused `handoff_assignment.assign` as a placement refusal of kind `assign`
   (`asset_suggestions.store_refusal`, codes `campaign_closed`／`launch_frozen`, sentence naming why) instead of `continue`;
   `_blocked` reads `assign` reasons even on a confirmed placement, so the slot reads `blocked` with that sentence.
3. Confirmed slot edit (R2 B5／P4): while the campaign's launch is not approved, `choose_copy`／`recheck` on a ready slot revise its
   assigned placement (new revision, `follow_revision`) instead of `slot_no_file`; after approval they refuse with
   `FROZEN_MESSAGE`; ready slots serve `copy_editable` (true until the launch is approved). `copy_options` lists only the campaign's sell-way copy: `workbench.material_options(..., product_id=)`
   (`material_handoff.options` filters by the brief's `product_id`; `None` keeps today's brand-wide list for other callers).
4. Structure: `workspace_reads.structure` serves `slot_state`／`slot_label` per planned ad from one `slots.read` call;
   `missing_material` stays only as `slot_state != "ready"` (same source, kept so today's structure tab compiles until F49-I13;
   no second readiness rule — `_missing_material`'s own `ready_material` call goes).
5. Material tasks: `dispatch` on a revision whose `dispatch_status` is `unknown` and that has a `pack_id` retries
   `workbench.start_material_pack` on that pack (no second pack) and writes `queued` on success; the API answers the task with
   `state_label` from Contract T's material labels (by `dispatch_status` + the pack state from `workbench.pack_for_source`);
   `material_routes` exposes the retry through the existing dispatch call. The old test asserting `unknown` with no retry path
   (`test_ads_material_tasks.py:273`) is inverted: enqueue failure → `unknown`, label 交棒沒送出・可重試, a second dispatch starts the
   same pack once.
6. TS types: `lib/adsSlotsApi.ts` (states `retrying`／`failed`, `state_label`, `state_text`, `retry_at`, `copy_editable`), `lib/adsWorkspaceApi.ts`
   (`slot_state`, `slot_label`), `lib/adsMaterialApi.ts` (`state_label`) — optional keys only; the many tests importing these
   type modules are unaffected and not in `touch`.
7. Machine checks. `test_ads_one_ruler.py`: every state passed to `slots._slot` has a `STATE_TEXT` entry; no comparison against
   `ads_user_asset` status literals (`pending|processing|retryable|error`) or brief status literals (`queued|running|failed`)
   outside `slots.py`'s state function, `user_assets*.py` and `app/workbench`. `oneRuler.test.ts`: in the slot pieces
   (`workspace/SlotTiles.tsx`, `workspace/AssetsBody.tsx`, `workspace/StructureTab.tsx`, `patterns/SlotGrid.tsx`) the served chip
   words (處理中, 等你, 卡住, 失敗) written as string／JSX literals, a word table keyed by ≥2 slot states, and any `missing_material`
   read fail; allowlist today's hits → F49-I13, with the stale-entry test.
8. Tests: one per state → its `state_label`／`state_text`; a `retryable` original shows its error and retry time; a failed brief
   reads `failed` with `last_error`; a confirmed placement whose assignment is refused reads `blocked` with the refusal and
   `recheck` does not answer `slot_no_file`; a confirmed slot on a draft campaign accepts a copy change (new revision, still
   ready) and refuses after launch approval; copy options exclude another sell-way's copy; the structure read carries `slot_state`.
