# Objective
Slots and upload-into-a-slot for the assets tab (Feature Contract F).

# Done
1. `slots.py` + `GET …/slots`: slot = planned ad (app-built) or platform ad (imported); thumbnail from the bound material or the platform creative (reuse the triage thumbnail helper, no copy); `in_progress` when a pack is being worked; `requests` = open replace tasks with `state_label` from the task's own state, 100 cap with `requests_truncated`.
2. `POST …/slots/{ad_id}/upload` binds an uploaded user asset to that planned ad through the existing placement path. Only if a column is needed, add it in `20260926000001_ads_slot_binding.sql` (ads prefix; check `grep -rn "REFERENCES <table>" supabase/migrations/` first).
3. A replace request on an app-built ad that already launched resolves to its platform entity when one is bound; otherwise the slot carries no request.
4. `adsSlotsApi.ts` types and calls.
5. Tests: draft with ready／missing／in-progress slots, imported campaign, upload binding, replace request on a launched app-built ad, a deleted replaced entity (null name/thumbnail), truncation.

# Verify
Issue verify plus manifest gates; run all `app/tests/test_ads*.py` before reporting. The lead applies the migration first if one exists.

# Blocked if
App-built ads never get a platform entity binding after launch, so a replace request cannot reach them — stop and report.
