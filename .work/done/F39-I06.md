# Objective
One wall clock on the two paths the drill could not move (drill-7 #17): the month-budget freshness check and the sync table's
`observed_at` both read `app.core.db.now_utc()`, which `scripts/drill/clock.py::patch_modules` already rebinds. Product
behaviour in real time is unchanged.

# Done
1. `app/ads/month_budget.py::_fresh`: `now_utc() - stamp < timedelta(hours=24)` (import `now_utc` from `app.core.db` at module
   level like `external_sync.py` does, so the drill rebinding finds the name).
2. `app/ads/external_repository.py`: the two `observed_at=now()` SQL fragments (upsert of daily rows near line 154 and the
   snapshot upsert near line 284) become `observed_at=%s` with `now_utc()` passed as a parameter. `updated_at` and
   `status_changed_at` audit columns stay SQL `now()` (audit stamps stay real, per the `today_for_org` docstring).
3. Tests: `test_ads_month_budget.py`: monkeypatch `month_budget.now_utc` 25 h ahead → `_fresh` false, 23 h → true.
   `test_ads_external_sync.py`: monkeypatch `external_repository.now_utc` to a fixed datetime, upsert a row, read back
   `observed_at` equals it.

# Touch notes
Other tests importing these modules are unaffected: `_fresh` keeps its signature and the SQL change only moves the timestamp from `now()` to a bound parameter; nothing asserts the SQL text (grep `observed_at=now` in app/tests: none).
