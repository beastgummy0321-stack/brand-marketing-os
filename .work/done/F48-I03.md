# Objective
One learning writer (feature Contract W): every `learning_ledger` row from `app/ads` goes through
`ads_learnings.write()` and carries the sell-way it belongs to, so the strategy's 「one verdict per product」 reader
(`strategy._newest_per_product`) sees every sell-way instead of one brand-level row (planning #9).

# Done
1. `ads_learnings.write(conn, org_id, brand_id, *, product_id, text, scope, confidence, sample_size, source_cycle_id,
   source_track, needs_revalidation=False, platform=None, actor="system")` — the only `bi_repo.record_learning` call in
   `app/ads`. `product_id` is a required keyword (pass `None` explicitly only for a campaign without a sell-way; the
   docstring says so). Returns the row.
2. Move the six call sites onto it: `ads_learnings.record_for_item`／`record_for_ab_item` (product = the campaign's
   `sell_way.of_campaign`), `coordinate_learning.write_coordinate_learnings` (the ad's `sell_way.of_ad`), `learning
   .write_learning` (campaign sell-way), `settle` (entity → bound campaign → sell-way; imported campaign → `None`),
   `visual_learning` (campaign sell-way). `sell_way.py` may gain `of_campaign_id(conn, org, brand, campaign_id)` if a
   caller only has the id.
3. `strategy._learnings_section` / `_newest_per_product`: no code change expected beyond a comment; the test proves the
   reader with rows the WRITER produced (two closed campaigns of two sell-ways → both verdicts in `basis.learnings`).
   `OneCurrentLearningPerProductTest` stops writing `product_id` itself.
4. Machine check in `test_ads_one_ruler.py`: AST scan — a `record_learning` attribute call anywhere in `app/ads/**` outside
   `ads_learnings.write` fails, naming file:line; a planted offender is caught; every writer test asserts the stored
   `product_id` equals the campaign's sell-way.
