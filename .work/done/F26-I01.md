# Objective
Judgement reads ACTIVE ads only; the response carries the closed ads; the 「資料不足」 queue row is raised. Read-only, no migration.
# Done
1. New `app/ads/ad_status.py`: `CLOSED_STATUSES` (PAUSED, DELETED, ARCHIVED, ADSET_PAUSED, CAMPAIGN_PAUSED) and `is_closed(status)` — `None` is NOT closed. Import it from `triage.py`, `triage_scale.py` (replacing its own three-value set) and `month_budget.py` (same five values it already lists inline).
2. `triage.classify()`: judge only non-closed ads; add the `closed` block of Feature Decisions (numbers from the same `_ad_window` read; ≤ 50 items + `truncated`); `counts`/`total_ads` cover active ads only.
3. `app/core/interrupts.py`: register `ads_triage_insufficient_data` (severity `rule_warning`, label 「活動資料不足待處理」) — the only change to that file.
4. `triage.refresh_queue`/`_queue_payload`: raise and supersede the insufficient-data row per Feature Decisions; payload `kind_key`/`insufficient`; `KINDS_AVAILABLE` gains it.
5. Types in `adsTriageApi.ts` (`CampaignTriage.closed`, `QueueItem.insufficient`, the new `kind_key`), fixing frontend test factories the required fields break (`cd frontend && npm run build` must pass).
6. Tests: a campaign of 5 active + 11 paused + 4 archived judges 5 and reports closed 15 with the split; a null status is still judged; scale/refresh rules unchanged by the shared constant (ADSET_PAUSED now excluded — add a case); insufficient-data row raised for missing days, for failed sync, for disconnected, not raised without active ads, deduped and superseded.
7. `docs/architecture/ads.md` §6.29: the constant, the rule, the payload, the new row.
