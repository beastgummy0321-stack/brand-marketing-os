# Objective
Drill-6 #15, ruling B: 「照上一期」 divides by the days that actually spent. Root cause: `channels.account_spend_history`
(`app/ads/channels.py:102-116`) computes `spend_summary(...)["spend"] / 30` with `"days": 30`, and
`repository._account_history` (`app/ads/repository.py:842-858`) hard-codes `sample_days: 30`; an account that ran 7 of the
last 30 days gets a diluted daily base. `meta_repo.daily_entity_spend` (`app/meta/repository.py:736`) is public and returns
one row per (spend_date, entity). Coupling to the connections coverage rule is out of scope (ruling C).

# Done
1. `channels.account_spend_history`: keep the 30-day window; read `meta_repo.daily_entity_spend(conn, org_id, account_ids,
   since, today + 1, level="campaign")`, sum spend per `spend_date`, `days_with_spend = number of dates with spend > 0`;
   `daily_spend = total / days_with_spend` (None／no history when 0 days); return `"days": days_with_spend` and keep the other
   keys (`cpa` may stay from `spend_summary`). Docstring states the rule.
2. `repository._account_history`: `sample_days = hist["days"]`; `source_text` becomes 「Meta 近 30 天有投放的 N 天平均日花費」.
3. `budget._history_scenarios` caption: prints the new `source_text` unchanged (verify it does not re-add 「30 天」).
4. `test_ads_strategy.py:455-471`: two spend days 300 + 600 → `last_daily_budget == 450`, `sample_days == 2`, source text names
   2 days; a window with zero spend days → no account history (the existing "no history" branch); 30 full days → unchanged result.
