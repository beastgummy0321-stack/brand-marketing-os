# Objective
One claims guard (feature Contract G, decisions 7 and 13): the workbench warning and the slot block judge the same text
the same way — registered names stripped, both forbidden stores read, scoped to the sell-way; a registered discount
sentence backs the discount family; a statutory hit is a reminder on the row, never a stored 「不能講」; the offer an ad was
written for is one resolver; the slot tile gets its statutory reminder.

# Done
1. `app/workbench/claims.py`: `forbidden_terms(conn, brand_id, product_id)` (forbidden claims of the sell-way's knowledge
   products + brand-level ones with no product; `rule_type='forbidden_word'` rules brand-level and for those products;
   each entry text squashed), `registered_names(conn, brand_id)` (active product and sell-way names, longest first).
   `unsupported(value, rows, *, names=())` strips `names` and approved statements before the RISK scan; approved product
   claims (`claim_type='approved'`, `product_id` set) enter `approved` as typed — the `< 10` chars and 不能／不可／禁止 and
   fulfilment-word filters apply to brand facts only (`test_workbench_claims.py:26` flips: 「全館免運」 approved → 「免運」 not
   reported). `_offer_backed`: a term of the discount family (`_OFFER_FAMILIES` `discount`, plus 優惠／原價／特價 moved into it)
   is backed when any offer row has `offer_key == "discount"`; every other family keeps the exact-term rule (限時 only by a
   `limited_time` row's text, 買N送 only by a `bundle` row's text); 滿額 stays exact-term. `forbidden_hits(value, terms)` →
   matched entries (squashed substring). Module docstring: supersedes F46 Contract O for the discount family only.
2. `workbench.validate_claims(...)` gains `forbidden_terms: list[str]` and strips names; `claims.warning` names them in
   the same message (「「頻尿」是你標了不能講的話」); new pure facade `workbench.statutory_reminder(value, regime)` → the
   `statutory_warning` shape or `None`.
3. `app/ads/asset_suggestion_policy.violations`: drop the `forbidden` argument and `source_rows`' brand-wide forbidden list;
   block on `validate_claims(...)["forbidden_terms"]` with the detail 「文案寫了「〈terms〉」，這是你標了不能講的話。」 (kind
   `copy`, terms). Both calls keep the sell-way. `source_rows` returns sources only.
4. Offer truth: `live_creative.offer_for(conn, org, brand, campaign_id, ad)` = the dispatched set's
   `coordinates_snapshot_json.offer` (same lookup `learning_coordinates` uses), else the ad's current `offer_key`.
   `asset_suggestions._judged`/the `offer_key` read at `:61-82` uses it; `slots` serves `offer_key` beside `offer_label`
   from the same resolver. Coordinates stay editable (§6.35); the test edits `offer_key` after dispatch and asserts the slot
   judgement and the stored learning name the snapshot's offer.
5. `slots.read`: each planned slot carries `statutory: {terms, sentence, href} | null` = `workbench.statutory_reminder`
   over the slot's copy (regime read once per call through `bi_repo.get_brand`); computed at read, nothing stored.
6. Intake: `product_onboarding._check_claims` keeps the sent verdict (a statutory hit no longer forces `no`); `unset`
   counting unchanged; `get_evidence` still attaches `statutory` per claim. `custom.py` returns `option["statutory"]` without
   rewriting `verdict`. The frontend step is F48-I12.
7. Tests: workbench `warning` and slot `violations` give one term list for the same copy (shared fixture); 「超能特惠組」 in
   copy with that sell-way registered → no 特惠 warning; a `forbidden_word` rule 「頻尿」 and a product-level forbidden claim each
   warn in the workbench and block in the slot; product B's forbidden claim does not block product A's copy; a discount row
   backs 「折扣」／「特價」 but not 「限時」／「買一送一」; a statutory-hit claim sent `ok` is stored `approved`; slot payload carries
   `statutory` for food_tw copy and `null` without a regime.
