# Objective
The background runtime stops reading campaigns that no longer need it and stops raising an unresolvable inbox row every day
(feature Contract N; audit W7 runtime gate; triage #4; drill-11 R4 H3／G3, R3 E3's read half). Today closed and ended campaigns
keep a 6-hourly 30-day platform read, a 15-minute readback of every bound item (confirmed ones too) and a fresh
「廣告追蹤有待確認項目」 interrupt per campaign per day.

# Done
1. `runtime.dispatch` enqueues only campaigns for which `lifecycle.monitored(campaign, today)` holds (selected through
   `lifecycle`, Contract L; review-monitor dispatch is unchanged). `run_campaign` re-checks `monitored` and returns without a read
   for a campaign that left the set between dispatch and run.
2. `external_sync.request_sync` builds per-campaign sections (`structure`, `creatives`, `observations`) only for roots of monitored
   campaigns, plus `campaign_ids` passed explicitly (`external_routes.campaign_sync` passes the campaign the user asked to
   re-read, monitored or not); account tasks (`list`, `monthly:*`) are unchanged. `dispatch_daily` and
   `runtime._sync_brand_accounts` keep reading every bound account.
3. `_readback` selects handoff items and actions whose state is not `confirmed`／`stale` (a confirmed item is never re-read by the
   tick; the user's 重新核對 still reads it).
4. Health: dedupe key `ads-runtime:{campaign}:{code}`; after raising, the tick resolves (`interrupts.resolve(..., actor="system")`)
   every open `ads_runtime_attention` row of this campaign whose key is not raised this tick, old dated keys included (prefix
   `ads-runtime:{campaign}:`). `plan_date_passed` is not raised (the queue's closeout row, F49-I05, carries it); the internal
   live → ended write stays `lifecycle.record`. `closeout.close` resolves the campaign's open `ads_runtime_attention` rows in its
   transaction.
5. `jobs.close_expired_campaigns` (compatibility handler) enqueues only monitored campaigns; the beat and queue-refresh brand
   selections stay as F49-I01 left them.
6. Tests (the machine check for this rule): a closed campaign and an ended one past `ENDED_GRACE_DAYS` with platform entities are
   never enqueued by `dispatch` and get no per-campaign task from `request_sync`, while an explicit `campaign_sync` still reads
   it; an ended campaign inside the grace days is still read; two ticks on the same alert leave one open interrupt; an alert whose
   condition cleared is resolved by the next tick; a confirmed handoff item is not re-read by the tick; closeout leaves no open
   runtime row.

# Touch notes
`lifecycle.py` is in touch only to add a selector the dispatcher needs (e.g. `monitored_ids`); Contract L's rules do not change
here. `_sources` already reads the sync outcome (F49-I02). The queue's closeout row is F49-I05. Interrupt resolution goes through
the public `interrupts.resolve`; `app/core/interrupts.py` is not edited.

# Rescope (lead, after first pass)
1. An alert must come back after it clears: the dedupe key carries the episode (`ads-runtime:{campaign}:{code}:{since}`, `since` = the day the condition was first seen in this run of it, kept in the campaign's runtime state and dropped when the condition clears). No core change.
2. A campaign that leaves the monitored set by the grace days has its open runtime alerts resolved (dispatch sweeps non-closed, unmonitored campaigns with open runtime alerts; cheap, at most once per day).
3. `recovery._pending_evidence` counts only items of monitored campaigns (sibling of Contract N).

# Blocked if

interrupts API: stop and report.
