# Objective
The strategy and delivery-plan models plan for the people who buy this sell-way (discovery root cause: the plan prompt sees no
product knowledge and `audience_hint` is ignored). Program assembles the groups; the model only uses them.

# Done
1. New `app/ads/customer_groups.py::prompt_section(conn, org, brand, campaign) -> (text, ids)`: groups of the campaign's
   `context_json.customer_group_ids` (default: all groups of `knowledge_product_ids` of the campaign's sell-way), ≤3 per knowledge
   product and ≤6 in all, each line 「第 N 群：〈who〉｜煩惱：〈pain label〉（pain=〈key〉）｜顧客會說：〈quote〉｜什麼時候用：〈when〉」, header
   【這個賣法的顧客】, a 「另有 N 群沒有列出」 line when capped, 「（這個商品還沒有建顧客群）」 when none.
2. `strategy.py`: `_products_section` groups by `knowledge_product_ids` (a bundle lists every component product's facts, same caps);
   the prompt gets the groups section after the products section; `knowledge_item_ids` include the group ids. `plan.py`: the same
   section before the vocabulary table (vocabulary stays last).
3. Department files: `strategy.md` — the allocation `rationale` names the group each role targets when groups exist;
   `delivery_plan.md` — each ad's `pain` comes from a listed group's pains and its `scene` fits that group's 「什麼時候用」. Keep each
   file's style; nothing else changes.
4. Tests: `test_ads_customer_groups.py` (new) — caps, default vs picked `customer_group_ids`, bundle with two products. Strategy/plan
   tests — the section appears (and appears before the vocabulary in plan), group ids reach `knowledge_item_ids`; the department
   files contain the new rule phrase. `SCRIPTED_REPLIES` shapes still pass (`test_ads_plan_scripted_reply.py`).

# Touch notes

assertions on other prompt parts stay valid; report if red.
`knowledge_product_id` stays in the facade for callers not moved yet; this issue moves `strategy.py` only.
