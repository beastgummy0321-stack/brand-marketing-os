# Objective
Stop `app.background` from holding idle queue connections it does not need (F31-I11 part 2 root cause). Measured by I11: each process holds the defer App's pool at procrastinate's default `min_size=4`, and `_sync_app_for_defer` rebuilds the App on a DSN change without closing the old one (conftest now closes it for tests; the structural fix belongs here). With 97 usable server connections, ~30 taken by Supabase and ~18 by the running dev stack, the manifest's `pytest -n 4` peaks at ~13–14 connections per xdist worker and exhausts the server.

# Done
1. The defer App's `SyncPsycopgConnector` pool opens lazily with `min_size=1` (keep a small `max_size`, e.g. 4; `enqueue()` is one short statement per call). Check procrastinate/psycopg_pool's accepted kwargs in the installed version; don't guess.
2. `_sync_app_for_defer` closes the previous App's pool when it rebuilds for a new DSN (same for the async `app()` rebuild at ~:187 if it leaks the same way — verify before changing).
3. One test in `app/tests/test_background.py` that fails before: after a DSN switch the old defer App is closed, and a fresh defer App holds at most 1 idle connection after one enqueue (count via `pg_stat_activity` filtered by a unique `application_name`, or the pool's own stats).
4. Report the measured per-process peak before/after (I11's method: tag connections, sample `pg_stat_activity`) on a -n 2 subset.

# Verify
Issue verify plus manifest gates. The runtime worker (`app/worker.py`) keeps working: run `test_background.py` which covers `run_worker`.

# Blocked if
procrastinate's `SyncPsycopgConnector` does not accept pool sizing in this version — report the version and the alternative (e.g. passing a pre-built `psycopg_pool.ConnectionPool`).
