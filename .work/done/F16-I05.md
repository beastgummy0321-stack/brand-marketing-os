# Objective
F16-I01 made `ads_outcome_daily.purchases`/`revenue` nullable, but `ingest_meta` still has nothing real to write:
`app/meta/repository.py::daily_entity_spend` returns spend/impressions/clicks/roas/currency only, so every Meta-sourced row
is still `NULL` and a real campaign still closes as 看不出. F16's Outcome and Acceptance line 1 are not met by I01 alone.
The data is already stored — `meta_entity_spend.actions` / `action_values` (jsonb) are populated by the existing daily pull
(4,196 of 5,203 rows carry `actions`; 1,885 carry a purchase action). Nothing new needs to be fetched from the platform.
# Done
- The existing meta public facade gains a per-entity per-day purchase count and purchase value, derived from the stored
  `actions` / `action_values` through the existing `external_purchase_values()` synonym rule
  (`app/meta/repository.py:815-829`). That rule stays the ONE definition of purchase synonyms — no copy, re-implementation
  or second priority list in `app/ads/**`. This is a facade addition only; no new Graph field, no new permission, no read
  beyond what the daily pull already stores.
- `ingest_meta` (`app/ads/outcome.py`) writes the real purchase count and revenue: `NULL` when the stored row has no
  purchase action, `0` only for a tracked zero. Revenue keeps its existing meaning and must not be double-derived from both
  `roas` and `action_values` — state in the docstring which one wins and why.
  Ordering dependency: F16-I01's `20260920000002_ads_outcome_legacy_meta_unknown.sql` normalises pre-F16 Meta literals to
  `NULL` and MUST sort before anything here that writes real Meta purchases. Getting NULL/0/real right at this write is what
  makes that normalisation a one-off — no later migration may be needed to repair rows this issue writes.
- The attribution window and the chosen action synonym are reported alongside the number (the same
  `attribution_key` / `action_type` shape the external path already uses), so a number is never shown without saying how it
  was counted.
- No double counting: `ads_outcome_daily` (internal campaigns, ingested from `meta_entity_spend`) and `ads_external_daily`
  (imported campaigns, ingested by `external_sync`) stay separate paths. State explicitly in `docs/architecture/ads.md`
  which campaigns read which path and why a campaign never contributes to both.
- Remove the three remaining stale claims that an ended campaign closes itself after 7 days:
  `app/main.py:454` (comment only — do not touch any code in that file), `app/ads/__init__.py:63`,
  `frontend/src/lib/adsApi.ts:726`. Text only, no behaviour change.
- `docs/architecture/ads.md` and the drill-4 backlog entry reflect the implemented state.

plus a fixture with no purchase action that stays `NULL` and yields 看不出, plus a tracked-zero fixture that stores `0`.
