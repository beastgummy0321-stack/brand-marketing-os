# Objective

畫面上永遠不出現一串使用者 id。實機走查（2026-09-13）抓到兩處把原始 auth uuid 直接印給人看：

- `frontend/src/components/ads/AllCampaignsPage.tsx:227-228`：
  「由 b0a57eef-0000-4000-8000-000000000123 建立」。
- `app/ads/judgment.py:202-204`：`action_line()` 的 `detail` 拼成
  `f"{approved_by}・{sync_text}"`，`approved_by` 是同一串 id，出現在首頁「最近做了什麼」
  與總覽分頁的時間軸。

**規劃師已經查過，工人不要再找**：這套系統沒有「顯示名稱」這個東西。`app/identity` 的
`app_user` 只有 `id`／`email`／`created_at`（`supabase/migrations/20260828000002_identity_baseline.sql`），
`identity` 的公開入口只出 `ActorContext`／`authenticate`／`register`，而且
`ARCHITECTURE.md` 的 `ads.may_depend_on` 只有 `["workbench"]`——為了一行署名去開一條
`ads → identity` 的模組相依（外加每筆 payload 一次查表）比這行字值錢的多。
**所以這一版的答案是：把 id 拿掉，不做名字解析。**（等 F05 真的有成員管理畫面、identity
出得了顯示名稱時再回來加。）

# Done

1. **清單頁拿掉署名那一行**（`AllCampaignsPage.tsx:227-228`）：刪掉
   `{c.created_by && (<p …>由 {c.created_by} 建立</p>)}` 整段，那一格只留建立日期。
   `CampaignCard.created_by` 這個欄位**留在 API 與型別裡不要動**（`frontend/src/lib/**`
   在 `do_not_touch`），只是不再印。

2. **時間軸 detail 不帶 id**（`app/ads/judgment.py:202-204`）：
   `detail = f"{approved_by}・{sync_text}"` → 只留同步狀態文字，
   `detail = sync_text or "已記錄"`（`sync_state` 認不得時的退路；`AdsActionLine.detail`
   在前端是必填字串，不可以回 `None` 或空字串）。
   `approved_by` 這一欄照樣寫進 `ads_action`、照樣出現在 `actions` 原始列裡——
   拿掉的只是「印給人看的那句話」。

**只做這兩條。** 不做名字解析、不加 `/api/identity/me` 呼叫、不改 payload 形狀、
不動首頁與總覽分頁的元件（它們印的就是這裡改好的 `detail`）。
