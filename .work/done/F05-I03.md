# Objective

一個看得到來源、改得動、而且**模型永遠碰不到**的地方（`ARCHITECTURE.md` §8 第 3 條）。

這張票只做那張表。它很小，但它是「誠實」這件事的物理位置——所以獨立一張票、規劃師審。

`source_text` 的規則（**唯一一處組這句話**，前端不重拼）：
- 有來源：`f"{label} · {note} · 來源：{source}"`
- 沒有來源（運費）：`f"{label} · {note}，之後可以再改"`——**不准出現「來源」兩個字**。

檔頭 docstring 要寫死三件事：
1. 證據檔是 `.harness/scratch/research-onboarding.md`（每一條都逐字查證過，含查不到的那些）。
2. **台灣沒有可引用的一手數字**（ECPay 的數字自己註明轉引自美國 WordStream；SHOPLINE／91APP 沒有公開
   基準；代理商貼文沒有方法論）。所以這三個值全是海外的，畫面必須說出來。
3. **模型永遠不提供這些數字**；正確的取代路徑是這個品牌自己的結案數字（F06），不是更好看的部落格。

# Blocked if

- 想加「產業別」對照表（電商 / 美妝 / 保健各一組數字）→ **不行**。research 檔查證過：D2C 那些
  「美妝 50-70%、保健 65-78%」只出現在沒有一手資料的聚合部落格。一個沒有來源的細分表比一個誠實的
  粗略值更糟。
- 想讓模型來猜毛利率 → 絕對不行。
- 想在這個檔案裡寫任何跟 `product_economics` 有關的寫入邏輯 → 不行，它只是一張表。
- 想把畫面文案拆到前端拼 → 不行，`source_text()` 是唯一出處。

# 為什麼 `legacy_migration: true`

檔案落在 `app/brand_intelligence/`（legacy 套件）。放這裡是因為它就是品牌永久層的資料，
而且唯一的寫入者 `save_product_economics` 也在那裡；放到別處會讓 `app/intake` 與 `app/ads` 各自
去 import 一個新套件。這是**新增一個同層的小資料檔**，不是在 legacy 裡長新能力。
