# Objective
The Meta history pull and daily pull, and the schedule tree's material pack, end with a stored outcome a screen can read
(feature Contract J, per-job table; audit W14; slots #8 (meta readers), #14; other F10 (backfill); drill-11 R7 A12; controls
a-66 「開始拉 37 個月」 按下去後頁面一模一樣、後端 running:false、ad_rows:0). Today `run_backfill` writes nothing, the backfill status
read carries only `running` and row counts (never-ran, ran-empty and failed look the same), and a failed `submit_pack` leaves the
tree `succeeded` with every brief 「missing」 and no reason.

# Done
1. `daily_pull.run_backfill` returns `Empty("no_rows")` when it wrote 0 rows, `Failed(code, text)` when an account failed (the
   accounts and the classified Graph reason in `text`, `app/meta/graph.classify_error` kinds as `code`), else done with the day count
   in `text`; `run_daily_pull` raises `JobFailed("account_failed", …)` instead of a bare `GraphError` (same accounts list).
2. `GET …/backfill` serves `outcome {state, code, text, finished_at} | null` from `background.outcome(backfill_lock(org))` beside
   today's `running` and counts; `lib/metaApi.ts` types it (optional).
3. Schedule: the tree job's `submit_pack` failure is written on the tree row (`structured_output_json.pack_error {code, text}`) and
   the handler returns `Failed("pack_failed", text)`; `state._briefs_for_tree` serves that reason on the missing briefs instead of
   `last_error: None`.
4. Tests: a backfill with zero rows → outcome empty and the route says so; an account failing → failed with the classified code; a
   daily pull with one failed account fails its job with `account_failed`; a raising `submit_pack` → tree row carries the reason and
   the brand state names it.
