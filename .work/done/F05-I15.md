# Objective

實機走查（重啟過的後端、全新組織）抓到：**只填品牌名稱＋選「完全沒投放過」建出來的品牌，
根本沒進精靈**——送出後直接落在經營概況，步驟 2～5（賣什麼與數字／接工具／品牌知識）一格都
沒出現，`product`／`product_economics`／`brand_fact`／`conversion_goal` 全空。

因果鏈：`app/intake/state.py::start_or_quick()` 是精靈唯一的「建不建草稿」判斷，描述／網址／
照片三者皆空時回 `None`（S4.9 時代的「陽春路徑」：沒東西可掃就不建草稿、不花錢）→
`routes_api.py:103` 因此回 `{"quick": true}` → 前端 `IntakeWizard.tsx:57` 把人導到
`/brands/{id}`。那條路徑是 F05 之前的真相：當年精靈只有「掃描＋問答」，沒東西掃就真的沒事做。
F05 之後精靈裡有三步跟掃描無關（賣什麼與數字／接工具／品牌知識），「沒東西可掃」不再等於
「沒事做」，但沒有人回頭改那一刀。所以 F05.md Acceptance 第 1 條（「只填名稱 → 進精靈，
步驟軌是五格」）與 Outcome（「走完精靈系統手上有投放需要的每一項地基」）在真實路徑上不成立。

修在**一個地方**：那一刀改成「永遠建草稿，沒東西可掃就略過第 2 步」。不在路由上加分支、
不新增欄位、不動前端元件——`quick: false` 之後前端既有的 `navigate(...)` 就自己走對了。
**「不花錢」的性質必須原封不動保住**：這條路徑上不准有任何模型呼叫。
