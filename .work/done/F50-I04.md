# Objective
A rate the user types is stored as the number they typed — 20 means 20% — on every field, and the browser keeps no copy of the
money rules (feature Contract I percent scale; decision 9; audit W12; intake #16; other F3, F8 (assumed cost), F9 (money mirror);
drill-11 R6 A14 scale; controls a-34 「毛利率旁邊寫 %，要填 0.7」, b-01 售價 0 沒紅字, faults F8-price0／pricenegative). Today the
margin card shows 「%」 and wants 0.7, `close_rate` is 0–1 on the detail editor and 0–100 on the step-4 table, the detail tab prints
a bare 0.2, the step computes the assumed cost in the browser, and a blank price is sent as 0.

# Done
1. Migrations (test data only; the lead applies them to 54322 before merge): `20261005000101_brand_intelligence_close_rate_percent.sql`
   — `product_economics.close_rate` and `product_economics_version.close_rate`: drop the 0–1 CHECK, `numeric(5,2)`, values ×100,
   CHECK `close_rate IS NULL OR (close_rate > 0 AND close_rate <= 100)`; `20261005000102_core_rule_card_margin_percent.sql` —
   `UPDATE rule_card_value SET value = value * 100 WHERE card_key = 'gross_margin' AND field_key = 'gross_margin_rate' AND value <= 1`.
   ALTER／UPDATE own tables only; no CREATE of another module's table.
2. Backend: every `close_rate` store goes through `input_rules.percent` (onboarding `_check_money`, `brand_intelligence`
   economics writers, `routes_products` economics); the margin card field = `Bounds(0, 100, low_open=True, high_open=True)`,
   default 70, help 「例如填 70 代表毛利 70%」; benchmarks serve `value` in % with `unit: "%"` (gross margin 45, close rate 20; labels
   unchanged); every multiplier uses `input_rules.rate_fraction` (`ads/budget._economics_for`, `schedule/diagnosis` margin card
   layer). The assumed cost is derived by the server at save: `assumptions` containing `cost` with an empty cost on a base sell-way
   with a price → `budget.whole(price × (100 − 45) / 100)` stored and returned flagged 假設.
3. Frontend editors print and send the typed percent with no ×100／÷100: `SellWayTable` (`percentText`／`moneyInput` lose the
   scaling; `moneyErrors` goes — the row shows the server's `field_errors`; a blank price is sent as null, never 0), `SellWaysStep`
   (`fillAssumed`: shipping and close rate copy the served value, cost only sets the 假設 flag and lets the save return the number),
   `BundlePage` (same table), `EconomicsPanel` (0–100 input with 「%」, hint from the server), `EconomicsTab` (prints 「20%」),
   `RuleCardsSection` (margin field is a percent like 每期調幅). TS types document the scale.
4. `test_input_rules_gate.py` and `clientRules.test.ts`: delete every allowlist entry naming F50-I04; the gate's 「every 「%」 field
   has Bounds(0, 100)」 rule holds.
5. Tests: a sell-way saved with close rate 20 reads back 20 and its per-lead value is `value × rate_fraction(20)` = value × 0.2;
   close rate 0 and 120 are refused with the percent sentence; the margin card accepts 70 and refuses 0 and 100 with the Bounds
   sentence; the migration turns 0.2 into 20 and 0.7 into 70; step 4 with an empty price shows the server's sentence under the
   field and sends null; 「空著的成本填參考值」 returns the server-derived cost (1,280 → 704).
