# Objective

An engineering note leaks into the image prompt the user copies. Acceptance screenshot (1024, normal,
dispatched 彈性格式 brief) shows ① 主圖提示詞 ending with
「【輸出】彈性格式——1～10 張同座標圖；asset_feed_spec images ≤10，2026-09-09 查證，一張」.

ARCHITECTURE.md §5.7 settles that the 【輸出】 line's 說明 is the format coordinate's own `situation`
text, verbatim. So that text must be something a user can paste into an image AI. Two seeded
`situation` values are engineering provenance instead:

- `app/schedule/repository.py:169` single_image: `4:5，1080×1350（查證日 2026-08-07）`
- `app/schedule/repository.py:171` flexible: `1～10 張同座標圖；asset_feed_spec images ≤10，2026-09-09 查證`
- `supabase/migrations/20260909000002_schedule_brand_coordinate_flexible_format.sql` back-filled the
  flexible string into every brand that existed then.

No frontend component renders `situation` (only the type in `frontend/src/lib/coordinatesApi.ts:24`);
the other reader is the model-facing vocabulary list, where the note is noise too. The workbench side
(`【輸出】` punctuation) is F01-T03-I06, not this issue.

# Done

- In `_SEED_COORDINATES["format"]` (`app/schedule/repository.py`), change only these two situation
  strings, verbatim:
  - `single_image`: `4:5，1080×1350（查證日 2026-08-07）` -> `4:5，1080×1350`
  - `flexible`: `1～10 張同座標圖；asset_feed_spec images ≤10，2026-09-09 查證` -> `1～10 張同座標圖`
  Keep the provenance as a Python comment on the line above each tuple, English:
  `# 4:5 1080x1350, verified 2026-08-07` and `# Meta asset_feed_spec images <= 10, verified 2026-09-09`.
  `carousel` and `video` are untouched.
- New migration `supabase/migrations/20260911000001_schedule_brand_coordinate_format_situation.sql`
  (module schedule owns `brand_coordinate`, ARCHITECTURE.md §3). A short English header comment saying
  why (the situation text is printed verbatim in the 【輸出】 line of a user-copied prompt; brands
  seeded earlier keep the old text because `ensure_coordinates_seeded()` never re-seeds a dimension),
  then exactly:

  ```sql
  UPDATE brand_coordinate
     SET attributes_json = jsonb_set(attributes_json, '{situation}', to_jsonb('4:5，1080×1350'::text))
   WHERE dimension = 'format' AND key = 'single_image';
  UPDATE brand_coordinate
     SET attributes_json = jsonb_set(attributes_json, '{situation}', to_jsonb('1～10 張同座標圖'::text))
   WHERE dimension = 'format' AND key = 'flexible';
  ```

  No CREATE, no ALTER. The applied `20260909000002` file is not edited.
- New `app/tests/test_schedule_format_seed.py`, pure (no DB), one `unittest.TestCase`, model the
  imports on `app/tests/test_workbench_image_prompt.py`:
  - build `{key: situation for key, _category, _label, situation in _SEED_COORDINATES["format"]}` from
    `app.schedule.repository`; assert `single_image` equals `4:5，1080×1350`, `flexible` equals
    `1～10 張同座標圖`, and no format situation contains `asset_feed_spec` or `查證`;
  - read the new migration file as UTF-8 and assert it contains `'4:5，1080×1350'` and
