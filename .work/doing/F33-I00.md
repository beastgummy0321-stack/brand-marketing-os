# Objective
The e2e scripted provider (`BRAND_OS_LLM_PROVIDER=scripted`) answers `ads_strategy` and `ads_delivery_plan` with the roles the prompt actually offers or adopted, instead of a fixed three, so a fresh e2e brand keeps working once F33-I01 stops offering `retarget` to brands without a retargeting source (Contract P in `.work/features/F33.md`).

# Done
1. `ScriptedProvider.complete` for `ads_strategy`: read the last user message; if it contains a line `【可用角色】` followed by a line of role keys joined by `、`, allocate only those roles (fixed pcts: 1 role → 100; 2 roles → 60/40 in the listed order; 3 roles → 50/30/20). Without that section, today's three-role reply. `rationale`/`why` text unchanged.
2. `ads_delivery_plan`: derive the roles from the prompt's adopted-allocation lines (`- <role>（<label>）：<pct>%`), one group with one ad per role, same coordinates as today. Without such lines, today's three groups.
3. `SCRIPTED_REPLIES` may stay as the templates; the prompt-aware selection is the only new logic. `select_provider` unchanged.
4. Tests: `test_ads_plan_scripted_reply.py` proves the two-role case (`new、explore` in the strategy prompt → plan reply with exactly those groups passes `plan._validate_reply`); `test_llm_gateway.py` scripted class gets one test that the strategy reply follows the offered roles and one that the absent section keeps the old shape.
5. `frontend/e2e/ads-cold-start.spec.ts`: the three literal counts (`toHaveLength(3)`, the 指派 `toHaveCount(3)` and the 「三則」 comment) become `planned.groups.length`-derived (one ad per group), so the test holds for two or three roles.
