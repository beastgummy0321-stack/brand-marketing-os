# Objective

F04-I24 把八條回 Campaign 的路由統一成 `campaign_detail` + `asset_readiness`，**漏掉第九條**：
`POST /api/ads/brands/{b}/campaigns/{c}/bind`。規劃師已經查證，工人不必再找：

- `app/ads/routes.py:619` 的 `bind_campaign` 直接 `return result`，`result` 來自
  `app/ads/adapters/manual.py::bind`，它回的是 `{"message": …, "campaign":
  ads_repo.campaign_detail(...)}`（`manual.py:134` 與 `:211`），**沒有 `asset_readiness`**。
- 前端 `frontend/src/lib/adsApi.ts:642` 宣告 `BindResponse.campaign: CampaignDetail`（必填
  `asset_readiness`），`PublishPage.tsx:178-179` 把它原封不動餵進
  `CampaignWorkspace.tsx:88 updateCampaign` → 工作區狀態就是這份缺欄位的 dict →
  回總覽或策略分頁時 `OverviewTab.tsx:28`／`StrategyTab.tsx:193` 讀 `asset_readiness.total`
  就丟 `TypeError`。I24 的 error boundary 讓它從白畫面變成「這一頁壞了」卡片，
  **但它仍然是一次不該發生的當機**，而且配對是手動發布路徑每個使用者都會按的那一顆。

這張票就是把 I24 的那一條規則補到最後一個缺口，一行。

```python

```

回應形狀，不是 adapter 的事——`manual.py` 回 detail、路由補欄位，跟其他八條同一條路徑。
helper 吃現成的 dict，不要拿 `campaign_id` 再查一次 `campaign_detail`。

detail），一樣會經過這一行——helper 的 `None` 分支已經處理過 detail 是 `None` 的情形。
