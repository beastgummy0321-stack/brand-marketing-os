# Objective
One planner context (feature Contract P) read by the brief and the strategy, and program-written strategy facts
(Contract S, decision 3): the strategist sees the product, its forbidden claims, the offers it may use, the groups, the
product's learnings, last period's learning goals and the capacity line; its prose carries no numbers because the
program prints them. The delivery plan's reader is F48-I06.

# Done
1. `app/ads/planner_context.py` (new, private to ads): `planner_context(conn, org_id, brand_id, product_id, *, campaign=None)`
   returning the Contract P dict — product (`bi_repo.get_product`, kind 單品／組合, each knowledge product's confirmed facts
   through the same cap `strategy._knowledge_fact_line` uses, the sell-way's current price), `forbidden`
   (`workbench.forbidden_terms` facade from F48-I04), `offers` (`bi_repo.offer_sources` keys ∩ `bi_repo.available_offer_keys`,
   with labels from `coordinate_vocabulary`), `customer_groups` (`customer_groups.prompt_groups` rows; the campaign given),
   `learnings` (`coordinate_learning.prompt_view` + `ads`-track rows whose `product_id` is this sell-way, newest first, the
   existing caps), `previous` (`{campaign_id, name, learning_goals}` of the newest closed internal campaign of this sell-way —
   `budget_basis_json.strategy.learning_goals`), `capacity` (`triage_capacity.can_support(daily_of(budget_planned, days),
   cap)` when the campaign has a `budget_planned`; else `None`), `knowledge_item_ids`. `section_text(ctx, which)` renders
   【這個賣法】／【不能講】／【這期可用的優惠】／【這個賣法的顧客】／【過去的學習】／【上幾期的排名】／【上一期想學的】／【這期撐得起幾則】
   with the exact existing headers where a block already exists (`customer_groups`, `coordinate_learning`, `plan.OFFERS_HEADER`
   wording) so `ScriptedProvider._reply_for`'s parsers keep working. Move the strategy's `_products_section`／
   `_learnings_section` bodies here (one implementation); `strategy.py` keeps thin wrappers or imports.
2. `brief.create_draft`: when a sell-way is picked (`checked is not None`) pass its id to `context_compiler.compile(conn,
   brand_id, product_id)` and add `section_text(ctx, "product")` + `"forbidden"` to the parse prompt; `brief_parse.md` tells
   the model names and `audience_hint` may not contain a 【不能講】 entry.
3. `strategy.generate`: builds the prompt from `planner_context` sections in today's order plus 【這期可用的優惠】 after the
   customers block and 【上一期想學的】 + 【這期撐得起幾則】 after the ranking; `basis` gains `planner_context: {product_id,
   forbidden_count, offers, previous_campaign_id}`. Contract S: `_validate_reply` refuses a reply whose `rationale`／`why`／
   `unknowns`／`learning_goals` strings contain `[0-9]`, `%` or `NT$`, and `alternatives` must be a list of strings (else
   `None`). `facts` are built after validation: `_facts(ctx, allocation, scenario_row)` → `[{kind, text}]` for groups,
   offers, numbers (cap through `learning_rank.whole`; newest closed campaign's best 每筆 with ad name and sales; 「已結案 N
   期」), capacity, learnings; stored in `budget_basis_json.strategy.facts` and recomputed on the campaign read
   (`repository.get_campaign`／`campaign_detail` → `strategy.current_facts(conn, …, campaign)`) so after adoption the groups
   line comes from the ads' bound customer groups and the offers line counts ads per offer.
4. `app/departments/ads/strategy.md`: the model is told the facts (groups, offers, numbers, capacity) are printed by the
   program under the strategy; it writes no digits, no `%`, no money, names groups by their 「who」 and ads by name without
   costs; the 「寫廣告名和它的每筆成本」 and 「第 N 群」 instructions go; 【不能講】 words never appear in its text.
5. `app/llm/providers.py` scripted replies: unchanged values (「e2e scripted reply」 has no digit); add the `%`-free
   assertion to the scripted-reply test if one exists, else leave.
6. Tests (`test_ads_planner_context.py` new + existing): context carries product name／kind／facts／forbidden／offers／groups／
   learnings／previous goals／capacity for a fixture brand; the strategy prompt contains every section header; a reply with
   「392」 in `rationale` is refused; `alternatives: [1]` refused; `facts` groups line names the listed groups before
   adoption; brief passes `product_id` to `context_compiler.compile` when a sell-way is picked. Machine check
   (`test_ads_planner_context.py`): AST — every module in `app/ads` calling `gateway.run_task` with a `task_type` starting
   `ads_` calls `planner_context(` in the same function or module; allowlist `plan.py` here with a comment 「F48-I06
   removes」.
