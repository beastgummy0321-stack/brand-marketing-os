# Objective

The information model and the upstream handoff contract: `ARCHITECTURE.md` §5.1–§5.4. A pack is a
real row, a version is a real row, and an upstream hands over **one pack in one call** instead of N
loose briefs. 檔期規劃 is the first caller and switches in this issue — the callee and its only
caller are one contract, and `app/tests/test_schedule.py` drives both sides (legacy seam,
`ARCHITECTURE.md` §2).

Display names only: `workbench_brief` is still the table behind 素材組, `workbench_output` behind
版本, `part` behind 產物類型. No renames.

# Done

**Migration** `supabase/migrations/20260912000001_workbench_pack.sql` (never edit an applied file;
follow `20260909000001_workbench_baseline.sql` for the RLS/grant/policy block verbatim):

- `CREATE TABLE workbench_pack`: `id` (`wbp_*` via `db.new_id("wbp")`), `org_id`, `brand_id`,
  `name TEXT NOT NULL`, `source_kind TEXT NOT NULL CHECK (source_kind IN ('schedule_node','free_job'))`,
  `source_ref jsonb NOT NULL DEFAULT '{}'`, `summary_json jsonb NOT NULL DEFAULT '{}'`,
  `context_json jsonb NOT NULL DEFAULT '{}'`, `constraints_json jsonb NOT NULL DEFAULT '{}'`,
  `completion_json jsonb NOT NULL DEFAULT '{}'` (the human ticks, F02-I03 writes them),
  `approved_at timestamptz`, `closed_at timestamptz`, `created_by`, `created_at`, `updated_at`.
  org/brand indexes ＋ RLS ＋ grants ＋ the org-isolation policy, same shape as the baseline.
- `ALTER TABLE workbench_brief ADD COLUMN pack_id TEXT REFERENCES workbench_pack(id) ON DELETE
  CASCADE` and `ADD COLUMN name TEXT`, `ADD COLUMN required_outputs_json jsonb NOT NULL DEFAULT
  '{}'`. `pack_id` stays nullable in SQL (no backfill of test data is worth a NOT NULL dance) but
  `repository` never writes a brief without one.
- `ALTER TABLE workbench_output ADD COLUMN version_index integer NOT NULL DEFAULT 1`; drop the
  `UNIQUE (brief_id, part, generation_round)` constraint and add
  `UNIQUE (brief_id, part, generation_round, version_index)`. `adopted_at` keeps its name and now
  means 選定 at version level.
- `grep -rn "REFERENCES workbench_brief" supabase/migrations/` before you touch anything, per
  `CLAUDE.md`.

**`app/workbench/repository.py`**

- `create_pack(conn, org_id, brand_id, pack) -> str` and `submit_pack(conn, org_id, brand_id, pack)
  -> str`: validate the contract of `ARCHITECTURE.md` §5.4 — `sets` non-empty; each set's
  `required_outputs` a non-empty dict of part names → int ≥ 1, where the accepted names are
  `copy`／`image_prompt`／`video_script` — **`free` is rejected** (`part_retired`): it is a legacy
  part whose rows predate packs, and `source_kind = "free_job"` is what 自由創作 uses instead
  (`ARCHITECTURE.md` §5.4). The existing `free` code path and `app/departments/workbench/free.md`
  are left alone — deleting them is not this feature's job; existing per-part generation
  counts keep their existing ranges and errors (`parts_unknown`, `copy_length_unknown`,
  `count_out_of_range`, `style_unknown`, `product_unknown`). Each set is one `workbench_brief` row
  (with `name`, `required_outputs_json`, `request_json` as today plus `parts` derived from
  `required_outputs`' keys) and each requested part still enqueues one
  `background.workbench_generate` job, same lock key. Returns the pack id.
- `repository.submit_brief` stays internal and gains a `pack_id` argument; `create_brief`
  (`POST /briefs`, still live until F02-I03 replaces the routes) creates its own one-set pack so
  nothing breaks in between.
- `write_output` becomes version-aware: it takes a list of version bodies and writes one row per
  version with `version_index` 1..n, sharing `generation_round`, `llm_task_id` and the round's
  `validation`/`warnings`. `jobs.py` passes 5 bodies for a copy round (`sets` from F02-I01), 1 for
  an image-prompt round (the rendered ①＋② pair, unchanged content), and one per script for
  `video_script`.
- `select_version` / `deselect_version` (`adopted_at` set/cleared, brief must be open, pack must not
  be approved → `ValueError("pack_approved")`), keeping the old `adopt_output` behaviour for the
  row-level write.
- Derivation helpers, one place only, exactly `ARCHITECTURE.md` §5.3: `product_state`, `set_state`,
  `pack_state`, and the set-table cell — which returns **both the state and the display text**
  (`已選定／需要` e.g. `2／5`, `未生成`, `—`), because the frontend renders that string and holds no
  copy of the rule. Everything else (the API in F02-I03, the schedule read in F02-I04) calls these;
  no second copy of the rules, in Python or in TypeScript.
- `pack_for_source(conn, org_id, brand_id, source_kind, source_ref)` — JSONB containment like
  `briefs_for_source`, returns the pack with `approved_at`, `sets_total`, `sets_done`, or `None`.
- `adopted_output` keeps its documented meaning and shape: the **earliest selected** version of that
  part, else the latest version, plus `is_adopted`. Multi-select must not change what 檔期規劃 reads.
- `_CHILD_TABLES` / cleanup registration covers `workbench_pack` so brand delete still works.

**`app/workbench/__init__.py`**: export `submit_pack` and `pack_for_source`; `briefs_for_source` and
`adopted_output` stay; **`submit_brief` is removed from the public entry** (a set only exists inside
a pack). Update the docstring's shape list — it is the contract page.

**`app/schedule/jobs.py`**: the per-leaf `submit_brief` loop becomes one `submit_pack` call after a
successful expansion — pack `name` = the tree/period name already used on the page, `source_kind`
`"schedule_node"`, `source_ref` `{"source_tree_task_id": row["id"]}`, `summary` = the 摘要 fields
the pack page shows (情境／角度／風格／目標受眾／重點訊息／參考連結, from the plan scope and the
tree), one set per deepest node carrying today's `source_ref` (`node_key`,
`source_tree_task_id`, `node_name`), coordinates, product, style, `required_outputs`
`{"copy": 1, "image_prompt": 1}`, `constraints` `{"copy_length": leaf's, "promotion_note": …}`.
Keep the whole call in one try/except: one failed dispatch logs one line and never touches the
committed tree row.

**Tests** `app/tests/test_workbench_pack.py` (new): a pack of 3 sets with mixed `required_outputs`
gives the expected per-set cells (`未生成`, `2／5`, `—`) and pack state transitions
待處理 → 進行中 → 待核准 as versions are selected; a copy round writes 5 rows with distinct
`version_index`; selecting two versions of one part leaves `adopted_output` returning the earliest;
`submit_pack` rejects an empty `sets`, an unknown part in `required_outputs`, `free` in
`required_outputs`, and a count of 0; a `required_outputs` of `{"image_prompt": 5}` with 4 versions
selected is still 進行中 and turns 已完成 at the fifth (`required_outputs` is not the generation
count);
tenant isolation (another org's pack id is invisible). Add `workbench_pack` to the two
enumeration tests.
