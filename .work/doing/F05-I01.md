# Objective

今天一個「薑黃錠」只能有一組數字。真實情況是同一個產品有很多**賣法**（單瓶／3 入組／5 入組／
隨身包），每個賣法的售價、成本、運費都不一樣，但**產品知識只有一份**。而且系統只算得出商品的
一次轉換值多少錢（`app/ads/budget.py:32-44`），服務／名單型生意完全沒地方放。

這張票把三件事一次做完（`ARCHITECTURE.md` §8 第 1～3 條，已定案，不要重新設計）：

> **產品有層級**：`product.parent_id` 可空、自我參照、只有一層。子＝賣法，知識掛母、金額掛子。
> **一次轉換的價值**：`(售價 − 單位變動成本 − 運費) × 成交率`，成交率是新的可空欄位 `close_rate`。
> **假設值會被記住**：使用者說「不知道」時填入的欄位記在新的 `assumptions_json`。

後面每一張票（精靈、檢查表、預算、策略）都吃這一個形狀。

# Done

## 1. Migration（新檔，不改已套用的檔）

`supabase/migrations/20260914000001_brand_intelligence_product_hierarchy_and_economics.sql`：

```sql
ALTER TABLE product ADD COLUMN parent_id TEXT REFERENCES product(id) ON DELETE CASCADE
    CHECK (parent_id IS NULL OR parent_id <> id);
CREATE INDEX idx_product_parent_id ON product(parent_id);

ALTER TABLE product_economics ADD COLUMN close_rate numeric(6,4)
    CHECK (close_rate IS NULL OR (close_rate > 0 AND close_rate <= 1));
ALTER TABLE product_economics ADD COLUMN assumptions_json jsonb;
ALTER TABLE product_economics_version ADD COLUMN close_rate numeric(6,4)
    CHECK (close_rate IS NULL OR (close_rate > 0 AND close_rate <= 1));
ALTER TABLE product_economics_version ADD COLUMN assumptions_json jsonb;
```

欄位註解：`parent_id` = 賣法掛在母產品底下，只有一層（第二層在 repository 擋，CHECK 看不到別的列）；
`close_rate` = 成交率，NULL＝一次轉換就是一次成交；`assumptions_json` = `["cost","shipping","close_rate"]`。
版本表兩欄都要加：成交率與「這是假設值」都會變，而 `20260903000004_..._version.sql` 存在的理由就是
「一改就是新的一版」。**不要重用 `cpa_roas_basis`**——它在 `20260903000004:45` 已經被 DROP，
而且名字講的是別的事。

## 2. `app/brand_intelligence/repository.py`

- `create_product(...)` 多收 `parent_id: str | None = None`。驗證寫在這裡：母產品必須存在、必須同一個
  `brand_id`、而且**它自己的 `parent_id` 必須是 NULL**；違反 →
  `ValueError("賣法只能掛在母產品底下，不能再往下一層")`。
- `list_products`／`get_product` 的回傳形狀要帶得出 `parent_id`。
- 新增**唯一的解析器**：
  `def knowledge_product_id(conn, brand_id, product_id) -> str`，回 `COALESCE(parent_id, id)`，
  找不到就原樣回傳。這張票只建立它，**不改任何讀者**（那是 F05-I02）。
- `save_product_economics(...)` 多收 `close_rate: float | None = None` 與
  `assumptions: list[str] | None = None`，兩個都寫進 `product_economics` **與**同一筆交易裡 INSERT 的
  `product_economics_version`。值域檢查在這裡：`close_rate` 非 None 時 `0 < x <= 1`；
  `assumptions` 只接受 `"cost"`／`"shipping"`／`"close_rate"`。
- 品牌刪除：`product` 現在有自我 FK。跑 `app/tests/test_brand_delete.py` 確認既有的逐表 DELETE 沒壞；
  壞了就在該處先刪 `parent_id IS NOT NULL` 的列。

## 3. `app/ads/budget.py::breakeven_cpa`

```python
    shipping = economics.get("shipping_cost") or 0
    value = float(price) - float(unit_cost) - float(shipping)
    close_rate = economics.get("close_rate")
    return value if close_rate is None else value * float(close_rate)
```

docstring 補一句（打平 CPA＝一次轉換的價值；服務／名單帶 `close_rate`，商品不帶）。
**`unit_variable_cost` 是 None 就回 None 這條不變。** 「選到母產品要落到第一個賣法」是 F05-I02。
