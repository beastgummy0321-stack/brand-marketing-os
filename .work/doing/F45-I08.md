data = Contract W (`docs/architecture/ads.md` §6.49, F45-I07).

# Done
1. `adsSlotsApi.ts`: `SlotState` gains `waiting`; `Slot` gains `waiting {action, text} | null` and `job {kind, done, of} | null`;
   `editSlotCopy(brand, campaign, adId, copyFields)` → `POST …/slots/{ad_id}/copy` with `{copy_fields}`.
2. Tiles as the prototype: `in_progress` → 處理中 chip and the job line (「預覽製作中：…」 / 「文案生成中：…」, the 已寫好 d／n bar only
   when `done`/`of` are set) with 「自動更新，不用重整」; `waiting` → 等你 chip and its action (`pick_on_workbench` → link to the slot's
   `workbench_href` with the server's text and 「→」; `confirm_copy` → button with the server's text that runs `recheckSlot`, plus
   「改文案」); `blocked` copy → 「改這句文案」, 「到工作檯換一版 →」 (only with a `workbench_href`; otherwise the existing 換一版文案
   picker) and 再檢查一次; `blocked` file → 換一張 and 再檢查一次.
3. Edit dialog: one labelled field per non-empty copy field (only 內文 → the prototype's single textarea), 「保存後馬上檢查」, 保存 →
   `editSlotCopy`, the returned slots replace the grid; toast 「文案已保存，這一格已確認」 / 「文案已保存，但卡住了，原因寫在格子裡」;
   empty text refused in the page.
4. Card head: 「x／y 格已備妥」 with 卡住／等你／處理中 count chips; progress segment per state (`waiting` gets its own colour in
   `ProgressSegments`); the bar hint 「〈counts〉：好了才會進上架清單」; polling only while some slot is `in_progress`.
5. Tests with real-shaped fixtures (prototype slots a1–a7): each state's tile and actions; the edit dialog path to blocked and to
   ready; no polling with only waiting / blocked slots; polling with an in_progress slot.
6. Deliver 「參考圖｜成品」 for the assets card, the edit dialog and a waiting tile. The prototype's carousel note on a2 is out of scope
   (feature Decisions; F46-I03 owns a `format_note` slot field — do not add or read it here).
