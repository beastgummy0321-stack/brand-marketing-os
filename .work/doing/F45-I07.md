# Objective
Every confirmation path keeps its refusal and a slot's state comes from facts (feature outcome 3, backend): refusal storage in the
shared confirmation, immediate re-check of a new revision, Contract W slot states, the typed slot copy edit, and photo-only sets —
`docs/architecture/ads.md` §6.49 is the spec.

# Done
1. `asset_suggestions`: one writer of `blocked_reasons` — a refused confirmation (`confirm_manual` and the batch path through
   `_refused`) stores its non-`wait` details on that revision; `slots._confirm_if_ready`'s `ValueError` branch stores through the same
   writer; `_apply_confirmation` still clears it. A refused confirm is not an error response; the stored reasons survive the request.
2. Re-check of a new revision: `PATCH …/placements/{id}`, `choose_copy` and the new typed edit point the ad's `slot_placement_id` at
   a placement that backs a planned ad's slot (its current `slot_placement_id`, or its assigned material's placement) and run
   `_confirm_if_ready` + `settle`; a launched or frozen ad is skipped without an error. `recheck` also points a slot whose assigned
   material's placement has an unconfirmed current revision back before confirming (no `slot_no_file` for that case).
3. `POST …/slots/{ad_id}/copy` accepts `{copy_fields: {headline?, body?, description?}}` (validated by `user_assets.validate_copy`)
   besides `{set_id, version_id}`; same guards and errors as today; returns `{placement, slots}`.
4. Contract W in `_planned_slot`, in this order for a planned, not launched, not ready ad: pending placement — original failed →
   `blocked` (`fix: "file"`); original `pending` → `in_progress` with `job {kind: "preview"}`; no copy → `image_only`; stored refusal →
   `blocked`; else `waiting` `confirm_copy`. Selected workbench copy, no file → `copy_only`. The ad's set (`_ad_sets`) with brief
   status `queued`/`running` → `in_progress` `job {kind: "copy"}` (`done`/`of` from the brief read when it carries them, else null);
   any other set without a selected copy → `waiting` `pick_on_workbench`. Otherwise `missing`. Every slot carries `waiting` and
   `job` (`null` when not in that state). The old 「pack exists, not approved → in_progress」 rule is gone.
5. `assets._ad_set`: a brand with `media_capability == "photo"` gets `required_outputs = {"copy": 1}` for single-image and carousel
   ads; drop request keys that only feed the image-prompt part if `workbench.submit_pack` refuses them (check, do not guess).
6. Tests: drill-10 B3 — a slot placement revised through `PATCH …/placements` with 「醫師推薦」 reads `blocked` with the unbacked
   sentence, revised back reads `ready`; the advanced confirm route's refusal is stored; the typed edit path (blocked and clean);
   `recheck` on a revised assigned material; a set with brief `running` → `in_progress` `job.kind == "copy"`; brief `succeeded`, no
   selection → `waiting` `pick_on_workbench`; an unconfirmed slot placement with a ready original and nothing stored → `waiting`
   `confirm_copy`; original `pending` → `in_progress` `job.kind == "preview"`; photo-only brand pack sets require only copy, a
   `photo_video` brand still requires the image prompt.
