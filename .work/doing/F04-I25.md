# Objective

演練四（persona 阿明、全新組織、品牌「常春健康」）在策略頁**走不下去**。規劃師已經查證整條
因果鏈，工人不必再找，也**不要順手修根因**（根因不在這張票裡，見下方「不在範圍內」）：

- 這個品牌的 `product_economics` **一列都沒有**（建檔精靈從來不寫這張表；
  `save_product_economics` 全專案只有 `app/brand_web/routes_products.py:479` 會呼叫，
  阿明在精靈裡打的售價／成本都變成 `product_fact` 的自由文字）。
- 所以 `app/ads/budget.py:33 breakeven_cpa` 回 `None` → `target_cpa` 回 `None` →
  `_cold_start_scenarios`（`budget.py:86-90`）三個情境的 `daily`／`total` 全是 `null`。
- 策略頁三張情境卡因此印「累積中」而且是 `disabled`（`StrategyTab.tsx` 的
  `disabled={… || s.total === null}`），**但主要按鈕「照這個方式進行」照樣送
  `scenario_key=recommended`**（`StrategyTab.tsx:136-137`）→
  `app/ads/strategy.py:308-311` 因為 `row["total"] is None` 丟 `scenario_unknown` →
  `routes.py:204` 印「找不到這個預算情境。」
- 這句話是**錯的**：情境存在，不知道的是金額。阿明的原話：
  「不知道為什麼會失敗，我也不知道要去哪裡補什麼。」

這張票只做一件事：**沒有商品售價成本時，策略頁要有出路**——訊息說真話，主要按鈕帶人去可以
自己決定的地方，畫面上寫得出「要補什麼、去哪裡補」。

# Done

## 1. 後端：分開「沒有這個情境」跟「這個情境算不出金額」

`app/ads/strategy.py::select_scenario`（`:307-312`）現在一個 `scenario_unknown` 蓋兩件事，拆開：

```python
row = next((r for r in scenario_result["scenarios"] if r["key"] == scenario_key), None)
if row is None:
    raise ValueError("scenario_unknown")
if row["total"] is None:
    raise ValueError("scenario_amount_unknown")
total = row["total"]
```

`app/ads/routes.py` 的 `_SELECT_SCENARIO_ERRORS` 加一條（snake_case code + 繁中訊息，
既有那條「找不到這個預算情境。」一個字不改）：

```python
"scenario_amount_unknown": (400, "這個情境還算不出金額：請先補上商品的售價與成本，或自訂預算。"),
```

`SelectScenarioRequest` 的欄位預設值維持原狀（routes.py 的慣例：租戶界線先於欄位驗證，
每個欄位都要有預設值）。`custom_total` 那條路一個字不動——手打金額本來就走得通。

## 3. 前端：`StrategyTab.tsx`

**一個旗標，三個用途**（不要為此新增 props、新元件、新檔案）：

```tsx
const amountsUnknown = !!scenarios && scenarios.scenarios.every((s) => s.total === null);
```

用 `scenarios` 自己的金額判斷，**不要**去讀 `scenarios.basis.target_cpa`——`basis` 的型別是
`Record<string, unknown>`（`frontend/src/lib/adsApi.ts`，在 `do_not_touch`），而且 history
模式的 `basis` 根本沒有這個鍵；「每一個情境都算不出金額」才是畫面真正在乎的條件。

### 3a. 主要按鈕不再送一個算不出金額的鍵

`handlePrimary()`（`:127-147`）在既有的 `hasGroups` 早退之後、呼叫 `selectScenario` 之前多一段：

```tsx
if (c.budget_scenario === null && amountsUnknown) {
  setBudgetHelpOpen(true);   // 展開「調整建議」
  setCustomOpen(true);       // 展開自訂預算輸入框
  if (!customValue && constraintBudget !== null) setCustomValue(String(constraintBudget));
  return;                    // 不打 API
}
```

- `constraintBudget`：`typeof c.constraints_json.budget === "number" ? c.constraints_json.budget : null`
  ——阿明在建立時打的 28000 就存在這裡，預填它等於「你講過的數字我記得」。
- 按鈕字在這個狀態改成「先設定預算 →」（其餘狀態的字一個字不改：有投放組是「前往投放結構」、
  一般狀態是「照這個方式進行 →」）。按下去會跳出一個輸入框，按鈕上就要先說。
- `budget_scenario` 已經有值時（阿明後來自訂 28000 成功，`budget_scenario === "custom"`、
  `budget_planned = 28000`）走既有那條：**直接 `adoptStrategy`**。這是今天就對的行為，
  這張票只是用測試把它釘住，不要重寫。

### 3b. 讓「調整建議」可以被程式展開

`patterns/Disclosure` 是 uncontrolled（只有 `defaultOpen`），而它在 `do_not_touch` 裡。
用 remount 的一行解決，不要改 `patterns/`：

```tsx
const [budgetHelpOpen, setBudgetHelpOpen] = useState(false);
…
<Disclosure key={budgetHelpOpen ? "open" : "closed"} label="調整建議" defaultOpen={budgetHelpOpen}>
```

天花板寫在旁邊一行註解即可：`key` 一換整塊會重新掛載，所以**不要**把任何狀態搬進 `Disclosure`
的子樹裡（今天 `allocationPct`／`customOpen`／`customValue` 全在 `StrategyTab` 自己身上，
成立）。

自訂預算的 `<Input>` 加 `autoFocus`——它本來就只在 `customOpen` 時才渲染，掛載即取得焦點，
不必拉 ref（`Input` 沒有 forwardRef）。

### 3c. 三張情境卡下面一句誠實的話＋一條出路

`amountsUnknown` 為真時，在三張情境卡的 grid 下面（自訂預算那一列的上面）加一段小字
（用既有的 `text-sm text-muted-foreground` 密度，不加新 token、不加新樣式）：

> 要估金額需要商品的售價與成本　[去補商品數字]

連結用 `react-router-dom` 的 `Link`（本檔目前沒 import，自己加），目的地：

```tsx
const productId = /* c.context_json.product_ids 的第一個字串，取不到就 null */;
const to = productId
  ? `/brands/${brandId}/products/${productId}?tab=economics-view`
  : `/brands/${brandId}/products`;
```

`context_json` 的型別是 `Record<string, unknown>`，要自己收窄（`Array.isArray(...)` +
`typeof x === "string"`），**不要**改 `adsApi.ts` 的型別。
規劃師已經查證：`/brands/:brandId/products/:productId` 與 `/brands/:brandId/products`
兩條路由都在 `frontend/src/App.tsx` 裡存在，商品詳情頁的 `?tab=economics-view`
就是「產品經濟數字」那一頁（`ProductDetailPage.tsx:104` 讀 `?tab=`，`EconomicsTab` 有
售價／單位成本／運費的表單）。

`amountsUnknown` 為假時這一段完全不渲染（有金額的品牌畫面一個像素都不變）。
