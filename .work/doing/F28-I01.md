# Objective
R1 storage: one cost-per-result cap per campaign (Feature "Contracts → Cap storage"; rules in `docs/architecture/ads.md` §6.32). Every backend reader uses it; the second store and the trailing-30 fallback disappear.

# Done
1. Migration `20260925000001_ads_one_cap.sql` (ads prefix, new file, never edit an applied one): back-fill `target_basis='own', target_cost=success_target` where `target_basis IS NULL AND success_metric='cpa' AND success_target > 0`; rows with `target_basis='trailing_30'` → NULL; `target_basis` CHECK allows only `own`／`break_even`; drop `success_metric` from `ads_campaign_internal_required`. Columns stay.
2. `targets.resolve`: own cap wins; else break-even when the product cost exists; else `value: null` with `missing` naming product／product_cost／result_kind. `_trailing_30` removed. Returns the cap view shape (break_even and price even when an own cap is set).
3. Readers switched to the resolved cap: closeout (cost per result vs cap), learning (cohort by result_kind + verdict, label 每筆成本), experiments, visual_learning, asset_suggestions, strategy prompt (「上限（每筆購買成本）：X／未設定」), budget cold start (the cap, no `TARGET_CPA_RATIO`), month_summary. Plan/launch snapshots and review premises no longer carry a target.
4. Brief: the prompt and `_validate_reply` ask for `cap` only (cost per purchase); unparsed or missing → no cap, never `roas`; a reply without `cap` still parses. Create/update paths never write `success_*`; campaign payloads return `cap` and never `success_*`; PATCH with a `success_*` key → 400.
5. Tests: `app/tests/test_ads_one_cap.py` — no non-test file under `app/ads` names `success_metric|success_target|success_basis`; the drill-5 case (typing 450 with the metric dropdown untouched) stores a 450 cost cap; resolve without product cost returns null, never a trailing actual. Update existing `app/tests/test_ads*.py` fixtures that relied on the old fields.
6. Frontend: `Campaign` type loses `success_*` and gains `cap`; `TriageTargetView`/`CampaignTarget` basis loses `trailing_30`. Minimal data-source swaps in StrategyTab (the metric dropdown becomes one NT$ integer cap input that PUTs the target), OverviewTab, PerformanceTab, UserAssetPlacements, CampaignCard, CampaignDetailPage, CampaignTargetPage; fixtures in the listed tests. No redesign here (I09 does it). `adsApi.ts` stays ≤ 800 lines.
