# Objective
User ruling 2026-10-04 (C decision 3): archived products and brands get a list and a restore button on existing screens, no new
layout (drill-11 R6 A5／A11: archived items could be restored only by typing a URL).

# Done
1. Backend: `GET /api/products/brands/{b}?status=archived` returns the brand's archived root products (same item shape as the
   active list; sell-way rows never listed). `GET /api/dashboard/archived-brands` returns the org's archived brands
   `[{brand_id, name}]`. `POST /api/library/brands/{b}/restore` sets an archived brand back to `active` (only that field; an
   active brand → 409 with a sentence); access as the brand's other writes. Restoring a product keeps using the existing
   `…/products/{p}/archive` toggle (its same-name collision sentence stays).
2. Products page (`ProductsPage.tsx`): a folded 「已封存（N）」 group under the list (existing fold／card pieces) with each archived
   product's name and 「還原」; after restore the product moves to the active list; the collision sentence shows on the row.
   Hidden when N = 0.
3. Brand overview (`App.tsx` `Overview`, new `components/overview/ArchivedBrands.tsx`): a folded 「已封存的品牌（N）」 section under
   the cards, each with 「還原」; after restore the workspace brand list refreshes (`refreshBrands`). Hidden when N = 0.
4. Tests: each route (archived lists, restore, 409 on an active brand, another org's brand 404); each screen (hidden at 0, restore
   moves the row, failure sentence shown).
