# Objective
Closing a campaign writes one learning per graded ad carrying its grade and its seven coordinate keys (F39 outcome 1), and one
program function renders the brand's coordinate scoreboard from those rows (outcome 2) for the two prompt builders that I02 wires.
No model call anywhere in this issue.

# Done
1. New `app/ads/coordinate_learning.py` (private to app/ads; only `closeout.py`, `plan.py`, `strategy.py` import it). Module
   docstring names the drill-7 root cause (report §3 #1) and the scope format below.
   - `write_coordinate_learnings(conn, org_id, brand_id, campaign_id, *, actor) -> list[dict]`:
     reads `campaign_detail` + `live_creative.with_learning_coordinates` (same as `visual_learning.write_visual_learnings`),
     grades every ad with `period_grades.grade_period(conn, org_id, brand_id, campaign.start_date, campaign.end_date)` filtered
     to `row["campaign_id"] == campaign_id`, maps `entity_id` to the ad through `ads_external_entity.native_id = ads_ad.external_id`
     (one query for the campaign's ad-kind entities), and for each row whose `grade` is one of `on_target/watch/over/wasted`
     calls `bi_repo.record_learning(conn, brand_id, actor=actor, learning_text=..., applicability_scope=..., confidence="observed",
     sample_size=<"高" when grade is on_target/watch/over else "低">, source_cycle_id=f"{campaign_id}:{ad_id}",
     source_track="coordinate", needs_revalidation=ads_learning._needs_revalidation(...))`.
     Skips `insufficient`/`no_target` rows, ads with no entity, and any ad whose `source_cycle_id` already has a row
     (idempotent: scan `bi_repo.list_learnings(conn, brand_id, source_track="coordinate", limit=500)` like `ads_learnings.py`).
     `learning_text` = `「<ad name>」每筆 <cost_per_result>（上限 <cap>）＝<grade_label>；audience=<k>、pain=<k>、angle=<k>、hook=<k>、proof=<k>、offer=<k>、format=<k>`
     (money through `learning._number`; a 沒賣出 row with `cost_per_result` None prints 每筆 —).
     `applicability_scope` = `coord；grade=<grade>；audience=<k>；pain=<k>；angle=<k>；hook=<k>；proof=<k>；offer=<k>；format=<k>`
     (missing key becomes `none`). Returns the written rows.
   - `scoreboard(conn, org_id, brand_id) -> dict`: parses every `source_track="coordinate"` row's scope back into
     `{grade, coordinates}`, tallies per `(dimension, key)` the four grade counts, and finds the latest closed campaign
     (`ads_campaign.status='closed'` ordered by `closed_at desc`) that has rows, returning
     `{"tally": {dim: {key: {"on_target": n, "watch": n, "over": n, "wasted": n}}}, "last": {"campaign_name": str,
     "on_target": [{"name", "coordinates"}], "bad": [{"name", "grade_label", "coordinates"}]} | None, "learning_ids": [...]}`.
     Ad names for `last` come from `ads_ad` by the `source_cycle_id` suffix.
   - `scoreboard_section(conn, org_id, brand_id) -> tuple[str, list[str]]`: text + learning ids. Empty brand →
     `【座標成績表】（還沒有結案過的廣告，沒有成績表）`. Otherwise header `【座標成績表（已結案活動，程式統計；划算＝每筆成本在上限內）】`,
     one line per dimension/key with ≥1 graded row, labels through `ads_repo.coordinate_vocabulary` (fallback = key):
     `- offer｜free_shipping｜免運：划算 2、偏貴 0、太貴 1、沒賣出 0`, then `上一期「<campaign>」划算的：「<ad>」（audience=<k>、hook=<k>、proof=<k>、offer=<k>）`
     one per ad, and `上一期太貴／沒賣出的：「<ad>」<grade_label>（…）`. Dimension order = `learning._COORDINATE_DIMENSIONS`.
2. `app/ads/closeout.py::close`: right after `write_visual_learnings` (same `incomplete_simulation`/`skipped_gap` guard: partial
   data writes nothing), call `coordinate_learning.write_coordinate_learnings(...)` and append its ids to
   `verdict_json["learning_ids"]`. Docstring sentence added.
3. Tests `app/tests/test_ads_coordinate_learning.py` (new, pattern of `test_ads_visual_learning.py`): a closed campaign with two
   bound ads and synced ad rows (spend ≥ 3×cap so the sample gate passes) → two coordinate rows with the exact scope string;
   an ad under the sample gate → no row; closing twice → no duplicate; `scoreboard_section` on an empty brand → the empty
   sentence; after the close → the tally line for the offer key and the 「上一期…划算的」 line naming the on-target ad.
   Existing tests asserting `learning_ids` length or the ledger row count after `close` are updated to the new count only where
   their fixtures actually produce graded rows (most fixtures have no synced ad rows, so their count is unchanged; do not add
   rows to make them pass).
