`app/ads/routes.py` 加一支私有 helper（檔案內用，不匯出、不進 `app/ads/__init__.py`）：

```python
def _with_readiness(actor, brand_id: str, campaign: dict | None) -> dict | None:
    """每一條回 Campaign 的路由都跟 GET 回同一個形狀（`campaign_detail` + `asset_readiness`）。
    少一個欄位，瀏覽器就是白畫面（F04-I24，演練四）。"""
    if campaign is None:
        return None
    campaign["asset_readiness"] = assets.readiness_summary(
        assets.readiness(web.conn, actor.org_id, brand_id, campaign["id"]),
```

## 3. 前端：一個路由層 ErrorBoundary

新檔 `frontend/src/components/layout/ErrorBoundary.tsx`——React 的 error boundary 只能是
class component（`static getDerivedStateFromError` + `componentDidCatch`），這是唯一寫法，
不要為它裝任何套件。fallback **直接用既有的 `EmptyState`**（同資料夾，
`title`／`description`／`onAction`／`actionLabel` 都有，不要另刻卡片、不要改 `EmptyState`）：

- `title`：「這一頁壞了」
- `description`：接到的錯誤訊息（`error instanceof Error ? error.message : String(error)`），
  沒有訊息時寫「畫面在顯示這份資料時出錯了。」——**不印 stack trace、不印元件名**。
- 按鈕「重新載入」→ `window.location.reload()`。
- `componentDidCatch` 裡 `console.error(error, info)` 一行就好（開發時看得到），不接任何
  上報服務。

`frontend/src/App.tsx`：在 `AuthenticatedWorkspace` 的 `<AppShell>` 裡面包住 `<Outlet />`
（殼層與側欄要活著，壞掉的是內容區）：

```tsx
<AppShell>
  <ErrorBoundary key={location.pathname}>
    <Outlet />
  </ErrorBoundary>
</AppShell>
```

`location` 來自 `useLocation()`（`react-router-dom`，本檔已在用同套件）。**`key` 是必要的**：
error boundary 一旦進入錯誤狀態就不會自己復原，用路徑當 key 讓使用者點側欄走去別頁時
自動重生，否則整個殼從此卡在錯誤畫面。放在 `RequireSession` 之內、`AppShell` 之內這一層，
一顆就蓋住所有登入後的路由（包含品牌底下每一頁），不必逐條路由包。

新測試 `frontend/src/components/layout/ErrorBoundary.test.tsx`（vitest + testing-library，
照 `frontend/src/components/ads/StrategyTab.test.tsx` 的寫法）：

- 一個會 `throw new Error("測試用爆炸")` 的子元件 → 畫面出現「這一頁壞了」與「測試用爆炸」，
  而且有一顆「重新載入」按鈕。
- 不會爆的子元件 → 原樣渲染子內容。
- React 會把 boundary 攔到的錯誤印到 `console.error`，測試裡用
  `vi.spyOn(console, "error").mockImplementation(() => {})` 壓掉再還原，
  **不要**因此去改任何全域設定檔。
- **不要點「重新載入」**：jsdom 沒有實作 `location.reload`，點了會噴 Not implemented。
  斷言按鈕存在就夠了。
