# Objective
Item 13: deleting a brand succeeds and leaves no brand data except the declared exemptions, guarded by the coverage test `cleanup.py` has always cited; the four dead tables are dropped.

# Done
1. `app/tests/test_cleanup_coverage.py` first (proved red on master): live `brand_id` tables from `information_schema` minus every registered `brand_tables` must be empty, apart from an explicit exemption list with one reason each — `llm_task` (kept on purpose, pinned by `test_orders_core_brand_cleanup.py`) and `audit_log` (audit outlives its subject). The list may only shrink. It imports only legacy facades.
2. Registries cover the rest: ads adds `ads_runtime_event`; schedule adds `campaign_period`, `channel_entity_map`, `period_node_membership`; `approval` is registered by core (after the modules whose rows reference it); `app/main.py` required-module list updated if a new registry name appears.
3. `llm_task.campaign_period_id` no longer blocks a period delete: `20260927000003_core_llm_task_period_fk.sql` recreates that FK with `ON DELETE SET NULL` (preferred over cross-module UPDATEs); other FKs into `campaign_period` are cleared by their owners before it.
4. Drops (grep `REFERENCES <table>` first): `20260927000002_core_drop_dead_tables.sql` (`decision`, `brand_dismissed_calendar_category`), `20260927000004_brand_intelligence_drop_strategy_hypothesis.sql`, `20260927000005_schedule_drop_budget_version.sql` (`campaign_period_budget_version`); remove them from `bi_repo` cascade lists and from tests that seed them.
5. Regression test: a brand with a period, bindings, runtime events, an approval and a kept `llm_task` deletes in one transaction; afterwards only exempt tables hold its `brand_id` and the kept `llm_task` has a null period.
