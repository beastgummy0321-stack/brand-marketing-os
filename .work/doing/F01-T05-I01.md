# Objective

Fix at the constraint, which is where both failing paths meet: `workbench_brief.product_id` becomes
`REFERENCES product(id) ON DELETE SET NULL`. Brand delete: 品牌智庫 deletes `product`, the briefs'
`product_id` go NULL, then 素材工作檯's `_delete_brand` deletes the briefs (outputs cascade). Product
delete: the brief survives unlinked. No change to the cleanup registry order (`app/core/cleanup.py`
is legacy and every other module relies on it) and no new product-level cleanup registration
(deleting a product must not destroy briefs and their adopted copy).

Verified before filing: `grep -rn "REFERENCES product" supabase/migrations/` shows the only
cross-module reference to `product` is `20260909000001_workbench_baseline.sql:27`; all others are
inside `brand_intelligence`.

# Done

- Write the test first and watch it fail with a foreign-key violation.
- New `app/tests/test_workbench_product_delete.py`, one `unittest.TestCase`. Follow
  `app/tests/test_brand_delete.py` for the connection (`db.current()`), brand/product creation and
  archiving (`bi_repo.update_brand(..., status="archived", actor=...)`,
  `bi_repo.update_product(..., status="archived", actor=...)` as in `app/tests/test_product_delete.py:74`).
  Insert the brief directly, no job enqueued:
  `INSERT INTO workbench_brief (id, org_id, brand_id, kind, source_kind, product_id) VALUES (%s, %s, %s, 'copy', 'manual', %s)`
  with `db.new_id("wbb")`, `db.DEV_ORG_ID`, then `conn.commit()`. Two tests:
  - `test_brand_with_product_linked_brief_deletes`: archive the brand, `bi_repo.delete_brand(conn, bid, actor=...)`
    does not raise; `bi_repo.get_brand` is None; `SELECT COUNT(*) FROM workbench_brief WHERE brand_id = %s` is 0.
  - `test_product_delete_keeps_brief_unlinked`: archive the product, `bi_repo.delete_product(conn, bid, pid, actor=...)`
    does not raise; the brief row still exists and its `product_id` is NULL.
- New migration `supabase/migrations/20260911000002_workbench_brief_product_fk_set_null.sql`, short
  English header comment (why: brand delete order and product delete, this ticket), then exactly:

  ```sql
  ALTER TABLE workbench_brief DROP CONSTRAINT workbench_brief_product_id_fkey;
  ALTER TABLE workbench_brief ADD CONSTRAINT workbench_brief_product_id_fkey
      FOREIGN KEY (product_id) REFERENCES product(id) ON DELETE SET NULL;
  ```

  The applied baseline is not edited.
