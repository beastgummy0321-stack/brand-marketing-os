# Objective

`parseFreeText` does not unwrap the response envelope, so 自由創作 dies on the first click. Found by
the F02-I11 e2e walk, 2026-09-12.

`app/workbench/routes.py:179` returns `{"parse": {parsed, note, spec}}` — exactly what the F02
Decisions' API surface list says. `frontend/src/lib/workbenchApi.ts:266` reads the body as
`FreeParseResult`:

```ts
return parseJsonOrThrow<FreeParseResult>(res, "AI 解析失敗，請稍後再試。");
```

So `result.spec` is `undefined`, `FreeJobPage.tsx:216` does `setSpec(undefined)`, the 「AI 解析結果」
table never fills and the button never becomes 「確認並生成」 — the two-click flow has no second
click and no pack can be created from 自由創作 at all. TypeScript does not catch it: the cast is
unchecked at runtime.

This is the only unwrap missing. Every other wrapper in the file already destructures its key
(`{packs}`, `{pack}`, `{set}`, `{styles}` at lines 226–369) — checked, so the fix is one call site,
not a pattern sweep.

# Done

- `parseFreeText` reads `{parse: FreeParseResult}` and returns `data.parse`, in the same shape as
  `getPack`/`getSet` two lines above it. No other function in the file changes; no `frontend/src`
  component changes (`FreeJobPage.tsx` is already correct once it receives a real `FreeParseResult`).
- New `frontend/src/lib/workbenchApi.test.ts`, following `frontend/src/lib/http.test.ts`'s pattern
  (`vi.mock` the module the function depends on, no server, no MSW): mock `@/lib/http`'s `apiFetch`
  to resolve a `Response` whose body is the real envelope
  `{"parse": {"parsed": true, "note": null, "spec": {…seven keys…}}}`, and assert
  `(await parseFreeText("brd_x", "五張夜跑廣告", {})).spec.outputs` is the array from inside `parse`.
  **The test must fail against today's code** — run it once before the fix to see it red, that is
  the whole point of the file.
- One test, one assertion path. Do not add coverage for the other wrappers, do not test the error
  branch, do not build a fetch-mock helper for future use.
