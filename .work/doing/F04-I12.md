# Objective

建立 Campaign 從「一句話＋必填日期 → 直接進策略頁」變成兩步：
`docs/design/ads/03-new-campaign.png`（描述）→ `docs/design/ads/04-understood.png`（理解如下，
六張可改的欄位卡）→ 按「產生策略建議」才花第二次模型錢。ARCHITECTURE.md §6.1 第 11 條。
§0 連結：**goal（the brief）**——使用者確認過的理解，才是後面每一步的輸入。

**動手前先用這兩張圖各呼叫一次 `Skill impeccable:impeccable`**（R6）。圖上的插畫、手寫字、
「AI 幫你規劃，讓投放更簡單！」貼紙**不做**；右側那張「MarketingOS 會自動幫你整理」說明卡**要做**
（它是新手要的預期管理），但用 tokens 的圖示與文字，不畫插圖。

# Fix

只剩一件，只准改 `ConfirmBriefPage.tsx` 的 `DateRangeField`（＋`ConfirmBriefPage.test.tsx`
那一個對應斷言）：

1. **1024 寬時「結束日期」輸入框仍然撐出「時間」卡、仍然被隔壁「受眾方向」卡蓋住**——
   第三輪的 `lg:flex-row` 沒有修好這件事，planner 在第三輪 build 出來的 `dist` 上重量
   （viewport 1024×900、`page.route` 假資料）：

   | 元素 | 1024 量到 | 卡片右緣 | 結果 |
   |---|---|---|---|
   | 起始日期 input | right 468 | 610 | OK |
   | 結束日期 input | **right 645.27** | 610 | **溢出 35.27px** |
   | 儲存 | right 368 | 610 | OK |
   | 取消 | right 430 | 610 | OK |
   | 鉛筆鈕 | right 693.27 | 610 | 被撐出去 83.27px |

   `document.elementFromPoint()` 打在結束日期右緣，回來的是隔壁卡的 `div.flex.size-10`
   （受眾方向卡的圖示圓盤）——那顆日期輸入在 1024 下點不到。卡片本身
   `scrollWidth 445 > clientWidth 361`。跟第二輪一模一樣的數字。

   - **成因（已查證，別再猜）**：Tailwind 的 `lg` 斷點是 `min-width: 1024px`，
     **1024 本身就在 `lg` 裡**，所以 `lg:flex-row` 在 1024 照樣是橫排 → 沒修到要修的那一格。
     實測 1023 寬（`lg` 不生效、真的直排）兩個輸入 right 都是 544.5 ≤ 卡片 609.5，
     直排的寫法是對的，只是斷點挑錯。1280 也是剛好塞下（輸入 right 685 ＝ 卡片內緣 685，
     **0px 餘裕**）——所以「改成 `xl:flex-row`」也只是把同一顆地雷往上搬一格，不要這樣修。
   - **這一輪的修法（照做，不要自己換方案）**：`DateRangeField` 裡包住兩個 `Input` 的那一層
     **永遠直排**——把 `lg:flex-row lg:items-center` 兩個 class 直接刪掉，剩
     `className="flex flex-col gap-2"`，兩個 `Input` 保持 `w-full`；中間那個 `~` 在直排時沒有
     意義，連同 `<span>` 一起刪（或保留但確定它不佔寬）。日期上下兩排在一張半寬卡裡是正常長相，
     不需要為了橫排再加任何 media query。
     **Tailwind 的 `lg` ＝ min-width 1024，`xl` ＝ min-width 1280：要修的那一格就是 1024 本身，
     所以任何 `lg:`／`xl:` 的橫排 class 都不行；這一層只准 `flex flex-col gap-2`。**
   - `ConfirmBriefPage.test.tsx` 那一個斷言要**換成會紅的寫法**：現在釘 `toContain("flex-col")`
     的斷言在第三輪那版 class（`flex flex-col gap-2 lg:flex-row lg:items-center`）上**也會綠**，
     等於沒守到東西。改成同時釘兩件：
     `expect(wrapper.className).toContain("flex-col")` **且**
     `expect(wrapper.className).not.toMatch(/flex-row/)`。其他四個斷言不動。

**驗收（誰來量）**：`width-overflow.spec.ts` 只量 `#root` 的溢出、不進編輯狀態，**看不到這個
bug**；這一輪**不要**改那支 e2e，也不准為了量測在 repo 內新增任何檔案（含 `frontend/e2e/**`，
那是 scope violation）。閘門是審查者在 1024／1280 的實截與實量。你要自己先量就把暫時腳本放在
repo 外的暫存資料夾，回報數字即可。
