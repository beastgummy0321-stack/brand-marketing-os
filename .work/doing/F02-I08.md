# Objective

Runs after F02-I07 and before F02-I09 — the four screen issues are a strict chain over the same
`App.tsx`／`workbenchApi.ts`／`components/workbench/**` (F02 Decisions). Add only your own route,
types and components.

Screen 2, the 任務包 page — reference image 2, 1:1 at 1672px. One pack, its sets, what is left, and
the one decision this page owns: 核准整包.

# Done

- Route `/brands/:brandId/workbench/packs/:packId` in `App.tsx`; breadcrumb 品牌 / 素材工作檯 /
  <pack name>.
- Pack-local left rail card 「任務包」: 「‹ 返回素材工作檯」, 總覽 (selected by default), one row per
  set with ✓ (已完成) ／● (進行中／等待決定) ／○ (待開始). **This is not the OS sidebar** and not a
  shared kit component; the OS sidebar keeps 素材工作檯 highlighted.
- Header: source badge, pack name, status badge, 「建立於 … ｜ 最後更新 …」; on the right the ⋯ menu
  and 「核准整包」. 核准整包 is disabled while `can_approve` is false, with the sub-line
  `blocking_text` 「尚有 n 個素材組未完成」.
- Meta strip: 平台 ／ 目標 ／ 需要完成 n 個素材組 (from `PackDetail.meta`).
- 「完成進度」 card: 「n / m 素材組完成」, %, legend 已完成／進行中／待開始 — the three legend numbers
  come from the API and must add up to `sets_total`; never compute a fourth bucket in the browser.
- 「素材組進度」 table: set name, status badge, then **one cell per required product type** rendering
  `cells[].text` **verbatim** — the API already spells 已選定／需要 (2／5), 未生成 and 「—」
  (F02-I03); the browser formats none of it and holds no copy of those strings (`cells[].state` is
  for styling only). That the user really sees 未生成 is asserted in F02-I11's e2e. Row chevron
  opens the set studio.
- Right column: 「摘要」 card, read-only, fields as the upstream sent them (情境／角度／風格／目標受眾／
  重點訊息／參考連結) — **no 編輯 button** (image 2 draws one; the ruling says read-only, the ruling
  wins). 「完成條件」 checklist from `completion[]`: computed item ticked by the system, the two human
  items tickable, each tick a `POST …/completion`. Ticking the computed item while it is false opens
  a `ui/dialog` that explains what is being overridden and is **skippable** — confirm proceeds,
  cancel leaves it unticked. Info box 「尚有 n 個素材組未完成，完成後即可核准整包。」
- 核准整包 → `POST …/approve`; on success the pack reads 已完成, the button is replaced by the
  approved state, and 選定 controls everywhere in the pack become inert (the API already refuses;
  the UI must not offer). A 409 shows the API's message; it never pretends to have succeeded.
- No new npm dependency. Reuse `ui/dialog`, `ui/badge`, `ui/button`, `ui/dropdown-menu`,
  `.table-surface`, `.surface`, tokens.
