# Objective
A queue row's done-ness has one owner, so the top bar, the home list and 「下一件」 agree, a deferred item has a way back, and a
failed decision leaves nothing behind (feature Contract D; drill-10 Q1, Q2, Q3, C3-D, C3-E). Today `home/status.ts` decides
done-ness, the top bar counts every open interrupt, and a decision is two writes.

# Done
1. `app/ads/queue_done.py` (new, pure): `done(row) -> bool` with exactly today's `isQueueItemDone` rule over the row's
   `kind_key` and `proposal` (stop_loss / worse / scale_budget / cleanup through the proposal's status and verification state;
   refresh_creative / insufficient_data never). `triage.get_queue` puts `done` on every row; `status_summary.open_items` counts
   rows with `done = false` (same queue read, not `interrupts.list_open` alone).
2. A cleanup candidate whose closable ads number 0 (all left are data-insufficient, `triage_capacity`) is not raised as an open
   row (Q1's 「核准清理（關 0 則）」 dead end).
3. Frontend: `QueueItem.done: boolean` (`lib/adsTriageApi.ts`); `isQueueItemDone` returns `item.done` (or is removed and its
   callers read the field); `nextOpenQueueItem` uses it — no second copy of the rule. Test factories that build `QueueItem` add
   `done`.
4. Q2: a deferred row on the home 「今天處理過」 chip links to its change set and shows 「M/D 再看」 (`proposal.revisit_at`); the
   top bar's count equals the home count.
5. Q3: one decision is one write — `POST …/change-sets` accepts an optional `decide: {decision, reason, revisit_at?}` and runs
   `change_control.decide` in the same transaction, rolling the new set back when the decision is refused; `ConfirmPage` uses it
   when no set exists yet (an existing set keeps today's `decideChangeSet`). A refused 暫緩 shows the reason and leaves no draft.
6. C3-E: 「回到確認」 / 「回到到平台完成」 on the handoff and verify pages land on the requested step instead of bouncing back
   (and the second label reads 「回到在平台完成」).
7. Tests: `done` per kind and status (deferred → done, draft → not); `open_items` ignores done rows; zero-closable cleanup not
   raised; create-with-decide rolls back on a past `revisit_at`; home deferred chip links and shows the date; `nextOpenQueueItem`
   skips done rows.
