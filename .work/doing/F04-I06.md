# Objective

建檔精靈是唯一一個「使用者給多少、我們就打幾次模型」的地方：`_read_photo_products`
（`app/intake/ai.py:143-152`）對草稿裡的**每一張**照片各打一次 `intake_photo_scan`，沒有上限；
`run_next_question`（:290-326）每一題都把**全部**初步印象與**全部**先前問答重送一次，最多 8 題。
前者是不受控的輸入（使用者一次拖 60 張照片就是 60 次呼叫），後者是可預期但白付的重複。
ARCHITECTURE.md §1 第 1、2 條。§0 連結：**context**（品牌建檔是所有鏈的起點）。

`legacy_migration: true`：`app/intake/**` 是 legacy，這張票只在既有函式上加上限，不搬呼叫端、
不加新能力。

# Done

## 1. 照片掃描有上限，而且說出來

`_read_photo_products`：模組層常數 `MAX_PHOTO_SCANS = 12`。只對前 12 張照片打模型；第 13 張起
**不呼叫**，直接產出一張 `status="skipped"` 的卡（`_photo_card` 已有這個狀態，`run_next_question`
:303 會跳過它），`message` 寫
`「一次最多讀 12 張照片，這張沒有讀；照片產品卡可以自己填，或先完成這批再上傳。」`

- 不是報錯、不是擋上傳：是誠實的上限，畫面照舊往下走（建檔精靈的鐵律：一次失敗不是死路）。
- 每張照片之後照舊 `state.save(draft, conn)`（進度要看得見），被略過的那些也要進
  `product_card_drafts`，不然使用者不知道它們存在。

## 2. 出題的上下文只帶最近的

`run_next_question` 組 `lines` 時：

- `draft["scan_impressions"]` 取**前 8 條**（`MAX_IMPRESSION_LINES = 8`）。截斷時補一行
  `另有 N 條初步印象沒有列出。`
- `draft["answers"]` 只列**最近 3 題**（`MAX_ANSWER_LINES = 3`）；被略過的較早問答不必逐字重送，
  因為「已覆蓋面向」那一行（:313）已經是它們的摘要——這句話寫成註解，讓下一個人知道為什麼可以砍。
  截斷時在「已問過」那一段之前補一行 `更早的問答已收斂成下面的「已覆蓋面向」。`
- 收斂規則那一大段（:315-323）與 `covered`／`missing` 兩行**一個字都不動**：那是指令，不是資料。

## 3. 不要順手做的

不動 `intake_scan` 的每 URL 3000 字（那是真的要讀的內容）、不動 `_QUESTION_SYSTEM`、
不動 `script.MAX_QUESTIONS`、不改 `persona_generation.py`（每商品一次 compile 是另一個決定，
本次不做）。

# Blocked if

- `_photo_card(..., status="skipped")` 的既有簽章不接受 `message`：照它的實際形狀做，
  別為此改 `_photo_card` 的介面以外的行為。
- 截掉較早問答會讓 `validate_question_reply` 判定重複出題而一直失敗——先跑測試看，真的發生就
  release 並回報，不要把上限調到形同沒有。
