# Objective

使用者：「廣告中心有排過就 Agent 自己抓歷史數據建議金額，沒排程過就由系統算出最佳試驗金額去做投放。」

現況：app/ads/repository.py:381 budget_history **只讀 ads_outcome_daily**，也就是只認得新迴圈自己跑過
而且已結案的 Campaign。一個有 37 個月 Meta 歷史、剛接上帳戶的品牌，第一次建 Campaign 照樣走
「冷啟動估算」——使用者在步驟一宣告的「投放過」在系統眼裡等於沒投放過（演練四 V-13）。

修法：沒有迴圈歷史時退回讀這個品牌自己綁的廣告帳戶。**數字全部程式算，模型不讀廣告歷史**
（ADR 0067；ARCHITECTURE.md §8 第 7 條）。

# Done

1. **app/ads/channels.py 多一支**（平台名字只准住在這裡）：
   `account_spend_history(conn, org_id, brand_id, conversion_goal) -> dict | None`
   - 走 app.meta.repository.bound_account_ids_for_brand ＋ spend_summary(level="campaign",
     半開區間 [今天−30, 今天+1)，把 conversion_goal 傳進去——那支的 docstring 明講 CPA 用哪個事件由
     呼叫端決定)。「今天」用 app.core.settings.today_for_org，不是機器的 date.today()。
   - 回 {"cpa": float|None, "daily_spend": float, "days": 30, "channel_label": "<label>"}；
     沒綁帳號或 30 天總花費是 0 → None。
   - total["cpa"] 是 None（沒追蹤到轉換）時 cpa 就是 None——**不要用 ROAS 反推、不要拿 0 當分母**。
2. **app/ads/repository.py::budget_history**：
   - 既有的 ads_outcome_daily 路徑成功時多回 "source": "ads_loop"、"source_text": "上一期日預算"。
   - 原本兩個 return None 的地方（沒有日 CPA、沒有已結案 Campaign）改成退回帳戶歷史：
     hist 是 None 或 daily_spend <= 0 → 仍然 return None（誠實冷啟動，維持現狀）；
     否則回 {"last_daily_budget": round(hist["daily_spend"]), "cpa": hist["cpa"],
     "sample_days": 30, "sample_ads": None, "source": "meta_account",
     "source_text": f"{hist['channel_label']} 近 30 天平均日花費"}。
   - conversion_goal 從 app.brand_intelligence.repository.get_brand 讀（既有 facade），這支函式裡讀一次。
3. **app/ads/budget.py::_history_scenarios**：caption（:112）改成吃 source_text
   （`base_text = history.get("source_text") or "上一期日預算"`，然後
   f"{base_text} NT${round(last_daily)} ×{mult:g}"）；basis 多一個 "source"。
   **三個乘數（×0.6／×1／×1.6）不動、冷啟動那條路不動。**
4. **測試**
   - test_ads_budget.py：帶 source_text 的 history → 三張卡的 caption 帶得出那句話，金額仍是

   - test_ads_strategy.py：有已結案花費 → source == "ads_loop"；沒有迴圈花費但有綁帳戶且
     meta_entity_spend 有近 30 天的列 → source == "meta_account"、last_daily_budget 等於總花費 ÷ 30
