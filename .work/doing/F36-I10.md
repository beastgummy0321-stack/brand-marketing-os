# Objective
`legacy_migration: true` — `app/brand_intelligence/**` is legacy; this is the minimal owned-table facade extension ARCHITECTURE §2
allows (F34-I01 precedent): two partial unique indexes on `product` and a guard in the existing `create_product`. The lead applies
the migration to the shared dev DB (54322) before merge (merge smoke hits that DB); the dev DB had no same-name active parent on 2026-09-28.
Drill-6 #16 guard, ruling H, Contract W in `.work/features/F36.md`. Root cause: name uniqueness lives in 5 of 9 callers'
hand-rolled checks (exact string, archived counted as known) and the data layer has none
(`supabase/migrations/20260826000002_brand_intelligence_baseline.sql:28-39`; `parent_id` from `20260914000001`);
`create_product` (`app/brand_intelligence/repository.py:316-344`) never looks. Nothing intentionally creates a same-name
active product (archive／restore toggles one row, `brand_web/routes_products.py:388-395`).

# Done
1. Migration (new file, brand_intelligence prefix, CREATE INDEX only):
   `CREATE UNIQUE INDEX product_active_parent_name_uniq ON product (brand_id, lower(btrim(name))) WHERE parent_id IS NULL AND status = 'active';`
   `CREATE UNIQUE INDEX product_active_sellway_name_uniq ON product (parent_id, lower(btrim(name))) WHERE parent_id IS NOT NULL AND status = 'active';`
   with a header comment naming F36 and the rule.
2. `repository.create_product`: `name = name.strip()`; before inserting, `SELECT * FROM product WHERE brand_id=%s AND parent_id IS NOT DISTINCT FROM %s AND status='active' AND lower(btrim(name)) = lower(%s)`;
   a hit returns that row unchanged (no audit, no update). Docstring: "get-or-create; the index is the backstop".
3. `repository.update_product`: wrap the UPDATE so a `psycopg.errors.UniqueViolation` becomes `ValueError("已有同名產品")`
   (rollback first); `brand_web/routes_products.py` already maps `ValueError` to a 4xx — do not touch it.
4. Tests: `test_product_hierarchy.py` — same name twice (with 「 超能特惠組 」 spacing／case variants) returns one id; a sell-way
   name may equal another parent's name; two sell-ways with one name under one parent collapse to one. `test_products_api.py`
   — manual POST with an existing name returns the existing product (200/201 with the same id, whichever the route returns
   today). `test_intake_offerings_api.py` — re-saving step 3 with a typed existing parent name and no `product_id` creates no
   row. `test_product_delete.py` — restoring an archived product while an active same-name one exists → 4xx 「已有同名產品」;
   creating an active product while only an archived same-name one exists → succeeds.
