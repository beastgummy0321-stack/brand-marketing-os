# Objective

`learning_ledger` gets the writer it has been missing since `app/ads/` died. §0: it serves the
**learning → next goal** link; its input is a finished campaign's verdict (passed in by the caller,
never derived here); its output is rows the strategy prompt and 品牌智庫 read; its trace is the
evidence, sample size, source campaign and time of every learning; it is **core** — without it the
loop does not close.

Storage only. The rules about *when* a learning is written, at what level and when it needs
revalidating live in `ads` (F03-I12) — this issue must not encode them (`ARCHITECTURE.md` §3).

# Done

- `app/brand_intelligence/repository.py` gains exactly two functions, next to the
  `product_economics` block, in the file's existing style (raw SQL, `_row`/`_rows`, `now_utc`,
  `new_id("lrn")`):
  - `record_learning(conn, brand_id, *, actor, learning_text, applicability_scope, confidence,
    sample_size, source_cycle_id=None, product_id=None, platform=None, needs_revalidation=False,
    learned_at=None) -> dict` — writes one row, `source_track` stays its default, `org_id` from
    `_org_id_for_brand`. `confidence` is validated against `("observed", "likely", "validated")`
    and `learning_text` must be non-empty (`_require`), because a ledger row with no sentence is
    worse than no row.
  - `list_learnings(conn, brand_id, *, product_id=None, include_expired=False,
    limit=50) -> list[dict]` — newest `learned_at` first, `expired` rows excluded unless asked,
    `needs_revalidation` passed through so the reader can label it.
  - `set_learning_revalidation(conn, brand_id, learning_id, *, needs_revalidation, actor)` is **not**
    part of this issue; F03-I12 sets the flag at write time.
- Nothing else in the file changes; no new table, no migration, no deletion entry (the module's
  cleanup registration already covers `learning_ledger` — confirm that and say so in the commit
  message rather than adding a second registration).
- `app/tests/test_ads_learning_ledger.py` (the falsifier): a written row comes back from
  `list_learnings` for its brand and never for another brand; an unknown `confidence` raises;
  an empty `learning_text` raises; `expired` rows are hidden by default and visible when asked;
  deleting the brand removes the rows (the existing cleanup path still holds — this is the
  regression `test_brand_delete.py` already writes by hand, so leave that test alone).

`uv run python -m pytest app/tests/test_ads_learning_ledger.py -q` and the two delete tests that

# Blocked if

`learning_ledger`'s columns cannot carry a learning without a schema change (they were checked and
they can: `learning_text`, `applicability_scope`, `confidence`, `sample_size`, `source_cycle_id`,
`needs_revalidation`, `learned_at`). If you disagree, report the missing column — do not add one and
do not create an `ads_learning` table.
