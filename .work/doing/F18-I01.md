# Objective
Write an absent platform action as a marked derived zero when the ruled three conditions hold, so "spend with zero results" can be known instead of unknown.
# Done
1. New `app/ads/tracked_zero.py::apply(conn, org_id, brand_id, campaign_id, start, end) -> dict`; platform-neutral, no adapter import, no platform literal. `OBSERVATION_WINDOW_DAYS = 28` at module top.
2. Demonstrated definition: over this campaign's entity rows with `day BETWEEN end - OBSERVATION_WINDOW_DAYS + 1 AND end`, collect distinct `(result_kind, result_action, result_attribution)` where `availability.result_count == 'available'` and `result_count > 0`. Exactly one triple ⇒ proceed; none or several ⇒ return `{"derived": 0, "reason": "no_demonstrated_definition" | "mixed_result_definition"}` and write nothing.
3. Derive a zero on a row only when ALL hold: `result_kind` equals the demonstrated kind and `result_count IS NULL`; the key `result_count` is present in `availability` (mapping ran; never a `_predates_result_columns` row); `availability.spend == 'available'` and (`spend > 0` or `impressions > 0`); `day <= settings.today_for_org(conn, org_id=org_id) - 1 day`; `day` inside the `[start, end]` the completed sync covered; row is not `is_monthly_budget_row(attribution_key)`.
4. The write sets `result_count = 0`, `result_action` / `result_attribution` to the demonstrated triple, `availability.result_count = 'derived_zero'`. It never touches spend, purchases, revenue, `attribution_key` or the unique key.
5. Exactly one call site: `external_sync.run_sync`, same transaction, where the `observations` section completes with no cursor and no errors and coverage is recorded (around `app/ads/external_sync.py:450-453`).
6. `review_evidence._result_view()` treats `availability.result_count in {"available","derived_zero"}` as known and adds `"derived_zero_days": <int>`. `_predates_result_columns`, `mixed_result_definition` and the length fail-closed rules are unchanged.
7. Grep every reader of `availability` under `app/` and confirm none breaks on the new value (`month_budget.py`, `aggregate()` METRICS loop, `targets.py`); report what you checked.
8. `docs/architecture/ads.md`: record the derived-zero rule next to the result-definition section and correct the METRICS drift named in the feature Decisions.
9. Tests: each condition independently blocks derivation; re-sync of the same window re-derives (idempotent); an account that never reported the action stays `result_unknown_days`; `targets._trailing_30` resolves on a window blocked only by derivable zeros.
