# Objective

手動交接、平台讀回與素材版本證據。

按 §6.9.4 產生手動上架交接並建立可追溯的版本對應，不把原有成效錯算給新素材。

# Done

1. 新增 ads_asset_binding 與 manifest，revision FK 同品牌 Campaign、有效期不重疊，完整保留確認来源和 native creative snapshot。
2. 交接 GET 回原檔授權下載、完整原／補文案、目的節點、用途、追蹤名稱；不修改平台設定。自述 API 與 verify API 分開，前者不產生平台證據。
3. 候選僅限同來源帳號活動範圍；用戶選定 ID 後重新平台 GET 核對父鏈與 creative，成功才 platform_confirmed。失敗保持待確認，名稱與縮圖不得作匹配證明。
4. UI contract 同時給廣告存在驗證狀態、素材版本 evidence_level、last_verified_at、stale_reason。第一個不涵蓋第二個，不輸出籠統已同步掩蓋不確定。
5. 本機 SHA256 不等於平台媒體 hash；只有 adapter 提供有契約依據的等價證據才能 media_verified。用戶核對為 user_verified，不能升為平台內容相同。
6. 首次觀測前／日內換 creative／多素材混用／無精確素材關聯，禁止派發該日期成效給單一素材。仍可讀原生廣告成效，標無法分到版本；同廣告不同版本不重複領同筆觀測。
7. 版本修改需重新確認；同步 creative 改變讓關聯 stale，狀態變動不刪證據。測試跨帳號／父層、同名候選、並行占用、回讀失敗、版本變更、歷史回填及日粒度混用。

必要介面補齊（2026-09-18 靜態核對）：ExternalReader 與 Meta facade 需新增唯讀、單物件廣告／父層回讀，現有 campaign ads 分頁不是指定廣告核對。外層仍只走既有憑證 facade，不持有 DB transaction 等待 HTTP；回讀後重新檢查綁定帳號及 placement revision。帳號可回傳既有 timezone_name，不猜時區。Meta 無連續素材歷史或媒體等價證據時，原生廣告成效可見但不歸屬單一素材版本。

UI 重開所需的最小 I04 接口補齊：新增同 org／brand／campaign、有界分頁的建議批次清單 GET，讓尚未確認、失敗或執行中的批次離頁後可找回，不依賴 localStorage 或重新模型呼叫。只加 ads_asset_suggestions 的讀取與隔離／分頁測試，既有生成與費用政策不變。
