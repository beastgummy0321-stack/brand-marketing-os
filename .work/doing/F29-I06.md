# Objective
A material request raised from an ad row binds to that ad as "replace this ad", and can be cancelled (Feature Contract H; Unresolved 6 defaults).

# Done
1. Migration `20260925000003_ads_material_replace.sql` (new file, ads prefix): `ads_material_task` gains `replaces_entity_id text`, `cancelled_at timestamptz`, `cancelled_by text`, and a partial unique index on (org_id, brand_id, campaign_id, replaces_entity_id) where not cancelled. Check `grep -rn "REFERENCES ads_material_task" supabase/migrations/` first.
2. Create accepts `replaces_entity_id` (must be an ad entity of this campaign via `bindings.entity`, `native_kind='ad'`); a second request for the same open entity returns the open task. One-click defaults per Unresolved 6 when the caller sends only `replaces_entity_id` and `operation_id`.
3. Cancel route; refused with 409 `material_task_in_use` once an approved change set references the task. The list omits cancelled tasks; the task view carries `replaces` and `cancelled_at`.
4. `handoff_new_ad.create` defaults `replaces_entity_id` from the placement's task when the payload has none (an explicit value still wins and is validated as today).
5. Tests: wrong campaign's entity, an adset entity, closed campaign (refused as today), repeat request, cancel then request again, cancel after approval (409), new-ad handoff inheriting the binding, operation-id replay.
6. `adsMaterialApi.ts`: `MaterialTask.replaces`/`cancelled_at` (required; the panel test factory sets them), `createReplaceRequest(brand, campaign, entityId)`, `cancelMaterialTask(...)`.

# Verify
Issue verify plus manifest gates. The lead applies the migration to the dev DB before merge (privileged).

# Blocked if
Material tasks are shared with the workbench in a way that a cancel would orphan a workbench pack or reservation — stop and report.
