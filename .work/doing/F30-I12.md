# Objective
One launch view and the batch operations the publish page needs (Feature Contract G, Unresolved 1 default).

# Done
1. The launch batch freezes only ads with ready material; `deferred_ads` lists the rest; a later approval version picks them up once ready. The decision lives in the shared core, not `adapters/manual.py` (which only renders what it is given).
2. `launch_view.py` + `GET …/launch`: step, version, approval time, summary, this batch's items only, per-item state, mismatches with observed values, unreadable fields.
3. `POST …/launch/readback` (auto-match by exact name under the expected parent), `…/items/{id}/unreport`, `…/items/{id}/confirm {key}` — the same self-confirm rule as settings readback; stored observed values on mismatch.
4. `adsLaunchApi.ts` types and calls.
5. Tests: one ad without material, readback match／ambiguous／missing, unreport after report, landing URL confirm reaching verified, a new-ad handoff not counted, stale after a plan edit.
