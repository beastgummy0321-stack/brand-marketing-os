# Objective
The strategy prompt carries a program-built 【這個品牌的起點】 section and a 【可用角色】 section (Contract P), and a reply naming an unavailable role is refused. Root cause: the program already knows these facts and never passes them; the department example fixes the role list.

# Done
1. `strategy.py`: one function builds the starting point from data already in `generate()` or one ads-owned read:
   - 投放過沒：`brand["advertising_history"]` → `has_history` 「精靈答過：投放過」／`none` 「精靈答過：沒投放過」／NULL 「精靈還沒問」.
   - 歷史來源：`history` (already computed) → its `source_text`＋`sample_days`, or 「沒有可用的花費歷史」.
   - 近 90 天平台讀回：one query on `ads_external_daily` (`metric_scope='ad'`, brand scope, `day >= today-90`) → clicks 與 purchases 合計；no rows ever for the brand → 「還沒讀過平台資料」 (never 0). Put the query in `repository.py` next to `budget_history`.
   - 迴圈購買：purchases from `ads_outcome_daily` for closed campaigns (the same rows `budget_history` reads) or 「沒有」.
   - 像素：`launch_settings.cached_pixels(campaign)` → 「已讀到 N 個像素」／「還沒讀像素」.
   - 訂單：one fixed line 「訂單資料不在這裡，別假設有回購名單」 (ads may not import `app.orders`).
   Each line states 不知道 when unknown; no number is invented.
2. Available roles: `retarget` is offered only when `advertising_history == "has_history"` or external clicks > 0 or any purchases > 0; `new` and `explore` always. Section exactly as Contract P. `_validate_reply(data, available)` refuses a role outside the set (returns None → `strategy_failed`, nothing saved), keeping today's duplicate/pct checks.
3. `strategy.md`: the role rule becomes 「只能用【可用角色】列出的角色，不能自己加」; the JSON example uses placeholders (no fixed three-role list); add one line telling the model to weigh the 起點 facts (a brand that never advertised has no warm pool; a small buyer count does not carry a 回購 group).
4. Tests (red first): fresh brand → prompt has `【可用角色】\nnew、explore` and the 起點 lines; the fixture `_VALID_REPLY` (three roles) is refused for it; a brand with `advertising_history='has_history'` (set through `app.brand_intelligence.advertising_history.set_advertising_history`) or with external click rows gets `new、retarget、explore` and the fixture passes. Existing tests keep passing by making their fixture brand eligible in `setUp`, not by weakening assertions.
