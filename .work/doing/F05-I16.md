# Objective

回到步驟 3 時，**只有一個賣法的商品品名會被清空**。`OfferingsStep.tsx:96`
（`deriveFromOfferings`）寫的是 `name: variants.length > 0 ? parent.name : ""` ——沒有子列的
商品（精靈自己存的單品、掃描建立的商品都是這種）反推回畫面時品名變成空字串，畫面只剩
「品名」placeholder，而 `:250` 的驗證是 `if (!group.name.trim()) return "商品品名還沒填。"`，
使用者要重打一次品名才存得回去。

實機證據（2026-09-14 審 F05-I14 時發現，8740 後端、真瀏覽器）：品牌 `常春健康`
（`brd_01M2D3397KT78QXRV7WBPFBZ88`）資料庫裡有 `薑黃錠`、`益生菌` 兩列 `product`，步驟 3 畫面
出現兩張商品卡但兩個品名欄都是空的。

因果鏈：單賣法商品的「母列就是那一列」，`variants` 為空，`rows = [parent]`；寫 label 的那一行
需要區分母子（`labelFromName`），寫 name 的那一行被一起套上同一個三元判斷，但 name 沒有這個
問題——母列的 `name` 永遠就是品名。這是 I07／I08 留下的缺陷，`?step=`（F05-I14）把它推到
「按紅燈按鈕就會看到」的主路徑上，所以要在結案前修掉。
