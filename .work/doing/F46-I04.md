# Objective
Every closed campaign leaves a ranked 留下／換掉 list with numbers and the next plan has to build on it (feature outcomes 1–2,
Contracts B, L, G; drill-10 root cause 1, L1–L4: the 555 winner was tagged 太貴 beside 1,769, the 290 winner never entered
learning, the plan re-ran the themes it had just cut).

# Done
1. `app/ads/learning_rank.py` (pure, no SQL): `rank(rows) -> list[dict]` over `period_grades.grade_period` rows of one campaign —
   Contract B exactly: who enters, order, verdict (`keep` / `keep_relative` / `replace`), labels and flags (`樣本少` = 1–4 sales;
   `相對最好，仍高於上限`, or `相對最好` with no cap), `rank` / `of`, and `rule_text(ranked, cap)` (feature Contract L wording). Ties
   and counter-examples: equal cost → more sales first, then name; cap `None` → relative rule; no sold row → all `replace` and
   「沒有一則賣出 → 全部換掉」; results unknown or spend unknown / mixed currency → not in the result.
2. `coordinate_learning.write_coordinate_learnings` writes one row per ranked ad with the Contract B scope (`v=2`, group from the
   ad's `customer_group_id`, format from `live_creative` coordinates) and text; idempotent per `<campaign>:<ad>` as today. The F39
   grade path and its per-dimension tally go; rows without `v=2` are skipped by every reader.
3. `app/ads/learning_view.py`: `learnings_view(conn, org, brand, *, campaign_id=None, sell_way_id=None, limit=12)` = Contract L,
   numbers from the stored scope only. `closed_on` is the closed time's org-local date (never a raw ISO timestamp); `empty_reason`
   from the campaign's `verdict_json` (`missing_days` or the incomplete-simulation sentence → 「資料缺天，這期沒有記學習」).
   Customer group `who` through `bi_repo` reads; a group id that no longer resolves → 「已刪除的顧客群」.
4. Prompt section (Contract G): `coordinate_learning.ranked_section(conn, org, brand, campaign) -> (text, learning_ids)` builds
   【上幾期的排名（程式排的；每筆＝花費÷成交）】 from the view (newest ≤3 campaigns, group summary first), numbering groups by this
   campaign's 【這個賣法的顧客】 list; empty → 「【上幾期的排名】（還沒有結案過的廣告）」. Both `strategy.generate` and
   `plan.adopt_strategy` use it where they used `scoreboard_section`; `knowledge_item_ids` carry its learning ids.
5. `strategy.generate` stores `basis.ranked_learnings` = the view it prompted with and stops writing `basis.coordinate_learnings`
   (old campaigns keep theirs). `basis.coordinate_scoreboard` keeps the learning ids.
6. Gate (Contract G) in `plan.adopt_strategy`, after F46-I01's group checks: refuse with `delivery_plan_failed` when an ad's
   (customer group, angle) is a `replace_pairs` member, or `keep_pairs` is non-empty and no ad hits one. Pairs only count for
   groups listed in this campaign's 【這個賣法的顧客】; rows with no group never count.
7. Department texts, in their own style: `strategy.md` — 【上幾期的排名】 replaces 【座標成績表】; `rationale` names the 留下 ads it
   builds on (ad name + 每筆) and the 換掉 group/angle it leaves; no English codes (existing rule). `delivery_plan.md` — keep at least
   one 留下 group + angle (other coordinates may change), never reuse a 換掉 group + angle unchanged, 樣本少 留下 rows are worth
   re-testing; refusal sentence like the offer rule.
8. `ScriptedProvider` delivery-plan branch: when the prompt lists a 留下 row whose group is listed, the first ad takes that group
   number and angle key; otherwise unchanged.
9. Tests: `rank` over the drill-10 P1 shape (555×6, 1,643, 1,769 under cap 450 → 555 `keep_relative`, others `replace`; 290×4 under
   cap → `keep` + 樣本少), ties, no cap, no sales, unknown rows; closeout writes `v=2` rows and skips partial data; view shape,
   ordering, `empty_reason`, deleted group, `sell_way_id` / `campaign_id` filters; prompt section text; plan gate refuses a
