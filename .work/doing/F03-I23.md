# Objective

Feature integration review follow-up (F03 `# Integration review`, notes 1 and 2). Two screens
print money wrong: 投放結構 shows no campaign money at all where the daily budget is edited
(Acceptance 4 fails exactly where the user acts), and 總覽 prints an untracked `0` as 購買 and
blends the two budget readings into one number (forbidden by the I11/I16 decisions). §0 link:
**strategy → delivery plan** and the campaign header the user reads before every step; input is
the `CampaignDetail` payload already on screen; output is captioned money a person can trust;
trace is the screen itself; **core**. Frontend only — every number needed is already in the
payload, nothing new is fetched and nothing is added to `app/**`.

# Done

## 1. One shared deriver in `frontend/src/lib/adsApi.ts`

Add **one** exported pure function next to the `CampaignDetail` type (no API call, no new type
unless TypeScript demands one), mirroring `app/ads/repository.py::_budget_total` exactly — days
inclusive of both ends, `null` when either date is missing or `days <= 0`:

```ts
export function currentBudgetTotal(c: CampaignDetail): { dailySum: number; days: number | null; total: number | null }
```

`dailySum = sum(c.groups[].daily_budget)`; `total = round(dailySum * days)` (whole NT$), `null`
when `days` is `null`. Both screens below call this and nothing re-derives the formula a second
time. Leave a one-line comment saying why the browser derives it: `campaign.budget_total` in the
payload is the value at load time, and `patchGroup` returns only the edited group — after an edit
the payload field is stale, `c.groups` is not.

## 2. `DeliveryTab.tsx` — the money the edit moves

Add one full-width `surface` card **above** the existing `grid-cols-[...]` tree/inspector grid
(it must stay visible while the 每日預算 field is edited), rendered only in the branch where
`c.groups.length > 0`. Header `<h2>預算（這個 Campaign）</h2>`; body is a `grid-cols-3`, each cell
label (`text-xs text-muted-foreground`) / value (`metric-number`) / caption
(`text-xs text-muted-foreground`) — design-system §7: every number captioned.

Exact strings (`t = currentBudgetTotal(c)`):

1. label 「目前投放組合計」
   - value `t.total !== null` → `formatCurrency(t.total)`; else 「尚未設定」
   - caption `t.total !== null` → `各投放組日預算 ${formatCurrency(t.dailySum)}／天 × ${t.days} 天（${c.start_date} ~ ${c.end_date}）`;
     else 「還沒設定投放起訖日，算不出總預算」
2. label 「採用時的計畫」
   - value `c.budget_planned !== null` → `formatCurrency(c.budget_planned)`; else 「尚未設定」
   - caption `c.budget_planned !== null` → `採用策略時的情境金額${c.budget_scenario ? `（${c.budget_scenario}）` : ""}，不會跟著日預算改`;
     else 「還沒採用預算情境」
3. label 「差額」 (`diff = t.total - c.budget_planned`, both non-null)
   - value: `diff === 0` → 「持平」; `diff > 0` → `＋${formatCurrency(diff)}`; `diff < 0` → `－${formatCurrency(Math.abs(diff))}`;
     either side missing → 「算不出來」
   - caption both present → 「目前投放組合計 − 採用時的計畫」; else 「兩邊都有金額才算得出差額」

Rules for this card, all falsifiable by reading the diff:
- **Never pass `null` to `formatCurrency` here** — it prints 「累積中」, which claims a number is
  coming; 「尚未設定」／「算不出來」 are the honest strings. Branch first, format second.
- The card reads `c.groups` (which `replaceGroup` already updates from `patchGroup`'s response),
  **never `c.budget_total`** — that is what makes the total follow the edit with no refetch.
- No new endpoint, no refetch, no `useEffect`. Nothing else in this file changes.

## 3. `OverviewTab.tsx` — no untracked zero, two budgets labelled apart

- **Delete** the `roas` derivation from `c.outcome` and the 購買／ROAS tiles. `c.outcome` is the
  SQL deriver (`COALESCE(...,0)`): a Meta-bound campaign's `purchases` `0` means 未追蹤, and a
  ROAS derived from it is a fabricated number. Drop the now-unused `formatCount`／`formatRoas`
  imports.
- **Do not call `getPerformance` here.** 總覽 stays a pure-props component (no fetch, no loading
  state, no error state); the tab that owns 成效 numbers is 成效, built in F03-I16.
- Tiles become **four**, in a `grid-cols-4`, and the tile element gains a caption line
  (`text-xs text-muted-foreground` under the value), same shape as 成效's KPI card:

  `hasOutcome = c.outcome.spend > 0 || c.outcome.purchases > 0 || c.outcome.revenue > 0`,
  `t = currentBudgetTotal(c)`.

  | # | published (`idx >= 4`) | not published |

  | 1 | label 「花費」 · value `hasOutcome ? formatCurrency(c.outcome.spend) : "還沒有成效資料"` · caption `hasOutcome ? "累計花費・平台回報" : "發布後才會有花費資料"` | label 「投放平台」 · value channels joined with 「・」 or 「尚未設定」 · caption 「已建立的投放組通路」／「採用策略後才會建立」 |
  | 2 | label 「目前投放組合計」 · value `t.total !== null ? formatCurrency(t.total) : "尚未設定"` · caption `t.total !== null ? \`日預算 ${formatCurrency(t.dailySum)}／天 × ${t.days} 天\` : "還沒設定投放起訖日"` | same |
  | 3 | label 「採用時的計畫」 · value `c.budget_planned !== null ? formatCurrency(c.budget_planned) : "尚未設定"` · caption 「採用策略時的情境金額」／「還沒採用預算情境」 | same |
  | 4 | label 「投放期間」 · value `start ~ end` or 「尚未設定」 · caption `共 ${t.days} 天`／「還沒設定起訖日」 | same |

- Under the tile grid, one muted line (`text-xs text-muted-foreground`), verbatim:
