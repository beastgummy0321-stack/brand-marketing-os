# Objective
Launch settings become choice fields with program-preselected values, and readback compares them with a Meta READ (Feature Contract I; Unresolved 4 and 5 defaults). Read-only on the platform; nothing is written (ads.md §6.4).

# Done
1. `app/ads/launch_settings.py`: options (with one-line plain notes per value, texts from the prototype's `SET_NOTE` and field notes), recommended values per Unresolved 4, validation: UTM `^utm_[a-z_]+=[^\s&=]+(&utm_[a-z_]+=[^\s&=]+)*$` with `utm_source` required, age_min < age_max, manual placement needs ≥ 1 position, pixel must be in the read list when the list is readable. GET/PUT in `manual_settings_routes.py`; `edited` = fields differing from `recommended`.
2. `manual_settings.FIELDS` loses the five keys moved into the structure; remaining free-text keys follow Unresolved 5. Existing saved free-text values stay readable (not deleted).
3. Launch approval (`change_control_launch.py`) freezes `launch_settings` into the content and refuses with 409 `launch_settings_invalid`; an edit after approval makes the launch stale through the existing F28 path.
4. Meta read: extend the read policy with exactly the fields needed (`optimization_goal`, `bid_strategy`, `targeting` with `age_min`, `age_max`, `genders`, `geo_locations`, `countries`, `publisher_platforms`, `facebook_positions`, `instagram_positions`, `messenger_positions`, `promoted_object`, `pixel_id`, `custom_event_type`, `url_tags`) and the `act_<id>/adspixels` path (fields `id,name`); the adset/ad object reads request them; a new read of the account's pixels through the existing credential facade. Policy tests prove every other field/path is still refused.
5. `handoff_check.py` compares each field per ad set (bid strategy falls back to the campaign when the ad set has none; automatic placement = no `publisher_platforms`; UTM from each ad's `url_tags`) and builds `settings_readback` (Contract I); a field any ad set differs on is `differ`, an unreadable permission is `unreadable` with its reason; `settings-confirm` route in `handoff_routes.py`. A `differ` counts as a mismatch in the handoff result.
6. Tests: Advantage+ audience returning 18–65, a region-level geo on Meta (differ, shows Meta's value), gender `[1,2]` = all, CBO bid strategy, pixel permission denied, UTM with a space, approve with invalid settings, edit after approval → stale, self-confirm on a `match` field (refused).
7. `frontend/src/lib/adsLaunchSettingsApi.ts` (client + types, including the `SettingsReadback` type). Adding `settings_readback` to `HandoffWorkspace` and its test factories is I16's (it owns the publish screens).
