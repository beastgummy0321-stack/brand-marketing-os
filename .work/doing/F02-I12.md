# Objective

`ARCHITECTURE.md` §5.13 (settled 2026-09-12 when F02-I09 blocked): the 素材組 studio's 右欄
「生成設定」 table is **shipped as text**, exactly like `cells[].text` and `image_generation.reason`.
Today `SetDetail` cannot draw it — `chips` has only platform/style/size, `products[].generation_
settings` has only `copy_length`/`count`, and the set never reads its `product_id`. This issue adds
the one field that fixes that, in the read path only. Additive: no existing key changes meaning.

# Done

- `app/workbench/repository.py::set_detail` returns a new **top-level** `generation_settings`:
  an ordered `list[{"label": str, "text": str}]`, **always these seven rows in this order** —
  1. `品牌／商品` — `f"{brand_name} · {product_name}"`; the 商品 half is `不指定` when the set's
     `product_id` is `None` or the product is gone. Brand name from `bi_repo.get_brand`, product
     name from `bi_repo.get_product(conn, brand_id, product_id)` (both already imported as
     `bi_repo`; `get_product` is brand-scoped and returns `None` across brands — that is `不指定`,
     never an error).
  2. `平台`, 3. `尺寸`, 4. `風格` — the same three values already computed for `chips`
     (`platform`／`size`／`style`), reused, not recomputed from another source.
  5. `人物`, 6. `場景` — from the **latest image-prompt round's structured reply**:
     `body_json["hero"]["person"]` and `["scene"]` (the model's own fields, §5.8). The latest round
     is the first entry of the already-built `products["image_prompt"]["versions"]` (that list is
     ordered `generation_round DESC`), so read it from there — do not issue another query and do
     **not** parse `rendered.hero`, which is the assembled prompt string, not fields. 探索模式 rounds
     have no `hero` at all.
  7. `主要訊息` — the pack row's `summary_json["重點訊息"]`; a multi-line value is joined into one
     line with `；`, blank lines dropped.
- **Every row is present in every response**; a row with no value reads `—` (the em dash used in
  §5.3's cells). No placeholder text, no row omitted, no `None` in `text`. Malformed stored JSON
  (`hero` not a dict, `summary_json` not a dict, a non-string field) degrades to `—`, never a
  500 — same tolerance as `_slice_body`／`_prompt_cards` right above it.
- `products[<part>].generation_settings` is **unchanged** — same key word, different field, and
  `_generation_settings()` is not touched. The new derivation is its own small helper next to
  `_prompt_cards`, with a one-line docstring pointing at §5.13.
- Nothing else in `SetDetail` changes; `routes.py` is untouched (it wraps whatever the repository
  returns).
- `app/tests/test_workbench_set_settings.py` (new, the falsifier; fixture shape copied from
  `app/tests/test_workbench_image_port.py`, which already builds a pack, a set and an image-prompt
  round through the API): for a set whose brief has a `product_id` and one 變體模式 image round,
  `GET /api/workbench/brands/{b}/sets/{s}` returns the seven labels in order, row 1 reads
  `<brand> · <product>`, and 人物／場景 equal the round's `hero.person`／`hero.scene`. Second case:
  a set with no `product_id`, no image round and an empty pack summary — the same seven labels, row
  1's 商品 half is `不指定`, and 人物／場景／主要訊息 all read `—`.
