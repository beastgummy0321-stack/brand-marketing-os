# Objective

The half of the 圖片 tab that e2e cannot reach: **a version that exists**. Per F02 Decisions
("e2e asserts only what runs with no worker and no provider key"), no `workbench_output` row can
exist during `npm run e2e`, so nothing today proves the studio renders `prompt_cards` or renders the
API's 席位保留 line instead of a re-spelt copy. `app/tests/test_workbench_image_port.py` already
asserts the API half (`versions[].prompt_cards` and the exact `image_generation` dict); this issue
adds the browser half over a hand-built `SetDetail` payload. Free, deterministic, runs in CI's
`npm test`.

# Done

- New `frontend/src/components/workbench/SetStudioPage.test.tsx`, following the existing
  `frontend/src/components/workbench/FreeJobPage.test.tsx` for setup style (render + stubbed API
  module, no new dependency, no new helper file).
- Over a `SetDetail` whose `products.image_prompt.versions[0].prompt_cards` has the ①主圖／②變體
  pair: both card labels and both texts are visible, each card has its copy button, and 複製全部
  appears.

  cannot make because it has no version card to toggle.

  `image_generation.reason` a value that is not the shipped literal and assert that value appears
  on screen (a hard-coded string in the component would fail this).

- No change to `SetStudioPage.tsx` or any other source file. If the component cannot be tested
  without an edit (missing export, untestable fetch), report it — do not change the screen here.
