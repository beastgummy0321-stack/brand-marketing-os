# Objective

At 結案 the system compares how the chosen images did by fingerprint within one audience, writes visual
learnings, and downgrades a winner that later loses — no model call, numbers from the program, a
correlation never reported as a cause. Rules: ARCHITECTURE.md §6.3 items 19–20 (read both in full);
F07 Decision 31. Row contract read through `workbench.adopted_output`: §5.8, only
`body_json.fingerprint`. Never delete or overwrite anything under `data/`.

# Done

1. New `app/ads/visual_learning.py::write_visual_learnings(conn, org_id, brand_id, campaign_id, *, actor,
   days, labels) -> list[dict]` (`labels` = `judgment.conversion_labels(...)`, already computed in
   `close`):
   - Ads from `repository.campaign_detail`; each ad's brief from `workbench.briefs_for_source(conn,
     org_id, brand_id, assets.PACK_SOURCE_KIND, {"ads_campaign_id": campaign_id})`, matched by
     `source_ref.ads_ad_id`. The image row is `workbench.adopted_output(conn, org_id, brand_id, brief_id,
     "image_prompt")`, kept only when `is_adopted` is true and `body_json.fingerprint` is a dict.
   - Ad outcome rows from `outcome._fetch_rows(conn, org_id, brand_id, campaign_id, "ad")`, grouped by
     `entity_id`.
   - Stratum = `ad["audience_key"]`; ads without one are skipped; only strata with ≥2 kept ads are used.
   - Dimensions, in this order, with names: `look` 風格 · `device` 視覺手法 · `layout` 版型 · `subject_role`
     主角出現方式 · `persuasion` 說服元素. Per stratum and dimension with ≥2 distinct fingerprint keys: group
     ads by key, run each group's rows through `outcome._bucket`, apply the campaign's `success_metric`
     (`cpa` lower is better; `roas` uses `roas_conservative`; `purchases` higher is better); sample =
     `outcome.sample_bucket(purchases or 0, days)`; a group is comparable when its metric is not `None`
     and its sample is not 低.
   - ≥2 comparable groups and a strict best → scope `visual；audience=<audience_key>；<dimension>=<best
     key>`, sentence 「<audience label>：<dimension name>「<best label>」<metric label> <value>（<n> 則廣告，樣本
     <bucket>），好過 <each other group: 「<label>」 <value>（<n> 則，樣本<bucket>）, joined 、>。這是相關，不代表是
     <dimension name>造成。」
   - Otherwise → scope `…；<dimension>=看不出`, sentence 「<audience label>：<dimension name>這次看不出差別
     （<reason>）。」, reason = the first that applies: 樣本太小 (any group 低), 成效未追蹤 (a metric `None`),
     數字一樣 (tie at the top).
   - Audience label from `repository.coordinate_vocabulary` (key → label, falling back to the key);
     value labels from the fingerprint `{key, label}`; metric label `{"cpa": labels["cpa"], "roas":
     "ROAS", "purchases": labels["count"]}`; numbers rounded to 2 decimals, purchases an int.
   - Confidence: 看不出 → `observed`; otherwise count non-expired rows from `bi_repo.list_learnings(conn,
     brand_id, source_track="visual", limit=500)` with the identical scope and `source_cycle_id !=
     campaign_id`, +1 → ≥3 `validated`, 2 `likely`, 1 `observed`.
   - **Downgrade** (only after a strict best B): for every other comparable group value A in that
     stratum and dimension, take the non-expired rows with scope `visual；audience=<a>；<dimension>=<A>`
     and `source_cycle_id != campaign_id`; when any exist, call `bi_repo.expire_learning(conn, brand_id,
     <newest by learned_at>["id"], actor=actor)` once. Return value includes only written rows.
   - `needs_revalidation`: reuse `learning._needs_revalidation`.
   - Write each row with `bi_repo.record_learning(..., source_track="visual", source_cycle_id=campaign_id,
     sample_size=<the smallest bucket (低 < 中 < 高) among the groups named in that row's sentence>)`.
2. `closeout.close`: after `write_learning`, call it and extend `verdict_json["learning_ids"]` with the
   visual ids, before the single UPDATE. The already-closed guard means no second write.
3. `test_ads_visual_learning.py` — build campaigns, groups and ads with `plan` helpers as
   `test_ads_closeout.py` does; insert group and ad `ads_outcome_daily` rows directly; patch
   `visual_learning.workbench.briefs_for_source`/`adopted_output` with `mock.patch.object` to return
   §5.8-shape rows (no workbench internals, no `workbench_*` SQL). Cases:
   - two `cold_unaware` ads, looks `phone_raw` vs `studio_hero`, other dimensions equal, each ≥10
     purchases over ≥3 days, metric cpa → exactly one visual row (look), scoped to the better look,
     `observed`, sentence contains both labels and 「不代表」;
   - a second campaign with the same direction → that look row is `likely`;
   - a third campaign where the other look wins → a new row for it, and the previous winner's newest
     (`likely`) row is expired, leaving its only non-expired row at `observed`;
   - two ads differing in `device` only → one device row; in `persuasion` only → one persuasion row;
   - one group with 3 purchases → a 看不出 row with 樣本太小 and no expiry;
   - the two ads in different audiences → no visual rows; `is_adopted` false on one ad → no visual rows;
   - closing twice → no additional rows; the campaign learning is still written and
     `verdict_json["learning_ids"]` lists both kinds.
4. `test_ads_closeout.py`: existing cases stay green; only add a patch returning no briefs where a case
   would otherwise reach the workbench.
