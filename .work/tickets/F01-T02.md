# Outcome

The plan-expansion AI decides which copy length each deepest node needs, the schedule hands that
length (and the period's promotion_note) to the workbench when it dispatches the brief, and the
素材準備 stage shows that one length instead of three tabs.

# Acceptance

- A tree reply whose depth-3 nodes carry `copy_length` keeps those values; a tree reply without the
  field still renders, every such node falling back to `short` - old trees must keep working.
- Each dispatched brief's `request_json` contains `parts: ["copy"]`, the node's `copy_length` and the
  period's `promotion_note`.
- 素材準備 shows one length block with its hint sentence and per-item copy buttons; nothing on the
  page offers 短／中／長 any more.
- `docs/design-system.md` §5.1 and `CONTEXT.md` 投放包 describe what the screen actually does.
