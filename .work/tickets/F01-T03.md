# Outcome

An image-prompt round produces two pasteable prompts instead of N nine-line prompts:

- dispatched brief (`source_kind = "schedule_node"`) -> 變體模式: (1) 主圖提示詞 for one image built
  from the node's coordinates, then (2) 變體提示詞 to paste with the approved hero image attached.
- manual brief -> 探索模式: (3) 探索提示詞 asking for N images, one persuasion angle each, then the
  same (2) 變體提示詞.

Every prompt is positive only: no prohibition line anywhere. The only guard is that 【圖上文字】 lists
every string that will appear on the image, and any number in those strings must be verbatim from
the brief's quotable text. Image generation is still a reserved seat - no provider, no cost.

# Acceptance

- An image-prompt round runs on a brief that has no adopted copy at all (the retired
  `on_image_texts` precondition is gone with the key itself).
- The rendered hero prompt contains no 禁止 line, no 保留｜禁止 line and no 「未列出的」 wording; the
  same for the variant and exploration prompts.
- A model reply whose headline contains a number that is not in the quotable text is reported as a
  failing validation item naming that number.
- A brief whose product has no official asset renders the 商品 line as 「無參考商品照，畫面以情境與人物
  為主」; a brief with no promotion note renders no 可用字句 line at all.
- `app/methodology/image-prompt-template.md`, `app/methodology/creative-matrix.md` §3 and
  `app/departments/workbench/image_prompt.md` agree with each other and with the code.
