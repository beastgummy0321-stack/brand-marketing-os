# Done

## 1. 新檔 `app/ads/judgment.py`（純函式，不碰 DB）

`app/ads` 私有模組（container 契約：只有 `repository.py`／`routes.py` import 它）。裡面只有字串
規則，沒有 SQL、沒有 LLM、沒有 `datetime.now()`（今天的日期一律由呼叫端傳進來）。

### `campaign_judgment(campaign, *, today) -> dict`

回 `{"tone": "neutral"|"good"|"warn", "text": str, "detail": str}`。規則（**照這個順序**，
第一個命中的就是答案）：

| 情況 | text | detail |
|---|---|---|
| `status == "closed"` | 判決：`verdict` 是 `達成`／`未達成`／其他 → 「已結案，達成成功條件」／「已結案，未達成成功條件」／「已結案，看不出來」 | 「結案於 {closed_at 日期}」 |
| `status == "ended"` | 「投放已結束，還沒結案」 | 「結束於 {end_date}，7 天後自動結案」 |
| `status == "live"` | 預算進度 vs 時間進度（見下） | 「已花費 {spend} ／ 總預算 {total}・第 {n}／{days} 天」 |
| `status == "ready"` | 「投放結構已就緒，還沒發布」 | 「預計 {start_date} 上線」（沒有日期就「還沒設定投放期間」） |
| `status == "draft"` 且有 `budget_basis_json.strategy` | 「策略已產生，還沒採用」 | 「下一步：選預算情境並採用策略」 |
| `status == "draft"` | 「還沒產生策略」 | 「下一步：產生策略建議」 |

live 的一句判斷（**只講看得到的事實，不講原因**，ARCHITECTURE.md §0：相關永遠不報成因果）：
`budget_pct = spend / budget_total`、`time_pct = 已過天數 / 總天數`，兩者都算得出來時
（`budget_total` 為 None 或 0 → text 「投放中」、detail 「還沒有可比的總預算」，tone neutral）：

- `budget_pct - time_pct > 0.15` → tone `warn`，text 「投放中，預算花得比時間快」
- `time_pct - budget_pct > 0.15` → tone `neutral`，text 「投放中，預算花得比時間慢」
- 其他 → tone `good`，text 「投放中，預算與時間同步」

**禁止**出現「表現佳」「高於同業平均」「建議…」這類字（參考圖上有，那是示意圖；我們沒有那個
資料，F05 才有）。

### `brand_headline(counts) -> dict`

回 `{"text": str, "facts": str}`。`counts = {"running", "upcoming", "ended", "needs_decision"}`。

- `running > 0` → text 「目前有 {running} 個 Campaign 進行中」
- `running == 0 and upcoming > 0` → 「還沒有進行中的 Campaign，有 {upcoming} 個即將上線」
- 全部 0 → 「這個品牌還沒有 Campaign」
- facts：把非零的那幾項用「・」接起來——「{upcoming} 個即將上線」「{ended} 個已結束」
  「目前沒有需要你決定的事」（`needs_decision == 0` 時固定這一句，F04 沒有產生端）。

### `action_line(action, *, campaign_name, target_name, today) -> dict`

回 `{"time_text", "title", "detail"}`。

- `time_text`：同一天 → 「今天 HH:MM」；前一天 → 「昨天 HH:MM」；更早 → 「M月D日 HH:MM」。
- `title`：`kind` 對照表（**程式擁有這張表**）＋目標名稱：
  publish 「發布了 {target_name}」／bind 「配對了 {target_name}」／budget 「調整了 {target_name} 的預算」／
  date 「調整了 {target_name} 的投放期間」／pause 「暫停了 {target_name}」／creative 「更新了 {target_name} 的素材」。
  `target_name` 取不到時用 campaign_name。
- `detail`：`budget`／`date` 有 before→after 時「{before} → {after}」（金額用 `NT$ 1,000` 格式，
  日期原樣）；其餘 kind 用「{approved_by 或 系統}・{同步狀態中文}」。同步狀態中文：
  待手動同步／已手動同步／自動同步。
- 註解一行：`ads_action` 的 `before_json`／`after_json` 是自由形狀，取不到鍵時整段省略，
  **不要**把 JSON 原樣印給使用者看（今天 `OverviewTab.diffSummary` 就是那樣，F04-I15 會換掉）。

## 2. `app/ads/repository.py`

- `list_campaigns()` 每一列多帶：`created_at`、`created_by`、`spend`（＝`outcome["spend"]`，
  不重算）、`budget_progress`（`{"spent": float, "total": float | None, "pct": float | None}`，
  `total` 是既有的 `_budget_total`，`pct = round(spent / total * 100)` 且 `total` 為 None／0 時是
  `None`——**不准回 0**）、以及 `judgment`（呼叫 `judgment.campaign_judgment`，`today` 用
  `coresettings.today_for_org`）。既有欄位一個都不刪。
- 新函式 `recent_actions(conn, org_id, brand_id, *, limit=20) -> list`：這個品牌**跨 Campaign**
  的 `ads_action`，`ORDER BY created_at DESC LIMIT %s`，每一列帶 `campaign_id`、`campaign_name`
  （JOIN `ads_campaign`，同一個 org/brand 條件），以及 `judgment.action_line()` 組好的三個字串。
  `target_name`：`target_kind` 是 group／ad 時各查一次名字（`limit` 最多 20，N+1 可以接受，
  寫一行 ponytail 註解）。
- `campaign_detail()` 也多帶 `judgment`（同一支 `campaign_judgment`，總覽分頁的判斷帶要用）
  與 `action_lines`（把它已經查出來的 `actions` 20 筆各跑一次 `judgment.action_line()`，
  **`actions` 原欄位保留不刪**——別的分頁還在讀）。同一個 Campaign 的判斷句因此只有一套規則。
- **不加**計數用的 SQL：同一支路由已經拿著 `list_campaigns()` 的完整結果（它本來就把每一列都
  撈出來，沒有分頁），四個數字在路由裡數三行就好（見下）。多一句
  `COUNT(*) FILTER (...)` 只是同一件事的第二份寫法。

## 3. `app/ads/routes.py`

一支新路由，形狀照既有慣例（`require_actor` → `require_brand` → 一支 domain 函式 → 包起來）：

```
GET /api/ads/brands/{brand_id}/home
→ {"home": {"headline": {...}, "counts": {...}, "campaigns": [CampaignCard…], "actions": [...]}}
```

- `counts`：在路由裡從 `list_campaigns()` 的同一份結果數出來——
  `running` = `status == "live"`、`upcoming` = `draft`／`ready`、`ended` = `ended`／`closed`、
  `needs_decision` = **固定 0**（建議的產生端是 F05，回 0 讓畫面顯示誠實的空狀態）。
  一行註解釘住前提：`list_campaigns()` 沒有分頁，拿到的就是這個品牌的全部，所以數得準；
  哪天它加了分頁，計數要跟著改成 SQL。
- `campaigns`：同一份結果**只留 `status == "live"`**，最多 6 筆（首頁只放進行中的
  卡片；「查看全部」去清單頁）。
- `actions`：`recent_actions(limit=6)`（圖 1 的時間軸是四筆，6 是留一點餘裕）。
- 這支路由不 fetch 成效、不打模型、不寫任何東西。

`GET /campaigns` 本身不改路由形狀（多帶欄位是相容的新增）。
