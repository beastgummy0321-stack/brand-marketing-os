# Objective

Rewrite the prompt-side spec (methodology + department task + style data) to the three shapes the
shell will render, and move the style catalogue to one photographic block.

The three shapes are settled in ARCHITECTURE.md §5.6-§5.9. Copy them, do not redesign them.

# Done

- `app/methodology/image-prompt-template.md` is rewritten: it describes the three prompts (主圖 /
  變體 / 探索), which line comes from where, and which fields the model returns. The 9-line template,
  the 8-module table, the 200-250 character band, the 固定段／變動段 split and the rule 「圖上文字逐字
  取自標題」 are all removed. It keeps: the shell renders and the model returns fields only; every line
  is omitted when it has no content; 圖上文字 is listed exhaustively and numbers are verbatim.
- `app/methodology/creative-matrix.md` §3 rule 4 loses 「禁止出現」 and becomes a positive rule: each
  prompt ends with the exhaustive 【圖上文字】 list. Rules 1-3 are unchanged; §1's 35-angle table is
  unchanged (探索模式 picks from it).
- `app/departments/workbench/image_prompt.md` is rewritten to two reply shapes, JSON-only as today:
  - 變體模式: `{"hero": {"scene", "person", "subject_position", "headline", "subhead"}, "warnings": []}`
    - `person` is written from the brief's 受眾 line, `subhead` may be `null`, and any number inside
    `headline` / `subhead` must be verbatim from the 可用字句 line or the brand context.
  - 探索模式: `{"angles": [{"name", "brief", "on_image_line"}], "warnings": []}` with exactly N items,
    each a different persuasion angle from `creative-matrix.md` §1, wildly different layouts.
  The shell tells the model which mode and which N in the worksheet section. The file must not ask
  the model to assemble any prompt string and must contain no prohibition list.
- `app/workbench/image_styles.json`: in the `ugc` entry, `capture_line` and `authenticity_hint` are
  **replaced** by one `style_block` (they have no other purpose once the 9-line template is gone) -
  the photographic paragraph only, verbatim:
  「iPhone 手持原生抓拍，未修圖，輕微晃動模糊、失焦柔焦、雜亂背景、不均勻光線／直閃、輕微色差，真實自然、
  不擺拍、有模糊瑕疵的日常照片感。文案文字樣式請用純色填滿。人物自然東亞日常面孔，像街上隨機遇到的普通人，
  而非廣告選角或韓系偶像。」
  `key` and `label` stay. Who appears in the picture is never part of the style; it comes from the
  受眾 coordinate.
- The three read sites of the two removed keys move with them, in this issue, so nothing is left
  broken between issues:
  - `app/workbench/prompts.py::brief_text` - the 風格 line becomes
    `f"風格：{style['label']}；{style['style_block']}"`.
  - `frontend/src/lib/workbenchApi.ts` - `ImageStyle` becomes `{ key, label, style_block }`.
  - `app/tests/test_workbench.py` - the `_STYLE` fixture in `BriefCoordinatesTextTest` and its
    assertion (that file is legacy, hence `legacy_migration` on this issue).
- `app/methodology/README.md` is only touched if the 對照表 row for 素材工作檯圖片提示詞 names a file
  that no longer exists (it should still be `creative-matrix.md` + `image-prompt-template.md`).

- **No new test file in this issue.** The assertions stay in `app/tests/test_workbench.py`, which the manifest lists as
  `legacy` - the container checker skips it, which is the only reason it may import both sides of the
  schedule/workbench line. A new `app/tests/test_workbench*.py` would be **workbench** code under
  ARCHITECTURE.md §2 and could not carry those imports; if you think one is needed, stop and report.
