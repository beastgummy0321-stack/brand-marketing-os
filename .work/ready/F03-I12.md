# Objective

The campaign is judged against its own success criterion and leaves one sentence the next campaign
can read. §0: it serves the **verdict → learning → next goal** links; its input is the outcome rows
and the campaign's `success_criterion` (set when it was created, not chosen now); its output is a
`learning_ledger` row read by the strategy task; its trace is the verdict with its numbers and the
learning with its evidence, sample and source campaign; it is **core** — this is where the loop
closes.

# Done

- `app/ads/closeout.py` — `close(conn, org_id, brand_id, campaign_id, *, actor, reason=None)`:
  compares `outcome.summary()` with the campaign's `success_metric` / `success_target`, writes
  `verdict` ∈ `達成` / `未達成` / `看不出` and `verdict_json` (the compared numbers, the window, the
  sample bucket, what was missing when it is 看不出), sets `status='closed'` and `closed_at`.
  **看不出 is a real verdict**: when the sample bucket is 低 or the target was `null`, that is what
  it says — it never rounds an unknown into a pass or a fail.
- `app/ads/learning.py` — `write_learning(conn, …, campaign_id, verdict_json, actor)`:
  one sentence built by the program from the campaign's own facts (what was delivered, what the
  numbers were, against which criterion) — no model call in F03. Level by the fixed rule:
  1 campaign = `observed`; ≥2 campaigns of this brand pointing the same way = `likely`;
  `validated` only from a same-period comparison or ≥3 campaigns (a human tick may also set it,
  F04). `needs_revalidation=True` when the source offering's price changed since the campaign ran
  (compare `product_economics` effective dates) — the 180-day rule is applied on read by the
  strategy task, so an old row is labelled, not rewritten. Persisted through
  `brand_intelligence.repository.record_learning` (F03-I02) with `source_cycle_id = campaign_id`,
  `sample_size` = the bucket, `applicability_scope` = the coordinates the campaign concentrated on.
  It never writes a `brand_fact` and never writes a `rule` row.
- `app/ads/jobs.py` + `register_tasks()` on the module's public entry (registered in `app/main.py`
  next to the other modules' `register_tasks()`, one line): a procrastinate task that closes
  campaigns whose `end_date` is more than 7 days past and whose status is `live`/`ended`,
  idempotently, and writes the same verdict and learning a manual close would. Follow
  `app/meta/daily_pull.py`'s registration pattern, including the second `register_tasks()` call
  tests need.
- `app/ads/routes.py`: `POST .../campaigns/{id}/close` (early manual close, body `{reason}`) and the
  campaign detail payload gains `verdict`, `verdict_json` and the learning ids written. `adsApi.ts`
  gains the types and the call.
- `app/tests/test_ads_closeout.py` (the falsifier): a campaign that beat its ROAS target closes as
  達成 with the compared numbers; one that missed it closes as 未達成; one with two purchases closes
  as 看不出 **and still writes a learning**, at `observed`, whose text says the sample was small;
  a second campaign in the same direction makes the next learning `likely`; closing twice does not
  write a second learning; the auto-close task closes an ended campaign at end+7d and not at end+6d;
  a learning is never written into `brand_fact` or `rule` (assert both tables are untouched).

# Verify

`uv run python -m pytest app/tests/test_ads_closeout.py -q` — the 看不出-still-learns case and the
no-rule-row case are the two that encode the user's rulings 16 and 15.

# Blocked if

The learning level rule needs data the campaign rows cannot answer (e.g. 「≥2 同方向」 across
campaigns). Then write `observed` only, leave the upgrade to F04, and report it — do not invent a
cross-campaign table in this issue.
