# Objective

素材準備 shows the one length the node asked for, with its hint sentence - no tabs - and stops
claiming a number of image prompts it no longer receives.

# Done

- `scheduleApi.ScheduleBriefCopy` drops `short` / `medium` / `long` and gains
  `copy_length: "short" | "medium" | "long"` and `bodies: string[]`, matching what the API now
  returns. The image-prompt summary type drops `count` and keeps `generation_round`.
- `CreativePackList.tsx`'s `CopyTabs` becomes one block: the label from `LENGTH_LABELS`, the hint
  from `LENGTH_HINTS`, then the items with their character count, ❌ line and copy button exactly as
  today. Drop the `Tabs` import if nothing else in the file uses it.
- The image-prompt line (today 「圖片提示詞：已產 N 條」) becomes 「圖片提示詞：已產第 N 輪」 / 「尚未產」,
  reading `generation_round`. The link to 素材工作檯 stays - the prompts themselves are read there.
- `LENGTH_HINTS` / `LENGTH_LABELS` stay in `frontend/src/lib/workbenchApi.ts` (both features import
  them from there); only their comment changes if it still claims three lengths are produced at once.
- `docs/design-system.md` §5.1: the 素材準備 row becomes
  「one card per deepest node | the node's one copy length with its fixed hint, headlines,
  descriptions, copy buttons; the image-prompt round and a link to 素材工作檯」.
- `CONTEXT.md` 投放包 entry: 「已採用的三種長度主文」 becomes 「已採用的那一種長度的主文」.

# Verify

`cd frontend && npx tsc -b --noEmit && npm run depcruise`, then open 檔期規劃 -> 素材準備 in a browser
on a restarted backend: one length block, no tabs, at 1024 and 1920.


- Before you report done, run `cd frontend && npx tsc -b --noEmit` and `cd frontend && npm run depcruise` yourself: both are part of the finish gate that discards the worktree, and both must print no errors.
