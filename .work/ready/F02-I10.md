# Objective

Screen 4, 自由創作 — reference image 4, 1:1 at 1672px. The standalone front door: a person who has
no upstream task still starts here, and what they get is a pack like any other.

Last of the screen chain (F02-I07 → I08 → I09 → I10, same three frontend paths, one at a time) and
the only consumer of F02-I06's parse endpoint.

# Done

- Route `/brands/:brandId/workbench/new`; it accepts `?type=image|copy|script` so 快速開始 on the
  入口 preselects 素材類型.
- Title ＋ 「用自然語言開始，AI 會幫你整理成可執行素材任務。」
- Card 「告訴 AI 你想創作什麼」: textarea with a live counter `n／1,000`; 「試試看」 example chips
  that fill the textarea; 品牌 select defaulting to the current brand **with 「不指定」 kept**; 商品
  select with 不指定 — when both are 不指定 the page still works as a plain generator and says
  nothing about being degraded; 參考圖 upload zone (JPG／PNG／WEBP, 單檔上限 10MB) using the existing
  upload path, client-side type and size validation with a plain-language error.
- 快速生成｜精準控制 toggle; 精準控制 expands 素材類型／平台／尺寸／風格／人物／場景／主要訴求／
  產出數量.
- **Two clicks, and the right column is empty until the first one** (this is the ruling):
  1. 「建立自由工作 →」 → **one call** to `POST /brands/{b}/parse` (F02-I06) with the textarea text
     and `defaults` = the form's current values. While it runs the button shows a pending state and
     the textarea stays editable; nothing is called while the user types. The response's `spec`
     fills 精準控制 **and** renders the 「AI 解析結果」 table 專案主題／需要產出（含張數）／風格設定／
     投放平台／尺寸／目標受眾／主要訴求. `parsed: false` is not an error screen: show `note` as one
     plain line above the table and render the table from the defaults — the flow continues.
  2. The button then reads 「確認並生成」; the second click `POST`s the pack (自由工作 #n) and
     navigates to the new pack's 總覽, where generation is already running. The mapping from `spec`
     to the create body is the one piece of logic on this page and it is fixed:
     **`required_outputs[part]` = that part's parsed `count`, default 1**, and the same number is
     the round's generation `count` — so one round can satisfy the pack (`.work/features/F02.md`
     Decisions: the two fields are different things and both come from the parsed count here).
     Editing 精準控制 after the parse overrides the parsed value; the second click always submits
     what the table shows.
- Bottom strip 「預覽將建立的工作項目」 shows the pack card that will be created (name, 自由創作 badge,
  the request line, 產出內容, 狀態 待建立) — it is a preview of the same card component the 入口 uses,
  not a second design.
- One small unit test for the spec → create-body mapping (`frontend` already runs `npm test`, no
  network in it): a `spec` with `outputs [{part: "image_prompt", count: 5}]` produces
  `required_outputs {image_prompt: 5}` and generation `count` 5; an `outputs` entry with no count
  produces 1; `parsed: false` with untouched defaults still produces a submittable body. That is
  this issue's real falsifier — the mapping is the only branching logic left in the browser.
- No new npm dependency.
