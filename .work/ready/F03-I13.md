# Objective

投放中心 exists as a place in the product, and a goal can be described there. §0: it serves the
**goal** link; its input is the campaign list API (F03-I01) and the create API (F03-I03); its output
is a draft campaign and the door to its workspace; its trace is that the sentence the user typed is
what the campaign stores; it is **core** (the entry to the loop).

Only this issue changes the shell, the vocabulary and the route list — every later frontend issue
renders inside what this one creates. **This issue is the one with the e2e gate: finish and merge it
while no other e2e-gated issue is in flight** (8720 collides).

# Done

- **Routes** (`frontend/src/App.tsx`): `/brands/:brandId/ads` → `AdsHomePage`,
  `/brands/:brandId/ads/new` → `NewCampaignPage`, `/brands/:brandId/ads/campaigns/:campaignId` →
  a placeholder that renders the campaign name and the five `PageTabs` labels
  (總覽／策略／投放結構／素材／成效) with an empty body — F03-I14/I15/I16 fill the tabs. Tab state in
  the query string (`?tab=strategy`), `docs/design-system.md` §4.2. `/brands/:brandId/schedule`
  stays mounted for now and is deleted by F03-I17.
- **Shell**: `Sidebar.tsx`'s 品牌經營 group reads 投放中心 → `/ads` (icon unchanged is fine);
  `Topbar.tsx`'s breadcrumb map gains `ads: "投放中心"`; `CockpitPage.tsx`'s 「排這期的檔期」 button
  becomes 「前往投放中心」 pointing at `/ads`.
- **投放中心 (AdsHomePage)** — `PageHeader` + one `.table-surface` of campaigns: name, status pill
  (草稿／待發布／投放中／已結束／已結案), dates, objective, budget, and this campaign's spend so far,
  every number captioned per §7. Right-aligned action 「建立 Campaign」. Honest empty
  (`EmptyState`): 「這個品牌還沒有 Campaign」 + one next step. **No work queue, no suggestion cards,
  no 本月預算 card, no 全部 Campaign filters** — those are feature 2; the prototype's
  `screen-overview.js` shows them and they stay out.
- **建立 Campaign (NewCampaignPage)** — prototype `screen-new.js`: one textarea 「你這次想做到什麼？」,
  start and end date (native `<input type="date">`), optional constraint chips (預算上限／必須使用的
  平台／指定商品／指定受眾／其他限制), one primary button 「讓行銷駕駛艙規劃」. While the parse runs,
  a loading surface says what is being read (品牌資料／商品／投放紀錄). On success it navigates to the
  new campaign's 策略 tab; when the API returns `parsed: false` it still navigates and shows one
  line saying the sentence could not be fully understood and the fields can be corrected — never a
  dead end, never a lost sentence.
- **Docs, in this issue and nowhere else**: `docs/design-system.md` §3's route count (15 → 17) and
  §5.1 rewritten — the staged 檔期規劃 workspace is replaced by 「投放中心：清單頁 ＋ Campaign 工作區
  （五個分頁：總覽／策略/投放結構/素材/成效，分頁狀態在查詢字串）」 with the same rules that were
  there (actions enabled by backend state, never by which tab is open; 核准 must not look like it
  publishes); §5.2's screen table row for 檔期規劃 replaced. `CONTEXT.md`: the 檔期 entry becomes
  **Campaign** (`ads_campaign`) with a line that 檔期規劃／檔期／重疊分帳 are retired vocabulary kept
  only for the legacy `schedule` package, and the 廣告管道 entry keeps its 「廣告屬於管道」 sentence.
- **e2e** (`frontend/e2e/smoke.spec.ts`): the brand page's link is 「前往投放中心」 and the heading it
  lands on is 投放中心; the 檔期規劃 assertions go. Keep the test's shape — this is a rename, not a
  new scenario.
