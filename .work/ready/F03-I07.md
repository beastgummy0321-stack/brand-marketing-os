# Objective

The workbench can say where a pack came from and can answer 「這一則廣告的素材好了沒」 through its
public entry. §0: it serves the **artifact** link; its input is the pack payload the upstream
already sends; its output is the origin line on screen and the per-set state the upstream reads;
its trace is that a person in the workbench can walk back to the campaign that ordered the work;
it is **pluggable** in the sense that the workbench still never interprets `source_ref` — remove
the ads module and this degrades to a label that is simply absent.

`ARCHITECTURE.md` §5.4 stands: the workbench stores and compares `source_ref`, never interprets it.
The origin line is **a string the upstream hands over**, rendered verbatim.

# Done

- **Origin, passed in, not derived.** `submit_pack`'s `pack["context"]` may carry `origin_label`
  (e.g. 「投放中心 → Beast Gummy｜9 月新客開發 → Meta → 新客｜Broad」) and `origin_href`
  (an app-relative path). Both are optional, both are stored inside the existing `context_json`
  column — **no migration**. `app/workbench/__init__.py`'s docstring gains the two keys in the
  `pack` shape it already documents.
- **Rendered verbatim.** `PackDetail` returns `origin_label` / `origin_href`; the pack page shows
  one line 「來源：<origin_label>」 with a 「回到投放中心」 link when `origin_href` is present, and
  the set page shows the same line above the set name (the per-set label is the set's own `name` —
  the ad name — which already arrives). Where `origin_label` is absent the existing
  `source_label` (「廣告排程」／「自由創作」) is used, so free jobs are unchanged. After 核准整包 the
  pack page's status line reads 「已同步至 <origin_label>」 (and keeps today's wording when there is
  no origin).
- **Readiness through the public entry.** `app/workbench/__init__.py` gains
  `sets_for_source(conn, org_id, brand_id, source_kind, source_ref) -> list[dict]`, each item
  `{brief_id, name, source_ref, state, pack_id, pack_approved_at}` where `state` is §5.3's derived
  set state (待開始／等待決定／已完成) produced by the **existing** derivation — no second
  implementation, no new SQL shape beyond the containment match `briefs_for_source` already uses.
  This is the only way an upstream may learn per-set readiness; `briefs_for_source` keeps its
  meaning and its callers.
- `frontend/src/lib/workbenchApi.ts` types the two new fields. Nothing else in the workbench
  changes: 成品上傳 stays deferred, the free-job backlog items stay in backlog, the IA is untouched.
- `app/tests/test_workbench_origin.py` (the falsifier): a pack submitted with an `origin_label`
  returns it verbatim through `PackDetail` (including characters like `｜` and `→`); a pack without
  one still returns today's `source_label`; `sets_for_source` returns one item per set with the same
  state the pack page derives, matches by containment (a `{"campaign_id": X}` ref finds all sets of
  that campaign), and returns `[]` for another brand's ref.

# Verify

`uv run python -m pytest app/tests/test_workbench_origin.py -q` plus the existing
`test_workbench_api.py` to prove the pack/set payloads did not change shape for anyone else.

# Blocked if

The set state derivation cannot be reused without moving code out of the pack-detail path. Report
it — do not re-derive the state a second time in `sets_for_source`, and do not add a column.
