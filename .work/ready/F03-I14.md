# Objective

The user sees where the campaign stands and decides the strategy and the money. §0: it serves the
**strategy** link; its input is the campaign detail and strategy payloads (F03-I01, F03-I05); its
output is the adopted scenario the plan is built from; its trace is 查看策略依據, which lists the
data the recommendation used; it is **core** (this is where a person decides).

# Done

- **`CampaignWorkspace.tsx`** replaces F03-I13's `CampaignWorkspacePlaceholder.tsx` (delete that
  file and point the route at the new one — the only `App.tsx` line this issue touches):
  `PageHeader` (campaign name, subtitle
  = brand ＋ 期間 ＋ status pill) → `PageTabs` (總覽／策略／投放結構／素材／成效, `?tab=`) → the tab
  body. The right side of the tabs row carries the period and the channel pill (`● Meta`), per
  `docs/design-system.md` §4.2. Tabs that have no data yet render their own honest empty with the
  one next step — never a disabled tab.
- **Inherited from F03-I13** (small, same file set, do them here rather than a new issue):
  delete `CampaignWorkspacePlaceholder.tsx` and its import in `App.tsx`; keep tab state in the query
  string but **preserve the other query params** when switching tab (the placeholder's
  `setSearchParams({tab})` drops them); the placeholder reads a `parseWarning` off `location.state`
  and renders it as one line above the tabs — the real workspace keeps that behaviour, it is the
  only thing standing between a not-fully-parsed sentence and a silent wrong draft. And in
  `AdsHomePage.tsx`, the 預算（總額） column currently prints `budget_total ?? budget_planned` under
  one caption: label the two apart (`budget_total` = 投放組日預算 × 天數, `budget_planned` = 採用的
  情境金額, neither set = 尚未設定, not 累積中) — same caption rule the 總覽 tiles follow.
- **總覽 tab** (prototype `screen-summary.js`): a state timeline (草稿 → 策略 → 投放結構 → 素材 →
  投放中 → 結案) marking done/current from **backend state**, a three-tile number row that shows what
  exists at this stage (before publish: 建議總預算／投放平台／投放期間; after: 花費／購買／ROAS),
  one 下一步 card whose link goes to the tab that is actually next, and 近期異動紀錄 = the campaign's
  `ads_action` rows (what changed, before → after, who, sync state). No suggestions, no queue.
- **策略 tab** (prototype `screen-strategy.js`, minimal fidelity): the recommended strategy card —
  allocation rows (新客／再行銷／探索, label, %, amount) that always sum to the chosen total; the
  三情境 selector 最低／推薦／積極 plus 自訂預算, each with its amount and caption, every caption
  carrying 冷啟動估算 when the backend says so; 為什麼 (the model's reasons) and 哪些是推估 (the
  fields the backend marked estimated) as two plain lists; 成功條件 card (metric, target, basis) with
  an edit affordance that writes through the PATCH from F03-I03 — `success_target` is
  `number | null` (F03-I18) and a null target renders 「尚未設定成功條件」 with the model's
  `success_basis` as the reason, never a 0 and never a dash; 查看策略依據 in a `SidePanel`
  listing the brand facts with their 更新時間, the product price with its effective date (labelled
  價格可能過期 when stale), and the learnings used (with level and 需要重新驗證). The primary action
  is 採用策略（建立投放結構）— wired in F03-I15; here it is present and disabled with a one-line
  reason when the campaign has no strategy yet. **No alternatives table unless the payload has
  alternatives** (it usually will not).
- Every number formatted through the shared formatter with a caption (§7); ROAS shows conservative
  as the main number and optimistic in the caption; no raw hex, no new kit component, tokens only.
- `adsApi.ts` only gains what is missing; it does not re-shape what F03-I01/I05 defined.
