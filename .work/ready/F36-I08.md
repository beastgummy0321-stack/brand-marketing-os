# Objective
`legacy_migration: true` — `app/identity/**` is legacy; this is the minimal facade extension ARCHITECTURE §2 allows
(exposing two values `app/core/settings.py` already computes through the existing `/me` read), not new product behaviour.
Drill-6 #20 first half, ruling G, Contract U in `.work/features/F36.md`: one source for "today". Root cause: the frontend
has no primitive for the org's timezone／today (`GET /api/identity/me` `OrgOut` = id／name／kind／role, `app/identity/routes.py:29,104-116`;
`WorkspaceContext.tsx` therefore cannot know it), so six ads screens use the browser clock. Backend already has
`settings.org_timezone(conn, org_id=…)` and `settings.today_for_org` (`app/core/settings.py:270-303`).

# Done
1. `app/identity/routes.py`: `OrgOut` gains `timezone: str` and `today: str` (YYYY-MM-DD). `me()` fills them for the current
   org from `settings.org_timezone(web.conn, org_id=actor.org_id).key` and `settings.today_for_org(...)`; for the `orgs`
   list and the other `OrgOut` producers fill the same two fields for that org (rename／invite responses included — the
   model is shared). Import `app.core.settings` the way other identity routes import core.
2. `frontend/src/lib/identityApi.ts`: `OrgOut.timezone: string; OrgOut.today: string`.
3. New `frontend/src/lib/orgClock.ts`: `orgToday(tz)` → today's YYYY-MM-DD in `tz` via `Intl.DateTimeFormat("sv-SE", { timeZone: tz })`;
   `orgDateShift(tz, days)` → that day ± days (compute from the zoned Y-M-D at noon UTC to avoid DST edge errors);
   `useOrgClock()` → `{ timezone, today: orgToday(timezone), shift: (d) => orgDateShift(timezone, d) }` from
   `useWorkspace().identity.org` (import `useWorkspace` from `@/components/layout/WorkspaceContext` — `lib/**` importing a
   layout hook must pass `npm run depcruise`; if it does not, export the pure functions only and have I09 read the timezone
   from `useWorkspace()` itself — say which in the report). Invalid／missing timezone falls back to `"Asia/Taipei"`.
4. Tests: backend — `/me` returns `timezone` and `today` matching the org setting (set a non-default timezone through the
   settings helper in the test); frontend — `orgToday("Pacific/Kiritimati")` and `("Pacific/Pago_Pago")` differ by a day at a
   fixed `vi.setSystemTime`, `orgDateShift(tz, -1)` crosses month boundaries correctly.
