# Objective
A brand can register the evidence it really has as 「證據」 brand facts, one of six kinds that are exactly the six `proof`
coordinate keys, and one facade answers 「which proof kinds does this brand have?」 for the ads and workbench prompt builders
(F38 decision 1). Reference screen: `.harness/scratch/prototype/f38-proof/index.html` (`#/fact`) — open it in a browser
(launch config `prototype`, port 8741) and match it; the side panel and list row are the spec.

# Done
1. Migration `supabase/migrations/20260929000002_brand_intelligence_brand_fact_key.sql`:
   `ALTER TABLE brand_fact ADD COLUMN fact_key text;` plus
   `CHECK (fact_type <> 'proof' OR fact_key IN ('customer_review','expert_endorsement','lab_report','sales_numbers','media_coverage','founder_voice'))`
   and `CHECK (fact_type = 'proof' OR fact_key IS NULL)`. Header comment names the ticket and the reader (`available_proof_keys`).
   The lead applies it to the dev DB before merge; do not run it yourself.
2. `app/core/vocab.py`: `BRAND_FACT_TYPES` gains `("proof", "證據")`; new `PROOF_KINDS = [("customer_review", "顧客評論原話"),
   ("expert_endorsement", "專家背書"), ("lab_report", "檢驗報告／認證"), ("sales_numbers", "銷售數據"), ("media_coverage",
   "媒體報導"), ("founder_voice", "創辦人第一手")]` (labels = the `proof` seed labels in `app/schedule/repository.py:155-164`,
   copied, not imported) and `proof_kind_label(v)`.
3. `app/brand_intelligence/repository.py`: `create_brand_fact` / `update_brand_fact` take `fact_key: str | None = None`;
   `fact_type == "proof"` requires a key from the six (else `ValueError("brand_fact.fact_key 必須是六種證據之一")`); any other
   type stores `NULL` regardless of input. Insert/update/audit rows carry `fact_key`. New facade
   `available_proof_keys(conn, brand_id) -> set[str]` = `fact_key` of every `status='confirmed'` proof fact ∪ `{"customer_review"}`
   when `list_customer_voices(conn, brand_id, status="active")` is non-empty. Read-only, no LLM.
4. `app/brand_web/routes_library_write.py` (`fact_create_api`, `fact_update_api`): read `fact_key` from the body; when
   `fact_type == "proof"` and the key is missing/invalid, `errors["fact_key"] = "請選擇哪一種證據。"` (400, same envelope as the
   other field errors). `app/brand_web/routes_library.py::_fact_shape` adds `fact_key` and `fact_key_label` (`None` for other types).
5. Frontend: `libraryApi.ts` — `LibraryBrandFact` gains `fact_key: string | null; fact_key_label: string | null`;
   `BRAND_FACT_TYPES` gains `["proof", "證據"]`; export `PROOF_KINDS` (same six pairs); `createFact`/`updateFact` payloads accept
   `fact_key`. `FactPanel.tsx` — when the type is `proof`, a required select 「哪一種證據？」 appears directly under the type select
   (placeholder option 「請選擇」, hint line 「投放與文案只會引用這裡登記過的證據；沒登記的種類不會出現在廣告裡。」); the label
   placeholder for proof becomes 「例如「PChome 4.8 星、1,200 則評論」」; switching the type away from proof clears the kind.
   `FactsTab.tsx` — a proof row prints `fact_key_label` in muted text right after the type badge (as the prototype list row).
6. Tests: `app/tests/test_brand_proof_facts.py` (new, module-style like `test_library_write_api.py`): proof without key → 400
   `errors.fact_key`; proof with key → stored and shaped with `fact_key_label`; non-proof with a key → stored NULL;
   `available_proof_keys`: empty brand → `set()`; one confirmed `lab_report` + one pending `sales_numbers` → `{"lab_report"}`;
   an active customer voice adds `customer_review`; an archived one does not. `FactsTab.test.tsx`: a proof fact renders its kind label.

# Touch notes
`_fact_shape` only gains two keys, so `test_library_api.py` is in touch for its list assertions; no frontend test builds a
`LibraryBrandFact` literal (grep `fact_type_label` under `frontend/src` — none), so the two new type fields ripple nowhere else.
`create_brand_fact` has other callers (`app/intake/repository.py`, tests listed by `grep -rln create_brand_fact app/tests`) that
pass no `fact_key` — the new parameter is keyword-only with a default, so they keep working; do not edit them. If `finish` reports
one of them red, report for rescope rather than patching around it.
