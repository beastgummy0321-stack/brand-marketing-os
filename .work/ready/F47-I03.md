# Done
1. Number forms send what was typed (empty → `null`), never `Number(x) || 0` or a clamp, and show the server sentence next to the
   field: economics panel, rule cards (each card field shows its own `field_errors` message), channel revenue dialog in
   `OrdersPage`. Errors clear when the field changes.
2. Disabled with a reason (`disabledReason`): brand onboarding step 1 main button (names the missing field), product step 1
   「下一步」 on `/products/new` (「先填商品名稱」), 「讓 AI 整理」 (`CustomEscape`, the missing input).
3. Edits survive navigation and reload: brand onboarding steps 1–3 and product step 2 keep unsaved edits in a per-brand
   (per-product) per-step `sessionStorage` draft, restored on return or reload and cleared on a successful save; 「← 上一步」 and
   「← AI 讀網站」 no longer reset step 3 to the AI text. A reload with unsaved edits restores them (no browser prompt needed).
4. `ProductDetailPage`: 「AI 再次調研」 with no URL says what is missing instead of doing nothing; pasting back text that yields
   0 items reads as a failure with the reason (not green 「貼回完成」) and keeps the pasted text.
5. `BrandReportPage`: a failed regenerate (rate limit included) keeps the existing report on screen and shows the reason inline
   with 「稍後再試」; the whole-page 「讀取失敗」 is only for a first load with no report.
6. `BrandCard`: one state per card (the colored status and the sentence below come from the same field; no 「有警示待處理」 next
   to 「一切正常」).
7. 「確認人」 never shows a user id: the product and library read shapes resolve a stored user id to the member's e-mail (through
   the identity facade); a typed name shows as typed.
8. Tests per screen: the server sentence shown; disabled reason text; draft restored after remount; regenerate failure keeps
   the report; 確認人 resolved.
