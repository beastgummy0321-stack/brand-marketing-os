# Objective
The pause proposal can read the ad itself (feature outcome 2, backend): `GET …/campaigns/{c}/triage/{entity_id}/pause`, Contract P
in `docs/architecture/ads.md` §6.49. That section is the spec.

# Done
1. One function (in `triage.py` or a new `triage_pause.py`) returning Contract P. `triage` is computed for this one ad with the
   same internals `classify()` uses (cutoff, coverage, target, the per-ad window walk, `bound_ad_id`, the ladder for an active ad) —
   one read of this ad's rows, no second definition of a grade or a window. A closed ad gets the same item shape.
2. States from the row: `active` (row exists, native ad of this campaign, `ad_status.is_closed` false — `None` status is active),
   `closed` (closed and not `DELETED`), `gone` (no row in this campaign / not `native_kind='ad'` / `DELETED`). `closed_at` =
   `status_changed_at`, `last_read_at` = `last_success_at`, both ISO or `null`.
3. `change_set_id` per the section (plain sets only: a cleanup or A/B set that lists this ad is not returned).
4. Route in `triage_routes.py`, same auth shape as `GET …/triage`; unknown campaign → 404 with the same message; another org's
   brand → 404.
5. Tests (`test_ads_triage_pause.py`, real rows in the sync tables): active ad with purchases → grade and numbers equal the item
   `GET …/triage` returns for it; paused ad → `closed`, `closed_at`, a `triage` item; deleted / unknown id → `gone`, `triage: null`;
   `native_status` NULL → `active`; an open draft pause set → its id; an approved set whose pause item is confirmed → `null`; a
   cleanup draft listing the ad → `null`; route guard covers the new route.
