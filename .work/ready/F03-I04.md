# Objective

The money numbers are computed by the program, not by a model. §0: it serves the **strategy** link;
its input is `product_economics` and this brand's own spend history (never the user retyping a
budget); its output is the three scenarios the strategy tab shows and the group budgets the plan
writes; its trace is the `basis` payload that says which numbers this came from and which parts are
estimates; it is **core** (the one place that decides what a day of delivery is allowed to cost).

# Done

- `app/ads/budget.py`, pure functions, no HTTP, no model call:
  - `breakeven_cpa(economics) -> float | None` = 售價 − 單位成本 − 運費 from one
    `product_economics` row; `None` when the row is missing or `unit_variable_cost` is `None`
    (never a guessed margin — an unknown stays unknown).
  - `target_cpa(breakeven) -> float | None` = breakeven × `TARGET_CPA_RATIO` (module constant
    `0.7`, one comment naming the ruling).
  - `scenarios(conn, org_id, brand_id, *, product_ids, days, history) -> dict` returning
    `{"mode": "cold_start" | "history", "scenarios": [{key, label, daily, total, caption}],
      "recommended": "recommended", "basis": {...}}`:
    - **cold start** (no settled campaign and no spend history): `daily = target_cpa ×
      events_per_day`, with `events_per_day` 2 / 5 / 10 for 最低 / 推薦 / 積極; every scenario's
      caption carries 冷啟動估算 and the basis says which product's price it used and that the
      purchase counts are an assumption.
    - **history**: `cpa = median CPA of the last 30 days` from this brand's own outcome rows
      (`ads_outcome_daily`; when a campaign has none, the brand has no history and cold start
      applies), `daily = last campaign's daily × (0.6 / 1.0 / 1.6)`, basis names the CPA, the
      number of days and the number of ads it was computed from.
    - `total = daily × days`; both are rounded to whole NT$ and both are returned — the screen
      never recomputes one from the other.
  - `split(total, weights) -> list` — the 新客／再行銷／探索 split applied to a total, returning
    whole amounts whose sum is exactly `total` (the remainder goes to the largest share, so the
    table always adds up).
  - Every function returns `None`/an empty result rather than a fabricated number when the input is
    missing; nothing in this file reads a rule card and nothing writes to the database.
- `app/tests/test_ads_budget.py` (the falsifier): breakeven with and without shipping; a missing
  `unit_variable_cost` returns `None` and no scenario claims a number; cold-start scenarios are
  2/5/10 × target CPA and all three carry the 冷啟動估算 flag; with history the three scenarios are
  ×0.6/×1/×1.6 of the previous daily and the basis names the sample; `split` sums exactly to the
  total for an awkward total (e.g. 30001 across 50/30/20).

# Verify

`uv run python -m pytest app/tests/test_ads_budget.py -q` — the split-sum and the
missing-economics cases are the two that fail loudly if someone "helpfully" fills a gap.

# Blocked if

`product_economics` for the campaign's product has no `unit_variable_cost` **and** you are tempted
to fall back to the `gross_margin` rule card. Do not: return `None`, let the strategy tab say
「還算不出打平 CPA，先去補商品成本」, and report it.
