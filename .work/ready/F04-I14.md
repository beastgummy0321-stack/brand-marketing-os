# Objective

策略分頁重做成 `docs/design/ads/05-strategy.png`：一張建議卡、一顆主要按鈕、其他全部收起來
（R9／ARCHITECTURE.md §6.1 第 9、14 條）。今天這一頁有三張統計卡、一張情境選擇卡、兩張理由卡、
一顆**永遠 disabled 的採用按鈕**（`StrategyTab.tsx:239-243`）——新手看不出下一步是哪一顆。
§0 連結：**strategy → delivery plan**（這一頁是使用者從建議走到真的投放結構的那一步）。

**動手前先用 `docs/design/ads/05-strategy.png` 與 `docs/design/ads/10-strategy-advanced.png`
各呼叫一次 `Skill impeccable:impeccable`**（R6）。圖 10 只借它的**進階設定欄位清單**，
它的右側欄、平台勾選框、下拉選單**一律不做**（R5：那些是佔位，不是功能）。
圖上的插畫、手寫字、「了解 AI 推薦機制 →」連結不做。

# Done

版面由上而下（`strategy` 存在時；`!strategy` 的空狀態維持現在的 `EmptyState`＋產生策略）：

## 1. `JudgmentBand`

`sentence = "行銷駕駛艙建議這樣投"`，`facts = strategy.why[0] ?? 三個角色的百分比摘要`
（例：`新客 70%・再行銷 20%・探索 10%`），icon `Sparkles`。**不要**自己編一句行銷話術。

## 2. 建議卡（一張 `surface`）

- header：`目標：{objective}`（15/600）＋右側一行 muted
  `這是根據你的資料整理的建議，可以直接使用，也可以調整。`
- **`KpiStrip`** 五格：
  | label | value | caption |
  |---|---|---|
  | 平台 | `constraints_json.platform` 的中文 label，沒有 → 「尚未指定」 | 「採用後會建立對應的投放組」 |
  | 預算 | `formatCurrency(budget_planned ?? 推薦情境 total)`，兩者皆無 → 「尚未設定」 | 已採用 → 「你採用的情境金額」；未採用 → 「推薦情境（可調整）」 |
  | 配置 | `新客 70% / 再行銷 20% / 探索 10%` | 「按角色分配預算」 |
  | 時間 | `MM/DD – MM/DD`，缺 → 「未設定」 | `共 N 天` |
  | 需要素材 | `{asset_readiness.ready_count}／{asset_readiness.total} 已準備`，`total === 0` → 「採用策略後才知道」 | 「每則廣告需要文案與圖片」 |
- **預估購買**：KpiStrip 下方一行（不是第六格）：
  `success_metric === "cpa" && success_target > 0 && total !== null` →
  `預估購買 {Math.floor(total / success_target)} 筆` ＋ 緊接著的 caption
  `推估（CPA 不變的算術）`（**逐字**，ruling 14）。條件不成立時整行改成
  `目標不是 CPA，或還沒有總預算，算不出推估購買。`
  **不准**出現「預估觸及」「預估成效」這類我們算不出來的數字（圖 10 上有，那是示意圖）。
- 三欄（`grid-cols-3`，1024 時 `grid-cols-1`）：
  `主要原因`＝`strategy.why`、`目前最大的未知`＝`strategy.unknowns`、
  `這輪想學到什麼`＝`strategy.learning_goals ?? []`。每欄一個 lucide 圖示＋標題＋清單；
  空陣列時印一行 muted：`這一輪沒有列出` ／ `沒有列出未知` ／ `這一輪沒有設定學習目標`。
  **標題不加「主要原因：」式的因果宣稱**——標題就是「主要原因」，項目照模型原句印。

## 3. 一顆主要按鈕

整寬 `Button`「照這個方式進行 →」。按下去依序（全部在一個 `async` 函式裡，中途失敗就停在那裡
並印一行紅字，**不留半套**）：

1. `campaign.budget_scenario === null` → 先 `selectScenario(brandId, id, { scenario_key:
   scenarios.recommended, custom_total: null })`（使用者沒選＝採用推薦，這就是「只管點下一步」）。
2. `adoptStrategy(brandId, id)`（既有 API）。
3. `onCampaignChange(結果)` 後 `onChangeTab("structure")`——策略分頁不負責畫投放結構。

按鈕在執行中 disabled ＋文字「處理中…」。已經有投放組（`campaign.groups.length > 0`）時，
按鈕換成 `variant="outline"` 的「前往投放結構」，只做第 3 步。
**把現在那顆永遠 disabled 的「採用策略（建立投放結構）」整段刪掉**（含 `adoptDisabledReason`）。

## 4. 三個收合（`Disclosure`，預設全部收起——「不點開是不會看到」）

- **`調整建議`**：**只在 `campaign.groups.length === 0` 時出現**。已經展開過投放結構之後，
  後端會用 `plan_already_adopted` 拒絕（F04-I13：投放組的日預算才是採用後的真相），所以這裡
  整個 `Disclosure` 換成一行 muted 說明：
  「投放結構已經建立，預算改在投放結構分頁的每個投放組日預算。」＋一顆
  `Button variant="link"` 「前往投放結構」（`onChangeTab("structure")`）。
  **不要**渲染一個按了會 400 的表單。展開後裡面放：
  1. 三個角色的百分比 `Input type="number"`（預設值＝目前 `allocation[].pct`），下方即時顯示
     `合計 {sum}%`；`sum !== 100` 時「套用」按鈕 disabled 並印一行 muted
     `三個角色加起來要剛好 100%`。「套用」→ `setAllocation(brandId, id, [{role, pct}…])`
     （F04-I13 的新 API），成功後 `onCampaignChange`。金額**不在前端算**——回傳的 campaign 已經
     帶新的金額。
  2. 既有的「預算情境選擇」卡整段搬進來（三顆情境按鈕＋自訂預算），一行字不改。
  3. 既有的「成功條件」卡與它的 `SuccessCriterionEditor` 側邊面板整段搬進來，一行字不改。
- **`查看完整判斷`**：點開後直接開既有的「策略依據」`SidePanel`（`basisOpen`）——把現在那個
  「查看策略依據 →」小連結換成這個入口，面板內容一個字不改。
  （這一個 `Disclosure` 只放一顆按鈕＋一行說明「品牌事實、商品價格、用到的學習」。）
- **`進階設定`**：裡面放一張 **`ReservedSlotCard`**：
  title 「進階投放設定」、description
  「這些設定會在自動發布接上之後開放，屆時可以在這裡微調；現在的投放結構仍然可以手動調整。」、
  tag 「自動發布接上後開放」、`bullets = ["平台結構", "受眾設定", "版位設定", "出價策略",
  "優化事件", "歸因設定", "追蹤設定", "UTM 參數"]`（圖 10 的八項）。
  **沒有輸入框、沒有勾選框、沒有 disabled 的假按鈕**（R5：席位保留不是拒絕，也不是壞掉的表單）。

## 5. 刪掉的東西

現在最上面那三張統計卡（投放期間／建議總預算／投放平台，`:102-118`）——它們被 KpiStrip 取代；
硬寫的「投放平台 Meta」也隨之消失（`constraints_json.platform` 才是真相，沒有就說「尚未指定」）。
