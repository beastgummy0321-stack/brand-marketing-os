# Objective
The assets tab renders Contract T (`.work/features/F35.md`): each slot tile is two halves with the four states of the
prototype, an upload into a copy-only slot is ready at once, and an image-only slot takes a workbench copy version from
the picker. Spec = `.harness/scratch/prototype/f35-slot-copy/index.html#/assets` (open it; click 上傳 on the first tile and
「選一版文案」 on the last one to see both interactions; shots `shots/assets-1024.png`, `assets-1920.png`,
`assets-after-upload-*.png`, `assets-picker-*.png`).

# Done
1. `adsSlotsApi.ts`: `SlotState = "ready" | "missing" | "in_progress" | "copy_only" | "image_only"`;
   `Slot.copy: { source: "workbench" | "placement"; label: string; headline: string | null; body: string | null; description: string | null } | null`;
   `Slot.workbench_href: string | null`; `getSlotCopyOptions(brand, campaign, signal?) → { options: { set_id: string; version_id: string; label: string; copy_fields: CopyFields }[] }`
   (`GET …/slots/copy-options`); `chooseSlotCopy(brand, campaign, adId, { set_id, version_id }, signal?) → { placement; slots }`
   (`POST …/slots/{ad_id}/copy`). Comment the two new states in the existing header comment.
2. `patterns/SlotGrid.tsx` — the tile is the prototype's `.slot`: `min-h-[212px]`, grid `minmax(148px,1fr)`. Variants:
   - `ready`: `SlotThumb`, name, the copy half (`data-slot="slot-copy"`: 「✓ 文案 · {label}」 line + a 2-line clamp of
     `headline　body`), status chip (caller's);
   - `copy-only` (`data-variant="copy-only"`): the dashed image half (＋, 「缺圖」, the caller's 上傳 action), name, the copy
     half, the caller's `extra` (看圖片提示詞 link), status;
   - `image-only`: `SlotThumb`, name, the dashed copy half (「缺文案」 + the caller's 「選一版文案」 action), status;
   - `missing`, `reserved`: as today (missing keeps 上傳 and 從素材工作檯).
   Copy text clamps with `line-clamp-2` and `[overflow-wrap:anywhere]`; nothing truncates a control at 1024 with the
   longest fixture names. Export nothing new from `index.ts` unless a piece needs it.
3. `AssetsBody.tsx`: render by `slot.state` — `ready`／`in_progress` → ready variant (in_progress keeps the 「處理中」 chip),
   `copy_only` → copy-only with 上傳 (same `upload()` path, body unchanged: no `copy_fields`) and 「看圖片提示詞」 →
   `slot.workbench_href` (omit the link when null), `image_only` → image-only with 「選一版文案」, `missing` → missing (從素材工作檯
   → `slot.workbench_href ?? workbenchHref`). Chips: 已確認 ok, 有文案，缺圖 warn, 有圖，缺文案 warn, 缺 1 則 neutral (missing
   tile's title as today). The progress segments: `ok` only for `ready`. Upload note: when `result.placement.confirmed_at` is
   set → 「已放進「{name}」這一格，文案跟著帶進去了，這一格備妥。」 (no button); when the returned slot is `image_only` → 「已放進「{name}」
   這一格；還缺文案，選一版就備妥。」 (no button); otherwise today's pending line with 「去確認安排 →」.
4. Picker: a kit `Dialog` (`@/components/layout/ui/dialog`, as `MaterialTaskEditor` uses it) titled 「選一版文案放進「{name}」」 with
   the prototype's one line, one button per option (`label` small, then `headline` bold + `body`), 取消. Options load on open
   via `getSlotCopyOptions` (a failed read shows `ReadFailed` inside the dialog); choosing calls `chooseSlotCopy`, sets the
   returned `slots` as `fresh` (like the upload), closes, and shows 「文案已放進這一格，備妥。」 as the status line; a 409
   shows its message inside the dialog and keeps it open. Focus lands on the first option; Escape closes.
5. Tests. `AssetsBody.test.tsx`: extend the `slot()` factory with `copy: null, workbench_href: null`; cases — the four states
   render their chips and halves (copy text visible on copy_only／ready); upload into copy_only sends no `copy_fields` and,
   with a confirmed placement in the response, shows the 備妥 line and no 去確認安排; upload into an ad without copy where the
   response slot is `image_only` shows the 缺文案 line; 「選一版文案」 opens the dialog, lists options from `getSlotCopyOptions`,
   choosing calls `chooseSlotCopy` with `{set_id, version_id}` and renders the returned slots; a 409 keeps the dialog with the
   message; 「看圖片提示詞」 links to `workbench_href` and is absent when null. `kit30.test.tsx`: the two new variants render with
   their `data-variant`. `AssetsTab.test.tsx`／`UserAssetFlows.test.tsx`: only the fixture keys (a required field added to
   `Slot` ripples into every factory that builds one — F34 lesson).
6. Evidence: `frontend/scripts/ui-evidence.cjs --proto ../.harness/scratch/prototype/f35-slot-copy/index.html --hash assets`
   first, read `facts-reference-*.txt` and `pieces`, build static from those pieces, then `--app` with the realistic fixture
