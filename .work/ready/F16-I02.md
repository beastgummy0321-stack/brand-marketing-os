# Objective
Resolve Meta budgets into real amounts. `meta_read.py:68-84` always writes `budget_amount=None` with
`"conversion":"unverified_currency_denominator"`. That blocks budget proposals at approve (`month_budget.py:453-469`), keeps
budget read-back `unknown` forever (`change_control_verify.py:109-111`), leaves the ad-count cap without input and makes month
`available` None for real accounts.
# Done
- The minor-unit rule per currency is established from the official Marketing API documentation (cite URL and date in the
  code comment and in ads.md) and cross-checked once, read-only, against a campaign whose daily budget the user states
  (Beast Prime: NT$2,000 per day). If the two disagree, stop and block; do not guess.
- `budget_amount`, budget kind (daily or lifetime) and currency are stored for campaign and ad set; where currency or offset
  is not provable the value stays None with an explicit reason (no silent default).
- Month-budget uncertainties drop "預算金額、單位或幣別未核實" only for resolved entities; budget change items read
  `before.daily_amount` and verify read-back against the resolved amount.
- The conversion lives in the ads-owned Meta adapter (`app/ads/adapters/meta_read.py`, which already receives `budget_raw`);
  `app/meta/**` is legacy and is not edited. Shared code receives amounts, never raw platform units.
# Verify
Targeted tests above with fixtures for a zero-decimal and a two-decimal currency; global gates per manifest.
# Blocked if
Official docs and the real read-back disagree, a second account currency appears with no rule, or any write or extra Graph
scope would be needed.
