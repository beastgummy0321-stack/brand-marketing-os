# Objective
Every screen that asks the platform for something says what came back, and panels open to system-built campaigns stop reading
imported-only data (feature Contracts O, D, B, L; frontend-ads F2, F4, F9; triage #17; drill-11 R3 M1-c, R4 C1 「要繞路」). Today
「來源讀取已排入，稍後按「重新讀取」查看候選」 never changes (a platform outage is silent), the connections re-read and the import
dialog say nothing about a partial read, the review's 「建立新廣告提議」 is always disabled on system-built campaigns (ad set looked up
only in `external_view`), and the asset／handoff／change panels tell a system-built campaign's owner to import a campaign.

# Done
1. Read outcome: `DataConnectionsPage` 重新讀取, `ExistingCampaignDialog` (list status), `ExternalCampaignPanel` and
   `ManualHandoffPanel` 「更新平台候選」 follow `useSyncOutcome` (job or campaign scope) and print its `text` — found, 讀過但沒有
   新候選, partial／failed with the reason; `ManualHandoffPanel` keeps the job(s) the POST returns instead of a fixed 「已排入」
   sentence. The import dialog shows cached rows plus the failed outcome when the account cannot be read (the listing GET no longer
   fails whole).
2. Destinations (Contract D): `review/MaterialStepPage` finds the ad's ad set through the handoff read's `destination_by_ad`
   (no `external_view`), so 建立新廣告提議 works on system-built campaigns; `UserAssetPlacements`' 目的節點 options come from the
   handoff read's `destinations`, and with none it prints `destinations_note` and hides the picker (the 載入本活動目的節點 button
   goes on internal campaigns); `AssetHandoffPanel` and `ChangeControl` print `destinations_note`／an origin-aware sentence instead
   of 「請先同步本活動的原始結構」／「先從投放中心帶入既有活動」; `ManualHandoffPanel`'s 保存清單 gets a `disabledReason`.
3. Words: `ManualHandoffPanel` and `ChangeSetView` print the served `status_label`／`verification_label` (local maps go;
   `ChangeSetView`'s status values print the served `status_labels`); `ExistingCampaignDialog` and `ExternalCampaignPanel` print
   `delivery_label` (no raw `native_status`); `nativeStatusWord` and its `NATIVE_WORD` map leave `patterns/campaignWords.ts` and
   `patterns/index.ts`.
4. Scanner: add to `oneRuler.test.ts` the Contract D rule — `.external_view` outside `PerformanceTab.tsx`,
   `detail/PeriodStatusRow.tsx`, `OverviewTab.tsx`, `workspace/WorkspaceHead.tsx`, `AssetsTab.tsx`, `DeliveryTab.tsx`,
   `CampaignWorkspace.tsx`, and `externalView(` outside `ExternalCampaignPanel.tsx`, `ManualHandoffPanel.tsx`,
   `lib/adsExternalApi.ts`, fail (a permanent list of imported-only readers, not debt); delete every allowlist entry that names
   F49-I14.
5. Tests: a partial re-read on the connections page prints its reason; the import dialog on a disconnected account lists cached
   rows with the failure; the handoff panel's candidate refresh shows failed／empty／found; on an internal launched campaign the
   material step's 建立新廣告提議 is enabled with the ad set from `destination_by_ad`; an internal draft's placement panel shows the
   note instead of an empty picker; status words come from the payload.
