# Objective
A new campaign starts from what the same sell-way ran last time, and what the form shows is what gets stored (feature outcome 6,
Contract D; drill-10 root cause 9: platform shown as Meta but stored 「未設定 猜的」, the cap re-entered every period, drill-9 #10).
Layout spec = `.harness/scratch/prototype/f46-learnings/index.html` screens `#/new?from=B` and `#/new?way=single` (port 8741): the
「期間、預算與平台」 section with tags, the learn strip, and the dashed note of what 下一步 stores (prototype-only, not built).

# Done
1. `wizard_options`: `previous_campaign(conn, org, brand, sell_way_id)` = the newest (created_at desc) internal, non-draft campaign
   whose `sell_way.of_campaign` is that sell-way, or None. Each option gains `previous` = `{campaign_id, campaign_name, platform,
   cap, budget, spend}` (platform = `constraints_json.platform`, cap = `target_cost`, budget = `constraints_json.budget`; spend =
   the closed campaign's Contract L `spend`, else null) and `learned` = `{campaigns [{id, name}], keep, replace}` from
   `learning_view.learnings_view(sell_way_id=…)` (null when no campaign). Options also carry `default_platform` = the brand's first
   connected channel key (same order the form lists) or null.
2. `brief.create_draft`, structured path, for a value the request does not send: platform = previous platform (`copied`) else
   `default_platform` (`brand`) else none (`system`); cap = previous cap (`copied`) else sell-way `cap_per_sale` (`sell_way`) else
   break-even of the sell-way's current economics (`break_even`, stored as the campaign's own cap) else none (`system`); budget
   source `copied` when the sent budget equals `previous.budget`, else `user`. The sentence path is unchanged. Counter-examples: a
   previous campaign with a null field falls through to the next rule for that field only; a previous campaign of another sell-way
   never counts; an archived / deleted sell-way has no option, so no previous.
3. `adsCampaignTypes.FieldSource` gains `"brand" | "break_even"`; `adsWizardApi` option types gain `previous`, `learned`,
   `default_platform`.
4. `NewCampaignPage` as the prototype: platform, 每筆上限 and 這個活動最多花 in the 「期間、預算與平台」 section with a tag each —
   沿用上一期 (title = the previous campaign's name) / 打平線 / 已接上的帳戶 / 你改的; the budget prefills from `previous.budget` when
   the form's budget is empty (a restored draft keeps its own value) with the hint 「〈previous name〉 花了 NT$〈spend〉」 when spend is
   known, 「第一次推，要自己填」 when there is no previous; the learn strip 「這期會用 N 期的學習・〈names〉 留下 n 換掉 m 看學到什麼 →」
   (link `/brands/{b}/library?tab=ads-learnings`) or 「「〈sell-way〉」還沒結案過・沒有學習可用，每筆上限先用打平線」. Only changed
   values are sent (the server fills the rest with the same rule, so shown = stored). Audience and landing stay in 進階.
5. `ConfirmBriefPage` / `WizardPieces`: the new sources show their tag instead of 「猜的，請確認」; `system` keeps it.
6. Tests: options `previous` / `learned` / `default_platform` (none, one, two campaigns of the sell-way, a draft ignored, another
   sell-way ignored); create stores platform / cap with the right source for each fallback; the page shows and sends the right
   values and tags for a sell-way with and without a previous campaign; the confirm page tags. `ads-cold-start.spec.ts`: keep its
   labels working (「這個活動最多花」); adjust only what the new layout changes.
