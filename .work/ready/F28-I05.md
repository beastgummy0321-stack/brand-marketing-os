# Objective
R3: a job left in `doing` by a worker restart is re-queued once; a job stranded a second time ends `failed` and says so (rule in ads.md §6.32). This is a fix to existing legacy recovery code, not new capability; the queue has no managed owner.

# Done
1. `recover()`: every task name found in `doing` is handled — the read-only list keeps today's retry; tasks with their own domain recovery (`background.ads_review_round`) keep today's fail-then-restore path; every other task is retried once. "Once" is counted per job from procrastinate's own durable records (e.g. its job events), never in memory, so it survives repeated restarts.
2. A job already retried once by recovery and stranded again → `failed` (not deleted), and the worker's start-up line names the task and job id. Abort-requested and queueing-lock behaviour unchanged.
3. `app/worker.py` docstring and print lines drop "付費工作不自動重送" and state the new rule.
4. Tests (real procrastinate schema, as the existing file does): unknown non-read-only task retried on the first strand and failed on the second; read-only retry unchanged; review-round path unchanged; limit/deferred unchanged.

# Verify
Issue verify plus manifest gates. Before live acceptance the lead restarts the worker (single-instance lock: stop, then start).

# Blocked if
A registered task would repeat a non-idempotent write that is not a model call when re-run (list them with evidence) — stop and report.
