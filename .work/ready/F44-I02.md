# Objective
The delivery planner sees what each available offer actually says and uses one (feature outcome 1; drill 9: `offer=none` 13/13
because the menu printed only `offer｜bundle｜組合加贈`).

# Done
1. New `app/ads/sell_way.py` (Contract A): `of_campaign(campaign)` and `of_ad(ad, campaign)`. `plan.adopt_strategy` reads the
   sell-way through `of_campaign` (replaces the inline `product_ids[0]`).
2. `plan.py` prompt: a section 【這期可用的優惠】 before the vocabulary table (vocabulary stays last), one line per sentence of
   `bi_repo.offer_sources(conn, brand_id, sell_way)` whose key is in the filtered menu: 「- offer=〈key〉｜〈sentence〉」 (a sentence
   listed once). No offer key other than `none` in the filtered menu → the section is omitted.
3. `delivery_plan.md`, in its own style: when 【這期可用的優惠】 is listed, at least one ad's `offer` is one of the listed keys and
   that ad's name and scene fit the offer; the other ads may use `none`; not listed → every ad uses `none`.
4. Program gate, after `_gate_reply`: the filtered menu has an offer key other than `none` and every ad's `offer` is `none` →
   `ValueError("delivery_plan_failed")` (same refusal as the scene rule; nothing is written).
5. `ScriptedProvider` delivery-plan reply: when the prompt has 【這期可用的優惠】, the first group's ad takes the first listed key
   as `offer`; otherwise unchanged.
6. Tests: `test_ads_sell_way.py` (new) — campaign first id, ad override, no product; plan — section content and position, omitted
   without offers, gate refuses all-`none` when an offer is in the menu and passes with one, no gate when the menu has none;
   scripted reply follows the section.
