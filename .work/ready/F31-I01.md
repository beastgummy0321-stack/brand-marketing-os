# Objective
Wizard items 1 and 2: the offerings step advances, remembers both of its choices and keeps sell-ways in the order entered; the start step keeps unsent text across navigation (Feature Contract M, agent choices for items 1–2).

# Done
1. Migration `20260927000001_intake_offerings_choice.sql` adds nullable `intake_draft.offerings_choice_json`; `update_draft` accepts it.
2. `POST …/offerings` stores `choice` and advances the draft to step 4 (the tools step path); `GET` returns `choice` and lists the sell-ways of each parent in creation order (`created_at, id`).
3. `OfferingsStep` sends `choice` and restores 賣什麼 and 廣告帶來的是什麼 from it (today's inference when null), so revisiting shows no 「選一下廣告帶來的是什麼。」 and Next is enabled.
4. `budget._economics_for` takes a parent's first sell-way in creation order, not name order.
5. `StartStep` keeps brand name, client name, description, URLs and the past-ads answer in browser storage keyed by user and brand (or "new"), restores them with 「幫你留著上次填的」 and clears them on successful submit; photos are not restored.
6. Regression tests (red on master): save → draft step 4 and `choice` round-trips; a product sold by 先詢問再成交 is not read back as a service; two sell-ways whose name order differs from input order come back in input order (API and budget); StartStep text survives unmount/remount and is gone after submit.
