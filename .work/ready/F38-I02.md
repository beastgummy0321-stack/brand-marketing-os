# Objective
The delivery plan only offers the proof kinds the brand has evidence for (F38 decision 1) and 「限時限量」 only when the
campaign has an end date, which the ads → workbench hand-over carries as the copy's one allowed deadline (decision 3). Root
cause (drill-6 report §4): `plan.py:146` hands the model every enabled `proof` row (`coordinate_vocabulary`), so the plan named
評論／檢驗／媒體 for a brand that has none, and the copy step (`workbench/claims.py`) then had to contradict the plan.

# Done
1. `app/ads/plan.py`: new pure helper `_prompt_rows(rows, available_proof: set[str], has_end_date: bool) -> list` — drops a
   `proof` row whose key is not in `available_proof | {"none"}`, and the `offer`/`limited_time` row when `has_end_date` is false;
   every other row passes through unchanged. In the plan builder (`plan.py:146`): `available = bi_repo.available_proof_keys(conn,
   brand_id)` (import `from app.brand_intelligence import repository as bi_repo`, the facade `strategy.py` already uses), then
   `vocabulary_rows = _prompt_rows(ads_repo.coordinate_vocabulary(...), available, campaign["end_date"] is not None)` feeds BOTH
   `_vocabulary_text` and `_vocabulary_lookup`. After `_validate_reply`, for each ad: if `("proof", key)` or `("offer", key)` is
   not in the filtered lookup, replace that key with `"none"` (agent choice recorded in F38.md: a stray key is a wording slip, not a
   retry). `create_ad`/`update_ad` (`plan.py:316`) keep the unfiltered lookup — a person editing an ad by hand may pick any enabled
   coordinate; the gate is for the model's menu.
2. `app/departments/ads/delivery_plan.md`: one sentence in the coordinates paragraph: 「證明那一段列出的就是這個品牌**確認有**的
   證據；沒列的不能用。限時限量只在活動有結束日時出現，截止日由工作檯帶給文案，這裡不寫日期。」 No other prompt change.
3. `app/ads/assets.py::_ad_set`: when `ad.get("offer_key") == "limited_time"`, set `request["offer_deadline"] = <ISO date>` from
   `group["end_date"]`, else `campaign["end_date"]`; when neither exists leave the key out (the workbench then writes the 無優惠
   version — F38-I04). Nothing else in the request changes.
4. Tests. `test_ads_plan.py`: (a) `_prompt_rows` unit cases — proof rows filtered to available + none, `limited_time` dropped
   without an end date, other dimensions untouched; (b) a plan run with the FakeProvider replying `proof: lab_report` for a brand
   with no proof facts stores `proof_key == "none"` and the prompt text (`FakeProvider` captured prompt) contains 「無證明」 but not
   「檢驗報告／認證」; (c) after `bi_repo.create_brand_fact(..., fact_type="proof", fact_key="customer_review", status="confirmed",
   confirmed_by=...)` the same reply with `proof: customer_review` is kept. `test_ads_plan_scripted_reply.py`: adjust only if its
   scripted reply names a proof key other than 無證明 (then seed the matching proof fact). `test_ads_assets.py`: `offer_deadline`
   present only for a `limited_time` ad, group end date preferred over campaign end date.
