# Objective

F05-I02 已經把「這個品牌能不能投放」算好了（`GET /api/ads/brands/{b}/readiness`，client 是
`adsApi.ts::fetchLaunchReadiness`）。這張票把同一份資料接到兩個入口，讓演練四那種「走到第七站
才發現地基是空的」不再發生。

兩個入口讀同一支端點、印同一份文字——**所有句子都是後端給的，瀏覽器不重拼、不重判**
（`ARCHITECTURE.md` §5.3／§6.1 第 10 條）。

# Done

## 1. 共用元件 `frontend/src/components/ads/patterns/ReadinessList.tsx`

`patterns/` 是 F04 定下的共用樣式庫（`ARCHITECTURE.md` §7），這一塊兩個頁面都要用，所以做在
那裡、從 `patterns/index.ts` 匯出。寫之前叫 `Skill impeccable:impeccable`，參考
`patterns/DecisionCard.tsx`／`KpiStrip.tsx` 的寫法與 `docs/design-system.md`。

props 就是後端的形狀：`{ readiness: LaunchReadiness }`。渲染：
- 三項各一列：`state === "ok"` 是綠勾＋`text`；`missing` 是灰／警示色＋`text`＋一顆連到
  `next_href` 的次要連結（文字用 `next_label`）。**不要自己造圖示以外的任何文字。**
- 底下把 `notes[]` 每一條印成一行小字。
- 讀取中用既有的 `Skeleton`；讀取失敗就整塊不渲染（檢查表壞掉不該讓整頁不能用）。

## 2. 精靈完成畫面（`IntakeCompletedPage.tsx`）

在「🎉 建檔完成」那張卡底下、人物誌進度上面，插一塊「可以開始投放了嗎」：`fetchLaunchReadiness`
＋ `ReadinessList`。三項全綠時，主要按鈕變成「去投放中心建立 Campaign」
（`/brands/{id}/ads`）；沒全綠時主要按鈕維持既有的「前往品牌頁」，缺的那幾項由列上的連結帶。

（跨模組 import：`@/lib/adsApi` 是 `ads` 的 client，manifest 已經宣告
`intake.may_depend_on = ["ads"]`，depcruise 也允許——**只准 import `@/lib/adsApi`，不准 import
`@/components/ads/**` 的內部檔**。`ReadinessList` 要走 `@/components/ads`（index.ts）。）

## 3. 投放中心首頁（`AdsHomePage.tsx`）

「建立新的 Campaign」那張虛線卡（`:122-137`）改成：

- 讀 `fetchLaunchReadiness`。
- `ready` 為 true → **畫面跟現在一模一樣**（不要為了好看多印一塊綠色的東西）。
- `ready` 為 false → 卡片裡多一塊 `ReadinessList`；主要按鈕變成
  **「先補齊地基」**（連到 `next_href` 裡第一個 missing 的那一項），既有的「開始建立」降成次要
  按鈕、文字改成 **「還是要先建立」**，而且**仍然可以按**。
  副標那句改成後端給的口氣：「還缺 N 項，補齊之後系統才算得出預算與成效。」——N 由
  `items.filter(missing).length` 算，這是數數不是判斷，可以在前端做。

**不准**把 `開始建立` 變成 disabled，不准跳 confirm dialog，不准擋住路由。檢查表永遠不拒絕人
（`ARCHITECTURE.md` §8 第 3 條）。

## 4. 測試 `AdsHomePage.test.tsx`（既有檔，照它的寫法加）

- `ready: true` → 畫面上沒有檢查表、主要按鈕仍是「開始建立」。
- `ready: false` 且三項 missing → 三句 `text` 都印出來、主要按鈕是「先補齊地基」、
  「還是要先建立」**沒有** disabled 屬性。
