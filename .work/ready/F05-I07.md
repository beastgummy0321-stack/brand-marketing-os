# Objective

因果鏈（已查證）：精靈把「薑黃錠售價 1200 成本 380」存成 `product_fact` 的自由文字 →
`save_product_economics` 全專案只有商品詳情頁一個呼叫端 → `product_economics` 空 → `breakeven_cpa`
回 None → 策略頁三張情境卡金額全 null。**每個新品牌都會走到這裡。** 實測：常春健康完成建檔、11 條
事實，`product_economics` **0 列**。

這張票在精靈裡插一個新步驟，把「賣什麼」與「數字」做成結構化欄位——而且是**母產品＋賣法**的形狀，
並且讓「不知道」變成一個有標籤的假設值，不是一個空白。

視覺唯一真相：`.harness/scratch/prototype/intake-foundation/index.html` 步驟三（`:230-340`）。
**原型那張是平的 SKU 表；實作要照 `ARCHITECTURE.md` §8 第 1 條做成「母產品標題列＋賣法列」**，
其餘（順序、字句、假設 chip、按鈕位置）照原型。

## 2. 後端：新檔 `app/intake/routes_offerings_api.py`（在 `routes_api.py` 檔尾比照 `t2_router` 併入）

- `GET /api/intake/brands/{brand_id}/offerings` →
  `{"data": {"offerings": [{"product_id","name","parent_id","selling_price","unit_variable_cost",
  "shipping_cost","close_rate","assumptions"}], "benchmarks": {...}}}`。
  `benchmarks` 直接給 `app.brand_intelligence.benchmarks` 三條的 `value` ＋ `source_text()`
  ——**畫面不自己拼那句話**。沒有經濟數字的商品也要出現（數字 `null`），初掃建的商品要能在這裡補完。
- `POST /api/intake/brands/{brand_id}/offerings`，body：
  ```json
  {"offerings": [{"parent": {"product_id"?, "name"},
                  "variants": [{"product_id"?, "label", "selling_price", "unit_variable_cost",
                                "shipping_cost", "close_rate"?, "assumptions": []}]}]}
  ```
  - 母產品：`product_id` 缺就 `bi_repo.create_product(name=...)`。
  - 每個賣法：`create_product(name=f"{母名} · {label}", parent_id=母.id)`，再
    `save_product_economics(..., currency="TWD", confirmed_by=str(actor.user_id),
    close_rate=..., assumptions=[...])`。**不要自己寫 SQL。**
  - 三個數字都是必填（`shipping_cost` 可以是 0，不可以空白）；缺一個回 400 並指名是哪一項的哪一欄：
    「「薑麥錠 · 3 入組」的運費請填數字，沒有運費就填 0。」
  - `close_rate` 選填；填了必須 0 < x ≤ 1。`assumptions` 只接受 `cost`／`shipping`／`close_rate`。
  - 空清單 → 400「至少要有一項要賣的東西。」
  - 成功回 204，並 `state.touch(draft, f"/brands/{brand_id}/intake/offerings", 3)`。

## 3. 前端：`steps/OfferingsStep.tsx`（新檔）

寫之前叫 `Skill impeccable:impeccable`，對照原型與 `docs/design-system.md`。由上而下：

- **「你賣的是什麼」**：商品／服務／兩者都有，**預設不選**（沒選就只有這一題，畫面乾淨）。
  重新進來時從既有 offering 反推（有 `close_rate` 的＝服務、沒有的＝商品、都有＝兩者）。
- **「廣告帶來的是什麼」**：直接下單／先詢問再成交／留資料（名單）。**只有後兩者才問成交率**
  ——這就是 `close_rate` 該不該有值的唯一判斷，不開新欄位。
- **商品區**：一個母產品一張卡（品名一列），底下是賣法列：`賣法名稱｜售價｜單位成本｜運費`。
  預設先給一列「單品」。有「＋新增賣法」「複製這列」「移除」。提示句照原型：
  「有多組入？每種組合各一列（例：薑黃錠 3 入組）。售價填組合價、成本填整組的、運費填一次。」
  另有「＋新增商品」可以再開一張母產品卡。
- **「不知道」**：成本與運費各有一個。**按下去之前欄位是空的（不預填）**；按下去才把
  `benchmarks` 的值填進欄位、掛上黃色「假設」chip＋`source_text()` 那一句，並把該欄位放進這一列的
  `assumptions`。使用者一改那格數字，chip 與 `assumptions` 立刻消失。**售價沒有「不知道」**。
  成本的預設值＝`售價 × (1 − 毛利率假設)`（毛利率 45% → 成本＝售價 55%），運費＝NT$80。
- **服務區**：「一次成交你收到多少錢」；checkbox「幾乎沒有每單成本（課程、數位商品、諮詢）」→
  成本 0；不勾就問每單成本（一樣有「不知道」）。成交率用 1/3、1/5、1/10、自己填，外加「不知道」→
  假設 20%。底下即時算一行：直接下單印「每單毛利 NT$X」，其餘印「一筆名單值 NT$X」，用了假設值就
  在後面加「（假設）」。
- 送出前在畫面上擋：有空格就 disable 主要按鈕，並在該格底下寫缺什麼、提示「填不出來就點『不知道』，
  先用假設值往下走」。**不要 alert、不要送出去等 400。**
- 文案全繁體中文、不出現英文欄位名、金額一律 **NT$**。
