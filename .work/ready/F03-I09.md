# Objective

A plan becomes something that exists on a platform, through one interface with more than one
implementation. §0: it serves the **action** link; its input is the campaign's rows and the
platform's own entity list; its output is the binding columns every later number depends on; its
trace is one `ads_action` per publish and per bind, with who approved it and its sync state; it is
**core** (the interface) with **pluggable** implementations.

# Done

- `app/ads/channels.py` — the channel registry: `CHANNELS = [{key, label, adapter}]` for
  `meta`（Meta）, `google_ads`（Google Ads）, `tiktok`（TikTok）, `shopee`（蝦皮）, `momo`（momo）,
  and `connection_state(conn, org_id, brand_id, channel_key)` returning `connected` / `未接上`.
  Only `meta` can be connected (via `app/meta/repository.py::bound_account_ids_for_brand`); every
  other channel reports 未接上 from data, not from a hard-coded screen string. No platform-specific
  branch outside this file.
- `app/ads/adapters/__init__.py` — the interface, three methods and nothing else:
  `describe(campaign) -> dict` (what the user must do / what will happen),
  `publish(conn, …, campaign_id, actor) -> dict`, `bind(conn, …, campaign_id, actor) -> dict`.
  `get_adapter(name)` returns `manual` or `simulated` (F03-I10); `auto_meta` is registered as a
  reserved third that raises a readable 「自動發布未接上」 — reserved, never phrased as a refusal,
  and nothing anywhere asks the user to run live ads.
- `app/ads/adapters/manual.py`:
  - `describe` → the checklist 逐節點, **starting with the campaign node itself** (its name and
    objective), then each group, then each ad: the exact strings the user copies (name, daily
    budget, dates, the selected copy and image prompt when the workbench has them), in platform
    order, plus the one-line reason each field matters. No field the platform does not accept.
  - `bind` → exact-name matching through `app/meta/repository.py`, **top down, because the lookups
    are hierarchical**: `campaign_ids_by_exact_name(conn, org_id, ad_account_ids, name)` binds the
    campaign node first, then `ad_set_ids_by_exact_name(conn, org_id, <bound campaign id>, name)`
    per group, then `ad_ids_by_exact_name(conn, org_id, <bound ad-set id>, name)` per ad. A level
    whose parent did not bind is not compared at all. It writes
    `external_id` / `external_name` / `external_status` / `local_state='bound'` / `bound_at` on the
    matched rows (`ads_campaign` included — F03-I01 gives it the same columns) and leaves the rest
    `unbound`. The failure wording rules of
    `app/schedule/binding.py` are reused **as behaviour, re-implemented here** (do not import it):
    no account bound → that message alone, verbatim in meaning 「還沒綁廣告帳戶：到「設定 → Meta
    廣告連線」貼權杖並勾選這個品牌，再回來配對。」; otherwise one message for the batch naming each
    node that did not match, deduplicated, ending with the 「名稱要一字不差」 sentence; a parent that
    did not match means its children were not compared, and the message says so.
  - The approval is written on **every** manual publish, never conditionally: `scope_type =
    plan.APPROVAL_SCOPE_TYPE` (imported, not a literal), `scope_ref` = the campaign id,
    `max_daily_amount` = the sum of group daily budgets, `amount` = `budget_total` when the
    campaign has a period and the same daily sum when it does not (`_budget_total` returns `None`
    whenever a date is missing, and campaign dates are optional at creation — a dateless campaign
    must still be approved, not silently published).
  - **The ceiling is per campaign.** `app/core/approval.py::latest()` ignores `scope_ref` on
    purpose (schedule trees re-sign a whole new row each time). This issue is the first writer of
    an `ads_campaign` approval, so `app/ads/plan.py::_check_budget_ceiling` stops being inert the
    moment it lands, and without a `scope_ref` filter campaign A's approval judges campaign B's
    budget edits. Add an **optional** `scope_ref: str | None = None` to `latest()` (default =
    today's behaviour, so `app/schedule` is untouched) and pass the campaign id from
    `_check_budget_ceiling`. Do not change what schedule sees.
  - `publish` on the manual adapter does not create anything on the platform: it records the intent
    (`ads_action kind='publish'`, `sync_state='pending_manual'`) and returns the checklist. `bind`
    writes one `ads_action kind='bind'` per matched row with `platform_ref` = the external id and
    `sync_state='confirmed_manual'`; the campaign moves `ready → live` only when the campaign node,
    every group and every ad is bound — and only **from `ready`**: any other status (notably
    `closed`) is left alone, re-binding never revives a closed campaign.
- `app/ads/routes.py`: `GET .../campaigns/{id}/publish` (adapter list + the chosen adapter's
  `describe`), `POST .../campaigns/{id}/publish` (body `{adapter}`), `POST .../campaigns/{id}/bind`.
  `adsApi.ts` gains the types and calls. **Both verbs return the same `describe` shape**: the
  checklist is built once in the route from the workbench-enriched campaign
  (`_enriched_campaign`), so `POST` does not silently drop `copy_text` / `image_prompt_text`
  the way `GET` returns them.
- `app/tests/test_ads_publish_manual.py` (the falsifier, Meta faked at the `graph` boundary the way
  `app/tools/simulate_meta_spend.py` does it): with no bound account the bind result is exactly the
  no-account message and nothing else; a campaign node that does not match means no group or ad is
  compared and the message says so; with the campaign matched and two of three group names matching,
  the two are bound, the third is named in the message, and the campaign stays `ready`; when all
  match the campaign is `live` and there is one `bind` action per row (campaign node included);
  `auto_meta` returns 未接上 without raising a 500; the checklist contains the campaign node plus
  every group and ad name exactly once; **one manual publish writes exactly one `approval` row**
  with `scope_type = plan.APPROVAL_SCOPE_TYPE`, `scope_ref` = the campaign id and
  `max_daily_amount` = the group daily sum, and it still does so for a campaign with no dates;
  **after publishing campaign A, a group budget edit on campaign B of the same brand is judged by
  B's own approval (or by none), never by A's**.
