# Objective
A platform read has one outcome that the sync writes and every screen reads (feature Contract O; audit W9; triage #2, #14, #17,
frontend-ads F4; drill-11 R3 M1-c). Today the outcome lives in three layers (job status, job `error`, task `errors`) and every
poller reads `job.error`, which only the runtime's fallback writes, so a half-failed 重新讀取 ends silently.

# Done
1. `external_sync.outcome(tasks, *, campaign_id=None)` per Contract O (states, code priority, `SYNC_TEXT`／`SYNC_REASONS` in
   this module, one sentence per `SourceReadError` code the adapters raise plus `no_rows`). `_save_page`／`_save_monthly` count
   saved rows into the task (`rows`, reset with a new generation).
2. `_update_task` writes `status ∈ {pending, succeeded, partial, failed}` and `error` = the job-wide outcome text when
   partial／failed, else NULL. `external_sync.record_request_failure(conn, org, brand, platform, account, code)` replaces the
   runtime's own backoff INSERT (`runtime.py:133-145`); `runtime._sources` reads `outcome(..., campaign_id=…)` instead of its own
   sentence. `connections` reads an account's failure through `outcome` (no direct task `errors` read); its monthly coverage
   proof read stays.
3. Routes: `GET …/sync-jobs/{id}?campaign_id=` → `{job, connected, outcome}`; new `GET …/campaigns/{c}/sync-outcome` → `{state,
   code, text, job_ids, last_success_at}` (worst over the covering jobs, Contract O); `POST …/campaigns/{c}/sync` → `{job, jobs}`
   (every requested job, `job` = the first, kept for callers not yet moved); `GET …/existing-campaigns` is read-only (cached
   listing + `job` + `outcome`; an unreadable account answers 200 with cached items, `job: null`, failed outcome — never 409
   because an enqueue failed).
4. Frontend contract: `lib/adsExternalApi.ts` types (`SyncOutcome`, `outcome` on the job read and listing, `jobs`) and
   `syncOutcome(brand, campaign)`; `lib/adsHandoffApi.ts` `refreshHandoffSources` returns `{job, jobs}`. New
   `lib/useSyncOutcome.ts` per Contract O (polls every 3 s while `running`, aborts on unmount, `refresh()` re-reads once) with
   `useSyncOutcome.test.tsx` (running → found; partial keeps its text; failed stops polling; unmount aborts).
5. Machine checks. `test_ads_one_ruler.py`: an SQL write of `ads_external_sync_job` `error`／`status` outside `external_sync.py`
   and a read of a sync task's `errors`／`error_code` outside `external_sync.py` fail (allowlist: monthly coverage proof reads in
   `month_budget.py`／`connections.py`, which read `coverage`／`last_covered`, not errors). `oneRuler.test.ts`: `.job.status`,
   `.job.error` and `syncJob(` outside `lib/useSyncOutcome.ts` fail, allowlist today's callers (`wait/WaitPage.tsx` → F49-I10,
   `CampaignWorkspace.tsx` → F49-I09, `connections/DataConnectionsPage.tsx`／`ExistingCampaignDialog.tsx`／
   `ExternalCampaignPanel.tsx` → F49-I14) with the stale-entry test.
6. Tests: one task failed of three → `status=partial`, `error` set, `outcome.state=partial` with that task's code; all failed →
   `failed`; clean read with zero observation rows → `empty`; `sync-outcome` on a two-account draft names both jobs and the worst
   state; `existing-campaigns` on a disconnected account → 200 with cached rows; the runtime fallback writes through
   `record_request_failure`.
