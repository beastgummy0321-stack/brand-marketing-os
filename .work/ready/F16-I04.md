# Objective
Give every campaign, system-built or imported, a resolvable target cost per result. Today `success_metric` is limited to
cpa, roas, purchases (`20260913000001_ads_tables.sql:22`) and imported campaigns have none ("未設定成功條件").
# Done
- A migration widens the metric vocabulary with `cost_per_result` and stores `result_kind`, `success_target`,
  `success_basis` in break_even, trailing_30, own; existing rows keep their meaning.
- `targets.resolve(campaign)` (pure, no LLM) returns value, basis, result_kind and missing[]: break-even through the existing
  `budget.breakeven_cpa()` and `product_economics` when the objective is sales and a product is known (imported campaigns:
  explicit product choice, else missing contains "product"); trailing-30-day actual cost per result from
  `ads_external_daily`, labelled provisional; a user-set value wins when present; nothing resolvable gives value None,
  never a default number.
- `GET` and `PUT /api/ads/brands/{b}/campaigns/{c}/target` with an optimistic revision like month budget; PUT accepts
  result_kind, basis, own value, and price or variable cost only by delegating to the existing product economics write path.
- Frontend API client functions and types only; the set-target screen itself belongs to phase 2.
# Verify
Targeted tests above: sales with and without cost, engagement trailing-30, no data, imported without product, user override.
# Blocked if
Writing price or cost would require changing another module's table or public interface; then expose "missing" only and
block for a planner decision.
