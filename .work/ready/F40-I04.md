# Objective
A new campaign starts from the previous one (drill-7 #10; user ruling: pre-fill, editable, no extra question). Backend half of `#/new`.

# Done
1. `app/ads/brief.py::create_draft` (picks path and sentence path alike): before writing the draft, read the brand's latest campaign
   with `status <> 'draft'` (by `created_at desc`) and, for each of the four values the request did not supply, copy it:
   `constraints_json.platform`, `context_json.audience_hint`, `target_cost`+`target_basis` (only when the previous basis is `own`),
   and `context_json.landing_url` (previous campaign's `context_json.landing_url`, else its first group's `manual_delivery` value).
   Record `context_json.copied_from = {"campaign_id", "name", "fields": [...]}` naming what was copied, and mark those entries in
   `field_sources` as `"copied"`. Request values always win; with no previous campaign nothing changes.
2. `create_draft` accepts the four keys in `picks` (`platform`, `audience_hint`, `cap`, `landing_url`); `routes.py`'s create endpoint
   passes them through (same validation as the existing PATCH paths: platform through `channels`, cap through `targets`).
2b. The campaign PATCH that accepts `audience_hint` (`routes.py` ~line 231) also accepts `landing_url` (string or null) into
   `context_json.landing_url`, so the brief page can edit it.
3. `app/ads/manual_settings.py::handoff` — a group whose record has no `landing_url` shows the campaign's `context_json.landing_url`
   as the value with `source: "campaign"` (the group's own saved value keeps winning); the required-field check treats the
   campaign default as filled.
4. Tests: `test_ads_brief.py` — second campaign copies the four values and lists them in `copied_from.fields`; a request value
   overrides; first campaign has no `copied_from`. `test_ads_manual_settings.py` — group without landing_url reads the campaign default.
