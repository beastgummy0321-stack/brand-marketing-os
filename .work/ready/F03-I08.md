# Objective

The plan orders its artifacts and knows when they are ready. §0: it serves the **artifact** link;
its input is the `ads_ad` rows and their coordinates; its output is one 任務包 in 素材工作檯 and a
readiness state per ad that the publish checklist reads; its trace is who ticked 素材已就位 and
when, or which pack approval made it ready; it is **pluggable** — an ad can be ready without the
workbench ever being used (that is the point of the manual tick).

# Done

- `app/ads/assets.py`:
  - `dispatch_pack(conn, org_id, brand_id, campaign_id, *, actor)` → one call to
    `workbench.submit_pack` (the module's public entry, `ARCHITECTURE.md` §5.4):
    `source_kind="schedule_node"` (the DB token for 「上游派工」; it is CHECK-constrained and it is
    what §5.7 keys 變體模式 off — do not invent a new value), pack `source_ref =
    {"ads_campaign_id": <id>}`, one `sets` entry per `ads_ad` with `source_ref =
    {"ads_campaign_id": <id>, "ads_ad_id": <id>}`, `name` = the ad's tracking name, the seven
    coordinates, `product_id`, `required_outputs = {"copy": 1, "image_prompt": 1}`,
    `constraints.copy_length` from the ad's `format`/角度 the same way the old dispatch chose it,
    and `context.origin_label` / `context.origin_href` (F03-I07) — 「投放中心 → <品牌>｜<Campaign>
    → <通路標籤> → <投放組>」 and `/brands/<brand>/ads/campaigns/<id>?tab=assets`. Dispatching twice
    for the same campaign is refused with a readable message (the pack already exists).
  - `readiness(conn, org_id, brand_id, campaign_id)` → per ad
    `{ad_id, state: "ready_workbench"|"ready_manual"|"in_progress"|"not_started", pack_id,
    set_id, source, by, at}`, built from `workbench.sets_for_source(...{"ads_campaign_id": id})`
    **or** the ad's own `asset_ready_source='manual'` columns. No SQL against `workbench_*`.
  - `mark_ready(conn, …, ad_id, *, actor, ready: bool)` → sets/clears
    `asset_ready_source='manual'`, `asset_ready_by`, `asset_ready_at`. It is not an `ads_action`
    (nothing reaches a platform); it is a fact about our own row.
- `app/ads/routes.py`: `POST .../campaigns/{id}/pack` (dispatch), `GET .../campaigns/{id}/assets`
  (readiness), `POST .../ads/{ad_id}/asset-ready` (tick / untick). The campaign detail payload gains
  the readiness summary (`ready_count` / `total`) so the 素材 tab and the publish screen agree.
  `adsApi.ts` gains the types and calls.
- `app/tests/test_ads_assets.py` (the falsifier): dispatch creates one pack with one set per ad and
  the set `source_ref` carries the ad id; approving the pack in the workbench flips those ads to
  `ready_workbench`; a hand tick on a third ad gives `ready_manual` with actor and timestamp;
  untick returns it to `not_started`; readiness never reads a `workbench_*` table directly (assert
  by calling only the public entry in the test's own setup); dispatching twice is refused.

# Verify

`uv run python -m pytest app/tests/test_ads_assets.py -q` — the approval-flips-state case is the
one that proves the one-way dependency still works as a state read, not a callback.

# Blocked if

`sets_for_source` (F03-I07) does not return what readiness needs, or `submit_pack` rejects the
`context.origin_label` key. Both are that issue's contract — report the mismatch rather than reading
workbench tables or adding a column here.
