# Objective

The Campaign object exists as rows and can be read. §0: it serves the **goal → strategy → plan**
links (everything later hangs off these rows); its input is the brand/product rows that already
exist (`brand`, `product`, `product_economics` — never re-asked); its output is the JSON the five
tabs and every later issue read; its trace is that a campaign records why it exists, how it will be
judged and who created it; it is **core** — remove it and the OS has no unit of work.

This issue is the shared contract: schema, the read API and the TypeScript types, settled once so
backend and frontend issues can proceed in parallel. No UI, no writes beyond what a test needs.

# Done

- **Migration** `supabase/migrations/20260913000001_ads_tables.sql` — five tables, every one with
  `org_id` + `brand_id`, RLS enabled, `GRANT ... TO authenticated` and the org-isolation policy
  copied from `supabase/migrations/20260912000001_workbench_pack.sql`. Ids via `db.new_id` prefixes
  (`adc_`, `adg_`, `ada_`, `adx_`, `ado_`). Only `ads_*` tables — no other module's table is created
  or altered:
  - `ads_campaign`: `name`, `goal_text` (the user's sentence), `objective` (our own vocabulary, text),
    `success_metric` CHECK in (`cpa`,`roas`,`purchases`), `success_target` numeric, `success_basis`
    text, `start_date`, `end_date`, `status` CHECK in (`draft`,`ready`,`live`,`ended`,`closed`),
    `budget_planned` numeric null (**the adopted scenario amount, for the record — never
    recomputed**; the total on screen is `sum(group.daily_budget) × days`, derived in the
    repository, and the two are allowed to differ by less than a day's rounding),
    `budget_scenario` text null, `budget_basis_json`, the same four binding columns as the other
    two levels (`external_id`, `external_name`, `external_status`, `local_state`, `bound_at`) —
    the campaign node is bound first because Meta's lookups are hierarchical, `context_json`
    (the ids of the brand/product/learning rows the draft was derived from, never copies of them),
    `constraints_json`, `verdict` text null, `verdict_json`, `closed_at`, `created_by`, timestamps.
  - `ads_delivery_group`: `campaign_id` FK, `channel_key` text (`meta`/`google_ads`/`tiktok`/…, no
    platform-specific column anywhere), `name`, `role` CHECK in (`new`,`retarget`,`explore`),
    `daily_budget` numeric, `start_date`/`end_date` null, `external_id`, `external_name`,
    `external_status`, `local_state` CHECK in (`unbound`,`bound`,`detached`,`retired`) default
    `unbound`, `bound_at`, timestamps.
  - `ads_ad`: `campaign_id` FK, `group_id` FK, `name` (the tracking name), the seven coordinate
    columns (`audience_key` … `format_key`) plus `coordinates_snapshot_json`, `product_id` null,
    the same four binding columns + `local_state`, `asset_ready_source` CHECK in
    (`workbench`,`manual`) null, `asset_ready_by`, `asset_ready_at`, timestamps. **No budget column
    at the ad level** (F03 decision 7).
  - `ads_action`: `campaign_id` FK, `target_kind` CHECK in (`campaign`,`group`,`ad`), `target_id`,
    `kind` CHECK in (`publish`,`bind`,`budget`,`date`,`pause`,`creative`), `before_json`,
    `after_json`, `approved_by`, `approved_at`, `sync_state` CHECK in
    (`pending_manual`,`confirmed_manual`,`auto_synced`), `platform_ref` null,
    `reverses_action_id` null, `created_at`.
  - `ads_outcome_daily`: `campaign_id` FK, `entity_kind` CHECK in (`group`,`ad`), `entity_id`,
    `day` date, `spend`, `impressions`, `clicks`, `purchases`, `revenue`, `currency`,
    `source` CHECK in (`meta`,`simulated`), `created_at`; `UNIQUE (entity_kind, entity_id, day)`.
- **`app/ads/__init__.py`** — the single public entry, docstring in the shape of
  `app/workbench/__init__.py`: `register(app)` only for now (mounts `/api/ads/*`), plus the sentence
  that everything else in the package is private and which legacy facades this module is allowed to
  reach (`ARCHITECTURE.md` §2). Register in `app/main.py`'s loop next to `schedule`/`workbench`
  (one line, same pattern, nothing else in that file changes).
- **`app/ads/repository.py`** — raw SQL, `org_id`+`brand_id` on every query: `create_campaign`,
  `get_campaign`, `list_campaigns`, `campaign_detail` (campaign + groups + ads + latest actions +
  outcome totals, one dict), and `app.core.cleanup` registration at the module tail (「投放中心」,
  brand dimension; product dimension explicitly `None`) so brand deletion cascades.
  `campaign_detail` and `list_campaigns` are the **one** place `budget_total` is derived
  (`sum(group.daily_budget) × days`); no screen and no other function recomputes it.
- **`app/ads/routes.py`** — `GET /api/ads/brands/{brand_id}/campaigns` (list: id, name, status,
  dates, objective, `budget_planned`, the derived `budget_total`, one outcome summary) and
  `GET /api/ads/brands/{brand_id}/campaigns/{campaign_id}` (the workspace payload). `require_brand`
  + `conn` exactly as `app/workbench/routes.py` does it. Read-only; writes arrive in later issues.
- **`frontend/src/lib/adsApi.ts`** — the types for both payloads and the two fetch functions, same
  shape and error handling as `workbenchApi.ts`. This file is the frontend contract; later issues
  extend it, never re-shape it.
- **`app/tests/test_ads_model.py`** (the falsifier): a campaign with groups and ads round-trips
  through `campaign_detail`; a second brand's campaign never appears in the first brand's list
  (tenant isolation); `ads_outcome_daily`'s unique key rejects a duplicate (entity, day); an ad
  cannot be created with a budget field (there is none) and a group's `daily_budget` survives;
  changing a group's `daily_budget` changes the derived `budget_total` and leaves `budget_planned`
  exactly as it was.
