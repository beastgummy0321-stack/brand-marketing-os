# Objective
Strategy tab: the one cap block and the budget scenarios against the budget cap. Spec: prototype `targetBlock()`, `budgetBlock()`, `allocBlock()` in `tabStrategy()`, hashes `camp/daily/strategy` and `camp/fall/strategy`, demos `over` and `tgt:none` (Feature "Screens"). The workspace header/rail/tabs are not part of this issue.

# Done
1. Cap block: shows own cap／暫用打平／沒設上限 states; integer NT$ input saved through the existing target PUT (revision guard, 409 → reload message); 用打平 X; 去填商品成本 link when `missing` has product_cost; ROAS 參考 = price ÷ cap only when both known; mid ruler from the campaign's triage items (empty for drafts). Product and result-kind choice for campaigns without a product sit in the block's fold. Imported campaigns show the block too.
2. Budget scenarios (internal campaigns): rows from the API, 推薦 tag on `recommended`, over-cap rows not preselected and marked with the amount over; choosing one opens the confirm sheet; confirming sends `confirm_over_cap: true`; save stays disabled while the sheet is open. Nothing is preselected or saved that the user did not choose (§1.7 item 3).
3. Budget cap is editable in place: the 「你的預算上限 X」 chip on the budget card has an 「改上限」 action that opens an inline integer field (save / cancel; empty = clear the cap) calling `setBudgetCap`. After saving, the scenarios reload; a saved scenario that is now over the cap shows its over-cap mark and nothing is re-chosen automatically. There is no toast placeholder.
4. `/campaigns/:id/target` redirects to `?tab=strategy`; `CampaignTargetPage` and its test are deleted; `ads-target.spec.ts` now covers the cap block (set, reload, 暫用打平, no cost); `ads-cold-start.spec.ts` follows the new labels.
5. Evidence per Feature "Screens" (app `brands/brd_bughunt/ads/campaigns/<id>?tab=strategy`, port 8740), no one-sided piece; §1.7 self-check.
