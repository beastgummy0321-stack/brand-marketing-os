# Objective
Every ads background job ends failed, empty or done with a code instead of a quiet success, and the model's own error survives to
the screen (feature Contract J, per-job table; audit W14; triage #3; slots #7, #9, #13; drill-11 R3 M1-c 「鈴鐺失敗數未增加」).
Today a sync whose tasks failed, a runtime tick that crashed, a brand whose accounts could not be read and a daily queue refresh
that threw all end as succeeded jobs; a refused／timed-out 補文案 batch says one generic sentence; an angle with no row re-queues on
every page load; a deleted original is told to retry.

# Done
1. `external_sync.run_sync` returns per Contract O's job-wide outcome (F49): failed／partial → `Failed(code, text)`, empty →
   `Empty("no_rows")`, found → done; the job row keeps what F49 writes.
2. `runtime.run_campaign`: a swallowed exception still writes its health row, then the handler returns `Failed("runtime_error",
   text)`; `runtime.py` logs it (it imports no logger today). `_sync_brand_accounts` records an unreadable account through
   `external_sync.record_request_failure` (the month budget's 「餘額不確定」 then has a reason) and never `continue`s silently.
3. Dispatchers: `ads.queue_refresh_daily` enqueues one `background.ads_queue_refresh` job per (org, brand) through
   `background.register` (the per-brand refresh + digest runs there; its failure fails that job); `routes_jobs_api.TASK_KINDS`
   names it (「整理今天的待辦中」). Other dispatchers (`ads.runtime_dispatch`, `ads.external_pending`, `ads.external_daily`,
   `ads.close_expired_dispatch`, `ads.user_asset_pending`, `ads.asset_suggestion_pending`) let their own failure raise.
4. `user_assets.process_preview`: `retryable` → `Failed("preview_retry", error)`; `storage.NotFound` → asset `status='error'` with
   「原檔不存在，請重新上傳。」 at once (no retries) and `Failed("original_missing")`; `GET …/content` on a missing object → 404 with the
   same sentence (today 502 「稍後重試」).
5. `asset_suggestions`: a batch whose task did not succeed serves the task's `error` and `error_code` (no generic sentence
   overwrites it; `get_batch` joins `llm_task_id`); a batch marked `unknown` by `dispatch_pending` settles its reservation;
   handler outcome = `Failed(error_code)` on a failed task. `lib/adsUserAssetsApi.ts` types `error_code` (optional).
6. `angles`: when `run` writes no row (entity gone, copy changed) it returns `Empty("nothing_to_judge")`; `GET …/angles` reads
   `background.outcome(lock)` — running → pending, failed → failed with text, empty → 「這則廣告已經不在，或文案改過了，沒有可以判讀的主打。」 —
   and enqueues only when no job for the lock exists.
7. Tests: a sync with one failed task → procrastinate failed + result `failed` with Contract O's code; a sync with zero rows →
   `empty`; `run_campaign` with a raising readback → failed + log; a queue refresh raising for brand A does not stop brand B and
   fails A's job; NotFound → asset error immediately; a provider refusal reaches the batch as `refused`; GET angles twice with a
   finished empty job enqueues nothing.
