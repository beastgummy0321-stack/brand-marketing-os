# Objective

One sentence becomes a draft Campaign that knows why it exists and how it will be judged. §0: it
serves the **goal** link; its input is the user's sentence plus the brand facts, products and
product economics that already exist (it never asks the user to re-enter them); its output is an
`ads_campaign` row the strategy task reads; its trace is `goal_text` verbatim, the `llm_task` row
and `context_json` naming which rows it used; it is **core**.

# Done

- `app/departments/ads/brief_parse.md` — one new department task file (F03 allows three). Input:
  the sentence, the dates, the optional constraints, the brand's confirmed facts and its product
  list with prices. Output JSON only: `{objective, success_metric, success_target, success_basis,
  product_ids, audience_hint, notes}`. `objective` is **our** vocabulary (`購買`／`加購物車`／
  `名單`／`流量`／`知名度`), never a platform constant. `success_target` must be a number the model
  can defend from the numbers it was given; when it cannot, it returns `null` and says why in
  `success_basis` — a null target is a legitimate answer, a made-up one is not.
- `app/ads/brief.py` — `create_draft(conn, org_id, brand_id, *, goal_text, start_date, end_date,
  constraints, actor)`:
  1. builds the context with `app/llm/context_compiler.py` (brand facts with their `updated_at`)
     plus the brand's products and today's effective `product_economics` (via
     `brand_intelligence.repository.get_product_economics`; a price whose effective window has
     passed is passed in **labelled stale**, never silently reused),
  2. calls `app/llm/gateway.py::run_task` (`task_type="ads_brief_parse"`, `campaign_period_id=None`),
  3. writes one `ads_campaign` row in `status='draft'` with `goal_text` verbatim, the parsed fields,
     `context_json = {brand_version, product_ids, economics_ids, llm_task_id}`, `constraints_json`,
  4. **never dead-ends**: a failed, timed-out or unparseable call still writes the draft with
     `objective='購買'`, `success_metric='roas'`, `success_target=null`, `success_basis` explaining
     that the sentence could not be parsed, and the response carries `parsed: false` — same rule as
     the workbench's `free_parse` (`ARCHITECTURE.md` §5.12).
- `app/ads/routes.py` — `POST /api/ads/brands/{brand_id}/campaigns` (body: `goal_text`,
  `start_date`, `end_date`, `constraints`) returning the created campaign detail, and
  `PATCH .../campaigns/{campaign_id}` for the fields the user may correct on screen (`name`,
  `objective`, `success_metric`, `success_target`, `success_basis`, dates, `constraints_json`,
  `context_json.product_ids`). The patch is plain editing of a draft — it is not an `ads_action`
  (nothing is bound to a platform yet).
- `frontend/src/lib/adsApi.ts` — types and functions for both calls; no UI.
- `app/tests/test_ads_brief.py` (the falsifier, fake provider as `test_schedule.py` does it):
  a parsed reply produces a draft whose `goal_text` is the user's sentence unchanged and whose
  `context_json` names the product rows used; a provider failure still produces a usable draft with
  `parsed: false` and no exception; a target the model returns as `null` survives as `null` (nothing
  fills it in); dates outside `start <= end` are refused with a readable message.

# Verify

`uv run python -m pytest app/tests/test_ads_brief.py -q` — it fails if the draft ever loses the
user's sentence, invents a target, or dead-ends on a provider error.

# Blocked if

`context_compiler.compile()` cannot be called for a brand that has no confirmed facts (a brand new
brand must still be able to create a campaign). Report the signature you found; do not write your
own context assembly.
