# Objective

The machine acceptance for the four new screens, replacing the assertions that described the retired
workbench page. One walk, the cheapest one that fails if the feature is broken: a brand with no pack
→ create a free job → see it on the 入口 → open the pack → open a set → open the 圖片 tab.

**Scope ruling (F02 Decisions, "e2e asserts only what runs with no worker and no provider key",
2026-09-12 — this replaces the blocked version of this issue).** `npm run e2e` starts uvicorn only;
`python -m app.worker` is the only thing that runs procrastinate jobs and nothing starts it here, so
no `workbench_output` row can ever exist during this walk. **Do not start a worker, do not edit
`playwright.config.ts`, do not seed a version row, do not assert on any generated version** — the
圖片 tab legitimately shows the 還沒有生成過 empty state in this walk. Prompt cards, the
顯示提示詞 before/after view and the 席位保留 line are F02-I13's component test, not this issue's.

# Done

- `frontend/e2e/smoke.spec.ts`: the transitional 素材工作檯 heading check becomes the real walk —
  入口 heading, empty state 「目前沒有任務包」, 「＋ 自由創作」 opens `…/workbench/new`; the
  two-click flow (pick 圖片 as the 素材類型 so the created pack requires `image_prompt`) creates
  自由工作 #1 and lands on the pack page (rail 任務包, 總覽, 完成進度, 素材組進度); the set row opens
  the studio, whose tabs are that set's required types and whose 圖片 tab shows the 顯示提示詞
  button and the 還沒有生成過 empty state.
- **One API-owned string is asserted on screen** (F02 Decisions — `未生成` appears nowhere under
  `frontend/src`, so seeing it in the browser can only have come from `cells[].text`): in the fresh
  pack's 素材組進度 table the set row's 圖片 cell reads 未生成.
  **Do not assert 「—」 anywhere** (F02 Decisions, 2026-09-12 — this replaces the blocked version of
  this issue): the table renders one column per part the pack requires, so a fresh free-job pack has
  a 圖片 column and nothing else, and no 「—」 cell exists to see. The API half of that text is proven
  in `app/tests/test_workbench_pack.py:163` and `app/tests/test_workbench_pack_api.py:299`; a 「—」 on
  screen would not prove it anyway, because `PackPage.tsx` falls back to the same literal when a cell
  is missing. Do not add the missing columns to `PackPage.tsx` — that is a rejected option, not a
  blocked-on dependency.
- The free job is created through the real 「建立自由工作」 click, so F02-I06's one model call runs
  against whatever provider the e2e backend has — **in CI it has none** (the 8720 backend boots with
  no `.env`, see `.github/workflows/ci.yml`), so the call fails and the page must fall through to
  `parsed: false` and keep going. Assert that the 「AI 解析結果」 table and 「確認並生成」 appear,
  never on a parsed value: this walk is exactly the falsifier for 「a failed parse is not a dead
  end」, and it is why CI never spends on this spec.
- **The bug this walk already found, fixed in F02-I14 (2026-09-12): `parseFreeText` did not unwrap
  `{parse: …}`, so `spec` was `undefined` and 「確認並生成」 never appeared.** The walk must reach
  that second button, click it, and land on the created pack — if it stops at the first click again,
  that is a red test, not a scope question.
- Assert on what the user sees (headings, button names, cell text), not on class names — the old
  block's `.workspace-subnav` locator is exactly the kind of assertion that outlives its screen.
- `frontend/e2e/width-overflow.spec.ts`: the existing workbench route check plus the three new
  routes (`…/workbench/new`, `…/workbench/packs/:packId`, `…/workbench/packs/:packId/sets/:setId`)
  using a pack created the same way.
- No `frontend/src` change. If a spec cannot see something it needs, that is a bug in the screen —
  report it, do not add a test id by editing the component from this issue.
- Nothing in any spec name, comment or assertion refers to running live ads.

# Verify

`cd frontend && npm run e2e` — it starts its own backend on 8720 (`supabase start` must be up), which
is why acceptance is never judged on the long-running 8710 process. Port 8720 is global: this issue
and its merge must run with no other `npm run e2e` in flight, or Playwright dies with
「http://localhost:8720 is already used」 — a scheduling collision, never a red test.

# Blocked if

An assertion listed above turns out to need a `workbench_output` row after all, or a string listed
above is not on screen because the component does not render it. Say which one and stop — the rulings
above are that a version-dependent assertion belongs to F02-I13, and that a missing column is a
screen decision for the planner, not a `frontend/src` edit from here.
