# Objective

系統現在只算得出「商品」的一次轉換值多少錢：`breakeven_cpa = 售價 − 單位變動成本 − 運費`
（`app/ads/budget.py:32-44`）。服務／名單型的生意沒有地方放「一筆名單值多少錢」，所以整條預算
引擎對它們回 `None`，策略頁三張情境卡全印「累積中」。

這張票只做**一個形狀**（`ARCHITECTURE.md` §8 第 1 條，已定案，不要重新設計）：

> 一次轉換的價值 = `(售價 − 單位變動成本 − 運費) × 成交率`，成交率是 `product_economics` 新的
> 可空欄位 `close_rate`。`close_rate` 是 NULL 就代表「一次轉換就是一次成交」——商品列的算法與
> 這張票之前**逐位元相同**。

不開新表、不開第二支 API、不為服務另做一套欄位。後面所有的票（精靈步驟 3、預算、結案）都吃這
一個形狀。

# Done

## 1. Migration（新檔，不改已套用的檔）

`supabase/migrations/20260914000001_brand_intelligence_product_economics_close_rate.sql`：

```sql
ALTER TABLE product_economics ADD COLUMN close_rate numeric(6,4)
    CHECK (close_rate IS NULL OR (close_rate > 0 AND close_rate <= 1));
ALTER TABLE product_economics_version ADD COLUMN close_rate numeric(6,4)
    CHECK (close_rate IS NULL OR (close_rate > 0 AND close_rate <= 1));
```

兩張都要加：成交率會變，而 `product_economics_version`（`supabase/migrations/
20260903000004_brand_intelligence_product_economics_version.sql`）存在的理由就是「成本一改就是
新的一版」。欄位註解一句：`-- 成交率；NULL = 一次轉換就是一次成交（商品）`。

## 2. `app/brand_intelligence/repository.py`

- `save_product_economics`（`:715`）多收一個關鍵字參數 `close_rate: float | None = None`，寫進
  `product_economics` 那一列，也寫進它同一筆交易裡 INSERT 的 `product_economics_version`
  （兩處都要，不然版本表會少一欄真相）。
- `get_product_economics` 不必改（`SELECT *`）。
- 值域檢查放在這裡（唯一寫入者）：`close_rate` 不是 None 時必須 `0 < x <= 1`，否則
  `raise ValueError("product_economics.close_rate 必須介於 0 與 1 之間")`——比照檔案裡既有的
  `_require` 風格。

## 3. `app/ads/budget.py::breakeven_cpa`

```python
    shipping = economics.get("shipping_cost") or 0
    value = float(price) - float(unit_cost) - float(shipping)
    close_rate = economics.get("close_rate")
    return value if close_rate is None else value * float(close_rate)
```

docstring 補一句：「打平 CPA＝一次轉換的價值；服務／名單型的列帶 `close_rate`（成交率），商品列
不帶（NULL＝×1）」。**`unit_variable_cost` 是 None 就回 None 這條不變**——不知道的成本永遠不准
猜（既有 Blocked-if）。

## 4. 商品頁的經濟數字表單也要看得到它

不然精靈填下去的成交率就是一個只能寫一次、之後誰都改不了的欄位。

- `app/brand_web/routes_products.py:459-485`（`economics_save`）多讀一個可空欄位
  `close_rate`：空字串／缺欄＝`None`；填了但不是 0–1 的數字 → `_error(400, "成交率請填 0 到 1
  之間的數字，例如 0.2 代表五筆名單成交一筆。")`，然後原樣傳給 `save_product_economics`。
- `frontend/src/lib/productsApi.ts`：型別與送出的 body 補 `close_rate: number | null`。
- `EconomicsPanel.tsx`／`EconomicsTab.tsx`：多一格「成交率（選填）」，說明一句
  「留空＝賣一次算一次轉換。填了才是名單型：0.2 代表五筆名單成交一筆。」顯示時沒有值就印
  「未設定」，**不要印 0 或「—」**（`docs/design-system.md` 的誠實空狀態）。

## 5. 測試（`app/tests/test_ads_budget.py`，既有檔，照它現有的寫法加）

三個 case，跑得起來就算數，不要開新框架：
- `close_rate` 是 None → `breakeven_cpa` 與這張票之前的數字**完全相同**（拿檔案裡既有的那組
  數字當基準）。
- `close_rate = 0.2`、售價 5000／成本 1000／運費 0 → `800.0`。
- `close_rate` 存進去再讀出來（`save_product_economics` → `get_product_economics`）值還在，
  而且 `product_economics_version` 的最新一版也有同一個值。

# 為什麼 `legacy_migration: true`

`app/brand_intelligence/**` 與 `app/brand_web/**` 是 legacy。這張票**沒有**在 legacy 裡長新能力：
`product_economics` 的擁有權本來就在 `brand_intelligence`（`ARCHITECTURE.md` §3 明寫「一次轉換的
價值只有一個家」），`save_product_economics` 本來就是宣告過的 facade，這裡只是給它多一個參數——
跟 F03 給同一個 facade 加 `record_learning`／`list_learnings` 是同一種動作。新東西（精靈、檢查表）
一個字都不在 legacy 裡。
