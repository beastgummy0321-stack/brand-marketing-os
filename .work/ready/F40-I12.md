# Objective
The new-campaign form opens pre-filled from the previous campaign (drill-7 #10). Reference: prototype `#/new` — the purple bar
「照上一期「〈name〉」帶入，可改」 + 「清空重填」, the new block 「這次怎麼投」 (平台 / 受眾方向 / 每賣一筆上限 with the 打平線 hint / 落地頁 with the
「從「追蹤」分頁搬來」 tag) in the main form, 期間 defaulting to the day after the previous end date, the 進階 fold unchanged.

# Done
1. `adsApi.ts`: `createCampaignFromPicks` body accepts `platform`, `audience_hint`, `cap`, `landing_url`; `CampaignDetail.context_json`
   types `copied_from` and `landing_url`. A read of the previous campaign for prefill: use the campaign list (`listCampaigns`) sorted
   by `created_at` and the detail of the latest non-draft one; no new endpoint.
2. `NewCampaignPage.tsx`: on open, if a previous non-draft campaign exists, prefill the four fields (+ product and objective from it
   when the draft key has nothing) and show the bar; 「清空重填」 empties the four fields, hides the bar and disables 下一步 until
   required fields are set. The four fields render in the main form under 「這次怎麼投」 as in the prototype; the cap hint prints
   「上一期 N・比打平線 M 低／高 D」 when the product's break-even is known (from the product card data already on the page). Submit sends
   the four keys; the server copies anything left empty (I04).
3. `ConfirmBriefPage.tsx`: 落地頁 shows in its main block (it edits `context_json.landing_url` through the campaign PATCH the page
   already uses for `audience_hint`) with the 「從「追蹤」分頁搬來」 tag; nothing removed from the 追蹤 tab.
4. Tests: `NewCampaignPage.test.tsx` — with a previous campaign the bar and the four values render, 清空重填 empties them, submit body
   carries the four keys; without one the form is as today. `ConfirmBriefPage.test.tsx` — landing URL edit PATCHes `landing_url`.
