4. Facade (`app/brand_intelligence/repository.py`), each with a docstring naming its readers:
   - `save_sell_way(conn, brand_id, *, sell_way_id=None, name, components: [{product_id, qty}], economics: {selling_price, list_price,
     unit_variable_cost, shipping_cost, close_rate, cap_per_sale}, landing_url, actor)`: one component on a knowledge product → a
     single-product sell-way (`parent_id` = it, name 「〈商品〉 · 〈賣法〉」); several → a bundle (`parent_id` NULL). Writes the product
     row, the component rows (full list) and the economics through `save_product_economics`. Components must be knowledge products of
     the same brand. `list_sell_ways(conn, brand_id, product_id=None)`.
   - `knowledge_product_ids(conn, brand_id, product_id) -> list[str]` (components in creation order; a row without components →
     `[COALESCE(parent_id, id)]`). `knowledge_product_id` stays as `ids[0]` for now (F43-I02/I03 move the callers).
   - `get_product_economics` returns effective values: `list_price` NULL → Σ(qty × each component's qty-1 sell-way price); a
     bundle's `unit_variable_cost` NULL → Σ(qty × single cost); unknown part → stays NULL; `derived_fields` lists what was filled.
     Raw values stay available to the editor (`raw=True` or a sibling function).
   - `list_customer_groups(conn, brand_id, product_id)` / `save_customer_groups(...)` (full list, ≤3, positions 1..n).
   - `available_proof_keys(conn, brand_id, product_id=None)` adds confirmed product proof keys of the knowledge products.
   - `available_offer_keys(conn, brand_id, product_id=None)` adds the sell-way's own offer: effective `list_price` > `selling_price`
     → `bundle` when Σqty > 1 or several components, else `discount`. `offer_sources` (F42-I01) adds the sell-way's own row with the sentence
     「〈賣法名〉優惠價 NT$〈售價〉（原價 NT$〈原價〉）」, so the copy guard and 「這期會用」 pick it up without changes.
   - `set_product_onboarding_step(conn, brand_id, product_id, step|None, *, actor)`; brand/product delete cleanup covers the new
     tables.
