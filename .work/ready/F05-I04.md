# Objective

因果鏈（已查證，工人不必再找）：建檔精靈把使用者打的「薑黃錠售價 1200 成本 380」存成
`product_fact` 的自由文字 → `save_product_economics`（`app/brand_intelligence/repository.py:715`）
全專案只有商品詳情頁 `app/brand_web/routes_products.py:479` 一個呼叫端 → `product_economics` 空 →
`app/ads/budget.py::breakeven_cpa` 回 None → 策略頁三張情境卡金額全 null。**每一個新品牌都會走到
這裡**，除非有人自己想到去開商品頁補。實測：常春健康完成建檔、11 條事實，`product_economics`
0 列。

這張票在精靈裡插一個新步驟，把「賣什麼」與「數字」做成結構化欄位，送出走既有的
`save_product_economics`。使用者的話：「品牌也沒有強制 sku 組數或金額等……我需要一開始就把地基
打好而不是現在東缺西缺。」

## 2. 後端：新檔 `app/intake/routes_offerings_api.py`

`routes_api.py` 已經 716／800 行，**新東西一律開新小檔**（既有慣例：`routes_t2_api.py`）。
在 `routes_api.py` 檔尾照 `t2_router` 那兩行的寫法把新 router 併進來。

兩支端點（信封照 `routes_api.py` 既有的 `_envelope`／`_error`）：

- `GET /api/intake/brands/{brand_id}/offerings` → `{"data": {"offerings": [...]}}`
  每一項：`{"product_id", "name", "selling_price", "unit_variable_cost", "shipping_cost",
  "close_rate", "currency"}`。資料來源：`bi_repo.list_products` ＋ 每項的
  `bi_repo.get_product_economics`（沒有經濟數字的商品也要出現，數字是 `null`——初掃建的商品要能
  在這一格被補完）。
- `POST /api/intake/brands/{brand_id}/offerings`
  body：`{"offerings": [{"product_id"?, "name", "selling_price", "unit_variable_cost",
  "shipping_cost", "close_rate"?}]}`
  - `product_id` 缺 → `bi_repo.create_product`；有 → 用既有那一列。
  - 三個數字都是**必填**（`shipping_cost` 可以是 0，但不可以空白）；缺一個回 400，訊息指名是哪
    一項的哪一欄：「「薑黃錠」的運費請填數字，沒有運費就填 0。」
  - `close_rate` 選填；填了必須 0 < x ≤ 1。
  - 逐項呼叫 `bi_repo.save_product_economics(..., actor=..., currency="TWD",
    confirmed_by=str(actor.user_id), close_rate=...)`。**不要自己寫 SQL**，`product_economics`
    是 `brand_intelligence` 的表（`ARCHITECTURE.md` §3）。
  - 空清單直接 400：「至少要有一項要賣的東西。」
  - 成功回 204，並 `state.touch(draft, f"/brands/{brand_id}/intake/offerings", 3)`。

## 3. 前端：`steps/OfferingsStep.tsx`（新檔）

版面**沿用既有精靈步驟的樣子**（`frontend/src/components/intake/steps/ScanStep.tsx`／
`StartStep.tsx` 是參考，`docs/design-system.md` 是規則）。寫這一頁之前先叫
`Skill impeccable:impeccable`。

- 最上面一個問題：**「你賣的是什麼？」** 三顆單選：`商品`／`服務`／`兩者都有`。
  這是**畫面上的控制項，不存任何欄位**（`ARCHITECTURE.md` §8 第 1 條）。重新進到這一步時，
  預設值從既有的 offering 列反推：有 `close_rate` 的＝服務、沒有的＝商品、兩種都有＝兩者都有、
  一項都沒有＝不預選。
- 選了才顯示下面的列表（沒選就只有那個問題，乾淨）。
  - 商品列：品名／售價／單位成本／運費，四格都要填，運費旁邊一句「沒有運費就填 0」。
  - 服務列：品名／成交價／單位成本／成交率，運費自動填 0 不顯示；成交率那格的說明
    「0.2 代表五筆名單成交一筆」。下面即時算出一行灰字：「一筆名單值 NT$800」＝
    `(成交價 − 成本) × 成交率`，四捨五入到元。
  - 「兩者都有」＝兩塊都出現，各自可以加列。
- 「＋ 再加一項」可以無限加；初掃猜到的商品名要**預先帶進來**（`GET /offerings` 已經回了）。
- 送出前在畫面上擋：有任何一格空白就 disable 主要按鈕，並在那一格底下寫缺什麼。**不要用
  alert、不要送出去等 400。**
- 文案全繁體中文、不出現英文欄位名；數字旁邊要有幣別。

`frontend/src/lib/intakeApi.ts`：型別 ＋ `fetchOfferings` / `saveOfferings`。
