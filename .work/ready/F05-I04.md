# Objective

演練四三個人裡有兩個走到第七站才發現地基是空的（小杰的品牌 `product` 0 列、`brand_fact` 0 列，系統
零提醒；他貼了權杖沒把帳戶指定給品牌，畫面給綠勾，到配對才爆）。成因是**沒有任何一處定義「一個品牌
要能投放，最少要有什麼」**——沒有前提就沒有東西可以檢查。

這張票做那個定義，一次、一支函式、程式算，而且**有三種顏色**：綠（真實數字）／黃（成立但站在假設值
或還在補的資料上）／紅（缺）。定義在 `ARCHITECTURE.md` §8 第 5 條，已定案。
接到畫面上是 F05-I10 的事。

## 2. `app/ads/readiness.py`（新檔）

```python
def launch_readiness(conn, org_id: str, brand_id: str) -> dict
```
回傳（欄位名就是這些，前端照抄）：

```python
{
  "state": "green"|"yellow"|"red",        # 三列裡最差的那個
  "items": [ {"key","label","state","reason","fix_label","fix_href"} ],   # 固定三列固定順序
  "notes": [ {"key": "knowledge", "text": "品牌知識 7 條（已確認）"} ],
  "primary": {"label": "...", "href": "..."},        # 跟著 state 走
  "secondary": {"label": "還是要先建立", "href": "..."} | None,   # 只有 red 才有
}
```

三列的判定（每一句都由後端出，瀏覽器逐字印，§5.3）：

| key | green | yellow | red |
|---|---|---|---|
| `offering` | 有賣法算得出 `breakeven_cpa`，而且沒有任何一列帶 `assumptions_json` | 算得出，但有列是假設值 → reason 例：「用假設值：單品的每單成本 — 之後用真實數字取代」 | 沒有任何一項填得出數字 |
| `goal` | `brand.conversion_goal` 有值（label 取 `app.core.vocab.CONVERSION_GOAL_LABELS`） | —（這一列沒有黃） | 沒設定 |
| `channel` | 綁了帳戶且 `backfill_done` | 綁了但補拉還沒跑完 → 「花費還在拉，拉完才能用近 30 天當預算依據」 | 沒綁 |

- `fix_href` 一律 `f"/brands/{brand_id}/intake"`（router 路徑，**不含 `/app`**）；`fix_label`
  分別是「去補商品與數字」「去設定成效目標」「去接廣告帳戶」，黃列的 `fix_label` 是「去改」。
- `primary`：red →「先補齊地基」＋ `fix_href`；yellow →「進入投放中心（有假設值）」；
  green →「進入投放中心」，兩者的 href 是 `f"/brands/{brand_id}/ads"`。
- `secondary` 只有 red 有（「還是要先建立」→ `f"/brands/{brand_id}/ads/new"`）。**永遠不拒絕人。**
- `notes[0]` ＝ `bi_repo.list_brand_facts(status="confirmed")` 的長度，**不影響 state**；0 條時印
  「品牌知識 0 條（已確認）——不影響投放，但文案會很空」。
- 讀資料一律走既有 facade（`app.brand_intelligence.repository`、`app.ads.channels`、
  `app.ads.budget.breakeven_cpa`）。**不准寫 SQL、不准 import `app.meta`、不准出現 `"meta"` 字串。**
  這支不寫任何東西、不打模型。
- `app/ads/channels.py:3-4` 的檔頭現在寫「只有 routes.py 會 import 這個模組」——這張票讓
  `readiness.py` 也 import 它，**把那句話改對**（改字，不動邏輯）。

## 5. 測試 `app/tests/test_ads_readiness.py`（新檔，照 `test_ads_budget.py` 的寫法）

- 全新品牌 → `state == "red"`、三列都 red、`primary.label == "先補齊地基"`、`secondary` 不是 None。
- 補上賣法＋真實數字 → `offering` green；改成帶 `assumptions_json` 的那一列 → `offering` yellow，
  `reason` 裡有「假設」兩個字，`fix_label == "去改"`。
- 設 `conversion_goal` → `goal` green。綁帳戶但補拉未完 → `channel` yellow、整體 `state` 是 yellow、
  `primary.label == "進入投放中心（有假設值）"`、`secondary is None`。
- 補拉完成且沒有假設值 → 三列 green、`primary.label == "進入投放中心"`。
- `notes[0]["text"]` 跟著 confirmed 事實數字動，而且 0 條時整體仍可以是 green。
