# Objective
The two model calls of brand onboarding, both through `app/llm/gateway.py`, both contract-checked, neither writing a confirmed fact:
(a) the scan that pre-fills `#b3`/`#b4` from the website and brand photos (`#b2`), (b) 「自訂」 — one sentence → one field value or
one option.

# Done
1. `app/intake/ai.py`: the scan becomes `run_prefill(conn, draft)` (task type `intake_prefill`, background job keeps the existing
   `background.intake_scan` registration): fetch the draft's URLs (≤5, `net.fetch_url`) and send up to 5 brand photos as image
   content blocks in **one** call. Reply contract (JSON): `{positioning: {value ≤60 chars, note}, tone: {values ⊂ TONES (1–2), note},
   visual: {value, note}, proof: [{fact_key ∈ PROOF_KINDS, text, note}], policies: [{key ∈ POLICY_TYPES, params, note}],
   products: [{name, url|null}] (≤20), not_found: [area]}`. Program checks every entry; an invalid entry is dropped (logged count),
   an unreadable reply fails the job with the existing parse-fail message. Result → `intake_draft.prefill_json` plus
   `pages_read`/`photos_read`. The prompt forbids inventing a source; `note` names the page or 「品牌照片」. No web search.
2. `GET|POST /api/intake/brands/{b}/onboarding/scan` (start / status: `{status, found: [{area, text, note}], not_found: [area],
   prefilled: n, pages_read, photos_read}` — `found` rows in the prototype order 品牌是誰／品牌證據／政策／可能的商品). Draft cost cap
   (`state.would_exceed`) refuses before calling, as today.
3. New `app/intake/custom.py::propose(conn, brand_id, block, text, context) -> dict`, task type `intake_custom`, synchronous,
   ≤1 call, small `max_tokens`. Blocks and contracts: `positioning`/`visual` → `{kind: "value", value}`; `tone` → `{kind: "option",
   option: {label ≤8}}`; `brand_proof` → `{fact_key ∈ PROOF_KINDS, text}`; `policy` → `{label, offer_key ∈ OFFER_LABELS keys,
   sentence}`; `forbidden` → `{text}`. Input = the block's current options (labels only, capped) + the sentence (≤200 chars). Contract
   failure → `ValueError("custom_unreadable")` → route 422 「AI 整理不出來，換個說法再試一次」. Route `POST …/onboarding/custom`
   `{block, text}`; nothing is saved (the step PUT saves). Add a `product_id`-free signature now; F43 extends the block set.
4. `app/llm/providers.py`: labels, thinking level (low) and `SCRIPTED_REPLIES` for `intake_prefill` and `intake_custom` (one reply
   shape each that passes the contracts above — e2e uses them).
5. Tests: `test_intake_prefill.py` — fake provider reply with one invalid tone and one unknown policy key → both dropped, the rest
   stored; photos sent as image blocks (≤5); cost cap refuses. `test_intake_custom.py` — each block's happy path; out-of-vocabulary
   `fact_key`/`offer_key` → 422; nothing written to `brand_fact`. A test pins that each `SCRIPTED_REPLIES` entry passes its contract.
6. `intakeOnboardingApi.ts`: scan start/status and custom clients + types.
