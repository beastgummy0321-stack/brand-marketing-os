# Objective
"How many decisions are open, which one is next" has one owner, and an ended campaign is a state the queue understands (feature
Contract Q; audit W8, decision 6; triage #5, #6, frontend-ads F6, F8; drill-11 R4 H3, H4／Q2, Q3). Today five readers count open
decisions five ways (the workspace counts every kind and ignores `done`; 下一件 walks every kind), the inbox keeps decided rows
until 06:30, an ended campaign still gets cleanup proposals with 「每天省約 730 元」, and `/wait` explains two of seven reasons.

# Done
1. `queue_done.DECISION_KINDS` = the ordered tuple of Contract Q; `is_decision(row)`; `open_count` counts open decision rows only.
   `triage.get_queue`／`refresh_queue` stamp every row `decision`, `done`, and `position` (open decision rows, board order, settle
   row included; null otherwise) and serve `decisions {kinds, open}`; `scale_budget`／`insufficient_data` rows are served with
   `decision: false` and are no longer enqueued as interrupts (rows built from candidates; `id` = the dedupe key); their open
   interrupts resolve at the next refresh. `status_summary.open_items`, `workspace_reads._open_queue_count` (→ `pending_count`)
   and `digest.build` (`open_count`, listed rows) read `decisions.open`／open decision rows.
2. Closeout row (Contract Q): kind `closeout`, category `ads_triage_closeout` added to `QUEUE_CATEGORY`／`KINDS_AVAILABLE`, one per
   internal campaign whose `lifecycle.state` is `ended`, payload `closeout {campaign_id, campaign_name, end_date, running}`.
3. Ended campaigns: no new interrupt for any kind; a candidate of an ended campaign is kept only while an open interrupt with its
   dedupe key exists (raised before the end — keys are stable because the judged window ends at the end date, F49-I03).
   Queue campaign selection = live + internal ended (`lifecycle.campaign_ids`); imported ended campaigns leave the queue.
4. Inbox sync: `triage.resolve_done(conn, org, brand, *, kind, identity_id)` resolves the open interrupt(s) of that row when
   `queue_done.done` holds; called by `change_control.decide`／`approve` (and the readback confirmation through
   `handoff_check._aggregate` once an action turns `confirmed`), `review_rounds.decide` (defer／complete), and `closeout.close`
   (every queue row of that campaign). `_row_cleanup_proposal` uses `change_control_data.worst_state`; proposals carry
   `verification_label`.
5. Wait reasons: `triage.REASONS` per Contract Q for every emitted `reason_code`; `triage.rules()` serves it as `reasons`
   (`GET …/rules`).
6. `lib/adsTriageApi.ts`: `QueueKind` gains `closeout`; rows `decision`, `position`; payload `decisions`; `closeout` payload;
   proposal `verification_label`; `AdsRules.reasons`. `patterns/rulesFixture.ts` (the served-rules test seed) gains the same
   `reasons` the backend serves.
7. Machine checks. `test_ads_one_ruler.py`: a list／tuple／set literal with ≥2 queue-kind strings in `app/ads` outside
   `queue_done.py` and `triage.QUEUE_CATEGORY`／`KINDS_AVAILABLE` fails; every `reason_code` string `triage.py` emits has a
   `REASONS` entry (AST); every kind in `KINDS_AVAILABLE` has a category, and every decision kind a done rule. `oneRuler.test.ts`:
   an array／`Set`／object-key literal with ≥2 queue kinds, or a table keyed by ≥2 wait reason codes, in `components/ads/**`／
   `lib/ads*.ts` fails (type unions are not literals); allowlist `home/status.ts`, `settle/SettlePage.tsx` → F49-I08,
   `workspace/OverviewBody.tsx` → F49-I09, `wait/WaitPage.tsx` → F49-I10, with the stale-entry test.
8. Tests: a campaign whose cleanup set was approved and confirmed has `pending_count == 0` and stage not 決定 (drill-11
   `controls/c3-06`); `status_summary.open_items == decisions.open == digest open_count` on one fixture; after
   `change_control.decide(rejected)` on a cleanup set, `interrupts.list_open(category="ads_triage_cleanup")` is empty in the same
   request; an ended campaign gets one closeout row and no new cleanup row, while a cleanup row raised before the end stays open
   until closeout and then resolves; an imported ended campaign has no rows; no `scale_budget`／`insufficient_data` interrupt is
   enqueued; `rules()["reasons"]` covers every code.

public `interrupts.resolve`. The frontend screens that read these fields are F49-I08 (home, settle), F49-I09 (workspace),

`touch`. Ripple (lib types): the `lib/ads*.ts` files above only gain optional keys (nothing renamed or removed); the many frontend tests importing them are unaffected and not in `touch`.
