# Objective
`app/core/input_rules.py` becomes the one table of store-time rules — counts, percent, ISO dates, enums, URLs, upload sizes,
the API key — with one refusal sentence per case, and the settings and orders stores use it (feature Contract I; audit W12;
intake #3–#5, #16, #20; other F2; drill-11 R6 A9 (AI key, channel quantity, dates), F11; controls a-07 「AI 金鑰接受任何字串」,
a-59 通路「數量」-2 存成功). Today each layer keeps its own bounds and sentences, dates go to the database unchecked (a non-ISO
date is a 500), and the settings page sends `Number("")` = 0 for a blank field.

# Done
1. `input_rules.py` per Contract I's table: `count`, `percent`, `rate_fraction`, `iso_date`, `date_within`, `one_of`, `url`, `urls`,
   `check_upload` + `UPLOAD_CAPS`, `api_key` — exact sentences from the feature table; docstring lists every rule (it is the
   authority). `vocab.require(kind, value)` = `one_of` over the vocab list named by `kind` (brand_fact, product_fact, rule, claim,
   channel, customer_voice_source, policy), with the vocab label as the field label.
2. Settings (`app/main.py`): spend cap and AI monthly limit through `positive` (blank → 「…請填數字。」, never 0), API key through
   `api_key`; `parse_number` leaves the settings writers. Orders: SKU `unit_cost` `non_negative` (0 stays 0, F47 Contract A),
   channel `quantity` `count(minimum=0)`, `entry_date`／`changed_at` `iso_date`, importer `order_date` parsed by `iso_date` (an
   unreadable vendor date refuses that row with its reason in the import result; no `str(x)[:10]`).
3. Frontend settings: `lib/typedNumber.ts` `typedValue(text) -> string | null` (trimmed text, blank → null; the server parses and
   refuses); `SpendCapSection` and `ApiKeySection` send it and print the server's sentence (no local bound).
4. Scanners. `app/tests/test_input_rules_gate.py` (Contract I backend rules; allowlist `(file, text, issue)`: today's hits in
   `app/intake/**`, `app/brand_intelligence/**`, `app/brand_web/**` naming F50-I03, rate checks naming F50-I04, `app/ads/**`
   naming F50-I05; stale entries fail). `frontend/src/lib/clientRules.test.ts` (Contract I／R frontend rules over
   `components/intake/**`, `components/products/**`, `components/settings/**`; allowlist: `SellWayTable.tsx`, `SellWaysStep.tsx`,
   `EconomicsPanel.tsx`, `EconomicsTab.tsx`, `RuleCardsSection.tsx`, `BundlePage.tsx` naming F50-I04; `ProductDoneStep.tsx`,
   `WhoStep.tsx` naming F50-I15).
5. Tests (`test_core_input_rules.py`): one test per rule and case — the bad value is refused with the exact sentence, the good
   value passes unchanged; `check_upload` empty vs oversize give different sentences; 10.04 MB is over a 10 MiB cap; `api_key("abc")`
   refused; `iso_date("13/06/2026")` refused, never a 500 through the orders route; channel quantity −2 refused.
