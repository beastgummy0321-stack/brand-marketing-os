# Objective

This issue fixes the F06 integration review finding against Acceptance item 1, where the tabs disagree about the
next step. The state is: the strategy is generated, and there are no delivery groups.

- 總覽 and 素材 already say 「前往策略 →」 (`nextStep` → `strategy_adopt`).
- 投放結構 does something else. `DeliveryTab.tsx:173-193` checks `groups`/`strategy` itself instead of reading
  the rule. It then offers its own 「採用策略（建立投放結構）」.
- That button calls `adoptStrategy` without choosing a budget scenario first. With `budget_scenario` empty,
  the backend refuses it with `strategy_not_adopted` (`app/ads/plan.py:134`). `StrategyTab.tsx::handlePrimary`
  does choose a scenario first.
- `StrategyTab.tsx:137,332,347` also branches on `hasGroups` rather than the rule's `id`. That breaks
  ARCHITECTURE.md §6.2 decision 15: a tab picks its in-place action only by `nextStep(c).id`.

The rule already has the answer (`strategy_adopt` → 策略), so no new ruling is needed. Adopting stays in one
place: the strategy page.
