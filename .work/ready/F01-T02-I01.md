# Objective

Every deepest (depth 3) tree node carries a `copy_length` the expansion AI chose.

Settled in ARCHITECTURE.md §5.5: the values are `short` / `medium` / `long`; anything else, or a
missing field, becomes `short`. This is never a rejection reason - trees produced before this change
must still render.

# Done

- `tree._collect_nodes` adds `"copy_length": _node_copy_length(raw.get("copy_length"))` to depth-3
  nodes and `None` at depths 1 and 2, mirroring exactly how `coordinates` is handled today.
  `_node_copy_length` returns the value when it is one of the three strings, else `"short"`.
- `app/departments/ads/campaign_tree.md`: the 交付內容 list gains a `copy_length` bullet for depth-3
  nodes and the JSON example gains the field. The guidance is the wording already used in the
  product, verbatim: 短版「折疊前一口氣講完，適合再行銷、已認識品牌的人」, 中版「痛點→證明→優惠，適合第一次
  看到你的人」, 長版「說故事，適合高單價、需要被說服的商品」. One length per node.
- New `app/tests/test_schedule_copy_length.py` drives `tree.build_tree` directly (pure function, no
  DB): a reply with `copy_length: "long"` on a depth-3 node keeps it; `"enormous"`, `null` and a
  missing field all become `short`; depth-1 and depth-2 nodes get `None`. `app/tests/test_schedule.py`
  has a `build_tree` reply fixture (`_tree_fenced` / `_one_tree_nodes`) of the right shape - retype
  what you need, see the imports rule below.
- **Imports allowed in the new file.** `tools/check_architecture.py` attributes
  `app/tests/test_schedule*.py` to the **schedule** module (manifest `owns`). So in
  `app/tests/test_schedule_copy_length.py`:
  - **no `from .test_schedule import ...`** - that file is `legacy` in the manifest and importing it
    is a violation (`managed module schedule imports legacy internals`).
  - **do not copy `test_schedule.py`'s import block wholesale.** It contains
    `from app.workbench import repository as workbench_repo`; schedule may depend on workbench but
    only through the public entry `app/workbench/__init__.py`, so that line is red outside legacy.
    This test needs no workbench import at all.
  - all this file needs is `unittest`, `json` and `from app.schedule import tree as tree_mod`
    (same module). `build_tree` is pure - no DB, no `TestClient`, no fixtures.
