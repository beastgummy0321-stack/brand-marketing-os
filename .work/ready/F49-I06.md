# Objective
Readback never asks the user to check what no reader can see, says why a read failed, and calls each verification state by one
name (feature Contracts B and D; audit W9, W17; decision 5; triage #8, #9; frontend-ads F2; drill-11 R3 E2／E3, R4 C1). Today
every launch lists 7–8 manual fields as 「讀不到，請到 Meta 看一眼」, the tick's no-op upserts race the user's check, a code bug and
"wrong object picked" read the same, a deviated item collapses to 核對中, and screens open to system-built campaigns look up ad
sets only in the imported-only `external_view`.

# Done
1. Declared readability: `manual_settings.FIELDS` entries gain `readable: False`; `handoff_check` declares `material` readable
   False. `_settings` never adds a declared key to `unreadable`: proven by the read (material evidence exact／equivalent) →
   matched, else the label goes to evidence `confirmed_at_approval`; the item state is computed over readable keys, so a launch
   whose readable fields all match is `confirmed` without a click. Launch-settings keys keep today's per-field eye confirm.
   `launch_view` serves each item's `confirmed_at_approval` and the view's `approval_confirms [{label}]` (the declared list for
   this launch's groups／ads) so the approval screen can print it (F49-I12).
2. Reason codes: every readback refusal carries a code (`SourceReadError.code`, or a per-raise code for the `ValueError`s at
   `handoff_check.py:312-434` — e.g. `parent_unread`, `owned_elsewhere`, `account_mismatch`, `identity_taken`, `original_as_new`,
   `preexisting_ad`, `wrong_level`, `parent_mismatch`, `root_required`, `item_taken`); `handoff_check` and
   `change_control_verify` catch `ValueError` only (an `AttributeError` propagates); evidence stores `reason_code` and the sentence
   from `handoff_check.READBACK_REASONS`; `launch_view._reason` prints it.
3. `change_control_data.worst_state(states)` (Contract B order) is the one aggregate; `handoff_check._aggregate` uses it (a deviated
   item makes its action `deviated`). `change_control_data.VERIFICATION_LABELS` → `verification_label` on change sets and items;
   handoff items carry `status_label`; the launch view serves `state_label` beside `state`; `unknown` and `reported` differ.
4. `external_repository.upsert_entity` bumps `updated_at` (and `status_changed_at`) only when a column changed.
5. Contract D: `handoff_data.workspace` serves `destination_by_ad` and `destinations_note` (origin-aware sentences).
6. TS types: `lib/adsLaunchApi.ts` (`state_label`, `confirmed_at_approval`, `approval_confirms`, `reason_code`),
   `lib/adsHandoffApi.ts` (`status_label`, `destination_by_ad`, `destinations_note`), `lib/adsChangeApi.ts` (`verification_label`).
7. Machine checks. `test_ads_one_ruler.py`: `except (ValueError, AttributeError)` anywhere in `app/ads` fails; every
   `verification_state` value written in `app/ads` has a `VERIFICATION_LABELS` entry. `oneRuler.test.ts`: a local word table for
   verification or launch-item states (object literal keyed by ≥2 of `pending|reported|unknown|confirmed|deviated|stale` or
   `todo|built|verified|mismatch|changed`, or a `switch` with ≥2 such cases holding a Chinese literal) fails; allowlist today's
   files with their fixing issue (`flow/CleanupVerifyRows.tsx`／`flow/VerifyPage.tsx` → F49-I11, `home/status.ts` → F49-I08,
   `publish/PublishVerify.tsx` → F49-I12, `ChangeSetView.tsx`／`ManualHandoffPanel.tsx` → F49-I14) and the stale-entry test.
8. Tests: a launch readback whose launch settings match and whose landing URL／audience fields are unread by design ends
   `confirmed`, with those labels under `confirmed_at_approval`; each raise site yields its own `reason_code`; an `AttributeError`
   in `_settings` propagates; one deviated item of three → action `deviated`; two identical upserts leave `updated_at` unchanged;
   `destination_by_ad` names the ad set of a launched internal campaign's ad; `destinations_note` on an internal draft.
