# Objective

The work view: one card per part the brief may produce, matching what the backend now produces.

# Done

- **Which cards exist** (ARCHITECTURE.md §5.4): by source, not by `kind`.
  `PARTS_FOR_KIND` in `BriefDetail.tsx` is replaced by
  `brief.source_kind === "schedule_node" ? ["copy", "image_prompt"] : brief.request.parts`.
  A card is rendered before anything has been generated for it - the card is where the user starts
  that part, so a dispatched brief shows 文案 and 圖片提示詞 from the moment it arrives.
- **文案 card**: the brief's one length (label + `LENGTH_HINTS` sentence), the bodies with character
  counts and per-item copy buttons, headlines, descriptions, the ❌ validation lines, rounds and
  「採用這一輪」 - all as today, minus the 短／中／長 switch.
- **圖片提示詞 card**: a count field (1-30) is part of the card for the first run as well as for
  「再產一輪」, because `repository.run_part` requires a count every time. It is prefilled from the
  brief's format coordinate (`brief.coordinates?.format`): 「彈性格式」 → 10, anything else or missing
  → 3. The user may change it.
  Once a round exists, the card reads `body_json.mode` and shows the copy buttons in order:
  - `variant`: ① 主圖提示詞 (`rendered.hero`), ② 變體提示詞 (`rendered.variant`).
  - `exploration`: ③ 探索提示詞 (`rendered.exploration`), ② 變體提示詞 (`rendered.variant`).
  Under ① one fixed sentence says what to do with it: 主圖先產一張，滿意了再用 ② 產變體.
  `CopyIconButton` from `components/layout/` is the copy control - do not write another one.
- **生成圖片 seat**: a disabled grey button reading 「生成圖片（席位保留）」 with the tooltip
  「站內生圖之後接上就在這個位置」. It is a reserved seat, never phrased as a refusal or an error.
- **影片腳本 / 自由生成 cards**: unchanged behaviour, moved into the new work view; the 影片腳本 count
  field (1-5) keeps today's rule.
- `workbenchApi.ts` gains the output body types for the two image-prompt modes and exposes
  `request.parts` on `BriefDetail` so the card list can read it. It also drops `on_image_texts` from
  `NewBriefRequest` - this issue removes its last reader, the `onImageTexts` / `noSourceForText`
  precondition in `BriefDetail.tsx` (today lines 263-264), which the rewritten image-prompt card
  replaces (an image-prompt round no longer needs any on-image text or adopted headline).
- `frontend/e2e/smoke.spec.ts`: the existing workbench step additionally asserts that the left rail's
  三個派工來源 are visible - one line, no new spec file.

# Verify

`cd frontend && npx tsc -b --noEmit && npm run depcruise`, then in a browser on a restarted backend:
a dispatched brief with no output at all shows both cards with the count prefilled from its format;
after an image-prompt round, both copy buttons appear in the right order and produce the two prompt
texts; the 生成圖片 button is grey and disabled. Check 1024 and 1920.
