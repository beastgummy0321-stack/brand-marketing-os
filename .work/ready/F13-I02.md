# Objective

唯讀平台能力、反向納入與可續跑同步。

按 §6.9.2 將既有 Graph 讀取封装到通路能力接口，從已綁定帳號列出並納入活動。

# Done

1. ads 管理產品同步流程；meta.graph／repository 只擴現有 transport／來源讀取 facade 欄位，不在 legacy 新增工作區／安排業務。core 只依能力接口，Meta 判斷留 adapters／channels。
2. API 在既有 /api/ads 品牌路徑下提供 existing-campaigns 分頁讀取／refresh、POST imports、POST campaigns/{id}/sync、GET sync-jobs/{id}；每個來源帳號都由 server 重新核對綁定。清單 GET 不做長同步。
3. 納入以原生鍵與 transaction 冪等；已被同品牌 internal 綁定的來源活動回既有工作區或明示衝突，不建立雙重歸屬。初次資料不完整仍保留來源與 pending。
4. 依 §6.9.2 實作快取自動刷新、每日排程、手動刷新、100 節點／批、游標續跑與帳號鎖；背景 task 含 org_id，register_tasks 可重入。交易中不長時間等待平台。
5. 成效預設近 30 日、可分期補讀；保留平台粒度、歸因及幣別與 unknown，不跨層相加；連線解除／部分 failure 保留先前數據和獨立新鮮度。Meta conversions 使用 facade 的來源定義，無法確認指標則 unavailable，不自行猜 purchase。
6. 單圖／影片／輪播／動態素材讀取按官方契約實作；逐欄保留 missing／unsupported 與來源時間，thumbnail 不能冒充影片。查官方文件及有限唯讀平台能力 probe 時不輸出 token、個資或完整原始帳戶資料。
7. 測試：campaigns 清單含 paused／zero spend、翻頁第二頁失敗續跑、重試／並行納入、來源帳號解除、部份素材失敗、三種指標未知／真零／有值、非 Meta 假 adapter 走相同核心，攔截任何平台 POST/PATCH/DELETE。
8. 若可讀取真實已綁定 token，以既有 facade 做最小只讀能力驗證並報告可讀種類；若帳號無合適資料或權限不足，保留未驗證項，不以 fixture 冒充。

既有背景 facade 僅提供 enqueue/is_active；尚未納入的活動沒有 Campaign 可存 cursor。可在 ads 擁有的新增同步狀態表保存帳號清單快取、job id、游標與完整子批結果，登記 ownership／品牌清理／隔離測試；不把這些業務狀態寫入 meta 或 llm 表。此為已核准持久續跑的必要儲存實作，不改產品範圍。
