# Objective
The delivery planner binds every ad to one customer group and knows what the brand has in hand (feature outcomes 3, 5 photo
count, 7; Contracts A and P). Today the copy step never learns which group an ad speaks to (drill 10: an athlete-group ad wrote
about meetings, operator-notes D15/D19), the planner put 6 ads on 4 photos (P4), and the October exam season is missing (O2).

# Done
1. Migration `20261004000021_ads_ad_customer_group.sql`: `ALTER TABLE ads_ad ADD COLUMN customer_group_id text;` (no FK, no
   default). `repository.create_ad(..., customer_group_id=None)` stores it; `campaign_detail` already selects `*`.
2. `customer_groups.prompt_section` keeps its text; the planner also needs the listed groups (id, who, pain_keys, quote,
   when_used) in prompt order — return or expose them without a second read of a different rule.
3. `plan._validate_reply` / `adopt_strategy` (Contract A): with groups listed, each ad needs `customer_group` = an integer 1..N of
   the listed groups; its `pain` must be in that group's `pain_keys` when that set meets the filtered menu's pain keys; all ads of
   one delivery group carry the same group. Any failure → `ValueError("delivery_plan_failed")`, nothing written. No groups listed →
   the key is ignored, `customer_group_id` NULL. The stored snapshot gains `customer_group: {"id", "who"}` beside the seven
   coordinates (or nothing when NULL).
4. Contract P: a prompt section 【手上的素材】「照片 N 張、影片 M 支」 placed before 【這期可用的優惠】 (vocabulary stays last). N =
   the brand's active official assets whose kind is not `logo`, plus the brand's ready ads user assets whose mime is not video;
   M = ready ads user assets whose mime is `video/*`. Read through `bi_repo` and the ads user-asset repository, no new SQL on
   another module's table. Counter-examples: an asset with no mime or an unready one is not counted; a brand with no assets prints
   「照片 0 張、影片 0 支」.
5. `delivery_plan.md`, in its own style: `customer_group` per ad from 【這個賣法的顧客】; one group per 投放組; the ad's `scene` is a
   moment of that group's 「什麼時候用」; the ad count does not exceed the photo count when it is ≥ 1. Reply example gains the key.
6. `assets._ad_set`: an ad with a group hands `request.customer_group` = 「〈who〉｜煩惱：〈pain labels〉｜顧客會說：〈quote〉｜什麼時候用：
   〈when〉」 (missing parts omitted; a group id that no longer resolves → key omitted). `workbench/prompts.brief_text` prints
   「顧客群：〈text〉（五組文案都寫給這一群人，情境是他們的時刻）」 after the 情境 line, only when present.
7. `calendar_tw.EVENTS`: convention rows 「國高中第一次段考週」 2026-10-12～2026-10-23 and 2027-10-11～2027-10-22 (`exam`); keep the
   table ordered as it is; extend the calendar test.
8. `ScriptedProvider` delivery-plan branch: when the prompt lists 【這個賣法的顧客】 groups, every ad takes `customer_group: 1`;
   otherwise unchanged. Change only that branch.
9. Tests: reply with a valid group stores the id and the snapshot; missing / out-of-range number, pain outside the group's pains,
   two groups in one delivery group → refused; no groups listed → NULL; photo-count section text and position; brief text line
