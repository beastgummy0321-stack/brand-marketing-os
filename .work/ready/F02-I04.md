# Objective

檔期規劃 reads the 「可以下一步」 signal and keeps working without it. `ARCHITECTURE.md` §5.5: the
signal is a state read through `workbench.pack_for_source` — the workbench never calls back. The
schedule page redesign itself is **out of scope**; this issue is the signal, one line of good news
and one skippable warning.

# Done

- `app/schedule/state.py`: the brand response gains `creative_pack` for the current tree —
  `{pack_id, status, approved_at, sets_total, sets_done}` or `null` when no pack exists — read via
  `workbench.pack_for_source(conn, org_id, brand_id, "schedule_node", {"source_tree_task_id":
  tree_row["id"]})`, module entry point only, next to the existing `briefs_for_source` read. No new
  SQL against a workbench table.
- 素材準備 stage (`CreativePackList.tsx`): when `creative_pack.approved_at` is set, one line at the
  top of the stage reads 「素材製作完，可以開始追蹤成效」. Nothing else about the stage changes — the
  one-length section, its fixed hint and the working copy buttons stay exactly as they are
  (F01-T02's human item is carried into F02's `human[]`).
- 投放結構 stage (`CampaignTree.tsx`): pressing 核准 while `creative_pack` is `null` or unapproved
  opens a `ui/dialog` confirm reading 「還沒製作素材」 with a one-line consequence and two buttons —
  「仍要核准」 (proceeds, unchanged behaviour) and 「先去做素材」 (navigates to the pack, or to
  素材工作檯 when there is no pack). The dialog is skippable per session: a 「不再提醒」 checkbox
  stores the choice the same way the page already remembers per-brand UI preferences; when the pack
  is approved the dialog never appears. 核准 itself is never disabled by this.
- `scheduleApi.ts`: the `creative_pack` field is typed; no new call.
- `app/tests/test_schedule_creative_pack_signal.py` (new, the falsifier): the brand response carries
  `creative_pack: null` with no pack, the derived counts with an unapproved pack, and `approved_at`
  once approved; a second tree's pack does not leak into the first tree's response.

# Verify

The commands above. Manual check lives in F02's `human[]` (the warning on a restarted backend).

# Blocked if

`pack_for_source` cannot identify the current tree's pack from `{"source_tree_task_id": …}` —
report it as an F02-I02 contract bug rather than matching on a name here.
