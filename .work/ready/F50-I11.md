# Objective
A workbench round whose job died is treated as failed instead of 「還在跑」 forever, a failed material set can be restarted from the
ads side, and the free-text parse keeps the reason it fell back (feature Contract J; audit W14; intake #11, #22; R7 B3 sibling
`free_parse.py:100-107`). Today `run_part` refuses `round_running` from the brief's own status, so a killed worker leaves a set
that can never be regenerated; `material_handoff.start` returns None for every non-idle status including `failed`; a timeout, a
refusal and an unreadable reply all read 「parsed: false」 with one note.

# Done
1. `repository.run_part` (and the set read that shows 「生成中」): a brief in `queued`／`running` whose part lock
   `workbench:{brief_id}:{part}` has `background.outcome()` failed — or None while the brief has waited longer than the generation
   timeout — is marked `failed` with that outcome's text as `last_error` (one helper, `_reconcile_running`), then the run proceeds;
   a live job still refuses `round_running`.
2. `material_handoff.start` returns the brief status it found and restarts a `failed` brief (`run_product` on the same pack, never a
   second pack); `queued`／`running`／`done` stay untouched. The facade (`app/workbench/__init__.py`) documents the return; the ads
   caller (`material_tasks`, F49-I07) keeps working with the returned status.
3. `free_parse.parse` returns `reason` (`llm_failed` + the task's `error_code`, `reply_unreadable`, `reply_invalid`) beside
   `parsed: false`, and the note names it (「AI 這次沒有讀懂（{reason 的白話}），先照預設往下」); `lib/workbenchApi.ts` types
   `reason` (optional).
4. Tests: brief `queued`, no procrastinate job for the lock, older than the timeout → `run_part` succeeds and the old round reads
   failed; a live job still refuses; `start` on a failed brief re-enqueues once and returns `failed`; a provider timeout gives
   `reason: llm_failed` with `timeout`.
