# Objective
Human acceptance on real synced data (2026-09-21, campaign adc_01M2T370NSGZDS0YXWTATKCN3T) found the campaign's own result
unresolvable: `GET target` answers `missing: ["product","needs_resync"]` right after a fresh re-sync. Two causes, both visible
in `ads_external_daily` for that campaign at `metric_scope='campaign'`:
1. Monthly-budget source rows (`attribution_key='account_monthly_spend'`, written by `external_sync.py:234` /
   `meta_read.py:498`, read by `month_budget.py:349`) share entity, day, scope and currency with observation rows. The
   F16-I03 result view groups by (metric_scope, currency) and ignores `attribution_key`, so it swallows them: spend is counted
   twice and their NULL `result_count` forces `result_unknown_days` on every window.
2. Superseded intraday rows: `attribution_key` embeds the purchase action type, so a day first synced before any purchase
   is stored under `…:unavailable` (e.g. 09-19 spend 722) and later under `…:omni_purchase` (spend 1747); the first row is
   never replaced. Both the per-key series and the result view then double count spend for that day.
Write the cause chain in the commit body. Fix at the point all readers route through, not per reader.
# Done
- Observation rows and monthly-budget source rows are told apart by ONE shared, platform-neutral definition (a named
  constant/predicate next to the existing marker, used by month budget, `aggregate()`, the result view and targets); the
  result view and the per-key series never include monthly-budget rows; month budget keeps reading only its own rows.
- When sync stores an observation for (entity, day, metric_scope, currency, source) it removes older observation rows of the
  same identity whose `attribution_key` differs only because the purchase action type changed, in the same transaction;
  monthly-budget rows are never touched. The uniqueness key and the `attribution_key` format are unchanged. A re-sync of an
  affected window therefore heals existing duplicates; no hand-written data fix.
- The trailing-30 window uses complete days only (today's partial day excluded), consistent with review windows.
- `missing[]` tells the truth: `needs_resync` only for rows that predate the result columns; genuinely unknown days report
  `result_unknown_days`, mixed definitions `mixed_result_definition`.
- Tests built from the real shapes above: a day with both monthly and observation rows; a day re-synced from `unavailable`
  to `omni_purchase`; trailing-30 resolving to spend/results of observation rows only; month budget totals unchanged.
- No "absent action means zero" rule is introduced (reserved for the user at phase-2 planning).
# Verify
Targeted tests above; global gates per manifest. After merge the architect re-syncs and re-reads the numbers with the user.
# Blocked if
Separating the two row families needs a schema change or a change to the uniqueness key, or healing duplicates would require
deleting rows outside the sync path.
