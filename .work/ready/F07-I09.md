# Objective

The old global style library retires end to end (ARCHITECTURE.md §5.10, F07 Decision 25). Nobody picks a
look: looks come from the derived identity and the program's slot plan (§5.9). Nothing validates, reads,
lists or offers a style any more; `workbench_brief.style_key` stays, unread.
Never delete or overwrite anything under `data/`.

# Done

1. Delete `app/workbench/image_styles.json`. Remove `repository.STYLES`, `get_style` and the
   `style_unknown` path. `submit_brief`/`create_free_pack`/`submit_pack` accept a `style_key` key and
   ignore it. The column is `style_key TEXT NOT NULL DEFAULT 'ugc'`
   (`20260909000001_workbench_baseline.sql:33`): drop it from the INSERT column list so the default
   fills it. No migration.
2. Remove `GET /api/workbench/styles` from `routes.py` and update its module docstring.
3. `prompts.brief_text` loses its `style` parameter and its 風格 line; update `jobs.py` callers (copy,
   video, free).
4. `free_parse.py`: delete `_valid_style_hint`; `_validate_reply` returns `"style_hint": None` (the key
   stays for the scripted e2e reply). `free_parse.md` stops asking for a style.
5. `app/workbench/__init__.py` docstring: drop `style_key` from the pack shape description and mention
   `request.variant_count`.
6. Frontend: `workbenchApi.ts` removes `fetchStyles` and `ImageStyle`; `FreeJobPage.tsx` removes the
   styles fetch, the 風格 select and the 「風格設定」 row, nothing else; `FreeJobPage.test.tsx` drops
   style expectations only.
7. Tests: `test_workbench_api.py` (legacy) replaces the `/styles` test with one asserting the route is
   gone (404); `test_workbench_free_parse.py`: `style_hint` is `None` even when the model sends 「ugc」;
   `test_workbench.py` `BriefCoordinatesTextTest` and any copy prompt assertion that included the 風格 line
   are updated. Payloads that still send `"style_key": "ugc"` stay and must pass.
8. Red-proof: every rule in `.harness/scratch/mutants/F07-I09/rules.md` has a test that turns red when that rule is broken (in
   memory only, as that file says), and the worker reports per rule ID which test caught it (`review` and `e2e` lines: what was
   read or run). The review judges only against that list, plus a new rule only if it maps to a F07 Decision the sweep could not
   have seen.
