# Objective
The three screens that start long background work say what came back — running, done with how much, done and empty, or failed and
why — from the stored outcome, also after a reload (feature Contract J; audit W14; other F10, F11 (backfill and customer-voice
reads); drill-11 R7 A12; controls a-64／a-66 「開始拉 37 個月」 按下去後頁面一模一樣). Today the history page and the onboarding
Meta panel read only `running`, end silent, and never clear their poll timer; the customer-voice placeholder lives in React and a
reload loses it; a failed status read reads as nothing.

# Done
1. `HistoryPage` and `MetaConnectPanel` read the backfill `outcome` (F50-I10): running → the existing running line; done → 「拉完了：
   {text}」; empty → 「拉完了：這段期間沒有廣告資料」; failed → the served text with 「再試一次」 (the existing start button); a failed
   status read shows the read error instead of nothing (no `.catch(() => undefined)`); poll timers are cleared on unmount.
   HistoryPage's 略過 stays browser-only (out of scope).
2. `CustomerVoiceTab` renders running／failed extraction rows from the library payload's `customer_voice_jobs` (F50-I07) instead of
   React-only placeholders, so a reload keeps them; a failed row shows its `error` and the existing retry; an `unknown` job shows
   nothing.
3. Tests: a backfill outcome `empty` renders the empty sentence; `failed` renders the text and the retry; unmounting stops polling;
   the library tab mounted with a running job shows the placeholder without a click.
