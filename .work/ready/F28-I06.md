# Objective
The month-level numbers home board D needs and no current response carries (Feature "Contracts → Home overview"; field list and scope choices in Feature Decisions). Read-only, no LLM, no write.

# Done
1. `GET /api/ads/brands/{b}/home?month=` in a new routes file registered in `app/ads/__init__.py`, same auth shape as the month-summary route. Month window and elapsed days reuse `month_summary`'s org-timezone rule; the cutoff excludes today.
2. Invariants the tests assert: one `spent` for the whole payload; quality buckets sum exactly to it (`ungraded` takes spend not on a graded active ad, closed ads included); grades are the triage grades from I02, never recomputed; earn = Σ purchase campaigns (purchases × break-even − spend), null with `earn_missing` when one lacks break-even, other result kinds in `excluded`; `previous_same_period` = same elapsed days of the previous month, capped at its length; `pace.daily` ends at `spent`; `budget_amount`/`available` come from `month_budget.view`, projection null on day 1.
3. Campaign rows: every non-closed campaign; live rows by month spend desc, drafts by start date; draft `ads_ready` uses the same material predicate the launch snapshot validates with (no second definition). Timeline: today, month end (review), campaign starts and ends in the next 31 days, ≤ 6 items.
4. Counterexample tests: zero purchases, null spend days, mixed currencies (→ nulls, never a sum), no monthly budget, no cap anywhere, a campaign with a non-purchase result, a draft with no ads, day 1 of the month, month-end timezone boundary, one read failing inside (that block null, the rest intact).
5. `frontend/src/lib/adsHomeApi.ts`: client + types for exactly this shape (new file, owned by `ads`).
