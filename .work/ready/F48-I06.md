# Objective
The delivery plan reads the one context, respects capacity, carries last period's 留下 ads with their creative, and hand
edits obey the planner's menus (feature Contracts K, C, P for `plan.py`; decisions 2 and 4; R2 E7 names).

# Done
1. `plan.adopt_strategy` reads `planner_context(conn, org, brand, sell_way, campaign=campaign)` and builds the prompt from its
   sections (product, forbidden, groups, offers, ranking, materials, capacity, vocabulary — vocabulary last as today).
   Remove the `test_ads_planner_context.py` allowlist entry for `plan.py`.
2. Contract C: `ceiling = max(triage_capacity.can_support(daily_total, cap) + 1, len(roles))` (cap unknown → no capacity
   line and `ceiling = _MAX_GROUPS × _MAX_ADS_PER_GROUP`); the prompt's 【這期撐得起幾則】 states daily, cap, `can_support`,
   the explore slot and the ceiling; `_validate_reply` refuses more ads than `ceiling − len(carried)`; the campaign payload
   serves `capacity {daily, cap, can_support, ceiling, carried}`.
3. Contract K: before the model call, `coordinate_learning.keep_ads(conn, org, brand, sell_way)` → the newest closed
   campaign's `keep`／`keep_relative` rows in rank order with their previous `ads_ad` row (through `source_cycle_id =
   <campaign>:<ad>`), group role, slot placement (`slot_placement_id` → `ads_asset_placement` asset + `copy_fields`) and
   `live_creative_json`. Up to `ceiling` rows become carried ads: `ads_repo.create_ad(...)` with the previous coordinates,
   name, scene, `customer_group_id`, `coordinates_snapshot={…, "carried_from": {"campaign_id", "ad_id"}}`, in the group whose
   role matches (fallback per Contract K) — groups are created first from the allocation, carried ads next, then the
   model's ads. Creative: `user_assets_repository.attach(..., ad_id=new_ad, copy_fields=previous copy)` on the same asset,
   then the existing no-AI confirmation path (`slots.settle_ready_asset` or the per-placement confirm the upload path uses)
   so the slot reads 已確認; no asset／copy found → the ad is created without a placement and `ad.carry_note` =
   「上一期的素材找不到，要重新準備」. The prompt gets 【已沿用的廣告】 (name + seven coordinates + group) and 「請再規劃 K 則」;
   `_builds_on_learnings` keeps only the 換掉 refusal. `assets.dispatch_pack` skips carried ads whose slot is `ready`. The
   payload's ads carry `carried_label` 「沿用上一期」 or `null`.
4. Hand edits: `plan.create_ad`／`update_ad` validate `proof`／`offer`／`format` keys that exist in `coordinate_vocabulary` but
   are not in `_prompt_rows` for this campaign → `ValueError("coordinate_unavailable")` (route 400 「這期不能用這個〈dimension
   label〉：〈reason〉」 with reasons 沒有登記證據／優惠不適用／沒有結束日／只有照片); unknown keys pass as today. Names (reply path
   and hand edits) run through `workbench.forbidden_terms` + `claims`-style squashed substring → `name_forbidden` (route 400
   「廣告名稱寫了「〈term〉」，這是你標了不能講的話」); the reply path refuses like the scene rule. The campaign payload serves
   `menu: [{dimension, key, label}]` (= `_prompt_rows`) for the editor (F48-I10 consumes).
5. `delivery_plan.md`: the capacity, carried-ads and forbidden rules in plain words; the photo-count rule stays.
6. `app/llm/providers.py::ScriptedProvider._reply_for`: when the prompt lists 【已沿用的廣告】 the scripted reply plans one ad
   per role minus the carried roles' ads only if the ceiling line says fewer remain (keep the e2e deterministic: parse 「請再
   規劃 K 則」 and emit `min(K, roles)` ads, one per role in order).
7. Tests: fixture with a closed campaign whose 留下 ad has a confirmed placement → the next adopt creates a carried ad with
   the same seven keys, `carried_from`, a placement on the same asset with the same copy, slot `ready`; a 留下 ad without
   creative → carried ad with `carry_note`, slot `missing`; a reply exceeding the ceiling → `delivery_plan_failed`; a reply
   reusing a 換掉 pair → refused; a hand `create_ad` with a proof key the brand has no evidence for → 400
   `coordinate_unavailable`; a name containing a forbidden word → 400 `name_forbidden`; `dispatch_pack` leaves the carried
   ready ad out of the pack; `capacity` and `menu` on the payload; the scripted e2e reply still adopts with three roles.
