# Objective

批次圖片影片原檔、預覽與可持久安排。

按 §6.9.3 保存自帶成品，沒有內部廣告也能上傳、重開、補充文案及掛入活動。

# Done

1. 新增 ads_user_asset／ads_asset_placement 與 ownership；完整保存 §6.9.3 欄位，原檔 hash 與各 Campaign 文案修訂分開，品牌暫存可找回。同品牌 hash 去重、不同品牌不可探知。
2. API 提供品牌 user-assets 批次 upload/list/preview/download、Campaign placements list/attach/update；require_brand 與原檔下載都校驗 org/brand，不可由任意 key 存取。未建立 Campaign 時先存品牌素材，建好才掛入。
3. JPEG/PNG/WebP／MP4/MOV、50 MiB、每批 10、並行 2 依契約；server 串流限制總量與單檔，不先讀無上限 request。FFprobe／FFmpeg 使用既有主機能力，逾時／損毀／工具缺失逐檔顯示，預覽不覆寫原檔。
4. Storage put/get/delete 只走 facade；路徑置於既有 org/brands/brand 範圍以配合品牌清理。成功原檔不被 metadata 重試刪除；孤兒檔補償可重試，清理只刪本 task 產物。
5. 已有 copy fields 原樣保存；修改確認版本產生新 revision，撤銷新版本確認但保留歷史。必用為預設，未安排與失敗皆保留有理由的列。
6. 測試內容偽裝、損毀、超限、混合成功失敗、FFmpeg timeout、原檔 bytes 不變、重開與去重、多 Campaign 不同文案、跨品牌下載拒絕、DB/Storage 單邊失敗。測試媒體以最小 fixture 於 tmp 產生，不提交大型二進位。
