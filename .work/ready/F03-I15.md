# Objective

The plan is visible and editable, and the user can see whether the artifacts are ready. §0: it
serves the **plan → artifact** links; its input is the campaign detail and the readiness payload
(F03-I06, F03-I08); its output is the edited rows and the dispatched pack; its trace is that every
edit to a bound row shows up in 近期異動紀錄 as an action; it is **core**.

# Done

- **投放結構 tab** (prototype `screen-delivery.js`, minimal fidelity — **no batch bar, no preflight
  panel, no search box**, those are feature 3):
  - 採用策略（建立投放結構） for a campaign that has a strategy but no rows; while it runs, the
    honest progress line; on success the tree appears.
  - Two columns: the tree (Campaign → 通路 → 投放組 → 廣告, indentation and status pills as in the
    prototype; the 通路 row shows its label and 已接上／未接上 from the payload) and, on the right,
    the selected node's fields in a `SidePanel`-style surface — group: name, role, daily budget,
    dates; ad: name, the seven coordinates, and its observed spend share (read-only, no budget
    field at ad level). Editing writes through the PATCH endpoints; a row that is already bound
    shows one line saying the change will need to be made on the platform too (`sync_state`
    pending), because that is what the action row records.
  - ＋ menu adds a group or an ad; delete is behind a confirm that states the consequence.
  - Empty state when there is no strategy yet, pointing at the 策略 tab.
- **素材 tab** (prototype `screen-assets.js`): one row per ad — 投放組, 廣告, 狀態 pill
  (已就位（工作檯）／已就位（手動）／製作中／未開始), 數量 (`已選定／需要` as the workbench spells it,
  the string comes from the API), and 最後同步. Header reads 「n／m 則已就位」. Actions: 派工到素材
  工作檯 (once per campaign; afterwards the button becomes a link to the pack), 「素材已就位」 per row
  with a confirm that records who and when and can be undone, and a per-row link to that ad's 素材組
  in the workbench (`/brands/:b/workbench/packs/:packId/sets/:setId`). Nothing here blocks publish.
- `CampaignWorkspace.tsx` mounts both tabs; `adsApi.ts` only gains what is missing.

# Verify

`cd frontend && npx tsc -b --noEmit && npm run depcruise && npm run build` and `npm test`. Then look
at it: a campaign with three groups and six ads, one ad ready from the workbench and one ticked by
hand, at 1024 and 1920.

# Blocked if

The readiness payload does not carry the workbench pack/set ids needed for the per-row link — that
is F03-I08's contract. Report it; do not call the workbench API directly from the ads screens.
