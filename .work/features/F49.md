# Outcome
Drill ruler dimensions 5／6／9 (state honesty, queue, reading the platform). Five defect generators from the 2026-10-04
audit (`docs/backlog/audit-2026-10-04/README.md` W7, W8, W9, W10, W17; decisions 5, 6, 11, 12, 14 user-confirmed 2026-10-04)
disappear, each with a machine check that goes red if the pattern returns:
1. **W7 one lifecycle** — `app/ads/lifecycle.py` owns a campaign's state (draft／live／ended／closed, imported campaigns
   included) and an ad's delivery state (the platform adapter owns its status table); the runtime reads and syncs only
   campaigns that still need it; no more daily unresolvable inbox row.
2. **W8 one decision queue** — `queue_done.DECISION_KINDS` is the one list, served with each row's `decision`／`position`;
   home count = 「第 N 件／共 M 件」 = 「下一件」 = the inbox's ads-queue rows; an ended campaign gets a closeout row instead of
   new proposals; every queue page has a forward exit.
3. **W9 one read outcome** — a sync job's outcome (running／failed／partial／empty／found + reason code) is written by the sync
   and read by every screen through one hook; coverage = cleanly read days plus days with rows, clipped to the campaign;
   readback never asks the user to check fields no reader can see (decision 5) and names why a read failed.
4. **W10 slot states told as they are** — the slot read serves every stored state with its own chip and sentence (retrying,
   failed, refused assignment included); a confirmed slot can be edited before launch; a failed hand-off is retryable.
5. **W17 no origin forks** — screens open to system-built campaigns read the handoff read's destinations; the imported-only
   payload `external_view` is read only by imported-only screens.

Out of scope (features C／D chain on this branch): time rules and "yesterday" (W11 — including the closed campaign's 「近 14 天」
window, R3 N2, and the browser clock), input rules (W12), readiness (W13), background job outcome for LLM／meta jobs and the
bell (W14 — this feature writes the ads sync outcome only), http／figure／wizard (W15, W16, W18), the platform-literal ratchet
beyond the status vocabulary (W19 — the change-set pause payload `{status: "PAUSED"}` stays, allowlisted). A W7–W10／W17 fix
that needs one of those makes the minimal local change and notes the sibling in Evidence.

Agent choices (settled so workers do not invent them; recorded in `docs/architecture/ads.md` §6.51 at crank closeout):
- **Contract L — one lifecycle (W7, decisions 6, 12).** `app/ads/lifecycle.py` (new module in `app/ads`, no new package) is the
  only code that turns stored status, root entity and dates into a campaign state, and a native status into a delivery state.
  It names no platform: it calls `adapters.delivery(platform, native_status)` (same lazy dispatch seam as
  `adapters.is_auth_error`).
  delivery — each platform adapter owns `STATUS_TABLE: native → (state, label)`; states `running | not_running | off |
  unknown`. Meta (`meta_read.py`): ACTIVE → running 投放中; IN_PROCESS／PENDING_REVIEW／PREAPPROVED → not_running 審核中;
  PENDING_BILLING_INFO → not_running 待付款設定; WITH_ISSUES → not_running 有問題; DISAPPROVED → not_running 被拒登; PAUSED → off
  已暫停; ADSET_PAUSED → off 所屬廣告組已暫停; CAMPAIGN_PAUSED → off 所屬活動已暫停; ARCHIVED → off 已封存; DELETED → off 已刪除;
  None or unmapped → unknown 平台狀態不明. `lifecycle.delivery(entity) → {state, label}`; `ad_running(entity) → True` (running)
  `| False` (not_running, off) `| None` (unknown); `may_spend(entity) = state != "off"`.
  consumers — triage judges `running` and `unknown` ads (unknown is never dropped, §6.30) and lists `not_running`／`off` in its
  `closed` block with `delivery {state, label}`; capacity, cleanup, scale and refresh read the judged items; 「在投」 on the
  home row and the workspace = running count, served as `running {count, unknown, read_at, stale}` (`read_at` = the
  campaign's newest clean structure read, `stale` = `read_at` older than the newest launch item `reported_at`, drill-11 E5);
  month-budget owner eligibility = `may_spend`; `handoff_new_ad` replace／new-ad checks = `ad_running is True`; runtime
  `source_date_passed` = running past the end date; `upsert_entity.status_changed` = off-ness changed; imported slots skip
  `off` ads. `ad_status.py` is deleted. Payloads that carry `native_status` also carry `delivery_label` (triage items and closed
  block, `external_view` entities, the existing-campaign listing, change-set items' before／after／observed status as
  `status_labels`).
  campaign state — `lifecycle.state(campaign, *, root, today) → draft | live | ended | closed`. Internal: closed ⇐ stored
  `closed`; draft ⇐ stored `draft`／`ready` with no root entity read (today's `home_overview._is_draft`); ended ⇐ stored
  `ended`, or `end_date < today` once on a platform (the end date is the last delivery day — supersedes §6.36's
  `end_date <= today`); live ⇐ otherwise (stored `live`, or `ready` with a root read). Imported: draft ⇐ no root entity
  read; ended ⇐ root delivery `off` or root `end_date < today`; live otherwise. Imported is never closed (closeout stays
  internal-only). Explicit transitions stay where they are (adopt → ready, `bind_campaign` → live, closeout → closed); derived
  transitions are written only by `lifecycle.record(conn, org, brand, campaign_id)` (internal live → ended; imported
  draft／live／ended), called by the runtime tick and by `external_repository.upsert_entity` when it writes an imported
  campaign's root. Readers call `lifecycle.state`, never the stored derived value alone. The existing CHECK allows every
  value: no migration.
  selection — `lifecycle.campaign_ids(conn, org, brand, states)` and `lifecycle.brands(conn, states)` are the only
  "which campaigns" selectors; `status != 'closed'`／`status IN (...)` campaign-selection SQL lives only there. Write guards
  that refuse edits on a stored `closed` campaign stay as they are (closed is terminal and stored).
  monitoring — `ENDED_GRACE_DAYS = 7`; `lifecycle.monitored(campaign, today)` = live, or ended with `today <= end_date + 7`
  (late purchases keep landing on the last days within the platform's default 7-day click window). Closed and draft: never.
  served — campaign detail, list, home rows and workspace serve `lifecycle {state, label, can_close}`; labels draft 草稿,
  live 投放中, ended 已結束・待結案 (internal) ／ 已結束 (imported), closed 已結案. `can_close` = internal and state ∈ {live,
  ended}; `closeout.close` refuses a draft with 409 `campaign_not_launched` (planning #19). `campaign_stage.stage` takes the
  state: ended → `review` (the closeout is the step waiting), closed → `review` done. Home serves `closed_this_month` so its
  empty state never says 「還沒有活動」 over closed campaigns (drill-11 N3).
- **Contract N — the runtime follows the lifecycle (W7, R4 H3／G3; supersedes §6.36 「Monitoring is not status-driven」).**
  `runtime.dispatch` enqueues only `lifecycle.monitored` campaigns; `external_sync.request_sync` builds per-campaign sections
  only for monitored roots plus a campaign the user asked to re-read (`campaign_sync`); account tasks (`list`, `monthly:*`)
  are unchanged, so the month budget keeps reading the account. `_readback` ticks only items／actions not yet `confirmed` or
  `stale`, only for monitored campaigns. Health alerts: dedupe key `ads-runtime:{campaign}:{code}` (no date); each tick
  resolves (`interrupts.resolve(actor="system")`) the campaign's open `ads_runtime_attention` rows whose code it no longer
  raises, including old dated keys (prefix match); `plan_date_passed` is no longer an alert (the queue's closeout row carries
  it); `closeout.close` resolves the campaign's open runtime rows. `runtime._sources` reads Contract O's outcome.
- **Contract Q — one decision queue (W8, decision 6).** `queue_done.DECISION_KINDS` = `("cleanup", "worse", "closeout",
  "settle", "refresh_creative")`, in board order. `scale_budget` (shown on the money card) and `insufficient_data` (shown on
  the campaign row and `/wait`) are notices: served in the queue read with `decision: false`, never enqueued as interrupts;
  their open rows resolve at the next refresh. `get_queue` stamps every row `decision`, `done` and, for open decision rows,
  `position` (1-based in board order, settle row included); the payload carries `decisions {kinds, open}`.
  `status_summary.open_items` = `decisions.open`; `workspace_reads.pending_count` = this campaign's open decision rows
  (`queue_done.open_count`, the same function).
  closeout row — kind `closeout`, one per internal campaign in state `ended`; identity = campaign id, `window_end` = end
  date; message 「「X」已結束，待結案」; `action_url` `/brands/{b}/ads/campaigns/{c}?tab=perf&close=1`; payload `closeout
  {campaign_id, campaign_name, end_date, running {count, read_at}}`; category `ads_triage_closeout`; never done (it leaves when
  the campaign closes).
  ended campaigns — triage's cutoff is `min(account cutoff, end_date)` (Contract V's window), so dedupe keys stop moving; for
  an ended campaign a candidate is kept only when an open interrupt with its dedupe key already exists (raised before the
  end), and those stay until closeout; nothing new is enqueued. Imported ended campaigns leave the queue (no closeout exists
  for them); their rows resolve at the next refresh. Closed campaigns are not triaged (as today).
  inbox — a row whose `queue_done.done` turns true has no open interrupt once the transaction that made it done commits:
  `triage.resolve_done(conn, org, brand, *, kind, identity_id)` is called by `change_control` decide／approve, readback
  confirmation (`handoff_check._aggregate`), review round defer／complete and `closeout.close` (all of that campaign's rows).
  wait reasons — `triage.REASONS = {code: {title, text, fix}}` for every `reason_code` triage emits (`too_new`,
  `result_unknown_days`, `needs_resync`, `mixed_currency`, `no_previous_window`, `result_kind_unknown`, `target_unresolved`),
  `fix ∈ resync | connections | cap | wait | null`; served as `reasons` in F48's `GET …/rules`.
  exits — every queue page has a forward exit: `/wait` on an ended campaign offers 「結案這一期 →」; the month-budget gate
  link carries `return=<path>` and the home budget editor offers 「← 回到剛才的核准」 after saving (drill-10 D3, drill-11 Q4).
- **Contract O — one sync outcome (W9).** `external_sync.outcome(tasks, *, campaign_id=None) → {state, code, text}` (pure).
  Scope = account tasks + that campaign's tasks (every campaign task when `None`). State in order: `running` (a scoped task
  pending) → `failed` (every finished scoped task failed) → `partial` (some failed) → `empty` (none failed and the scoped
  `observations` tasks — or the `list` task when no campaign task is in scope — saved 0 rows) → `found`. `code` = the first
  failed task's `error_code` by a fixed priority (disconnected, permission_denied, unsupported, source_error, page_limit,
  invalid_source_page, invalid_monthly_scope, partial_source_page, derive_failed), `no_rows` for empty, else null; `text` from
  one table in `external_sync` (`SYNC_TEXT[state]` + `SYNC_REASONS[code]`). Tasks count their saved rows (`rows`).
  `_update_task` writes job `status ∈ {pending, succeeded, partial, failed}` (adds `failed`) and `error` = the job-wide
  outcome text when partial／failed, else NULL; the runtime's backoff row is written through
  `external_sync.record_request_failure(conn, org, brand, platform, account, code)`. Only `external_sync` reads task
  `errors`／`error_code` (connections and runtime read `outcome`; monthly coverage proof stays readable by `month_budget` and
  `connections`).
  endpoints — `GET …/sync-jobs/{id}?campaign_id=` → `{job, connected, outcome}`; `GET …/campaigns/{c}/sync-outcome` →
  `{state, code, text, job_ids, last_success_at}` = the worst over the jobs covering the campaign (its roots' accounts; no root:
  every bound account, list scope; running wins while any runs, then failed > partial > empty > found); `POST …/campaigns/{c}/sync`
  → `{job, jobs}` (every requested job; drill-11 #14). `GET …/existing-campaigns` is read-only: cached listing + `job` +
  `outcome`; an unreadable account answers 200 with cached items, `job: null` and a failed outcome (refresh stays the POST).
  frontend — `frontend/src/lib/useSyncOutcome.ts`: `useSyncOutcome({brandId, campaignId} | {brandId, jobId})` polls every 3 s
  while `running`, returns `{state, code, text, refresh}`; it is the only reader of job status／error.
- **Contract V — coverage (W9, R3 C3-D6; refines the audit's "days with rows").** `app/ads/coverage.py` (new):
  `day_states(conn, org, brand, campaign, start, end) → {date: data | empty | missing}` — `data` = a non-monthly
  `ads_external_daily` row of the campaign that day (any metric scope); `empty` = no row, but the day lies in a clean
  observations read range recorded for the campaign; `missing` otherwise. `window(campaign, cutoff, days)` ends at
  `min(cutoff, end_date)` and starts no earlier than `start_date`. `missing_days`, `covered`, `gap` derive from it; triage's
  `_coverage`／`_missing_days`／`_window_covered`／`coverage_gap` delegate or go. `record_sync` keeps `observations.ranges` = the
  merged union of clean ranges (the legacy single `coverage` is read as one range), never replaced by the last finished task;
  `simulated.extend_coverage` adds a range the same way. Triage `data` serves `days [{day, state}]` for the judged window. A
  cleanly read day with no row is `empty`, not `missing`: Meta returns no row for a zero-delivery day and `tracked_zero`
  only updates existing rows (counterexample to "days with rows" alone); consistent with §6.33 A/B and §6.34 Connections.
- **Contract B — readback (W9, R3 E2／E3, decision 5; supersedes §6.34 「a required field the platform read cannot see is
  confirmed per field」 for declared fields).** `manual_settings.FIELDS` entries carry `readable: False` (every plan field);
  `material` is `readable: False`. `handoff_check._settings` never lists a declared key as unreadable: proven by the read
  (material evidence exact／equivalent) → matched, else listed in the item's evidence `confirmed_at_approval` (labels); the
  item state is computed over readable keys. Launch-settings keys stay readable (a key the reader did not return is a read
  gap, still confirmed by eye). The launch view serves `approval_confirms [{label}]` and the approval screen prints them before
  核准; approving is that confirmation (no new stored list). Reason codes: readback raises carry a code (`SourceReadError.code`
  or a per-raise code); `handoff_check` and `change_control_verify` catch `ValueError` only (AttributeError re-raised); evidence
  stores `reason_code`, and `READBACK_REASONS` (handoff_check) gives the sentence `launch_view` prints.
  `change_control_data.worst_state(states)`: `deviated` > `unknown` > `reported` > `pending`, `confirmed` only when all are —
  read by `handoff_check._aggregate` and `triage._row_cleanup_proposal`. `change_control_data.VERIFICATION_LABELS` is served
  as `verification_label` beside every served `verification_state` (queue proposals, change sets and items, handoff items) and
  the launch view serves `state_label`; `unknown` (read, not provable) ≠ `reported` (not read yet). `upsert_entity` bumps
  `updated_at` only when a column changed.
- **Contract T — slot states (W10).** `slots.STATE_TEXT` is the one table; every slot serves `state`, `state_label` (chip) and
  `state_text` (sentence): ready 已確認; in_progress 處理中 (「圖片處理中」／「文案產生中」); retrying 處理中 「圖片預覽沒做成（{error}），
  {retry_at} 會再試」 (asset `retryable`, `next_attempt_at`); failed 失敗 「文案沒產生出來：{last_error}」 with the workbench exit
  (brief `failed`); blocked 卡住 = first stored reason (F44) — a refused assignment is stored as reason kind `assign`
  (`asset_suggestions.store_refusal`, codes `campaign_closed`／`launch_frozen`) and read even when the placement is confirmed;
  image_only 等你 「有圖，還缺文案」; copy_only 等你 「有文案，還缺圖」; waiting 等你 (the two `WAITING` sentences); missing 缺
  「還沒有素材」. Before the launch is approved a ready slot can change its copy (`choose_copy`／`recheck` revise the assigned
  placement → `follow_revision`), served as `copy_editable`; after approval the frozen sentence shows. Copy options are the campaign's sell-way only
  (`workbench.material_options(..., product_id=)`). The structure read serves `slot_state`／`slot_label` per planned ad from
  `slots.read` (`missing_material` survives only as `slot_state != "ready"` until no reader is left). Material tasks: `dispatch` on `unknown` retries `workbench.start_material_pack` on the
  stored pack (never a second pack); labels: not_requested 還沒交棒, unknown 交棒沒送出・可重試, queued 工作檯製作中, pack failed
  工作檯沒做成, candidates 有候選圖, adopted 已採用. The pack route's `nothing_to_prepare: true` is an outcome the structure tab
  prints (「這期的素材都沿用上一期，不用準備」), not an error.
- **Contract D — destinations (W17).** `handoff_data.workspace` serves `destination_by_ad {entity_id: destination_entity_id}`
  for the campaign's platform ads and `destinations_note` (null when destinations exist; internal not on a platform:
  「這個活動還沒上架，平台上還沒有投放組；新廣告請到投放結構加」; otherwise 「還沒讀到這個活動的平台結構，按重新讀取」). The payload
  `campaign.external_view` is read only by imported-only screens (`PerformanceTab`, `detail/PeriodStatusRow`, `OverviewTab`,
