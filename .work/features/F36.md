# Outcome
The nine drill-6 yellow items land as one batch of small, root-cause fixes: the campaign wizard asks the per-sale cap
instead of presenting break-even as a fact; self-brought assets take one copy for a batch and one "apply to all"; the
account-history base divides by days that actually spent; review evidence refuses an uncovered window instead of reading
zeros; the manual hand-off checklist shows the plan's audience as a read-only hint; every date default in the ads UI
reads the organisation's today from one place; same-name parent products cannot be created twice; two misleading texts
are replaced. Nothing here changes the launch rule, the cap ruling (§6.32) or the copy contract (§6.9.3).

# Decisions
**User rulings** (2026-09-28 dig, all eight recommendations accepted; prototype approved the same day):
- A (#4) 「每賣一筆最多花」 is an optional 7th field on wizard step 2; empty by default; break-even is hint text only; no ROAS
  input, no brand-level default. Saved through the existing `PUT …/target {basis:"own"}`.
- B (#15) 「照上一期」 divisor = days with spend > 0 inside the same 30-day window.
- C (#13) This batch does only the review-evidence coverage gate; retiring the manual-ingest pipeline for real campaigns
  (performance tab / `ads_outcome_daily` / closeout source) is its own /dig later.
- D (#17) Upload dialog gets 「本批共用原文」; the placements fold gets 「套用到全部待處理」 which overwrites unconfirmed
  placements only.
- E (#8) A read-only 「受眾提示」 row per group on the checklist: role label + every distinct audience coordinate label of
  its ads; never a Meta targeting mapping, never stored in the frozen snapshot.
- F (#19) No regeneration. The AI block is 「補空白文案」, disabled with its reason when nothing is blank, with a link to the
  slot picker 「選一版文案」.
- G (#20) `/api/identity/me` carries the org's `timezone` and `today`; one frontend clock helper; six date defaults use it;
  the three `revisit_at` inputs keep the browser clock (they send an instant, not a date).
- H (#16) `create_product` is get-or-create on a trimmed, case-insensitive name within the same parent scope, backed by a
  partial unique index on active rows; manual add lands on the existing product; an archived same-name product does not
  block a new active one; sell-way names are unique within their parent.
- #16 itself is re-verified as design (parent + sell-way), see `docs/backlog/handoff-after-f34.md`.

**Verified state** (at `9f1e6c3f`, three read-only evidence passes on 2026-09-28; file:line in the issues): cap resolved
read-time by `targets.resolve` (own → break-even), no wizard writer; `channels.account_spend_history` divides by a constant
30 and `_account_history` hard-codes `sample_days: 30`; `review_evidence` guards dates only, no coverage gate while
`triage._window_covered` exists; `launch_view._fields` builds group rows from the frozen snapshot which drops `role` and
`audience_key`; six ads screens compute dates from `new Date()` (some local, `AssetHandoffPanel` UTC) and `/me` has no
timezone; `create_product` has 9 callers, 5 dedupe by exact name, no unique index, no duplicates in the dev DB today;
`ScanStep` keys the empty message on photo cards while the list reads `scan_products`; `WorkbenchHomePage` names a
button that no longer exists.

**Agent choices** (reversible):
- #13-A: an uncovered observation window is refused like the date guards (`ValueError` naming the missing days), the same
  rule triage uses to grade — not a soft note.
- #8: the hint is computed at view time in `launch_view.view` from `campaign_detail` (never written into `expected_json`,
  so readback stays unchanged); `adapters/manual.describe` shows the same row so both checklists match.
- #20: `orgClock.ts` uses `Intl.DateTimeFormat` with the org timezone; `today` from `/me` is only the initial value, the
  helper recomputes from the timezone so a long-open tab does not freeze on the load date.
- #16: on a unique-index violation inside `update_product` (rename／restore) the repository raises
  `ValueError("已有同名產品")`, which `brand_web/routes_products.py` already maps to a 4xx.
- #17: 「這張另外寫」 opens a per-file editor seeded with the shared copy; apply-to-all runs `revisePlacement` per unconfirmed
  placement (no bulk route: ≤10 items, each keeps its own revision history).
- Concurrency: every issue is independent except I09 (call sites) after I08 (`/me` + helper). Two at a time.

**Rejected routes**: requiring the cap before 「產生策略」 (changes §6.32); a bulk PATCH for placements (atomicity nobody
asked for); putting the audience hint into the launch snapshot (would make every approved launch stale and readback
"unreadable"); deriving today from the browser with an offset (the org timezone is a setting, not a guess).

## Contracts (every issue uses exactly these names)
- **U. Org clock (I08 writes; I09 reads).** `GET /api/identity/me` `org` gains `timezone: str` (IANA, `settings.org_timezone`)
  and `today: "YYYY-MM-DD"` (`settings.today_for_org`). `frontend/src/lib/orgClock.ts` exports `orgToday(tz: string): string`
  and `orgDateShift(tz: string, days: number): string` (YYYY-MM-DD in that zone) and `useOrgClock()` returning
  `{ timezone, today, shift(days) }` from `useWorkspace().identity.org`.
- **V. Audience hint (I07).** Checklist group rows gain `{"key": "audience_hint", "label": "受眾提示", "value": "<角色>・<label1>、<label2>"}`
  after the date rows, only when the group has a role or any ad has an `audience_key`; `value` is plain text; never in `expected`.
- **W. Product get-or-create (I10).** `bi_repo.create_product(conn, brand_id, *, name, actor, parent_id=None)` returns the
  existing active row when `lower(btrim(name))` matches within the same `parent_id` scope (NULL-safe); the migration adds
  `product_active_parent_name_uniq (brand_id, lower(btrim(name))) WHERE parent_id IS NULL AND status='active'` and
  `product_active_sellway_name_uniq (parent_id, lower(btrim(name))) WHERE parent_id IS NOT NULL AND status='active'`.
- **UI spec = the prototype** (design-system §1.7): `.harness/scratch/prototype/f36-yellow/index.html` — `#/cap` (wizard step 2
  7th chip: empty state 「還沒填（選填）」 + hint line; editing = `.money` input, 「用打平 N」, preview line 「比打平 N 高/低 M・ROAS 參考 R」,
  完成／取消; the chip spans both columns while editing; bar hint 「有 1 項是猜的・上限沒填會先用打平」), `#/upload`
  (「本批共用原文」 block above the file list, per-file chip 「沿用共用原文」 + 「這張另外寫」), `#/placements` (「一份文案套到全部待處理」
  block, 「補空白文案（選用）」 block with count chip, disabled button + 「到素材頁選一版文案 →」). Shots in `shots/`.
