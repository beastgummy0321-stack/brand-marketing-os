# Outcome
On a draft campaign the assets tab's slot shows its two halves — the image and the copy — and the copy comes from the
program: the ad's selected workbench copy when the campaign pack produced one, else the copy of the placement in the
slot. Uploading a file into a slot whose ad already has copy carries that copy into the placement, fills the purpose,
confirms it and assigns it, so the slot is ready at once; a slot with a file but no copy offers 「選一版文案」 from the
brand's workbench copy versions. The launch rule is unchanged: no file, never ready. The 「開始做素材 →」 primary is back
on the bar of 投放結構, and a draft campaign no longer offers 「只準備新文案」 (its only exit needs a platform ad).

# Decisions
**User rulings** (2026-09-28, dig of drill-6 gap #1, prototype approved the same day):
1. The slot is two halves, 圖｜文案, with visible states 已確認／有文案，缺圖／有圖，缺文案 (and today's 缺 1 則). Copy never
   makes a slot ready on its own (§6.34 one readiness rule stands).
2. Not "approved copy becomes a placement" and not "the slot picks a set": a placement needs a file, so the automatic step
   is "when a file lands in the slot, the program carries the ad's copy in, fills the purpose, confirms and assigns". The
   picker exists only for a slot that has a file and whose ad has no workbench version.
3. A draft campaign hides 「只準備新文案」; 「開始做素材 →」 leaves the 「調整結構（進階）」 fold and is the bar's primary.
4. Prototype = UI spec: `.harness/scratch/prototype/f35-slot-copy/index.html` (`#/assets`, `#/structure`, `#/modes`), shots
   in `shots/`. The three open choices were confirmed as recommended: keep 「看圖片提示詞」 on a copy-only tile; the picker
   only on image-only tiles (changing copy on a ready slot = a new version in the workbench); purpose = the ad's name.

**Verified state** (at `c139efc0`): `slots._planned_slot` maps `readiness == "in_progress"` to in_progress and everything
else without a material to missing — a selected／approved workbench copy is invisible (`app/ads/slots.py:118`). The slot
upload sends `copy_fields: {}` (`AssetsBody.tsx:188`) and the placement then waits in the 進階 fold for the user to retype
headline／body／description and a purpose (`asset_suggestions._result` problems). The ad→set link already exists:
`workbench.briefs_for_source(... {"ads_campaign_id": c})[i]["source_ref"]["ads_ad_id"]`, read today by
`routes._enriched_campaign` (`copy_text`) and `assets.readiness`. `workbench.material_options(part="copy")` and
`material_source(set_id, version_id)` give the brand's copy versions with `copy_fields` {headline, body, description}.
`asset_suggestions.confirm_manual` is the no-AI confirmation path; `slots.settle` assigns a confirmed placement.

**Agent choices** (reversible):
- The ad's copy is the **selected** (`is_adopted`) copy output of the ad's latest set, regardless of pack approval (the
  pack lock is a separate fact; the user picked the version). Label 「工作檯第 N 版」 from `version_index`.
- Purpose auto-fill = the planned ad's name; `attach`／`attach_selected` gain a keyword `purpose` (never from the request
  body). A confirmation that still has `pending_reasons` (zero budget, missing copy) leaves the slot waiting exactly as
  today; nothing is forced.
- `image_only` = the slot's pending placement has no headline and no body in its effective copy. Any other pending or
  stale placement stays `in_progress`.
- The picker writes into the pending placement (`revise` copy_fields + purpose → `confirm_manual` → `settle`); a slot
  with no file has no picker (upload first). Canonical copy comes from `material_source`, never from echoed text.
- Slot rows carry `workbench_href` (`workbench.set_action_url` of the ad's set) for 「看圖片提示詞」／「從素材工作檯」;
  null when the ad has no set (the tab-level 到素材工作檯 stays).
- Sequential merge: I02 consumes I01's slot fields; I03 is independent and may run in parallel with I01.

**Rejected routes**: a placement without a file (schema `asset_id NOT NULL`, launch needs a creative); a copy home on
`ads_ad` (a third copy home); letting the copy-mode material task target a planned ad (the campaign pack already writes
one copy per ad); a picker on every tile (the slot would become a copy editor).

## Contracts (every issue uses exactly these names)
- **T. Slot copy (F35-I01 writes; I02 reads).** `GET …/campaigns/{c}/slots` `Slot` gains
  `copy: {source: "workbench" | "placement", label: str, headline: str | null, body: str | null, description: str | null} | null`
  and `workbench_href: str | null`; `state` adds `"copy_only"` and `"image_only"` (existing `ready`／`in_progress`／`missing`
  keep their meaning; `ready` and `total` still count the launch rule). Imported campaigns: `copy: null`, `workbench_href:
  null`, states unchanged. `POST …/slots/{ad_id}/upload` unchanged in shape; without `copy_fields` in the body it carries the
  ad's workbench copy, sets purpose, confirms and settles. New `GET …/campaigns/{c}/slots/copy-options` →
  `{"options": [{set_id, version_id, label, copy_fields}]}` (= `workbench.material_options(part="copy")`). New
  `POST …/slots/{ad_id}/copy` `{set_id, version_id}` → `{placement, slots}`; 409 `slot_no_file` 「這一格還沒有圖，先上傳圖再選文案。」
  when the slot has no pending placement, 409 frozen as the upload.
- **UI spec = the prototype** (design-system §1.7): `.harness/scratch/prototype/f35-slot-copy/index.html`. Pieces:
  `.slot[data-slot="slot-tile"][data-variant=ready|copy-only|image-only|missing|reserved]`, `.half.img` (96px thumb or the
  dashed 缺圖 box with 上傳), `.nm`, `.half.txt` (label 「✓ 文案 · <label>」 + 2-line clamp; or the dashed 缺文案 box with
  「選一版文案」), one status `Chip` (ok 已確認 / warn 有文案，缺圖 / warn 有圖，缺文案 / neutral 缺 1 則), the
  「看圖片提示詞」 link on copy-only. `#/structure`: the bar's primary 「開始做素材 →」 with hint 「交棒後工作檯替每則廣告寫文案和
  圖片提示詞；圖仍由你上傳」, after dispatch 「前往素材 →」 with hint 「工作檯做好的文案會出現在素材頁的格子裡」. `#/modes`: three
  source cards on a draft. 「新增」 purple tags are prototype-only.

# Acceptance
- Contract T: a planned ad with a selected workbench copy and no file reads `copy_only` with that copy; a file uploaded
  into it comes back confirmed and assigned in the same response (`placement.confirmed_at` set, slot `ready`); a file
  uploaded into an ad with no set reads `image_only`; `POST …/copy` with a workbench version makes it `ready`; a slot with
  no file refuses the copy with `slot_no_file`; imported slots unchanged; every existing slots test still passes.
- Assets tab renders the four tile states from the prototype; upload into copy-only needs no 進階 step; the picker lists the
  brand's copy versions and the tile flips to 已確認.
- 投放結構 bar shows 開始做素材／前往素材 by `nextStep`; a draft's material sources are three cards.
- Human item above.
