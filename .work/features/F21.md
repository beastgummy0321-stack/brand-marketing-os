# Outcome
A data-connections page at `/brands/:brandId/ads/connections`, built to v7 `connections()`: header (title, 「N 項需要處理」, read-only chip) and one status card per data source — Meta ad accounts, Meta budget amount, shop order report, product price and cost, past ad records — plus one grey unsupported-platform card. Each card shows a state chip, one fact line, the 影響 chips and one button into the EXISTING settings entry. The home page 「查看資料連線」 link lands here. Also the measured trial of `frontend/scripts/ui-evidence.cjs` against the F20-I02 baseline (59 min, 2 bounces, 240 worker calls).
# Decisions
- User-confirmed 2026-09-22: this screen is next; one screen, one issue; the HTML prototype is the spec (`docs/design-system.md` §1.7). User instruction in force for this feature: on ANY problem (failed check, mismatch against the prototype, review finding, scope or plan defect) nobody returns or reworks — the worker stops and reports, the lead pauses, investigates the root cause and reports to the user.
- User-confirmed: the Meta 「帳戶權限失效」 state has no backend data (no expiry/invalid field anywhere) and is NOT built or faked; the Meta accounts card shows account count and last read time with a neutral/ok chip only. Recorded as a gap.
- Agent choice: the frontend composes five existing GETs; no aggregation endpoint. Sources — accounts: `fetchMetaAccounts` (accounts whose `bound_brand_ids` include the brand) + `fetchMetaSpend().last_pull_at`; budget: `getMonthlyBudget` (`currency === null` or non-empty `uncertainties` → warn 「預算待核實」); orders: `fetchOrders().orders.items[0].order_date` (the list is already `ORDER BY order_date DESC` over all time, `app/orders/repository.py:438`; no backend change — `app/orders` is legacy and may not gain capability; empty list → warn 「尚未匯入」, else fact 「最新到 M/D」, warn when older than yesterday); products: `fetchProductList` (count, count with `economics_status === "confirmed"`; ok when ≥ 1); history: `fetchMetaBackfillStatus` (months between `earliest_spend_date` and `latest_spend_date`; `running` → 「帶入中」; none → warn).
- Agent choice: button targets — accounts `/settings?tab=meta`; budget `/brands/:brandId/ads` (the month budget card); orders `/brands/:brandId/orders`; products `/brands/:brandId/products`; history `/brands/:brandId/intake/history`.
- Agent choice: 影響 chips are fixed product copy per card, taken from the prototype, shown only while the card is in warn state; the campaign-name chip on the accounts card needs the missing data and is omitted.
- The unsupported-platform card is a grey non-clickable card; its platform name comes from a list constant in the page, not from shared core. Independent blocks fail independently (§1.7 item 9): one failed GET turns that card into 「讀取失敗・重試」, the other cards still render.
- The shell header 「最近同步・N 項待處理」 chip is out of scope (no brand-level sync endpoint).
- Fixture: `.harness/scratch/F21/fixture/*.json` = real responses of the five GETs from `brd_bughunt`.
- Measurement: the lead records worker minutes, tool calls and bounces from metrics and the agent result, and appends to discovery §5f. No separate report.
- Constraints: 800-line file cap; `cd frontend &&` before npm; gates via `uv run python -m <tool>`; preview port 8731＋issue number; docs committed before `integrate`.
# Acceptance
- The page renders the five cards with real data and the states above; the header count equals the number of warn cards; no horizontal overflow at 1024 and 1920; keyboard reachable.
- Each button lands on the listed existing route; 「查看資料連線」 on the home month-budget card lands on this page.
- One failing source does not blank the page. A loading state exists.
- Side-by-side evidence from `ui-evidence.cjs` under `.harness/scratch/F21/I02/`.
