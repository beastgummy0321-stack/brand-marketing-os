# Outcome
A campaign handed off by hand reaches `live` the moment launch readback binds its campaign node to a platform id, and `ended` once its planned end date has passed, so the list, the cockpit judgment and the performance tab's 結案 entry agree and a close-out (and its learning) is reachable again. The period-settle wizard keeps every pick (a non-default AI candidate or a typed custom angle) across its three steps and writes exactly what the user chose.

# Decisions
**User ruling** (2026-09-26, dig of drill-6 red group 1): option A. `live` means "bound to a platform object by readback", not "platform reports ACTIVE". Judgment copy keeps saying 不代表已投遞. Nothing writes to a platform; no issue asks the user to run real ads.

**Root causes** (verified in code at `50a36c6a`):
- `ads_campaign.status` has writers only for `ready` (`plan.py:208`), `closed` (`closeout.py:125`) and, in the simulated adapter only, `live`; nothing anywhere writes `ended`. `PerformanceTab.tsx:195` shows the 成效／結案 block only for live/ended/closed, so a manually launched campaign can never be closed from the UI, hence never writes a learning. Monitoring is unaffected (`runtime.dispatch` keys on `ads_external_entity`, not on status); the drill audit's `jobs.py:22` claim is wrong.
- `AppShell.tsx:27` keys the page on `pathname`; the settle steps each have their own path, so `SettlePage` remounts between steps and its `picks` state resets: a custom angle bounces back to step 2, a non-default candidate silently degrades to candidate 0 (`angleOf`). Query strings do not remount (AppShell's own rule).

**Agent choices** (reversible):
- The status write lives in `repository.bind_campaign` (the one readback binding point, ads.md §6.35), guarded `status='ready'`, so the simulated adapter and re-binds are untouched. `live→ended` is written by the runtime health beat where it already emits `plan_date_passed`; ended is not closed (jobs docstring: dates prompt a review, never close).
- `ads_action.sync_state='confirmed_manual'` (column exists, no writer, read once in `judgment.py:196`) stays as is; not on this chain.
- Settle steps move to `/settle/:month?step=result|angle|note`. The old `/settle/:month/:step` path stays as a redirect so `settle.py:200`'s `action_url` and existing home links keep working; the backend does not change.

# Acceptance
- Backend test: readback binding a `ready` internal campaign's campaign node gives `status='live'`; binding a group/ad node or re-binding a live campaign leaves status alone; runtime health on a live campaign whose `end_date <= today` gives `status='ended'` plus the existing `plan_date_passed` alert; a `closed` campaign is never touched.
- Frontend test: inside a wrapper that re-keys on `pathname` (AppShell's behaviour), picking candidate 2 on one row and a custom angle on another, then 下一步, renders step 3 with those picks and the POST body carries them.
