# Outcome
Judgement (triage) reads only ads that are really delivering; ads the user closed on the platform stay visible and queryable but never dilute a count, a strip or a decision. Plus the prototype's 「！資料不足」 queue row, which F24 built as a campaign-card state only.
# Decisions
- User-confirmed 2026-09-22, after reviewing `docs/design/ads/prototype-v8-active-only.html` (the approved reference for this feature): judgement reads ACTIVE ads only; closed ads are kept and shown, never hidden; 「看紀錄」 goes to the existing workspace performance tab (option A: `/brands/:b/ads/campaigns/:c?tab=performance&ad=<entityId>` — no new page).
- Measured cause (2026-09-22, real `brd_bughunt` data): `triage.classify()` selects ads by `native_kind='ad'` only (`triage.py:54`), so all 20 ads are judged although only 5 are ACTIVE (11 PAUSED, 4 ARCHIVED) — the home strip read 「資料不足 17」 mostly from closed ads. `month_budget.py:131` already excludes five statuses; `triage_scale.py:15` (F25) excludes only three; triage excludes none. One constant, three consumers.
- I01 (backend): new `app/ads/ad_status.py::CLOSED_STATUSES = {"PAUSED", "DELETED", "ARCHIVED", "ADSET_PAUSED", "CAMPAIGN_PAUSED"}` + `is_closed(status)`; `triage.py`, `triage_scale.py` and `month_budget.py` all import it (month_budget keeps its own entity-level use, same set). `classify()` judges only ads whose `native_status` is not closed AND not null (a null status is unknown, not closed → still judged, as today); its result gains `closed: {paused: N, archived: N, other: N, total: N, items: [{entity_id, name, native_status, thumbnail_url, spend, cost_per_result, result_label}]}` — the closed ads' own last-window numbers from the same `_ad_window` read (no second query), capped at 50 items with `truncated: bool`. `counts`/`total_ads` count active ads only. The queue is unaffected except that rows can no longer be raised for a closed ad.
- I01 also raises the 「資料不足」 queue row: category `ads_triage_insufficient_data` (severity `rule_warning`, label 「活動資料不足待處理」), one per campaign, dedupe `ads-triage:insufficient_data:<campaign_id>:<window_end>`, raised when the campaign's `data.missing_days` is non-empty OR `data.sync.state` is failed/disconnected (the F24 §6.25 block), and it has ≥ 1 active ad. Payload: `kind_key: "insufficient_data"`, `insufficient: {campaign_id, campaign_name, missing_days, sync_state, coverage}`; `triage` = the first active ad's item (else the first item). `kinds_available` gains it.
- I02 (frontend): `home/CampaignCard.tsx` — the count chip reads 「<目標類型>・投放中 N 則」; the strip and legend use the active counts; a new bottom line 「另有 N 則已關閉（暫停 X・已封存 Y），不列入判斷」 + 「查看 →」 to the detail page (omitted when N = 0). `detail/CampaignDetailPage.tsx` — purpose line 「只判讀投放中的 N 則；已關閉的廣告保留紀錄，不列入判斷」, groups from active ads only, plus a grey collapsed 「已關閉」 group (count + 「暫停 X・已封存 Y・不列入判斷」) listing `closed.items` with an 「已暫停／已封存」 chip and a 「看紀錄」 button to `?tab=performance&ad=<id>`; `truncated` → a last line 「…其餘 N 則」. `home/QueueRow.tsx` + `home/status.ts` — the `insufficient_data` row: KindMark warning 「！資料不足」, title 「這個活動暫時無法判斷」, viz = `DayTiles` of the 7 days ending at coverage end with the missing ones hollow + captions 「缺 M/D、M/D」／the sync state, button 「去處理」 → the F24 wait page; never done.
- I03 (frontend): `month/MonthReviewPage.tsx` — 素材 groups become 有效 = active `better`; 無效・已停 = every closed ad (note 「已暫停或封存，含這個月關掉的」); 還看不出 = active `flat` + `insufficient`; the 12-tile cap stays. A grey line 「這個月關掉 N 則・關掉的原因與當時的成效都留著」 only when the backend can say N — it cannot today (no closed-at date), so the line is omitted and the group note carries the honest wording instead.
- Gaps kept honest: no 關掉時間 (Meta gives no closed-at in the entity payload), so no 「這個月關掉 N 則」 number; a null `native_status` is judged as today (unknown ≠ closed) and counted in neither closed bucket; the workspace performance tab does not yet scroll to `?ad=` — the param is passed for the future, the tab opens normally (say so in the issue, do not build scrolling).
- Constraints: as F25 (typecheck = `npm run build`; worktrees need `.env` + `frontend/.env`; uvicorn via `uv run python -m uvicorn`; kill only your own server by PID/port; never create files outside touch; ports 8731＋issue; docs before `integrate`).
# Acceptance
- On real `brd_bughunt` data the home card reads 「投放中 5 則」 with a five-class strip over 5, and 「另有 15 則已關閉（暫停 11・已封存 4）」; the detail page lists the 15 under a collapsed group with working 「看紀錄」 links; the monthly review groups follow the new rule; a campaign with missing sync days shows the 「！資料不足」 queue row leading to the wait page.
