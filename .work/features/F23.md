# Outcome
A 變差 row on the ads-centre home leads into steps 1–3 of the v7 six-step flow — 看證據 (`review()`, with the async 「AI 正在整理證據」 state and the 暫緩／無法判定 sheet), 選方向 (`prepare()`), 改文案 (`copy()`) — on top of the EXISTING review-round API (`frontend/src/lib/adsReviewApi.ts`, `app/ads/review_rounds.py`) and change-control API. Step 3 hands into the F22 confirm page with a `copy` change set carrying `review_id`/`recommendation_id`. The home queue row shows where a 變差 item stands.
# Decisions
- User-confirmed 2026-09-22: batch B follows batch A's workflow; the ladder 改文案→換圖→退役 is a GREY PLACEHOLDER (option A): every step grey, labelled 接上後開放; 選方向 offers 只改文案 and 停掉這則 (→ F22 propose/pause route) and 先觀察 (= review `deferred`); 換一張圖 and 用現成素材 are reserved cards. User goal: finish every prototype screen of the ads centre this conversation.
- Agent choice — routes: `/brands/:brandId/ads/campaigns/:campaignId/review/:entityId` (entry from a 變差 row: loads or creates the review round for the row's triage window), then `.../reviews/:reviewId` (看證據), `.../reviews/:reviewId/prepare`, `.../reviews/:reviewId/copy`. Entering `review/:entityId` FIRST uses the queue row's `proposal.review_id` when present (navigate replace, no request); only with no proposal does it call `createReview({entity_id, start: triage.window.start, end: triage.window.end})` (backend dedupes on `evidence_hash`), then `navigate(replace)` to `reviews/:id`. The triage window's `end` moves every day (`triage.py:120,264`), so the round is never re-created from the window alone. createReview can be refused (campaign closed, `end >= today`, LLM budget `_reserve`, `review_evidence.py:222-228`, `review_rounds.py:82-83`) → the page shows the backend message with 「回投放中心」.
- Field → state rules (challenged against the backend before dispatch; corrections land here):
  - Review step from a round: `status` queued/running → 看證據 with the async card (poll); waiting → NOT the async card: a card 「資料還不夠，這回先不判」 listing `evidence_json.waiting_reasons` (a waiting round never advances by itself, `review_rounds.py:198`); failed/unknown → card with `error` — no retry button (`submit()` dedupes on evidence, `review_rounds.py:151-163`, so re-sending returns the same round); in waiting/failed/unknown the bar offers only 先不決定 (deferred/unjudgeable are legal from those states); ready → 看證據 with evidence; decision completed → 選方向 (or 改文案 when a `copy` change set with this `review_id` exists — I01 tells); deferred → 看證據 closed 「M/D 重看・reason」 with 「改變決定」 = the sheet again offering only 暫緩 (new time) / 無法判定 — `completed` is legal only from `ready` (`review_rounds.py:221-224`), so a deferred round cannot proceed to 選方向; the closed bar says 「要改文案請等下一回證據」; unjudgeable → closed 「無法判定・reason」, same 改變決定 options.
  - 看證據 cards: (1) AI 建議 = the first recommendation of `result_json.recommendations` (title by `recommendation`: adjust 「保留圖片，換文案試試」, observe 「先觀察一段時間」, retain 「維持現狀」, new_test 「做新的素材測試」; why = `hypothesis`; 依據與風險 = `risks` + `next_step`); no recommendations → the card says 「AI 沒有給出建議」 + `result_json.limitations`. (2) 這則廣告 rows from `evidence_json.current/previous`: 花費 = the SUM of `series` with `metric_scope === "ad"` (any null → unknown, more than one currency → unknown — same as `triage.py::_ad_spend`, lines 138-150; NOT `series[0]`, which `ReviewEvidence.tsx:32` uses and is an arbitrary attribution); 成果數／單次成本 = the `result_views` entry with `metric_scope === "ad"` (`result_count`, `cost_per_result`, label from the triage `result_label`); ROAS row omitted (no per-ad revenue accessor is trustworthy) — three rows, not four; the 「N/M 天有資料」 chip = `current.days_present`/`days_expected`; 「目標 X」 from the triage target (queue row) when present. (3) 商城訂單 rows from `evidence_json.commerce.current/previous.order_summary`: 訂單數 = `count`, 訂單淨額 = `order_net_amount`, 已付款淨額 = `paid_net_amount` (null → 待確認); `coverage` is always the literal "unknown" (`app/orders/commerce_evidence.py:88`), so it is NOT a condition: the 「報表期間待確認」 chip shows only when `unknown_amount_count > 0 || unknown_payment_count > 0`; 「補報表」 → `/brands/:brandId/orders`. No commerce evidence (`commerce` missing/null) → the card is omitted. Legend dates from `evidence_json.window`.
  - Sheet (先不決定 ▾): 暫緩 = decideReview deferred + future `revisit_at` (timezone ISO); 無法判定 = unjudgeable.
  - 選方向: options copy / observe / retire / image (reserved) / existing (reserved). Recommended = copy when the first recommendation is `adjust`, observe when `observe`, none otherwise. Save: copy → decideReview completed (reason) → 改文案; observe → decideReview deferred WITH a required future `revisit_at` (timezone ISO; the page shows the 何時重看 segmented picker like the sheet) → 看證據 closed; retire → decideReview completed → F22 `propose/pause/:entityId`. `completed` is only allowed from `ready`; a round already `completed` skips the decide call.
  - 改文案: 目前 = `evidence_json.conditions.creative_snapshot.copy_fields` (title/body keys as the existing copy flow uses them — worker reads `ChangeComposer.tsx`); 新版 prefilled from the adjust recommendation's `suggested_copy` (else empty); reason default 「測試新的文案訴求」. 加入變更清單 = createChangeSet `{kind:"copy", target_id: review.entity_id, after: only the NON-EMPTY of {title, body} (an empty string is refused, `change_control_data.py:175-177`; a subset is legal), reason}` with `review_id` + `recommendation_id` (the backend requires the recommendation to be `adjust`; when none is, the set is created WITHOUT the pair and the page says so in one line) and `operation_id = review-copy:<reviewId>:<uuid in page state>`; then navigate to F22 `changes/:setId/confirm`. Lost response → retry with the same body. A 409 (premise changed / age > 30 days / non-adjust) shows the backend message; the page keeps the draft. 「要更多版本 →」 links to the existing material workbench route the `ReviewPanel` uses (`?tab=assets&material_new=1&review=…`).
  - Queue row state for `worse` rows (I01 `proposal`, kind `"review"`): the newest review round of this entity whose `window_end` falls inside `[triage.window.start, triage.window.end]` (the window end moves daily, an exact match would lose the round the next morning); none → 「看證據」 → `review/:entityId`; queued/running/waiting → 「整理證據中」 → reviews/:id; ready → 「等你決定」; completed with a copy set → that set's step via the F22 labels; completed without → 「選方向」 → prepare; deferred → 「M/D 重看」 (done); unjudgeable → 「無法判定」 (done); failed/unknown → 「證據沒整理成」 → reviews/:id; waiting → 「資料不足」 → reviews/:id.
- Gaps kept honest: ladder placeholder (above); 「這條素材的紀錄」 card (non-sales campaigns) has no data → omitted, the 商城訂單 card is shown for every campaign that has commerce evidence; brand-learning not involved here.
- Lead work before dispatch: kit pieces added in `patterns/ReviewPieces.tsx` (EvidenceRow, Ladder, OptionCard, CopyBlock) + `ui-evidence.cjs --settle`; references in `.harness/scratch/F23/ref/` (review via `--settle 1600`, review-sheet via `--acts menu,sheetOpen`, prepare via `--acts toPrepare`, copy via `--acts toPrepare,savePrepare`).
- Constraints: as F22 (800-line cap; `cd frontend &&`; `uv run python -m`; ports 8731＋issue; docs before `integrate`). The review round calls the LLM through the existing gateway (local `codex_cli` in dev); nothing writes to a platform; no issue asks the user to run real ads.
- Pre-dispatch challenge 2026-09-22 (108 s, read-only): eight corrections folded in above (window matching, no retry on failed/waiting, deferred cannot complete, observe needs revisit_at, per-ad spend accessor, `coverage` constant, empty copy fields, unknown/409 states). Sound: date strings accepted by CreateRequest; recommendation vocabulary; commerce fields; `ChangeControl.tsx:51` set shape; 30-day age never hit for ≤28-day windows.
# Acceptance
- From a 變差 row: 看證據 shows the async card, then the three evidence cards from the real round; 先不決定 defers or marks unjudgeable with a reason; 選方向 saves the direction; 改文案 creates the copy change set and lands on the F22 confirm page, which then leads through handoff and verify.
- Reload on any step lands on the step the round is in; a lost response can be retried without duplicates.
