# Outcome
A campaign detail page built to v7 `campPage()`: header (name, objective・count, target, budget chips, 調整目標, 全部資料 ›), the campaign's ads grouped by triage class (停損／變差 open, others folded), each row with thumbnail, name, spend, cost per result and a 去處理 button when the ad is in the decision queue. The home campaign card and the queue's 看證據 land here; the existing five-tab workspace stays where it is and is reached through 全部資料 ›. This feature is also the measured trial of harness 3.0.6 + the four UI workflow rules.
# Decisions
- User-confirmed 2026-09-21: frontend first; one screen per issue; the issue's layout spec is the reference screenshots (1024／1920), not prose; workers develop against a realistic-shape fixture; hand-in carries a 「參考圖｜成品」 side-by-side; the lead compares before review; the user reviews once after the whole batch; agents do not stop mid-way. Stop and report on pointless rework, surplus documents or forced long .md reads. Rules: `docs/design-system.md` §1.7, CLAUDE.md.
- User-confirmed: capabilities without a backend are grey, non-clickable 「接上後開放」 placeholders (`ReservedSlotCard`); never faked, no backend added for them. On this screen: the 改文案→換圖→退役 ladder, the 「同時在投 N 則／提議暫停」 capacity card, the 「14 天幾乎沒投」 chip (definition still open, discovery §6). The ladder and idle chip are simply omitted from rows; the capacity card is one placeholder.
- Agent choice: the detail page gets a new route `/brands/:brandId/ads/campaigns/:campaignId/detail`; the workspace URL `/brands/:brandId/ads/campaigns/:campaignId` is unchanged (12 frontend files, backend action URLs and three e2e specs link to it). Only the home campaign card name, the target page's back link and new queue rows' `action_url` move to the detail route.
- Agent choice: 看證據 anchors on the ad through `?ad=<entity_id>` (opens that ad's group, scrolls to and highlights the row). Closes discovery §5c gap 1.
- User-confirmed 2026-09-22: the spec is the HTML prototype itself, not screenshots of it. `docs/design/ads/prototype-v7-ads-center.html`, `campPage()` (≈ lines 341–355) plus the CSS classes it uses; open it in a browser at `#/camp/<id>` (ids in the `CAMP` object; one with a target, one without) and click through it. Do not copy its inline styles — use the kit, tokens and `components/ads/patterns`. Screenshots of it are only the left half of the side-by-side evidence; the worker captures them. Fixture: `.harness/scratch/F20/fixture/triage.json` = a real `GET …/triage` response from `brd_bughunt`.
- Labels come from the backend (`label`, `result_label`); the frontend never prints a raw `class` or `result_kind`. No platform, brand or industry literal in new components. No currency symbol (responses carry no currency, §5c).
- Measurement (user-requested): the lead records per-stage time from `.harness/metrics.jsonl`, review bounce count and documents read, and appends one short section after discovery §5c. No separate report file.
- Constraints: 800-line file cap; `cd frontend &&` before npm; gates via `uv run python -m <tool>`; preview port 8731＋issue number; merges serial (e2e port 8720); docs committed before `integrate`.
# Acceptance
- Detail page shows real triage items grouped by class with counts; 停損／變差 open by default; empty classes hidden; rows show thumbnail (neutral tile when none or load error), name, spend, cost per result.
- Ads present in the open decision queue show 去處理 → the queue item's existing action; others show no button.
- No-target state: warn band with 設定目標 → target route, all ads still listed. Read failure: retry. Loading and zero-ads states exist.
- `?ad=` opens and highlights the row; home card name and new 看證據 links land on the detail page; 全部資料 › opens the workspace.
- Keyboard reachable; no horizontal overflow at 1024 and 1920; side-by-side evidence under `.harness/scratch/F20/<issue>/`.
