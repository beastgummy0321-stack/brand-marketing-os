# Outcome
A 停損 row on the ads-centre home leads into the v7 three-step "light" flow — 確認提議 (`confirmPage()`), 到平台完成 (`handoff()`), 核對結果 (`verify()`) — plus the 拒絕／暫緩 sheet, on top of the EXISTING change-control API (`frontend/src/lib/adsChangeApi.ts`, `app/ads/change_*.py`). The home queue row shows where each item stands (等你決定／等你核准／到平台完成／核對中／已核對／已拒絕／M/D 重看). The three pages render any change set by item kind (`pause`, `budget`, `copy`), but only `pause` has an entry this batch: 加預算 has no queue source (`kinds_pending`) and 改文案 arrives with steps 1–3 (handoff batch B).
# Decisions
- User instruction 2026-09-22 (`docs/backlog/handoff-v7-remaining-screens.md`): build the remaining v7 screens with the F21 workflow; one screen, one issue; the HTML prototype is the spec (`docs/design-system.md` §1.7). On ANY problem the worker stops and reports; the lead finds the root cause first. The user reviews once after the batch merges.
- Agent choice — routes (must not depend on the queue row: the interrupt id changes every day with `window.end`, §6.18, and the row vanishes when the ad leaves `stop_loss`):
  - `/brands/:brandId/ads/campaigns/:campaignId/propose/pause/:entityId` — confirm page for a proposal that has no change set yet.
  - `/brands/:brandId/ads/campaigns/:campaignId/changes/:setId/confirm|handoff|verify` — everything after the set exists.
- Agent choice — the draft is created lazily, on the first write (核准, 拒絕 or 暫緩), never on page load: `createChangeSet` with first reuse `proposal.change_set_id` when the queue row has one; else `operation_id = "triage-pause:<entityId>:<uuid kept in page state>"` (the backend dedupes on `operation_id`, and its request hash covers title and month, so the SAME id and body are resent after 「未收到伺服器回應」; never derived from `window.end`, which changes daily), `title = "暫停「<ad name, cut to 60 chars; null → 未命名廣告>」"`, `month` = current `YYYY-MM` (browser local), one item `{kind:"pause", target_id: triage.entity_id, after:{status:"PAUSED"}, reason:"花費超過停損線（目標 × 3）仍未達成目標"}`; then `approveChangeSet` / `decideChangeSet` (`revisit_at` is always a timezone-carrying ISO instant, as `ChangeSetView.tsx:74` sends it; a date-only string is refused). When approve answers 409 because the premise changed, the page rebuilds the draft once with a NEW `operation_id` and `supersedes_id` = the old set, and asks for approval again; then `navigate(replace)` to the `changes/:setId/...` route.
- Field → state rules (to be challenged against the backend before dispatch; corrections land here):
  - Step from a change set: `status` draft → confirm; rejected/deferred/superseded → confirm, closed (chip 「已拒絕／已暫緩・reason」, superseded → 「已由新清單取代」); approved + item `verification_state` pending AND `reported_at === null` → handoff; pending with `reported_at` set (the read-back found the old setting; `check()` writes `pending` back with `setting_matches=false`, `change_control_verify.py:116`) → verify 「平台上還是原本的設定」 + `evidence_json.message`, primary 「回平台完成」, secondary 「重新核對」 (`report` is a no-op once `reported_at` is set, so only `check` is called); reported/unknown → verify 「核對中」 (the prototype has no such state: neutral hero 「還沒讀到平台上的新設定」 + `evidence_json.message` + 「重新核對」); confirmed → verify ok; deviated → verify warn; stale → verify bad (`stale_reason`/`evidence_json.message`). A page opened on the wrong step redirects to the right one, as the prototype does. Multi-item sets: the flow shows `items[0]` only when `items.length === 1`; otherwise it links to the campaign workspace change list (existing `ChangeControl`) instead of rendering.
  - Confirm (pause): ad name/thumbnail from the queue/triage item (`name`, `thumbnail_url`; null → neutral tile), meter = `current.spend` against `target.value × 3`, caption 「已花 X・<result_label> N・D 天」 from `current.result_count`, `window.days`; any null → same honest texts as `home/QueueRow.tsx`. When entered by `:setId` and the triage item is gone, the evidence block falls back to the item's `target.name` and `reason` only.
  - Verify: 「讀回於」 = `evidence_json.observed_at` (the two `*_at` columns are COALESCE-written once and go stale), browser-local time; absent → 「尚未讀到」; rail cells only from fields that exist (設定相符 from `evidence_json.setting_matches === true`); cells with no data source (花費停止, 學習期, 成效回看) are omitted.
  - Queue row state (I01 payload `proposal`): for a `stop_loss` row, the newest (`created_at DESC`) change set of the row's campaign whose `status != 'superseded'` and whose items include `kind == "pause"` with `target_id == triage.entity_id`; `proposal.verification_state` is that matching item's; a set with more than one item is reported with `multi: true` and the row links to the campaign workspace; a deferred set counts as none once `revisit_at <= now()`; `stale` and `deviated`-then-abandoned are NOT hidden (the row leads to verify, whose primary action re-proposes with `supersedes_id`); a `confirmed` set counts only while the ad entity's current `native_status` is still paused — triage does not read `native_status` (`triage.py:228-307`), so a paused ad can stay `stop_loss` for up to 28 days and a re-enabled one must get a fresh proposal; a rejected set counts only while its `created_at` day is inside the row's current `triage.window` (start..end), so an old refusal does not silence a new window forever. `worse` rows: always `null` this batch. None → 「等你決定」 → propose route; else label/step as above.
- Gaps, shown honestly, not faked: 「這則主打什麼？」 brand-learning tags and the 「已記入品牌學習」 rail cell have no backend (only `closeout` writes learnings) → one grey `ReservedSlotCard` on confirm, nothing on verify. 「第 N 件／共 M 件」 = position among the queue's open items; omitted when the item is no longer in the queue.
- Agent choice — 「↗ 打開平台」: the backend has no platform link today. I01 adds `platform_url` (nullable) per change item at READ time through an adapter function (no Meta string in shared core; never stored in `plan_json`, so hashes do not change). `null` → the button is replaced by the target's name and native id with 「複製編號」.
- Lead work before dispatch (workers keep `patterns/**` and `frontend/scripts/**` in `do_not_touch`): add the missing kit pieces to `components/ads/patterns` with `data-slot` + variant attribute and a mapping line in `ui-evidence.cjs` (all in `patterns/FlowPieces.tsx`): `FlowHeader` (`.sh/.dots/.d/.dl/.qpos/.camp` + title/purpose), `Meter` (`.meter/.cap`; `home/QueueRow.tsx` keeps its own copy — not refactored in this feature), `KindMark` (`.kind.stop/.up`), `TodoRow` (`.todo/.no`), `ResultHero` (`.hero.ok/.warn/.bad`), `StatusRail` (`.rail`), `Segmented` (`.seg`), `ActionBar` (`.bar`, sticky like `CampaignTargetPage`), `DecisionSheet` (`.sheet/.fld`). Already added: `ui-evidence.cjs --acts` (click prototype `data-act`s to reach a later step).
- References: `.harness/scratch/F22/ref/` (confirm-pause, handoff-pause via `--acts approve`, verify-pause via `--acts approve,report`, sheet via `--acts rejectSheet`).
- Constraints: 800-line file cap; `cd frontend &&` before npm; gates via `uv run python -m <tool>`; preview port 8731＋issue number; dev commands through the source CLI `run`; docs committed before `integrate`. Nothing in this feature writes to a platform; no issue, doc or report asks the user to run real ads.
- Pre-dispatch challenge 2026-09-22 (85 s, read-only, against the backend code): seven rule corrections folded in above; sound as written: pause is not hit by the month-stale override, `approve` is idempotent, any triage `entity_id` is a valid pause target, approved sets cannot be rejected/deferred (no such buttons on handoff/verify).
# Acceptance
- From a 停損 queue row: confirm → approve → handoff → 「我做完了，開始核對」 → verify, each page matching its reference at 1024 and 1920; reject and defer close the item with a reason (defer requires a future date) and the home row shows the result.
- Reload or direct URL on any step lands on the step the change set is actually in; a lost response on create/approve can be retried without duplicates.
- Budget and copy change sets created elsewhere render in the same three pages.
- Side-by-side evidence under `.harness/scratch/F22/<issue>/`.
