# Outcome
Every failure the drill-10 operator and fault agents hit says **why**, offers **one exit that fixes that reason**, and **keeps the
user's data**; controls that looked dead react; the main cosmetic defects are gone. Scope = drill-10 report §4.2 groups root
cause 4 (Q1, Q2, Q3, Q5, Q6, Q7, Q8 — not B2), root cause 6 (V1–V9), root cause 7 (W1–W4), root cause 8 (R1–R6), S3, the main
§4.3 cosmetics, drill-9 open #4 (「在投」) and #5 (manual re-read = R6). Each group disappears from one upstream change:
1. **Input checks live where values are stored** (V1, V3–V6, Q6): one rule module, every store path uses it; the frontend never
   coerces a typed value and shows the server's sentence.
2. **One way to turn a failed response into a sentence** (V2) and one copy / disabled-reason / close-label piece (cosmetics, V7).
3. **Background work says when the worker stopped** (W1, W2) and the workbench recovers from its own races and overrides (W4, Q7).
4. **Unreadable is never reported as read** (R1–R6): a read keeps what it read and what failed; Meta errors have one classifier;
   a failed account read can be re-read from the connections page.
5. **A queue row's done-ness has one owner** (Q1–Q3) and the top bar, home and 「下一件」 read it; the top bar's anomaly count is
   the connections page's own count (Q4).
6. **The campaign overview tells "on the platform, not spending yet" from "spending" from "closed"** (S3, drill-9 #4).

# Decisions
User-confirmed (2026-10-02, carve request):
- No product trade-offs in this feature: every fix is 「原因＋出口＋資料不丟」. A worker who finds a fix needs a product choice not
  settled below stops and reports (issue `Blocked if`).
- Runs after F45 and F46 (base = master after both merge). Not in scope here (owned by them): B1/B2/B3, M1–M2, S1–S2, L1–L6,
  P1–P5, D1–D5, O1–O3, the sell-way editor rows, slot states, the pause proposal page's ad lookup, closeout next step.
- UI: these are fixes on existing screens with no new layout. Per CLAUDE.md 「UIUX 驗收」 the reference for each UI issue is the
  drill-10 screenshot(s) it names (`.harness/scratch/drill10/…`, the 「before」) plus the existing screen; the worker delivers a
  「演練十截圖｜成品」 pair per listed screenshot. A change that would need a new layout is out of scope: stop and report.

Agent choices (settled so workers do not invent them; record in the domain pages at crank closeout):
- **Contract A — input rules (backend, `app/core/input_rules.py`, new).** A store either keeps exactly what was sent or refuses
  with one Chinese sentence naming the field; it never coerces (no negative → 0, no 0 → unset, no clamp). Optional number sent
  empty / `null` = unset. Rules:
  money — finite; selling price `> 0`; cost fields `>= 0`; shipping may be negative (the form already promises 「可填負數表示折抵」)
  and is stored as typed; monthly budget total `> 0` (unset = `null`; 0 has no planning meaning and divides by zero on the home
  chart); channel revenue `>= 0` and 0 is stored as 0; group daily budget `> 0` (unchanged).
  ranges — each rule-card number field declares its own bounds (a margin is `0 < x < 1`); a (min, max) pair with min > max is
  refused; dates: end `>=` start (the stored other side counts when only one side is patched).
  ids — pixel id format belongs to the platform adapter (Meta: digits only, 10–20 long); a platform without a rule accepts any
  non-empty text.
  bid — `launch_settings.bid_amount` (money `> 0`) is required when `bid_strategy` is `cost_cap` or `bid_cap` and cleared
  otherwise; it is written into the handoff copy next to 出價方式; it is not a readback field.
  uploads — one content sniff (JPEG, PNG, WebP, GIF, MP4, MOV signatures) in the same module; `app/ads/media_probe.sniff`
  delegates to it. Each path keeps its own allowed kinds and size cap (brand photos JPEG/PNG/WebP ≤ 10 MB; library assets
  JPEG/PNG/WebP/GIF ≤ 50 MB; campaign slots unchanged). Content wins over the file name: a real PNG named `.jpg` is accepted and
  stored with the sniffed type; an empty file → 「「〈name〉」是空的檔案，請換一個。」; other content → 「「〈name〉」的內容不是
  〈allowed kinds〉圖片，請換一張。」.
  copy apply (Q6) — an empty field means "keep the current text"; all fields empty → refused 「三欄都是空的，沒有可以套用的內容。」.
- **Contract B — frontend failure plumbing (shell).** `lib/http.ts` is the only place that turns a non-OK response into an
  `Error` (`errorMessageFromResponse` already reads both envelopes and `detail`); a 「…（狀態碼 N）」 text exists only as the fallback
  passed to it. A guard test fails when a `lib/*.ts` file builds a status-code message without it, or when `navigator.clipboard`
  is called outside `CopyIconButton` / `ads/patterns/CopyField`. Copy feedback: visible text 「已複製」 for 2 s; failure
  「請手動選取複製」. `Button` gains optional `disabledReason` (one muted sentence shown while disabled). `useFormSubmit`'s error
  clears as soon as a field value changes. Dialog close label 「關閉」. Supabase sign-in errors are shown in Chinese; a 401 redirect
  says 「登入已過期，請重新登入」 on the login page.
- **Contract C — worker liveness.** `background.queue_snapshot()` gains `worker_alive: bool` = some `procrastinate_workers` row has
  `last_heartbeat` within **60 s** (procrastinate heartbeats every ~10 s); memory-queue mode → `true`. `GET /api/jobs/active` adds
  `worker_alive` and `stalled: bool` (= not alive and the org has ≥ 1 queued/running job). One frontend hook + one notice:
  「背景程式停了：這件工作還排著，已填的資料沒丟。重新啟動行銷系統後會自動接著做。」 + 「再檢查一次」. Shown by the jobs bell and
  every page that waits on a job (brand site read, product page read, campaign copy generation, workbench set generation).
  Callers commit the rows a job reads before enqueueing it (documented in `app/background/__init__.py`; fixed where the race is
  evidenced: `app/workbench/repository.py`).
- **Contract D — queue done-ness (ads backend owns it).** Every row of the brand queue read carries `done: bool`, computed in one
  pure Python function with today's `home/status.ts::isQueueItemDone` rule (deferred / rejected / confirmed proposals are done; a
  cleanup row is done once its set is done; refresh / insufficient rows never). `status_summary.open_items` counts rows with
  `done = false`. The frontend reads `item.done`; no second copy of the rule. A cleanup candidate with zero closable ads is not
  an open row.
- **Contract E — campaign delivery (workspace read).** `delivery: "waiting" | "live" | null`: `null` for a draft, a closed campaign,
  or when the read failed (unknown is never promoted); `waiting` when the campaign is on the platform and the sync table has no
  day with spend > 0 for it; else `live`. 「在投」 = the campaign's platform ads whose own status is not closed
  (`ad_status.is_closed`), shown only for a non-closed campaign; a closed campaign with such ads reads
  「已結案・平台上還開著 N 則」. Overview wording for `waiting`: 「已上架，等平台開始投放」 /
  「平台開始花錢後，下次同步（HH:MM）會出現第一筆數字。」; the money cells read 「還沒開始花」 instead of 「未知」.
- **Contract F — a read keeps its input and its failures.** The brand prefill stores `urls_read` and
  `pages_failed: [{url, reason}]`; `GET …/onboarding/scan` returns them; a saved URL list that differs from `urls_read` makes the
  old result stale and the scan startable again. The product page read uses the URL sent with the retry (`start_scan` accepts
  `page_url`, stores it, then reads it). 「讀完你的網站了」 only when ≥ 1 page was read.
- **Contract G — one Meta error classifier** in `app/meta/graph.py`: `auth` (190 and its subcodes), `scope` (100, 10, 200–299 —
  today's mapping), `transient` (`retryable`, 1, 2, 4, 17, 32, 341, 613, 80000–80014), `other`. Token connect: `auth` → today's
  「Meta 拒絕了這個權杖」; `scope` → today's text; `transient` / `other` → 502 「Meta 暫時讀不到（代碼 N），這把權杖還沒驗證、
  沒有存。請稍後再試。」. A token that lists zero accounts is not stored: 400 「這把權杖讀不到任何廣告帳戶：可能填錯，或這個帳號
  沒有廣告帳戶的權限。」 and the token input stays on screen. `app/ads/adapters.is_auth_error` for Meta reads the same classifier.
- **Contract H — connections.** Each `ad_account` source gains `reread: {platform, source_account, start, end} | null` (non-null
  for `failed`, `missing_days`, `never`; `start`/`end` = the missing range or the month window); 「重新讀取」 posts the existing
  `…/existing-campaigns/refresh`. A failed source's note is reason + gap (today the gap hides the reason). The status summary
  replaces `failing_campaigns` with `attention: {count, note}` taken from `connections.get_connections` (same number and first
  note the page shows); the top bar reads 「N 個資料來源要處理」.
- **Workbench override (Q7):** a pack approved with a manual override keeps `approved_at` (ads keep reading it), but a set that
  still misses a required output stays open for generating / selecting **the missing parts only**; selections already made stay
  locked. Supersedes `docs/architecture/workbench.md`'s "approval locks every selection" for that case.
- **Product suggestion cards (Q8):** a suggestion is hidden when a product has the same name (casefold) or the same page URL, and
  each card gets 「不用了」, stored as a dismissed-name list inside the intake draft's `prefill_json` (no migration).
- Money display: every per-sale / money figure on ads screens rounds with the one `formatAmount` (no `Math.floor`); CSV numbers
  are written rounded to 2 decimals by `ads/patterns/csv.ts`.
- Legacy code: most stores, the job queue, the jobs route and the Meta client are legacy (`ARCHITECTURE.md` §2). These are
  defect fixes of existing legacy behaviour, not new capability; issues that touch legacy carry `legacy_migration: true` and
  `review: planner`. `app/core/input_rules.py` is declared a legacy facade (manifest, this carve) so `ads` and `intake` reach the
  one rule module instead of keeping copies.
- No migration is expected. If an issue needs one: `supabase/migrations/2026100400003N_<module>_<desc>.sql`, lead applies it to
  54322 before merge.

Open (none block a worker): see Evidence for the items left out on purpose.
