# Outcome
Backend only, no LLM, no platform writes. An absent platform action becomes a marked derived zero under the ruled three conditions; every imported ad is classified by program against its own previous window; a brand-level queue lists the 停損 / 變差 decisions through the existing `interrupts` inbox. The v7 front end, pause/scale proposals and suppression are later batches.
# Decisions
- User-confirmed (discovery `docs/backlog/discovery-creative-lifecycle-and-triage.md` §2, §5a): program triage without LLM; own previous window; sample gate spend ≥ 3 × target cost or ≥ 7 days with enough events; window auto-extends 7 → 14 → 28; stop-loss = spend ≥ 3 × target with zero results; objective-aware via `result_kind` + target; conditional tracked zero needs all three conditions and must stay distinguishable from a platform-reported number.
- User-confirmed 2026-09-21 numeric defaults: `MIN_RESULT_EVENTS = 10`; `OBSERVATION_WINDOW_DAYS = 28`; `FLAT_BAND = 0.20`.
- Shared contract (agent choice, frozen before issues run):
  - class enum `stop_loss | worse | better | flat | insufficient | no_target`; Chinese labels 停損·變差·變好·持平·資料不足·尚未設定目標 are produced by `app/ads`.
  - reason codes: `spend_over_target_no_result`; `cost_per_result_up|_down|_flat`; `below_sample_gate | no_previous_window | result_unknown_days | needs_resync | mixed_result_definition`; `target_unresolved | result_kind_unknown`.
  - triage item: `{entity_id, native_id, name, campaign_id, class, label, reason_code, window:{start,end,days,previous_start,previous_end,extended_from}, target:{value,basis,result_kind,missing[]}, current:{spend,result_count,cost_per_result,result_kind,derived_zero_days,reason}, previous:{same}, change_pct, sample:{gate,spend_multiple,days_with_events}}`.
  - derived zero = `ads_external_daily.result_count = 0` with `availability.result_count = "derived_zero"` (platform-reported stays `"available"`, unknown stays `"unknown"`). No migration; `ads_outcome_daily` is not touched in this batch.
- Core stays platform-neutral: no platform literal in `tracked_zero.py` / `triage.py`; platform specifics stay in adapters (`docs/architecture/ads.md` §6.14).
- Queue kinds in this batch: `stop_loss`, `worse` only. `scale_budget` and `refresh_creative` are reported as pending, never as an empty "nothing to do".
- Known doc drift for workers: `docs/architecture/ads.md:630-633` says `METRICS` gained `result_count` / `cost_per_result`; the code did not (`app/ads/review_evidence.py:18,135-140`). Result metrics live only in `result_views`.
# Acceptance
- Each of the three conditions independently blocks a derived zero; a re-sync re-derives idempotently.
- Every class and reason code is covered by tests; a non-sales ad with an incidental purchase is never judged on purchases; stop-loss never fires without a target.
- Queue enqueue is idempotent per window; existing 首頁待辦 ordering and counts are unchanged for brands with no triage items.
- Human acceptance runs on real synced data.
