# Outcome
The five drill-8 small items (report `docs/drills/drill-8/report.md` §3 #3 #4 #5 #6 #11) plus the advanced-assignment copy bug
land at their root cause, against the approved prototype `.harness/scratch/prototype/f41-drill8/index.html` (user 「可以，切票」
2026-09-30; screens ② `#/strategy`, ③ `#/assets`, ④ `#/publish` only). The prototype is the layout spec: each UI issue names its
route; the worker opens it in a browser (launch config `prototype`, port 8741).
1. **Preview done → slot ready** (#4): the preview job itself confirms and assigns every slot waiting on that original, through the
   same two calls the slot upload uses. No frontend polling change.
2. **Advanced assignment carries the ad's copy**: 「將成品指派給計畫中的廣告」 ships the ad's adopted workbench copy, like the slot upload.
3. **Strategy shows its reasons** (#3, route ②): each role row in 「預算怎麼分」 prints its `rationale`.
4. **No English codes; one current learning** (#11, route ②): stored learning text, the planner-facing lines and the workbench set
   sidebar use coordinate labels; 「用到的學習」 lists the last closed period's per-ad coordinate results with labels, and the
   campaign-verdict learnings are cut to the newest per product (prompt and panel alike).
5. **Default name keeps its dates** (#5): 「<商品名>・MM/DD～MM/DD」, the product part shortened if needed, the dates never.
6. **Month budget on the first approve** (#6, route ④): the same 「本月預算放得下」 card on the first-launch list, fed by the
   backend's own launch preflight numbers, with the blocking reason beside 核准上架清單.

# Decisions
User-confirmed (drill-8 review + prototype 「可以，切票」 2026-09-30):
- Screens ②③④ of the f41-drill8 prototype are the spec; screen ① (「這期手上有什麼」 on new campaign) is rejected — offers, proof and
  media move to onboarding (F42/F43), not per campaign.
- #4 is fixed where the preview finishes, not with more frontend polling (report §5 red #4).
Agent choices (reversible):
- #4: only placements an ad points at through `slot_placement_id` are auto-confirmed; a library attach still waits for the user's
  own confirmation. Actor for the automatic confirmation = the placement's `created_by`, else the string `system:preview`.
- Advanced assignment: when the ad has an adopted workbench copy that differs from the chosen placement's effective copy, the
  assignment goes through the slot-upload path for that asset (one rule, one place); `slots.settle` keeps calling plain `assign`.
- 「用到的學習」: the prototype shows only coordinate rows; the (≤1 per product) surviving verdict line is kept under them because the
  basis panel must list what the model read (F04 basis rule).
- The prototype's 「沿用上一期划算／換新試」 chip has no backing field (`allocation[]` = role/label/pct/rationale/amount): not built.
- 「這期會用：…」 chips on ② need onboarding data: built in F42, not here.
- #6 blocker text comes from the backend (one owner of the month rule); the frontend renders it verbatim.
Unresolved (for the user, not blocking F41):
- Prototype ③ 「改成單圖」 (a video slot switched to single image when the brand can deliver video but not for this ad): not in this
  feature's item list; recommend deciding after F42's media step lands, because a photo-only brand never gets a video slot then.
