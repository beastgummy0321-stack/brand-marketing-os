# Outcome

投放中心從「走得完一圈」變成「新手敢自己用」：首頁是四塊判斷（一句整體判斷／需要你決定／
進行中的 Campaign／最近做了什麼）而不是一張表，建立 Campaign 會先把你那句話讀成六個可改的
欄位再花第二次模型錢，策略頁的四顆按鈕真的會動，總覽分頁照著參考圖長。同時把這一圈的
外部模型花費收進上限裡——每個進 prompt 的清單有上限、大 prompt 不重送、花費欄位存得下小數——
讓 F05 的建議任務一出生就在上限之下。

# Decisions

這一節是已定案的。工人照做，不重開；跟 F03 衝突的地方以本節為準，其餘 F03 決定照舊有效。

## 使用者的裁決（2026-09-13，原話照錄）

- **R9（前端唯一一條規則）**：照顧新手與老手，一個頁面預設顯示簡單化面，進階配置才給熟手。
  預設版面配置永遠乾淨簡潔，照顧新手使用者優先，新手可以基本輕鬆上手，AI 丟數個建議讓使用者
  參考，使用者看完沒問題基本只管點下一步就可以無壓力排程廣告；老手也可以針對 AI 給的建議去做
  細部調整（但都是預設在原始頁面下，不點開是不會看到），不要把版面做的像是另外一個 meta 後台／
  google 後台。
- **R8（後端）**：維持模組化、container 規則、一個模組一個公開入口，沒有例外。
- **R7（成本）**：外部模型只做判斷；算數、固定文字、label 對照一律寫在程式裡；絕不整批列、
  絕不長參數清單。這是 SaaS，成本會乘上去。
- **R6（視覺）**：每一張 UI 票都要指名它的參考圖，並要求工人在動手寫 UI 之前先用那張圖呼叫
  `Skill impeccable:impeccable`；驗收含截圖與參考圖並排比對。
  使用者 2026-09-13 開工時重申：整體前端視覺規範「參考」外部原先的預覽圖（`docs/design/ads/*.png`）；
  必要時使用設計元件與設計 plugin／skills——本專案的元件庫是 `frontend/src/components/layout/ui/`
  （shadcn 風格，radix-ui＋cva），新版型先用它組，不夠再加；設計 skill 只准 `impeccable`（方向由圖決定）。
- **R5／R1（佔位）**：「席位保留」不得寫成拒絕——「自動執行接上後開放」／「自動發布接上後開放」，
  灰色、不可點；保留的讀取來源與欄位名只寫在 ARCHITECTURE.md §6.1 第 13 條，不建進資料庫。
- **R4**：2026-09-12 第 22 條「meta 只加三個讀取」作廢。F04 不碰 Meta；Meta 購買／營收讀取是 F05。

## F03 留下、任何一張票都不得推翻的規矩

不要求、也不提醒使用者去實機投放 Meta（提示詞、素材、排程完全落地前，任何畫面與回報都不寫
「要看到真結果得讓活動跑」）· 沒有任何模型讀原始廣告歷史（ADR 0067）· 文案全繁體中文 ·
產品名一律「行銷駕駛艙」 · 誠實的空狀態（未追蹤／累積中／還沒有…，永遠不是 0 或「—」）·
每個數字都要說明期間／來源／口徑 · `success_target` 是 null 時畫面寫「未設定」。

## 規劃師在這次 carve 裡定的（工人不要重開）

1. **判斷句歸程式**：一句整體判斷、每個 Campaign 的一句判斷、每一行「最近做了什麼」都在
   `app/ads/judgment.py` 組好字串隨 payload 出去，瀏覽器原樣印。不打模型，也不在前端重拼。
2. **建立 Campaign 只花兩次模型錢**：解析一次、產生策略一次。理解如下是確認畫面，改欄位走
   `PATCH`，不重新解析。
3. **不動 schema，除了一個**：F04 只有一支 migration——`llm_task.cost` 改 `numeric(14,6)`
   （`supabase/migrations/20260913000003_core_llm_task_cost_precision.sql`，已套用的檔一律不改）。
   解析出來的預算上限與平台寫進既有的 `constraints_json`，日期寫進既有的 `start_date`／`end_date`，
   欄位來源（你說的／系統帶入）寫進既有的 `context_json.field_sources`。`platform_settings_json`
   只是被保留的名字，不建。
4. **死路不做保養**：`app/schedule` 的 `schedule_plan`／`schedule_tree` 兩支 prompt（每則廣告一列的
   月表、投放史表、每個商品重編一次品牌上下文）在 F03 退掉檔期規劃頁之後，前端已經沒有任何
   呼叫端（`frontend/src` 找不到 `createPlan`／`createTree`；`scripts/`、`frontend/e2e/` 也沒有）。
   替它們加上限省不到一毛錢，這次不做，理由寫進 ARCHITECTURE.md §1。還活著的花費現場才做：
   `context_compiler`（每一個部門都經過）、`ads` 三支 prompt、素材工作檯的派工、
   `performance_reading`（經營概況的判讀面板還在打它）、建檔精靈的照片迴圈。
5. **座標詞彙保留 `label`**：`key` 是英文 slug、`label` 才是中文意思，拿掉等於要模型用猜的。
   要省的是「模型回覆用不到、又是模型自己能推的」欄位——`strategy.md` 的 `label`（角色固定三個，
   程式自己對照）與品牌事實的 `updated_at`（畫面從 `basis` 讀，不必進 prompt）。
6. **快取只加在真的重送的地方**：`gateway` 不替大 prompt 重送（省下整次重試），
   `performance_reading` 的三個鏡頭前綴一模一樣才加 `cache_control`。其他呼叫點的 prompt 每次都
   不同，加 cache 只會多付 25% 寫入費。這是在「便宜且正確」之間選便宜的那一邊。
7. **共用元件放 `frontend/src/components/ads/patterns/`**，不是 `layout/`：這些是投放中心的版面
   樣式不是全站 kit，放在 ads 模組自己的資料夾才符合 dependency-cruiser 的邊界（功能資料夾只從
   `index.ts` 進出），也不必動全站 kit 與 shadcn generator。
8. **e2e 會撞埠**：`npm run e2e` 自己起 8720 後端，兩張票同時 finish／merge 會撞。帶 e2e 閘門的
   票（I08、I09、I10、I12、I14、I15）一次只跑一張 finish／merge。
