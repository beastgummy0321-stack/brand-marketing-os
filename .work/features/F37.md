# Outcome
A real internal campaign has one performance pipeline: the platform sync (`external_sync` → `ads_external_daily` + recorded
coverage) feeds the performance tab, the closeout verdict, budget history, A/B pairs, experiments, visual learning and the
strategy starting point — the same rows and the same coverage rule the home, the workspace, triage and review already read.
The manual ingest path (`app/meta/daily_pull` → `meta_entity_spend` → `POST …/ingest` → `ads_outcome_daily`) is retired for
campaigns; the simulated adapter registers its nodes and writes observations like a platform, so no reader branches on
real/simulated. Closeout refuses an uncovered window, names the days, offers 重新讀取, and only after a failed re-read may
the user skip (verdict 看不出). A never-synced campaign no longer passes the review gate. `ads_outcome_daily` is dropped.
Same round: `ReviewWindow.missing_days` reaches the frontend type; the twelve `currentBudgetMonth()` no-argument callers
read the organisation clock.

# Decisions
**User rulings** (2026-09-28 dig of handoff #13-B, recorded in `docs/backlog/handoff-after-f34.md` "#13-B dig rulings"):
1. Sync table B (`ads_external_daily` + `context_json.external_sync.observations.coverage`) is the only performance source;
   the simulated adapter also goes through B; `ads_outcome_daily` and `POST …/ingest` are retired.
2. 「更新成效」 on the performance tab becomes 「重新讀取平台」 — the same `POST …/campaigns/{c}/sync` job imported campaigns use.
3. Closeout with missing coverage days: refuse, name the days, offer 重新讀取; only after a re-read of the range ended
   `failed` may the user 跳過缺日結案 (verdict 看不出, missing days recorded in `verdict_json`).
4. Also this round (from the handoff board): a never-synced campaign must not pass the review gate (F36 as-built gap);
   `ReviewWindow.missing_days` frontend type; `currentBudgetMonth()` no-argument callers.

**Verified state** (2026-09-28, file:line at `b8f4bfbf`): `handoff_check.py:426-446` registers readback nodes in
`ads_external_entity` AND binds `ads_ad.external_id`/`ads_delivery_group.external_id` = `native_id` (`repository.bind_*`,
otherwise only called by `adapters/simulated.py`), so a real campaign feeds both pipelines; `external_sync.request_sync`
syncs every `ads_external_entity` root regardless of `origin` and `external_routes.py:164` already accepts an internal
campaign; `meta_read.read_observations` reads campaign/adset/ad levels (`metric_scope` = level); `triage._coverage` /
`_missing_days` (`triage.py:199-226`) return `[]` when never synced; `ab_pairs._entities` (`ab_pairs.py:48-62`) already
maps `ads_ad.external_id` → `ads_external_entity`; `simulation_recovery.py` writes `ads_outcome_daily` directly and
`simulated.py` never registers external entities; `app/schedule` and `channels.account_spend_history` still read
`meta_entity_spend` (kept); `app/tests/test_cleanup_coverage.py` compares the cleanup registry
(`repository.py:1258`) with live tables.

**Agent choices** (reversible):
- Read seam: `outcome.py` keeps its public shape (`summary()`, `sample_bucket`, `_bucket`, `_fetch_rows`) but reads B through
  Contract P; readers that queried `ads_outcome_daily` themselves call `outcome.rows()` instead of a second query.
- Simulated = a platform: `channels.external_reader("simulated")` returns a `SimulatedReader` whose `read_observations`
  regenerates the same deterministic rows `generate_outcomes` writes (one pure generator), so 重新讀取 and the 05:00 daily
  dispatch work for simulated campaigns with no branch in the core; the platform key is `"simulated"`, source account `"sim"`.
- Coverage window for a campaign = `start_date` … `min(end_date, org yesterday)` (today is never a complete day, same as
  review_evidence); never synced = refused with 「還沒讀過平台資料」, not a wall of dates (Contract Q).
- `can_skip` = the campaign's `external_sync.observations.status == "error"` (the last observations read failed); the
  skip is an explicit `{skip_missing: true}` on the close request, never a default.
- Order: I01 first (the flip). Then I02 (simulated reader) and I05 (clock callers) in parallel; I03 (closeout/review rule)
  after I01 and serialised with I02 by shared test files; I04 (frontend) after I03 and I05; I06 (drop table) after I01–I03. Two at a time.

**Rejected routes**: mirroring B rows into `ads_outcome_daily` at sync time (a second copy of the truth); keeping
`ads_outcome_daily` for simulated brands only (every reader would branch real/simulated); deriving skip permission from the
mere presence of an error message (a stale error from months ago would unlock the skip — the status is reset by every
successful read via `record_sync`).

## Contracts (every issue uses exactly these names)
- **P. Performance rows (I01 writes; I02/I03 read).** `app/ads/outcome.py::rows(conn, org_id, brand_id, campaign_id, kind)`
  with `kind in {"group","ad"}` returns dicts `{entity_id, day, spend, impressions, clicks, purchases, revenue, currency,
  source, observed_at}` where `entity_id` is the LOCAL `ads_delivery_group.id` / `ads_ad.id`: `ads_external_daily` rows of this
  campaign with `metric_scope = 'adset'` (group) / `'ad'` (ad), non-monthly (`is_monthly_budget_row` false), joined to
  `ads_external_entity` on `entity_id` and to the local node on `external_id = native_id` (the `ab_pairs._entities` mapping,
  now in one place). Rows for a local node with no bound platform id, or platform rows with no local node, are not returned.
  `summary()` keeps `totals/daily/groups/ads/last_data_at`; `coverage` becomes
  `{"start": "YYYY-MM-DD"|null, "end": …|null, "expected": <days in window>, "missing": <len(missing_days)>, "missing_days": [...],
  "never_synced": bool}` computed by Contract Q over the campaign window. `ingest_meta`, `_conflicting_campaigns`,
  `_upsert_outcome` and `POST …/ingest` are deleted.
- **Q. Coverage check (I01 writes `coverage_gap`; I03 applies it to closeout and review).** `app/ads/triage.py::coverage_gap(campaign, start, end)`
  → `{"never_synced": bool, "missing_days": [ISO...]}` built from `_coverage`/`_missing_days` (never synced ⇒ `never_synced`
  true and `missing_days` empty). `closeout.close(..., skip_missing=False)`: when the gap is non-empty and not `skip_missing`
  raise `ValueError("coverage_missing")`; the close route maps it to HTTP 409 `{"code": "coverage_missing", "message": …,
  "missing_days": [...], "never_synced": bool, "can_skip": bool}` where `can_skip` =
  `context_json.external_sync.observations.status == "error"`. With `skip_missing` and `can_skip`, verdict is 看不出 with
  `verdict_json.missing = "有 N 天沒讀到平台資料：…"` and `verdict_json.missing_days`. `skip_missing` without `can_skip` → 409
  as above. `review_evidence.snapshot` uses `coverage_gap` and refuses `never_synced` with 「這個活動還沒讀過平台資料；先重新讀取平台。」.
- **R. Simulated platform (I01 writes entities + observations; I02 adds the reader).** `simulated.publish` registers
  `ads_external_entity` rows (platform `"simulated"`, source_account `"sim"`, native ids = the `sim_…` ids, campaign →
  adset → ad chain with `parent_native_*`) through `external_repository.upsert_entity`, then binds the local nodes as today.
  `simulated.generate_outcomes` writes each day through `external_repository.upsert_observation` (`metric_scope` `adset`/`ad`,
  `attribution_key "simulated"`, `source "simulated"`, real non-null purchases/revenue) and, for every completed window,
  `external_repository.record_sync(section="observations", state={"status": "success", "last_success_at": now,
  "coverage": {"start", "end"}})` extending the recorded coverage (union with the existing range). `simulation_recovery.save_day`
  writes the same way for one day (delete-then-insert of that day's `source='simulated'` rows) and records coverage for that
  day; `read_day` reads `outcome.rows(kind="ad")` for that day. The daily generator is one pure function
  `simulated.day_rows(detail, day, rng) -> list[dict]` (group + ad rows) that I02's reader reuses.
- **S. Frontend (I04).** `adsApi.CampaignPerformance.coverage` follows P; `ingestOutcome` is removed; `closeCampaign(brand, id,
  {reason?, skip_missing?})`; a 409 `coverage_missing` is surfaced as `CoverageMissingError {missing_days, never_synced, can_skip}`
  (thrown by `closeCampaign`, never swallowed). `adsReviewApi.ReviewEvidence.window` gains `missing_days: string[]`.
- **UI spec = the prototype** (design-system §1.7): `.harness/scratch/prototype/f37-pipeline/index.html` — `#/perf` (「目前成果」
  header button 「重新讀取平台」; 資料狀態 line 「平台已讀到 A ～ B」 + warning line listing unread days), `#/close` (結案 dialog:
  state 缺日 = amber note with the days + 「重新讀取平台」, 確認結案 disabled; state 重讀仍失敗 = red note with the sync error,
  「再讀一次」 and 「仍讀不到，跳過缺日結案」). Open it in a browser; the state buttons on `#/close` switch the three dialog states.

# Acceptance
- A real campaign with synced adset/ad rows: `GET …/performance` totals equal the sum of its `metric_scope='adset'` rows,
  the ads table equals its `'ad'` rows keyed by local ad id; `coverage.missing_days` names days outside the recorded range.
- `POST …/ingest` is gone (404); `outcome.ingest_meta` does not exist; `meta_entity_spend` is not read by `app/ads/outcome.py`.
- Simulated publish → `ads_external_entity` chain + `ads_external_daily` rows + recorded coverage; `POST …/sync` on a
  simulated campaign succeeds and a second run writes no duplicate rows; recovery `save_day` then `read_day` round-trips.
- Closeout: window with missing days → 409 `coverage_missing` naming them, `can_skip` false; after an observations read
  recorded `status: "error"`, `can_skip` true and `{skip_missing: true}` closes as 看不出 with the days in `verdict_json`.
- Review evidence on a never-synced campaign refuses with the 「還沒讀過平台資料」 sentence; a covered window judges as before.
- Frontend: the performance header button reads 「重新讀取平台」 and triggers the workspace sync; the close dialog renders the
  three prototype states from the 409 payload; `ReviewEvidence.window.missing_days` is typed.
- Twelve `currentBudgetMonth()` calls pass the org timezone; a test with timezone `Pacific/Kiritimati` near midnight UTC shows
  the org's month.
- The migration drops `ads_outcome_daily`; `test_cleanup_coverage` passes with the registry entry removed; `test_architecture_boundaries` passes.
