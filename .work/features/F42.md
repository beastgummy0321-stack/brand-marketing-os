# Outcome
Drill-8 red #1 and #2 (report §3, §5) closed at brand level: everything the owner knows about the **brand** is asked once, in a
seven-step brand onboarding that the AI pre-fills from the website and brand photos and the user confirms step by step
(prototype `.harness/scratch/prototype/f41-onboarding/index.html`, routes `#/b1`–`#/b7` and `#/home`; launch config `prototype`,
port 8741; user 「可以，切票」 2026-09-30). The prototype is the layout spec.
1. **Brand onboarding** `#/b1` 基本 → `#/b2` AI 讀網站 → `#/b3` 品牌是誰 → `#/b4` 證據與政策 → `#/b5` 素材 → `#/b6` 接工具 → `#/b7` 完成,
   re-enterable from a small 「品牌資料（建檔時填的）」 link on 經營概況 (`#/home` title row). Every AI-judged block has 「自訂」.
2. **The data the planner and the copy guard were missing now exists and is read**: brand proof (F38 `fact_key`), a registry of
   store policies each mapped to an offer key, forbidden phrases, media capability, conversion goal.
3. **Offers become derived data**: the delivery plan offers an `offer` key only when a confirmed policy (or, in F43, the sell-way's
   price) supports it — the `DEFAULT_OFF_COORDINATES` toggle stops being the gate; the copy guard accepts an offer's words when that
   offer is available for the ad's product.
4. **Formats follow media capability**: a photo-only brand never gets a `video` slot.
5. **Old stage removed**: research → paste → truth card, the 8-question Q&A and the old step 3 「賣什麼與數字」 are gone; products
   are created on the existing products page until F43 replaces it with product onboarding.
6. **Readiness** shows the brand rows (品牌是誰／證據與政策／素材／廣告帳戶與成效目標／商品) the completion screen lists; the strategy
   tab shows 「這期會用：…」 (route ② `used` row of `.harness/scratch/prototype/f41-drill8/index.html`).

# Decisions
User-confirmed (dig + prototype review, 2026-09-30; source `docs/backlog/intake-rebuild-discovery.md`):
- Owner knowledge is asked once at onboarding, not per campaign (the per-campaign 「這期手上有什麼」 card was rejected).
- Remove research → paste → truth card and the AI Q&A; each step is AI-prefilled from the website/photo scan and confirmed on
  下一步 (one writer per fact, every fact has a field).
- Every AI-judged block ends with 「自訂」: a plain-language sentence → one small LLM call through the existing gateway → a field
  value or a new option, contract-checked, saved to the brand.
- Brand onboarding (once, low-key entry, re-enterable) is separate from product onboarding (F43, prominent block on 經營概況).
- Brand photos = logo, store, team, brand image; product photos belong to product onboarding.
- Store policies are a registry (the prototype's 26 `POLICIES`, 8 common shown, rest behind 「更多政策」), each mapped to an offer
  key or `none`; custom policies via 自訂; the 7-day cooling-off (消保法 §19) is fixed, 「不適用」 only for a statutory exception
  with its disclosure text.
- Tools = a connector registry declaring what each connector reads (Meta live; Google/TikTok, GA4, Search Console, shop platforms,
  MCP, custom API = seats); extend the `app/schedule/channel_catalogue.json` pattern, no framework.
- Existing data is test data and may be rebuilt; the `supabase/seed.sql` account keeps working.
Agent choices (settled here so workers do not invent them; reversible before F42-I01 merges):
- **Where each brand fact lives** (existing stores first, one field each):
  | fact | store |
  |---|---|
  | positioning / tone (1–2 + custom) / visual style | `brand_fact` `positioning` / `tone` (`params_json.tones`) / `visual_base`, confirmed |
  | brand proof | `brand_fact` `proof` + `fact_key` (F38) |
  | store policy | `brand_fact` new type `policy`, `fact_key` = registry key or `custom`, `params_json` = params (custom: `{label, offer_key}`), `value` = the program-composed ad-ready sentence (e.g. 「滿 NT$999 免運」) |
  | 7-day cooling-off exception | `brand_fact` `policy` key `cooling_off_exempt`, `params_json.disclosure`; no row = applies |
  | forbidden phrases | `rule` `forbidden_word`, `product_id` NULL (statutory words stay in `workbench/statutory_tw`) |
  | media capability | new `brand.media_capability` ∈ {`photo`,`photo_video`}, NULL = never asked (no format filter) |
  | brand photos | `official_asset`, `product_id` NULL, `asset_kind` ∈ logo/store/team/brand_image/other |
  | AI prefill | new `intake_draft.prefill_json` (what the scan found + its source note); never a confirmed fact |
  Tables stay with their current owner (`brand_intelligence`, legacy facade, extended the way F05/F38 did); the capability
  (onboarding flow, prompts, readiness, plan filters) lives in managed modules. `review: planner` on I01.
- **Policy registry** = one list `POLICY_TYPES` in `app/core/vocab.py` (beside `PROOF_KINDS`): key, group, label, params (name,
  label, kind), offer key, common flag, threshold param, sentence template. Python is the source; the API ships it to the screen.
- **Offer availability** = `bi_repo.available_offer_keys(conn, brand_id, product_id=None)`, the `available_proof_keys` pattern
  (F38): confirmed policy facts' offer keys; a threshold policy (滿額免運, 超商免運, 滿額折, 滿額贈) counts only when the product's
  current price ≥ the threshold (no product → counts). F43 adds the sell-way's own discount/bundle. The coordinate toggle stays a
  brand veto (enabled ∩ available); offers are seeded enabled again (new `_schedule_` migration; `DEFAULT_OFF_COORDINATES` removed).
- **Copy guard**: a RISK word whose offer family (免運→free_shipping; 折／折扣／折價／折抵／優惠／discount→discount; 贈／加贈／買N送→bundle;
  試用／試吃／試飲→trial_sample; 退款保證→guarantee) is in `available_offer_keys(brand, set product)` is not flagged; proof words keep
  today's exact-sentence rule. This relaxes 「a bare category never authorizes its paraphrases」 for structured, true offers only.
- **Readiness rows**: identity, evidence, media, channel (reason also names the conversion goal; the separate goal row merges into
  it, as `#/b7` shows), offering (CTA 「建第一個商品」 → the products page until F43). Colours: identity/media green when set, yellow
  when never set; evidence green with ≥1 confirmed proof or policy, else yellow 「還沒有登記證據或政策；廣告只會講產品本身」.
- 「自訂」 returns a proposal only (no save); the step's 下一步 saves it with everything else (「按下一步才算你確認」).
- The prototype has no AI-cost rail: the old `CostGauge`/`BudgetPanel` go; the server-side draft cost cap still refuses calls.
- `#/b1`'s 「投過網路廣告嗎」 keeps the existing `advertising_history` field and its history backfill behaviour.
- Personas (人物誌) are not part of this feature (not named by the user); F43's customer groups may supersede them — decided there.
Unresolved (for the user):
- Split: F42 (brand) and F43 (product onboarding + sell-ways + slim new campaign) are proposed as two features instead of one
  (≈29 issues together). Merge back into one if preferred; issue content does not change.
