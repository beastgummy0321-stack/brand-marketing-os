# Outcome
Every ad the system reads can be judged on real numbers before any new screen is built: platform-reported purchases reach
close-out verdicts; Meta budgets are stored as real amounts in the account currency; each campaign is measured on the result
that matches its own objective (purchase, engagement, link click, lead …) as "cost per result"; and every campaign can resolve
a target cost (break-even, own trailing 30 days, or user-set). No UI redesign in this feature; existing screens keep working.

# Decisions
User-confirmed (2026-09-20; full list in `docs/backlog/discovery-creative-lifecycle-and-triage.md` §2, probe facts §4a):
- Keep F15 and build on it. Campaigns are long-lived containers; nothing here closes, rebuilds or writes to a platform.
- Thresholds and targets are formulas scaled per brand, never constants; judge only where a result definition AND a target exist; unknown is never zero.
- Target cost default = break-even (price − variable cost, existing `app/ads/budget.py`), else the account's trailing-30-day actual labelled provisional, else user-set.
- Program organises and computes; the model is not called by anything in this feature.
Agent choices:
- This is phase 1 of 3. Phase 2 (triage, decision queue, proposals, new 投放中心 UI from prototype v7) and phase 3 (creative lineage, learning at retirement, monthly review) are carved only after this feature closes — see discovery §5.
- Shared vocabulary stays platform-neutral (`result_count`, `result_kind`, `cost_per_result`); the objective → result mapping lives in the Meta adapter.
Unresolved (must be settled inside the named issue, not invented by a worker):
- Meta budget minor-unit rule per currency — I02 must prove it against official docs AND a read-only comparison with a budget the user knows.

# Acceptance
- A closed campaign with real Meta purchase rows gets 達成／未達成 when the sample gate passes, 看不出 only for genuine gaps.
- Imported ad sets/campaigns show a numeric daily/lifetime budget with currency; month budget no longer reports "預算金額、單位或幣別未核實" for resolved entities; unresolved ones stay explicitly unknown.
- An ENGAGEMENT or TRAFFIC campaign yields per-ad `result_count` and `cost_per_result`; a SALES campaign's numbers are unchanged.
- `GET` target for any campaign returns value, basis (break-even | trailing-30 | own | none) and what is missing; `PUT` persists it.
- The three texts promising an unattended close are gone. Full project suite green.
