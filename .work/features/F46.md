# Outcome
The system learns 「哪一種賣得動」 from every closed campaign and the next plan builds on it; planned coordinates match what
shipped; a new campaign does not need re-entry (drill-10 report root causes 1, 2, 9 and the calendar part of 10; defects L1–L6,
P1, P2, P4, P5, D1–D5, O2; operator-notes D15, D19). **Starts after F45 is merged to master** (F45 = sell-way BASE / COMPOSED,
per-sell-way free shipping, offer sentences; this feature does not touch those).
1. **Closeout ranks the campaign's ads by cost per sale** and writes 留下／換掉 per ad with its numbers (Contract B); ads with ≥1
   sale always enter, few sales are flagged 樣本少, 沒賣出 ranks last.
2. **Both planners get the ranked rows with numbers and verdicts** and the delivery plan must build on 留下 and may not re-run a
   換掉 customer group + angle unchanged (program gate, Contract G).
3. **Each planned ad binds one customer group** (8th coordinate, Contract A); the copy prompt gets it; learning tallies it.
4. **The owner sees the learnings**: 品牌智庫 tab 「投放學到的」, closeout dialog exits, month review suggestion, strategy basis
   (prototype `.harness/scratch/prototype/f46-learnings/index.html`, launch config `prototype`, port 8741).
5. **What shipped wins** (Contract F, O): the actual uploaded format is what the handoff list and learning record, the slot says
   when planned ≠ actual; an ad planned with an offer whose copy lacks the offer sentence is refused with a reason; offer words
   outside the registered sentence are caught; the planner knows the photo count.
6. **Defaults are stored and reused** (Contract D): platform, per-sale cap and budget come from the same sell-way's previous
   campaign (「沿用上一期」); the first campaign uses break-even; the shown value is the stored value; the monthly-budget link opens
   the form; picking an ad account assigns it.
7. The Taiwan calendar has the October exam season.

# Decisions
User-confirmed (2026-10-02):
- Learning ranking rule = outcome 1 with the verdict rule in Contract B; the program decides, the model uses it.
- Customer group is the 8th coordinate, stored on `ads_ad`, in the learning scope, tallied; scene stays the ad's moment and must
  belong to its group.
- 品牌智庫 tab, closeout exits, month review and strategy basis read the same learnings; the prototype above is the layout spec.
- Actual uploaded format wins; offer-labelled copy without its sentence is refused by the program; offer-word detection widened
  (「買一送一」 on a bundle ad = 要繞路, F44 ruling 「至少一則帶優惠＝提示＋程式把關」 extended to 「帶了就要寫」).
- Defaults from the same sell-way's previous campaign; first campaign = break-even; shown = stored. Supersedes
  `docs/architecture/ads.md` §6.47 (「not copied from the previous campaign」) for platform / cap / budget, and the F36-I04 rule
  「cap chip empty by default」 for the structured create.
- October exam rows are a data change.

Agent choices (settled so workers do not invent them):
- **Contract A — customer group coordinate.** Migration `20261004000021_ads_ad_customer_group.sql`: `ALTER TABLE ads_ad ADD COLUMN
  customer_group_id text` (no FK: `product_customer_group` belongs to brand_intelligence; a deleted group reads as unknown).
  Delivery-plan reply: each ad gains `"customer_group": <N>` = the 第 N 群 number of this prompt's 【這個賣法的顧客】; the program maps
  N → group id (`customer_groups.prompt_section` order). With groups listed: N must be a listed number; the ad's `pain` must be one
  of that group's `pain_keys` when that set meets the menu's pain keys (else no pain check); **all ads of one delivery group share
  one customer group** (one ad set = one set of people; the audience hint names it). Any failure → `delivery_plan_failed`, nothing
  written. No groups listed → the key is ignored and stored NULL. Hand-made ads store NULL (no 8th dropdown in this feature).
  The pack hands `request.customer_group` = 「〈who〉｜煩惱：〈pain labels〉｜顧客會說：〈quote〉｜什麼時候用：〈when〉」; the workbench brief
  prints it after the scene. Audience mixing inside a group (D19) is not gated: the audience key is the awareness stage.
- **Contract B — ranked learning row** (written at closeout, replaces the F39 grade rows). Input: `period_grades.grade_period` rows
  of the campaign window for this campaign (spend, results, cost_per_result, cap, currency). A row with unknown results or spend
  (`results is None`, mixed currency) is not ranked and writes nothing. Sold (results ≥ 1): ordered by cost per sale asc, then
  sales desc, then name; 沒賣出 (known 0 results, spend > 0) after them, spend asc. Verdict: cap known and cost ≤ cap → `keep`
  「留下」; when no sold row is ≤ cap (or no cap): sold rows with cost ≤ best × 1.3 → `keep_relative` 「留下」 + flag
  「相對最好，仍高於上限」 (no cap: 「相對最好」); every other row incl. 沒賣出 → `replace` 「換掉」. Flag 「樣本少」 = 1–4 sales
  (prototype `SAMPLE_FEW = 5`). `applicability_scope` = `coord；v=2；verdict=<v>；rank=<n>；of=<n>；sales=<n>；spend=<n>；cpr=<n|none>；
  cap=<n|none>；few=<0|1>；group=<id|none>；audience=…；pain=…；angle=…；hook=…；proof=…；offer=…；format=…` (format = actual, Contract
  F, through `live_creative`). Text: 「第 r／n 名「〈ad〉」每筆 X（賣 s 筆、花 Y；上限 C）＝留下（樣本少）；顧客群：〈who〉；〈labels〉」.
  `sample_size` = 低 when few or 沒賣出, else 高. Rows without `v=2` (F39/F41) are not read anywhere; no backfill (test data).
  Partial data (skipped gap, incomplete simulation) still writes none.
- **Contract L — learnings view** `coordinate_learning.learnings_view(conn, org, brand, *, campaign_id=None, sell_way_id=None,
  limit=12)` → `{campaigns: [Campaign], groups: [Group], next: {sell_way_id, new_campaign_href} | null}`. Campaign = closed
  internal campaigns newest closed first: `{campaign_id, campaign_name, sell_way_id, start_date, end_date, closed_on (org-local
  date), cap, currency, spend, sales, cost_per_sale, counts {keep, replace}, rule_text, empty_reason, rows}`; `rule_text` e.g.
  「2 則每筆低於上限 450 → 留下；其餘換掉」／「沒有一則低於上限 450 → 留下最好的 555 和 722 以內的；其餘換掉」／「沒有一則賣出 → 全部換掉」;
  `empty_reason` (rows empty) 「資料缺天，這期沒有記學習」 or 「這期沒有花到錢的廣告」. Row = `{rank, of, ad_id, ad_name, customer_group
  {id, who} | null, coordinates [{dimension, dimension_label, label}] (none omitted), spend, sales, cost_per_sale | null, verdict,
  verdict_label, flags [str]}`. Group = per customer group over the listed rows: `{customer_group_id, who, ads, spend, sales,
  cost_per_sale | null, cap}` (cap of the newest listed campaign with that group; a deleted group's who = 「已刪除的顧客群」; rows
  without a group are not grouped), sorted by cost per sale (null last). Numbers come from the stored scope, never recomputed.
  `new_campaign_href` = `/brands/{b}/ads/new?sell_way=<id>`. Served at `GET /api/ads/brands/{b}/coordinate-learnings
  [?campaign_id=][&sell_way_id=]`; the strategy basis stores the view it prompted with as `basis.ranked_learnings` (a new key:
  `basis.coordinate_learnings` is no longer written and stays readable for strategies made before F46).
- **Contract G — planner use and gate.** Prompt section 【上幾期的排名（程式排的；每筆＝花費÷成交）】 replaces 【座標成績表】 in both
  prompts (same position): per-group summary lines, then the newest ≤3 closed campaigns' rows, one line each:
  `- 〈campaign〉第 r／n 名｜〈verdict_label〉〈・flags〉｜顧客群 〈N | 這期沒列：who | 未指定〉｜「〈ad〉」｜每筆 〈X | 沒賣出〉｜賣 s 筆｜花 Y｜〈label（dim=key）×7〉`.
  The per-dimension grade tally is dropped (the group summary replaces it). Gate after Contract A's checks, over customer groups
  listed this time: `keep_pairs` = (group, angle) of 留下 rows of the listed campaigns; `replace_pairs` = (group, angle) of 換掉 rows
  of the newest closed campaign minus its own 留下 pairs. Reject when any ad's pair ∈ `replace_pairs`, or when `keep_pairs` is
  non-empty and no ad's pair ∈ `keep_pairs`. Department texts: build on 留下 (name it in `rationale`), do not re-run a 換掉 group +
  angle unchanged; the strategy has no gate.
- **Contract F — actual format.** One reader (ads-private): a confirmed asset whose `mime_type` starts with `video/` → `video`, any
  other file → `single_image` (a slot holds one file). Learning coordinates (`live_creative.learning_coordinates`) take it over the
  planned `format` when the ad has an assigned material; the launch handoff list's ad fields gain 「格式」 = actual label (+
  「（規劃是〈planned〉）」 when different), view-time only; every slot gains `format_note: str | null` when planned ≠ actual, text as
  the f45-slot-states prototype: 「規劃是輪播，只放了 1 張圖，會以單圖上架」, generic 「規劃是〈planned〉，放的是〈actual〉，會以〈actual〉上架」.
- **Contract O — offer sentence.** Workbench facade `validate_claims` gains `missing_offer: list[str]` = the registered sentences
  of the ad's `offer_key` when none of them appears (whitespace removed) in any copy string; `[]` for `None` / `"none"` / a key with
  no row. A RISK offer word is backed only when that exact term appears inside one of the (narrowed) available offer sentences
  (replaces F42 family-wide backing; 「優惠」 included). RISK widened: 第二件半價／半價、特價、特惠、下殺、限時、原價、早鳥價、加購價、組合價、
  現折、滿額、滿 N 送／折、再送、加送、送 N、回饋、點數、抽獎 (a bare 「送」 is not flagged: 送禮／送貨 are ordinary words). Asset
  confirmation refuses a planned ad with a `missing_offer`: detail `copy`, 「這則規劃的是「〈offer label〉」，文案沒有寫這個優惠：「〈sentence〉」。」.
- **Contract P — photo count.** The delivery-plan prompt gets 【手上的素材】「照片 N 張、影片 M 支」 (active official assets except
  `logo`, plus ready ads user assets, by mime); department rule: ads ≤ photo count when N ≥ 1.
- **Contract D — create defaults.** Each wizard option gains `previous` = the newest non-draft internal campaign of that sell-way
  (`sell_way.of_campaign`): `{campaign_id, campaign_name, platform, cap, budget, spend}` (spend = its stored learning rows' total
  when closed, else null) and `learned` = `{campaigns [{id, name}], keep, replace}` from Contract L for that sell-way (null when
  none). Structured create, for a value the request does not send: platform = previous (`copied`) else the brand's first connected
  channel (`brand`); cap = previous `target_cost` (`copied`) else sell-way `cap_per_sale` (`sell_way`) else break-even
  (`break_even`, stored); budget source `copied` when it equals previous `budget`. `FieldSource` gains `"brand"`, `"break_even"`.
  Tags: copied 「沿用上一期」, break_even 「打平線」, brand 「已接上的帳戶」, user 「你改的」.
- Not in this feature: O3 (strategy text content check — not cheap); the prototype strategy tab's 「這期 N 則廣告」 card with
  沿用／帶回再驗／新寫 tags (needs per-ad learning provenance, not ruled); a monthly-budget default amount; daily budget on create.
