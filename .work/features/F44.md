# Outcome
Every step that handles an ad asks one place which sell-way it sells and which offer it carries (drill-9 red #1＋#2,
`docs/drills/drill-9/report.md` §3).
1. **Planner** sees each available offer's registered sentence (price and list price included) and must use one in at least one ad.
2. **Copy follows the ad's offer coordinate**: `none` → no offer sentence, no offer price / list price; an offer key → that offer's
   sentence is written.
3. **Asset confirmation** judges the copy against the ad's sell-way and offer coordinate — the same sources the copy step used.
4. **A refused slot says why**: 「卡住」, one sentence, the exit that fixes that reason, and 「再檢查一次」 (prototype
   `.harness/scratch/prototype/f44-blocked-slot/index.html`, launch config `prototype`, port 8741).
5. The `bundle` offer reads 「組合優惠」.

# Decisions
User-confirmed (dig 2026-10-01):
- The offer coordinate decides the copy (outcome 2).
- 「At least one ad uses an available offer」 = prompt rule + program gate that rejects the whole reply.
- 「做」 after the dig summary: campaign owns the sell-way; planner prints registered offer sentences; refused slot shows reason +
  one exit; AI-filled copy may cite sell-way-level claims; `bundle` → 「組合優惠」.
Agent choices (settled so workers do not invent them):
- **Contract A — sell-way of an ad** (`app/ads/sell_way.py`, ads-private): `of_campaign(campaign) -> str | None` = first of
  `context_json.product_ids`; `of_ad(ad, campaign) -> str | None` = `ad["product_id"] or of_campaign(campaign)`. `ads_ad.product_id`
  stays an optional override; nothing fills it at plan time. `budget._economics_for` (first sell-way *with economics*) is a different
  rule and stays.
- **Contract B — offer narrowing** (workbench): `claims.sources(conn, brand_id, product_id, offer_key=None)` and the facade
  `validate_claims(conn, org_id, brand_id, product_id, value, *, offer_key=None)`. `None` = today's behaviour (every available
  offer row); `"none"` = no offer rows; another key = only the offer rows with that `offer_key`. Non-offer rows are never filtered.
- **Contract C — refusal detail** (ads): `{"kind": "copy" | "file" | "campaign" | "wait", "text": str, "terms": [str]}`.
  `pending_reasons` stays the list of `text` (the AI-batch screen reads it). `wait` = the original's preview is not made yet.
  Texts: coordinate mismatch 「這則規劃的是「〈offer label〉」，文案卻寫了「〈terms joined by 、〉」。」; unbacked promise
  「文案寫了「〈terms〉」，品牌資料裡沒有登記這個優惠或背書。」; every other existing sentence is kept as is.
- **Contract D — slot payload** (`GET …/slots`): `state` gains `"blocked"`; each slot gains
  `blocked: {"text", "terms", "fix": "copy" | "file" | null, "more": int} | null` (first non-`wait` detail; `more` = how many others)
  and `offer_label: str | null` (the ad's offer coordinate label; `null` on imported campaigns). `POST …/slots/{ad_id}/recheck`
  re-runs the confirmation and returns `{"slots": …}`. `ready` / `total` keep their meaning; a blocked slot is not ready.
- Refusals are stored in a new `ads_asset_placement.blocked_reasons jsonb` (list of Contract C details); `pending_reason` keeps its
  current use.
- The scripted (e2e) delivery-plan reply uses the first offer key the prompt lists, so the gate passes without a model.
- Out of scope: other swallowed states outside the slot auto-confirm path; drill-9 #3–#12.
