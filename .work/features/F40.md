# Decisions
User-confirmed (dig 2026-09-29 + prototype 「通過」):
- 結案 and 重新讀取平台 move to the top status row of the 成效 tab; 整期合計 on the main screen; the 「整期 vs 每月回顧」 caption.
- Same image for several ads (per-ad placement), not a warning.
- New campaign copies the previous campaign's platform / audience direction / cap / landing URL, editable, no extra question.
- Prototype approved as the spec; a ticket may not add screens or text the prototype does not show.
Agent choices (reversible):
- **#7 premise corrected on the dev DB (2026-09-29)**: the drill-7 period-2 campaign has 6 platform entities (4 bound ads, 2 unbound;
  statuses ACTIVE×2, PAUSED×4). 「在投 6 則」 counted platform ads, not planned ones. The rule stays 「platform ads that are not
  closed」 (§6.33 one ruler); the two program lines name what differs: platform ads with no bound local ad, and local ads never
  built. Backend adds `bound_ad_id` to triage items so the page needs no second read.
- Period grade for the status row comes from the backend (`outcome.summary().totals.grade` through `triage.grade_window`), never
  a frontend copy of the ruler.
- 「核准整包」 lives on the workbench pack page, not the assets tab; the assets tab keeps the 主力／探索 chip + link. The 探索 warning
  stays a warning (F07 decision 29); the grey button's reason = the unticked completion items (`blocking_text`). The prototype's
  one-click 「改為探索」 is not built: no API changes a set's slot and inventing one is out of scope.
- Landing URL at create time is stored as `context_json.landing_url`; `manual_settings` uses it as the default `landing_url` of every
  group that has none (per-group values still win).
- Placement uniqueness becomes `(org, brand, campaign, asset_id, ad_id)` with `ad_id` nullable for library attaches (legacy rows keep
  NULL); `attach` looks up by that key.
- 「全部標記」 = one route `POST …/handoff/launch/confirm-all` looping the two existing confirm functions in one transaction.
- Regenerate (#16): the button label becomes 「正在生成〈part〉，完成後才能再生成」 when the running part is another one; no status-model change.
As built (2026-09-30), deviations from the prototype recorded in ads.md §6.44: 主力／探索 chip not built (no payload field);
confirmed readback rows keep 「你確認一樣」; 受眾方向 is free text; 「設定 N 月月預算 →」 links to the ads home (no route);
confirm-all is idempotent, not atomic. Two files hit the 800-line cap (SetStudioPage.tsx, adsApi.ts) → helpers split out.
Unresolved: none blocking.
