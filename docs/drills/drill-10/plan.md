## 4. 按鈕全檢（面向 6；和阿虎分開的代理）

時機：阿虎三期跑完、量測匯出之後，在 drill-10 組織上做（那時有三個活動、成效、結案、學習）。
代理另建：第二個品牌草稿（建檔各步的按鈕）、一個新活動走到交接（建活動流程的按鈕）、備用商品／組合（刪除類按鈕點在備用品上）。
依區域拆三個代理並行（各自 playwright session），避免一個代理上下文塞爆：

| 區 | 頁面（`frontend/src/App.tsx` 路由） |
|---|---|
| 甲 入口與建檔 | `/login`（登入、註冊）、`/accept-invite`、404、外殼（側欄、頂列、品牌切換）、`/`、`/inbox`、`/settings`、`/intake/new`、品牌建檔 7 步 `/brands/:id/intake`、`intake/history`、品牌首頁 `/brands/:id`、品牌智庫 `library`、`orders`、`report` |
| 乙 商品與工作檯 | `products`、`products/new`、商品建檔 5 步 `products/:id/onboarding`、商品詳情 `products/:id`、`products/bundles/new`、`bundles/:id`、`workbench`、`workbench/new`、`packs/:packId`、`packs/:packId/sets/:setId` |
| 丙 廣告中心 | `ads`（首頁）、`ads/new`、`ads/new/:id`（確認需求）、`ads/campaigns`、活動工作區（各分頁）、`target`、`detail`、`publish/:step?` 各步、`connections`、`month`、`settle/:month` 各步、`wait`、`propose/pause`、`propose/budget`、`propose/cleanup`、`review/:entityId`、`reviews/:reviewId`＋`prepare`／`copy`／`material`、`changes/:setId/confirm`／`handoff`／`verify` |

做法（每頁）：
1. 用 playwright 列出所有可點控制項（按鈕、連結、分頁、開關、下拉、輸入框、勾選、上傳、收合），含收合區展開後的、彈窗裡的。
2. 每顆在有資料的狀態下點一次（輸入框填一個合理值）。記三件事：**有反應**（畫面／網址／請求有變）、**反應有意義**（和按鈕上的字相符）、**沒報錯**（console error、4xx／5xx、錯誤提示）。
3. 停用的按鈕另計：畫面有說為什麼停用＝通過；沒說＝缺陷（要繞路）。外連（到 Meta）只驗網址，不真的出去操作。不可逆的（刪除、結案、核准）最後點，點在備用物件上。
4. 到不了的頁面（沒有對應資料狀態）列為「未檢」並寫原因，不算通過。

產出 `docs/drills/drill-10/controls.md`：每頁一張表（控制項｜動作｜反應｜判定），總共幾顆／通過幾顆／未檢幾顆，每個缺陷附截圖（`.harness/scratch/drill10/controls/`）與程式位置。
報告用語固定：「每顆都點過一次，找到 N 個缺陷（未檢 M 顆）」，不寫「沒有 BUG」。
