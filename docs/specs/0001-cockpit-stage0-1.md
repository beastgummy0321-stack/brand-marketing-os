# 駕駛艙規格（階段 0＋1）

標籤：`ready-for-agent`
依據：`docs/redesign-blueprint.md`、ADR 0003/0005、CONTEXT.md 詞彙表。詞彙以 CONTEXT.md 為準。

## Problem Statement

打開系統看到的是純文字表格與功能清單：不知道各品牌現況是好是壞、不知道現在最該做什麼、廣告數據要自己按同步再自己解讀、完全沒有檔期時間感（雙11 快到了系統也不會提醒）。功能越加越多，迷路越來越容易。

## Solution

系統變成行銷駕駛艙：打開先看跨品牌總覽（每品牌一張卡，健康度＋關鍵數字＋最重要的一件下一步），點卡進單品牌駕駛艙（KPI 卡、主趨勢圖、下一步指南卡、異常警示區、AI 油錢錶）。成效每天自動同步；預算燒太快或花不完會主動警示；檔期日曆提前提醒備戰。舊功能頁面在過渡期從新殼連過去照常可用。

## User Stories

1. 作為品牌經營者，我想打開系統就看到所有品牌排排站的卡片總覽，才能一眼掌握全局而不必逐一點進去。
2. 作為品牌經營者，我想在每張品牌卡上看到健康度燈號，才能立刻分辨哪個品牌需要關注。
3. 作為品牌經營者，我想在品牌卡上看到本月營收與環比漲跌，才能不點進去就知道錢的趨勢。
4. 作為品牌經營者，我想在品牌卡上看到進行中檔期的狀態，才能知道廣告現在走到哪一關。
5. 作為品牌經營者，我想在品牌卡上看到這個品牌最重要的一件下一步，才能決定先處理哪個品牌。
6. 作為品牌經營者，我想點品牌卡就進入該品牌的駕駛艙，不需要先在側欄選品牌再猜要點哪個選單。
7. 作為品牌經營者，我想在駕駛艙第一屏看到四張 KPI 卡（本月營收、廣告花費、ROAS、訂單數），各帶迷你趨勢線與環比，才能十秒內判斷這個品牌好不好。
8. 作為品牌經營者，我想看到營收與廣告花費的疊線主圖，才能一眼看出「錢花下去有沒有換回來」。
9. 作為品牌經營者，我想要一個常駐的下一步指南卡區塊，平時沒出事也主動列出現在最該做的 1–3 件事，每件附一鍵前往。
10. 作為品牌經營者，我想在沒有待辦時看到指南卡顯示「一切正常」，才能安心關掉系統。
11. 作為品牌經營者，我想要異常警示區把打斷佇列的警報按嚴重度分色呈現，才能先處理會流失錢的事。
12. 作為品牌經營者，我想在駕駛艙看到 AI 油錢錶（本月已花／上限），才能控制 AI 花費不爆表。
13. 作為品牌經營者，我想看到內容產線小計（待審／已發），才能知道有沒有東西卡著等我。
14. 作為品牌經營者，我想要 Meta 與 GA4 成效每天自動同步，不必記得手動按同步鈕。
15. 作為品牌經營者，我想在自動同步失敗時收到警示（而不是默默沒更新），才不會拿舊數據做決策。
16. 作為品牌經營者，我想在檔期預算會提前燒完或明顯花不完時收到 pacing 警示，才能及時調整。
17. 作為品牌經營者，我想要系統內建台灣檔期日曆，在大檔提前 90 天、中檔 45 天、小檔 30 天提醒備戰，才不會錯過檔期。
18. 作為品牌經營者，我想在檔期前 14 天收到素材完稿提醒，才有時間測試素材。
19. 作為品牌經營者，我想看到檔期內目前處於預熱／高潮／衝刺哪個階段，才知道現在該衝曝光還是收轉換。
20. 作為品牌經營者，我第一次進駕駛艙時想要 30 秒的重點導覽（這是指南卡、這是警示區），之後不再打擾。
21. 作為品牌經營者，我想在任何頁面沒資料時看到「這頁是幹嘛的＋第一步按鈕」，而不是一片空白。
22. 作為品牌經營者，我想從新殼連到所有還沒搬家的舊功能頁，過渡期不中斷日常操作。
23. 作為品牌經營者，我想要不可用的選單項目明確變灰並說明原因，而不是看起來能點卻沒反應。
24. 作為品牌經營者，我想在任何深度的頁面都看得到自己在哪、一鍵回駕駛艙，才不會迷路。

## Implementation Decisions

- 新前端：React＋Vite＋TypeScript 單頁應用；shadcn/ui 組件、ECharts 圖表、Driver.js 首次導覽；淡色單一主題；1440px 純桌機。設計 token 以 ui-ux-pro-max 技能包產出的設計系統為準（階段 0 產出）。
- 部署形態：production 由 FastAPI 以靜態檔掛載新殼；開發期走 Vite dev server。既有 HTML 路由全數保留至切換日（ADR 0003）。
- **儀表板 API（唯一新接縫）**：新增 dashboard 模組，提供跨品牌總覽與單品牌駕駛艙兩組 JSON 端點，統一回應信封（data／generated_at）。只讀，不寫任何資料。
- **接口鐵則**：dashboard 模組只透過各模組的公開查詢函式取數，禁止直接讀寫其他模組內部；資料來源為既有資料表（performance_snapshot、derived_metric、ga4_summary、order_record、llm_task、interrupt、rule_cards），不新增業務資料表。
- KPI 口徑：本月營收＝訂單實收；廣告花費＝成效快照 spend 加總；ROAS 取自 derived_metric；環比＝與上月同期比較。
- 健康度燈號第一版：有未結 money_loss 警報＝紅、有未結 rule_warning＝黃、其餘綠。純規則，不用 AI。
- **指南卡引擎**：純函數判定（沿用判讀狀態機模式：資料進、結論出、不碰資料庫、不呼叫 LLM）。規則採登記制（同打斷佇列類別登記的做法），每條規則輸出（優先序、標題、一鍵前往目標）。第一版文字用程式模板，不花 AI 錢；AI 翻人話留待後續。
- 指南卡第一批貨源：待確認事實數、檔期卡在哪道關卡、判讀結果出爐未讀、下期草案已備好、檔期日曆備戰提醒、pacing 警示。
- 指南卡與打斷佇列分工不變：打斷佇列＝出事才進的警報；指南卡＝常駐掃描的建議。警示區直接讀打斷佇列，不另建通知機制。
- **自動同步**：應用程式啟動時註冊程式內排程，每日拉一次 Meta 與 GA4（沿用既有唯讀同步邏輯，僅觸發者從人變排程）；失敗事件進打斷佇列。手動同步鈕保留。
- **pacing 判定**：純函數——比較檔期預算消耗進度與時間進度，偏差門檻存進規則卡（可視可改），超標產生 pacing 警示進打斷佇列。
- **檔期日曆第一層**：檔期資料為系統內建資料檔（節日＋電商大檔，含等級：大／中／小）；提前期計算為純函數（大 90 天、中 45 天、小 30 天、素材一律 14 天）；到期提醒以指南卡呈現。AI 聯網（ADR 0005）不在本規格。
- 關卡去具名（ADR 0004）不在本規格，屬階段 2。

## Testing Decisions

- 好測試只測外部行為：給定已知資料，驗證 API 回應與純函數結論；不測內部實作細節。
- 受測模組：儀表板 API（隔離測試資料庫＋假金鑰，沿用既有路由測試的 TestClient 模式）、指南卡引擎、pacing 判定、檔期提前期計算（後三者為純函數情境測試）。
- 先例：判讀狀態機的純函數測試、打斷佇列測試、各路由 TestClient 測試。
- 驗證紀律：每條新檢查要當場證明會紅（弄壞被測行為、看它失敗、改回來）。
- 測試品牌一律虛構，不用真實品牌資料。
- React 畫面不寫自動化測試：逐模組人工預覽驗收＋頁內同源 iframe 視口檢查。

## Out of Scope

- 階段 2–4 全部：企劃強化（KPI 對齊、預算拆層、排期策略）、QA 升級、關卡去具名、週報、結案格式、AI 聯網、全站頁面遷移。
- 多平台插槽的實作（本階段僅在 API 形狀上不寫死 Meta 專屬欄位名）。
- 手機／平板、深色模式、交接包自動化、內容/SEO/口碑/推播模組。
- 指南卡的 AI 翻人話。

## Further Notes

- 每完成一個可視模組即給使用者預覽驗收；驗收前重啟服務再驗。
- 廣告模組整體完工定義（體檢表全綠）橫跨多份規格，本規格只涵蓋其中「監控與 pacing」「檔期日曆」兩列。
- 切換日前新舊介面並存，後端改動需兩邊確認不破壞。
