# 建檔精靈從來不寫 `product_economics`，打過的售價變成一句文字

Status: 2026-09-13 演練四（persona 阿明、全新組織、品牌「常春健康」）撞到；
規劃師有 DB 權限，下面每一條都查證過，不是推測。

## 事實

- 阿明在建檔精靈裡填了「薑黃錠售價 1200 成本 380」「益生菌售價 890 成本 260」，
  建檔完成顯示「品牌資料 11 條已生效」。
- 這個品牌的 `product_economics` 表**一列都沒有**。他打的價格全部落在 `product_fact`
  的自由文字裡。
- 原因：`save_product_economics` 全專案只有一個呼叫端——
  `app/brand_web/routes_products.py:479`（商品詳情頁的「產品經濟數字」表單）。
  **建檔精靈沒有任何一步會寫這張表。**
- 後果沿著投放中心一路放大：`app/ads/budget.py:33 breakeven_cpa` → `None` →
  `target_cpa` → `None` → `_cold_start_scenarios`（`budget.py:86-90`）三個預算情境的
  金額全是 `null` → 策略頁三張情境卡印「累積中」且不可點。
  **每一個新品牌都會走到這裡**，除非有人自己想到去開商品頁補數字。
- 策略依據面板直接寫出來了：「薑黃錠目前沒有價格資料，無法以價格或促銷訊息作為分配依據。」

## 使用者看到的（阿明，`run.md` station 1／station 5）

> 「剛剛在建檔精靈那邊明明已經填過薑黃錠售價 1200、成本 380，這裡卻說『目前沒有價格資料』
> ——是不是我剛剛卡半天改來改去、最後救回來的那些資料其實沒存進去？」

同一站還有第二個洞（同一格輸入、同一次流程，所以記在同一張）：按「完成建檔」跳紅字
「這些產品事實要掛在一個真正的產品上，不能是『整個品牌』」，點名 3 條（薑黃錠售價、
益生菌售價、差異化）。「適用範圍」選單只有「整個品牌」和「建立新產品…」兩個選項，
**沒有他前一步剛存過的品項可以選**，於是每條都用「建立新產品…」重打一次商品名；
改完回到「等你確認」卡片，**剛剛填好的售價欄位與『可以』按鈕全部被清空**，要重填一次。

> 「這種事真人遇到大概會停下來打電話問。」

證據：`.harness/scratch/drill4/aming/run.md`（station 1、station 5）、
`.harness/scratch/drill4/aming/step01h-scope-error.png`（紅字與那 3 條）、
`step01f-confirm-facts.png`（清空前）、`step01i-fixed-ready.png`（重填後）。

## 已經被吃掉的半邊（不要重複做）

`F04-I25` 只處理**下游**：策略頁在沒有售價成本時的出路（錯誤訊息說真話、主要按鈕改成
先設定預算、情境卡下面一句「要估金額需要商品的售價與成本」＋連到商品經濟數字頁）。
它**不碰**建檔精靈。上游這張還開著。

## 提案（未裁決，給 F05 /dig）

精靈的「等你確認」那一步，把售價／單位成本／運費做成**結構化欄位**（每個商品一組，
不是自由文字），送出時寫 `product_economics`（走 `brand_intelligence` 既有的
`save_product_economics`，不要新開表、不要新開 API 形狀）。順帶一併決定「適用範圍」
選單要不要列出這個品牌已經存在的商品——今天它只有「整個品牌」和「建立新產品…」，
是上面那個重打一次的直接原因。

要先量的一件事：新品牌走完精靈之後 `product_economics` 有幾列——現在的答案是 0，
這是這張票唯一要被推翻的數字。
