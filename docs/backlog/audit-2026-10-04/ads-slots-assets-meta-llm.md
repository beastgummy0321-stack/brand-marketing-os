## Answers to the brief's specific questions

**(a) Slot / placement state machine.** Stored states (4 tables, 5 vocabularies):
- `ads_user_asset.status`: `pending | processing | retryable | error | ready` (`app/ads/user_assets.py:212,220-224,283-289,320-321`).
- `ads_asset_upload.status`: `pending | failed | uploading | storage_pending | reconcile_pending | complete` (`user_assets_repository.py:62`, `user_assets.py:49,124,144,157,187`).
- `ads_asset_placement`: `confirmed_at` NULL/set, `blocked_reasons` jsonb, `status='manual_ready'` on confirm, `is_current` (`asset_suggestions.py:573-587,622-649`).
- `ads_ad.slot_placement_id` / `material_placement_id(+revision)` (`slots.py:532-537`, `handoff_assignment.py:101-106`).
- `workbench_brief.status`: `queued | running | done | failed` + `last_error` (`app/workbench/repository.py:227-247`).
Displayed slot states (`slots.py:146-175,242-324`): `ready | blocked | in_progress | image_only | waiting | copy_only | missing`. Sentences: `WAITING` has exactly two (`slots.py:179-182`: 「等你：到工作檯選定一版文案」「等你：確認這版文案」); `blocked.text` = first stored refusal or 「這個檔案處理失敗…」 (`slots.py:209-222`); the tile chips are 處理中／等你／卡住 (`frontend/src/components/ads/workspace/SlotTiles.tsx:112-114,158`). Conflations are rows 1–4 below.

**(b) Claims / statutory / offer checks, slots vs workbench.** Same primitives (`claims.sources`→`unsupported`→`missing_offer`, `claims.statutory`), **different inputs and different verdict**: slot judges against `sell_way.of_ad(ad)` + the ad's *current* `offer_key` (`asset_suggestions.py:59-83`, `asset_suggestion_policy.py:82-95,132-134`) and blocks; workbench judges against `brief.product_id` + the brief's *dispatch-time* `coordinates_snapshot_json.offer` (`app/workbench/jobs.py:705-709`, `repository.py:1415-1423`) and only warns (`claims.py:228-248`). Statutory: slot path through `validate_claims(…, sell_way)` (`asset_suggestion_policy.py:146`), placement list through `validate_claims(…, None)` (`user_assets_routes.py:230`) — equivalent because `statutory()` ignores product. Forbidden claims: checked only on the slot path (row 6). Rows 5–6.

**(d) File validation copies.** Size cap: **two constants** (`app/ads/media_probe.py:12`, `user_assets_repository.py:13`, both 50 MiB) and **five sentences** (`user_assets_repository.py:63` 「單檔必須介於 1 byte 與 50 MiB。」, `user_assets.py:39` 「檔案超過 50 MiB 或沒有內容，請另建批次。」, `user_assets.py:111` 「檔案大小不符或超過 50 MiB，請重試。」, `user_assets_routes.py:112` 「單檔不能超過 50 MiB。」, `media_probe.py:45`); empty-file and oversize share one sentence at `user_assets.py:39,111` and `user_assets_repository.py:63`. Siblings outside ads: `app/brand_web/routes_library.py:60,82,315` (50 MB), `app/intake/state.py:240-241` (10 MB), `app/llm/providers.py:185,194` (10 MB base64). `app/core/input_rules.py:11-13` *declares* the cap stays per path. Type: one sniff (`input_rules.sniff`) but the allowed set is per path (`media_probe.SLOT_KINDS:20` excludes GIF; `input_rules.KIND_LABELS:144` includes it) — by design, with its own sentence (`media_probe.py:28`). Date-order copy: `user_assets_repository.py:382-383` re-implements `input_rules.date_order:129-137`. Copy-field validity has three rules: `validate_copy` (≤20 keys, ≤12000 chars, any key; `user_assets_repository.py:195-205`), `slots._copy_body` (only `COPY_FIELDS`; `slots.py:659-677`), `validate_reply` (≤4000; `asset_suggestion_policy.py:167-173`).

**(e) `app/meta` imported by shared core.** Outside `app/ads/adapters/`: `app/ads/channels.py:11-12` (daily_pull + repository), `app/ads/simulation_recovery.py:11`, `app/ads/__init__.py:117` (parent-owner hook; its own docstring `:28-29` says the package does not import `app.meta`). `channels.py` is the sanctioned home of the platform name (`test_ads_no_platform_literal.py:15`), yet it hard-codes the branch and the label (row 10). Daily pull outcomes: `run_daily_pull` raises on any account failure (`daily_pull.py:120-131`) → only a procrastinate `failed` event; `last_pull_at` just stops advancing (`repository.py:221-226,474-484`); `run_backfill` writes nothing (`daily_pull.py:251-260`); `GET …/backfill` returns `running + row counts` only (`meta/routes.py:221-262`) — never-ran / ran-empty / failed are identical (R7 A12 sibling, row 8).

**(f) `app/schedule` state vocabulary and silent paths.** Vocabulary is `llm_task.status` + `job_outcome` placeholder (`state.py:73-102`), brief `status/last_error/"missing"` (`state.py:279-305`), pack `state` passthrough (`state.py:308-326`), period/binding states (not read fully). Silent paths found: `jobs.py:643-646` (pack submit failure logged only; row 14); `graph._to_entity_row` drops unparsable rows (documented, `meta/graph.py:485-496`). `history.py:118-130` and `diagnosis._round_result:444-445` handle failure honestly.
