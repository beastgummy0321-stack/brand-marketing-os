# 0022 檔期可「現在結算」、匯入可整批撤銷；M1 排在 P1 之前（2026-08-23）

依據 `.scratch/e2e-adflow/REPORT.md`（瀏覽器全程實測）第 1–3 節，使用者逐題裁決。

## 決定

1. **現在結算**：覆盤分頁新增「現在結算」按鈕，直接呼叫 `reading.finalize()`，不再只靠
   結束日＋14 天的背景工。前提只有一條：這期至少一筆未隔離的成效列（CSV 或手填皆可）；
   不要求結束日已過。一鍵確認框（ADR 0004 精神，不填名字），框內寫明狀態不可逆、
   晚到資料仍可補匯，並依 Spec 13 同一套寫法先說會花多少 AI 額度。
2. **結算後匯入照常**：不擋、不加確認。匯入區只在已結算時顯示一行：
   「這期已經收帳了。現在補進去的數字，系統會重新算一次結論，並告訴你哪裡變了。」
   走既有 `rerun_for_late_data()`。
3. **匯入撤銷＝整批，不做單列**：成效分頁列出最近 5 批匯入（時間／來源／寫入／跳過／
   隔離筆數），每批一個撤銷鈕；依既有 `import_batch_id` 刪，連 derived_metric 一起
   （重用 `delete_snapshots()`）。不含 simulated 來源。「改單列數字」一律不做——錯了就撤批重傳。
4. **撤銷後自動重判**：撤銷即跑 `reading.run()`；已結算的檔期改走 `rerun_for_late_data()`。
   撤銷有一鍵確認框，合併寫「這批數字會消失、要重傳才找得回、結論會自動重算＋花費約 US$x」。
5. **結算後仍可撤銷**：資料可增可撤，只有狀態 CLOSED 不可逆（沿用票 06「D2 不可降級」）。
6. **看板順序改為 S1（結算/撤銷）→ M1 → P1 → U1**：報告第 2 節證實切角歸因完全依賴
   `external_ad_mapping`，而該表只在「具名投放授權」時寫入，需要真實 Meta 廣告 ID。
   P1「帶單切角下期加權」在 M1 自動建廣告並回寫 mapping 之前沒有輸入，先做即空轉。

## 當時排除了什麼

- 結算前提加「結束日已過」——等於 14 天鎖的翻版，實測就是要提前收。
- 單列檢視／編輯／刪除——成效列來自 CSV，改單列違反 append-only；批次撤銷已覆蓋實測污染
  情境（4 筆測試列同一批上傳）。需要時再開。
- P1 先做、用「CSV 廣告組合名 ↔ 切角名」字串對應過渡——報告已驗證 AI 產生的切角名
  對不上固定夾具名，會是第二個空轉。
- 撤銷只刪資料、叫使用者自己按重新判讀——留坑。

## 後果

- `reading.run()` 每跑一次都呼叫 AI 翻人話；結算與撤銷都是花錢動作，兩處 UI 必須先報額度。
- 三個月後若「最近 5 批」不夠用，升級路徑是完整列表，不是單列編輯。
