# 0026 一條學習＝一個結論＋一個適用範圍；重複驗證是信心加強，不是第二份證據（2026-08-25）

起因：B0-23（`.scratch/orchestrator/rehearsal-B0/FINDINGS.md`）記為「累積智慧沒有去重」，
B2 覆核（`B2-VERIFY.md` 第 29 行）判為「非漏（代理 A 誤報）：不同期各自驗證同一結論的設計」。
兩份紀錄各對一半，至今沒有定論——本 ADR 是那個定論。

## 一、查證結果（實測 `data/app.db`，非推測）

同一句結論（正規化後完全相同）目前有三列 `expired = 0`：

| id | 來源期別 | sample_size | confidence | 文字 |
|---|---|---|---|---|
| `lrn_…RR31` | `ccy_…09SH`（07-30） | 132 | `moderate` | 無括號，**不點名任何切角** |
| `lrn_…TEZA` | NULL（期別已 purge） | 99 | `reinforced` | 有「（實證成分／成分對比）」 |
| `lrn_…VARD` | `ccy_…PXRX` | 99 | `reinforced` | 有「（實證成分／成分對比）」 |

由此確認三件事：

1. **「第一次看到這個結論」的錯標已修好。** `reading.py:765` 的 `_ledger_confidence()`
   先查 `learning_ledger_entry_exists()`，命中就標 `reinforced`。實跑
   `_normalize_learning_text()`，那兩句話正規化後**相等**（括號夾註被
   `_LEARNING_ASIDE_RE` 整段刪除）。B2 的裁決在程式裡是真的存在的設計。
   使用者看到標 `moderate`／樣本 99 的那一列是 `lrn_…S175`，現已 `expired = 1`，
   是修好前的殘留。
2. **設計只實作了一半。** 標籤收斂了，讀取端沒有：`repository.py:1535`
   的 `list_learning_ledger()` 與 `context_compiler.py:288` 都是逐列輸出。
   下期企劃 prompt 今天真的收到**三行**同義結論、各帶各的樣本數（132／99／99）。
   `reinforced` 這個等級在畫面與 prompt 上等於沒有作用。
3. **去重與贏家橋接互相矛盾。** `carry_forward.py:76` 的 `_signed_off_winners()`
   靠切角名稱是否**出現在 `learning_text` 這句人話裡**認贏家（票 F11 裁決）。
   於是同一句話的兩種寫法行為完全不同：帶括號那句認出「實證成分」「成分對比」兩個贏家，
   會被 F12／F15 的硬規則要求下期方案逐一交代；不帶括號那句認出 0 個贏家，方案可以
   一個字都不提。**而去重正規化做的第一件事就是把括號整段刪掉。**
   一旦開始合併，「合併後留哪一句文字」就會無聲決定下期方案的守門強度。
   這是本 ADR 必須先於程式碼存在的原因。

## 二、決定

1. **同一條學習的判準只有兩項：結論文字正規化後相同 ＋ 適用範圍相同**
   （品牌整體／同一個產品）。兩項都成立才是同一條。

2. **不用來源假設 id 當判準。** 每期都會開新的 `strategy_hypothesis` 列，id 天生不同；
   用它等於「永遠不會有同一條」，直接廢掉 `reinforced` 這個等級。

3. **不用點名切角集合當判準。** 點名切角是「這一次拿什麼證據驗的」，屬於每一次驗證
   各自的證據，不是結論的身分。同一個結論這期用實證成分驗、下期用成分對比驗，
   正是「不同期各自驗證」的定義，不該因此裂成兩條。
   代價：第一節第 3 點的矛盾不會自動消失，由決定 5 處理。

4. **`learning_ledger` 維持 append-only 存 N 列；收斂做在讀取端。**
   累積智慧頁與企劃 prompt 對同一條學習**只出現一次**，形如
   `…（已加強：3 期各自驗證過，對照樣本 132／99／99）`。
   理由不是版面：AI 讀到三行同義結論會把它當最強方向，而它只是同一個發現被記了三次——
   這正是 B0-36 污染鏈的溫床。「已加強・3 期」比三行重複資訊更多，也更誠實。

5. **收斂後對外露出的文字，取那一組裡最長的原始 `learning_text`。**
   決定 3 把點名切角排除在身分之外，但它決定使用者與模型讀到哪幾個贏家的名字。
   同一組的成員正規化後相等，差別**只在括號夾註**（`_LEARNING_ASIDE_RE` 刪掉的正是那段），
   而切角名字就住在夾註裡——取最長那列＝保留最多切角名字，資訊只會多不會少。
   取最新一列或任取一列，會讓 prompt 讀到不點名任何切角的版本（如 `lrn_…RR31`），
   模型連要交代哪個贏家都不知道，卻仍會被 F12／F15 的閘門擋下，變成必然失敗的迴圈。

   **閘門本身不受收斂影響**：`_signed_off_winners()` 讀的是
   `list_learning_ledger()` 的原始列（`carry_forward.py:95`），不是收斂後的視圖，
   所以 `prior_winners()` 認出的贏家集合不會因為收斂而減少。收斂是呈現層的事。

6. **樣本數改為「對照樣本」：只算這句結論點名到的那幾個切角的轉換數加總。**
   這不是新規定，是把已經寫下來的意圖補實作：`reading_hypotheses.py:137`
   `guard_supported_verdict()` 的 docstring 明寫「只算這次真的拿來對照的那幾個切角自己的
   轉換數加總，不是這個產品／這期的全部轉換數——後者會把沒參與這次對照的流量也算進
   『樣本』，用統計語氣包裝一個沒對照過的數字」。但它的實作是
   `sum(c["conversions"] for c in comparison_cells(...))`，而 `comparison_cells()`
   回的是**那期所有對得回成效的切角**，沒有依假設篩選——132／99 就是這個落差。
   判斷「哪些切角被點名」用 `_signed_off_winners()` 現成的子字串比對零件，
   不新增啟發式規則（沿用該函式 `ponytail:` 註記的天花板與升級路徑）。

7. **句子一個切角都沒點名時，對照樣本為空，不落回整期加總。**
   `lrn_…RR31` 正是這種列。算不出就留白，不用整期數字冒充（鐵則 16）；
   這與同一條路上 `_signed_off_winners()`「句子沒提到任何切角就不貢獻贏家」一致。

7b. **受眾類假設的對照樣本一律留白（2026-08-25 使用者裁決）。**
   `strategy_hypothesis.hypothesis_type` 有 `audience`／`message` 兩種，
   而 `comparison_cells()` 的軸是 `creative_angle`——那是訊息軸。
   受眾假設（「通勤族比在家工作者更會下單」）的句子裡永遠不會出現切角名字，
   所以它落在決定 7：對照樣本留白，`_ledger_confidence()` 因此回 `preliminary`。
   這不是降級，是把一直存在的事實講出來：**系統從來沒有受眾對照格**，
   之前填的那個數字一直是訊息軸的數字借來充當受眾樣本。
   已知上限（記錄不修）：`guard_supported_verdict()` 目前用「切角格數 ≥ 2」
   當「這期真的做過對照」的代理，對受眾假設而言這個代理本身就不成立——
   受眾假設仍簽得下「成立」，只是不再帶著一個借來的樣本數。
   要根治得先有受眾維度的對照格，是另一張票、另一張 ADR。

8. **不回頭改寫任何既有列的 `learning_text` 或 `sample_size`。**
   沿用 F9／F13 的「不改寫歷史」。重複列由決定 4 的讀取端收斂自然解決，
   不需要動歷史資料。舊列的對照樣本留白（決定 7），不補算。

9. **唯一動到既有資料的動作：把演練殘留的孤兒列下架。**
   `source_cycle_id IS NULL` 且來源期別已 purge 的列（如 `lrn_…TEZA`）走既有
   `deactivate_learning_ledger_entry()` 標 `expired = 1`——該函式不刪列、不碰內容欄位、
   有審計軌跡，`expired` 是建表時就留給下架用的狀態欄，**用它不算改寫歷史**。
   B2 覆核當時已寫「演練殘留，可設 expired」；與 B0-47 的舊卡清理同一類一次性收尾。

## 三、不改的東西

- **`learning_ledger` 不加唯一鍵、不改 append-only。** 收斂是讀取端的呈現規則，
  不是儲存規則。加唯一鍵會讓「第二次驗證」寫不進去，等於刪掉 `reinforced` 的資料來源。
- **`learning_ledger_entry_exists()` 的 `product_id IS ?` 精確比對維持不動。**
  同一句話掛不同 `product_id` 不互相偵測（票 F3 已記錄為已知限制）。
  決定 1 的「適用範圍相同」刻意與這個實作對齊，不製造新落差。
- **`_LEARNING_ASIDE_RE` 的刪夾註行為不動。** 票 F3 R6 的裁決（漏抓比誤刪安全）仍成立；
  決定 5 是在收斂那一步補回被刪掉的資訊，不是回頭放寬正規化。
- **`_SIGNED_OFF_CONFIDENCE` 三級全收不動**（`carry_forward.py:28`）——
  `reinforced` 本來就在裡面，收斂不會讓一條學習掉出贏家來源。

## 四、實作票的紅檢查（本輪不寫程式）

日後開票時，下面第 1 條必須在動程式之前先跑、看它紅：

1. 同一句結論三列（其中一列不點名切角）→ 企劃 prompt 只出現**一行**，且該行文字是
   點名切角最多的那一列（決定 4、5）。
2. 一條學習點名兩個切角、那期另有第三個沒被點名的切角 → 對照樣本只加前兩個（決定 6）。
3. 一句都沒點名的學習 → 對照樣本留白，不出現整期加總數字（決定 7）。
4. 回歸網：`test_ads_carry_forward.py::SignedOffLearningWinnerTest` 全綠——
   收斂只動呈現層，`prior_winners()` 認出的贏家集合一列都不能少（決定 5 第二段）。
