# 凍結猜消費者反應的拒絕理由，刪除試水溫解禁整套機制

舊規則（決策 0030 第二節第 6 點、第 14 點；決策 0035 第一節、第 5 點 G3）：`REASON_TO_AXIS`
（`app/ads/fingerprint.py`）九條拒絕理由裡，`too_stiff`（太生硬）、`off_brand`（不是品牌
調性）、`too_ad_like`（太像廣告）、`discount_too_deep`（折扣太深）、`hook_weak`（開頭抓不
住人）五條有軸的理由，退到門檻（3 期時間窗內被退 2 次且比例偏高）都會升級成候選規則卡、
接受後鑄成永久寫進生成 prompt 的長期禁令——這張對照表在決策 0030 第二節「本表為定版」，
使用者 2026-08-02 逐條審畢。決策 0030 第 14 點另外定義了「解禁卡」：系統挑一條現行生效
中的禁令，每期刻意生一則違反它的「野路子實驗組」素材，若該素材沒被退、且所屬產品這期
判讀達到 `scale_candidate`（可以加碼），就產一張解禁卡，接受後停用原本的禁令。決策 0035
發現這整套統計缺陷（規則卡只數分子不數分母、假設結案入帳是確認偏誤幫浦、解禁判定拿
n=1、無對照組的單次實驗當證據），第一節定調用 `app/ads/learning_halt.py` 的
`LEARNING_LOOP_HALTED` 開關即刻停用三個機制，明文「用明確開關而不是刪程式碼，統計缺陷
修好之後改回 False 即可重新啟用」；第 5 點 G3 進一步定調「統計修好後，規則卡門檻對所有
指紋軸值一律重新開放」。

0030、0035 兩份原始決策文件已不存在於檔案系統（`docs/decisions/` 在 git 歷史裡從未出現
過），它們的內容只殘存在程式碼註解與測試 docstring 裡——本 ADR 是這兩份決策裡跟本次
變更相關的部分，唯一留得住的紀錄。

推翻理由：使用者 2026-08-06 逐條審視 `REASON_TO_AXIS` 才發現，五條可升級理由裡有三條
（`too_stiff`、`too_ad_like`、`hook_weak`）猜的不是使用者自己的品牌或商業政策，而是**消費
者會怎麼反應**——這是預測，不是事實，全程沒有任何真實成效數據（曝光、點擊、轉換）驗證
過。業界對「主觀否決測試結果」是有記載的昂貴失誤模式；成效創意的定義是「以可衡量的商業
結果為優先，而非主觀設計偏好」。門檻只要求 3 期內憑感覺退兩次，比例判準也只是跟同軸其他
值比較，並不需要真的了解消費者——兩次隨手的主觀否決就可能鑄成永久寫進 prompt 的約束，
而且是系統自己選的門檻，不是使用者要求的力度。

至於解禁整套機制：拿掉三條猜測性理由的升級資格後，唯一還會被鑄成禁令的只剩品牌調性、
折扣力度兩條——那是使用者自己的商業政策，政策要改，使用者自己去累積智慧頁把規則下架
即可，不需要「系統刻意生一則違規素材去市場試水溫、成效達標就自動解除」這整套繞了一圈
的機制。停用旗標（`learning_halt.py`）存在的唯一理由是「等統計修好再開回來」，但試水溫
實驗組的統計問題（n=1、無對照組、不可重複）不是能修好的統計錯誤，而是這個設計本身的
天花板——沒有回頭路可开，開關因此也失去存在意義。

新規則：

1. **白名單制**：`app/ads/fingerprint.py` 新增 `RULE_UPGRADABLE_REASONS =
   {"off_brand", "discount_too_deep"}`。只有落在這個白名單內的拒絕理由，其拒絕次數才計入
   規則卡升級判準的分子。刻意用白名單、不用「凍結三條」的黑名單：日後新增拒絕理由，預設
   不能鑄成永久禁令，除非明確把它加進白名單——不能讓「忘記排除」意外解鎖新的永久約束。
2. **三段判準**（`app/ads/nextcycle.py` 的 `_rule_card_verdict`）：政策拒絕次數（白名單內）
   達門檻且比例明顯高於同軸其他值 → `pending`（可升級）；否則只要總拒絕次數（含猜測性
   理由）達門檻 → `observing`（永遠停在觀察中，只顯示不進 prompt）；否則 → `insufficient`。
   猜消費者反應的三條理由因為政策次數恆為 0，永遠只能停在 `observing`，不會被靜默丟棄、
   也不會鑄成禁令。
3. **短期記憶不變**：`app/ads/creative.py` 的 `_rejection_constraints`（拒絕記憶的第二條、
   與規則卡完全獨立的入 prompt 路徑）不受本次變更影響——退掉的寫法下一批生成仍會避開，
   只是永遠不會升級成永久禁令。
4. **刪除三套機制**：`app/ads/learning_halt.py` 整支刪除；`app/ads/nextcycle.py` 的
   `build_unban_cards`、`UNBAN_TARGET_STATUS` 刪除；`app/ads/creative.py` 的野路子實驗組
   生成（`_generate_wildcard_variant`、`_build_wildcard_user_text`、
   `WILDCARD_VARIANT_TYPE`）刪除；`decide_rule_card` 拿掉解禁方向，只剩候選禁令卡與
   overclaim 候選卡兩種目的地。
5. **頁面誠實化**：累積智慧頁不再宣稱這個機制「重建中」——機制是永久移除，不是暫停等
   統計修好再開回來。

## Consequences

- 品牌調性、折扣力度以外的意見（文案生硬、太像廣告、開頭弱）不會再自動變成長期規則，
  即使使用者連續好幾期都退同一種寫法——這是刻意的取捨：短期記憶（`_rejection_constraints`）
  仍會讓下一批生成避開，觀察中清單仍會列出來提醒，只是不會鑄成永久約束。使用者若真心
  認定某個猜測性方向是品牌調性問題，需要自己手動改用 `off_brand` 理由拒絕，或到累積智慧
  頁的前朝教訓訪談自述登記。
- 拿掉解禁機制後，一條政策類禁令一旦被接受，除非使用者自己到累積智慧頁手動下架
  （`deactivate_rule`），否則會一直生效，不會有系統自動用實驗結果解除它的路徑。
- `nextcycle.build()` 回傳的 dict 拿掉 `unban_cards_created` 鍵；沒有任何模板讀過這個鍵，
  只有測試斷言過，不影響任何現有頁面。
- 這是繼決策 0035 之後，第二次把「等統計修好再開回來」的暫停機制改成永久刪除——
  日後若要再引入類似「用開關代替刪程式碼」的暫停設計，必須先說明為什麼這次的統計問題
  跟解禁機制不同，是真的能修好的錯誤，不是設計本身的天花板。
