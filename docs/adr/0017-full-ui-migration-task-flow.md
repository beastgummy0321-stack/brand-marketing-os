# 0017 全站搬家提前＋任務流互動模型（2026-08-11 定案）

## 決定

1. 總綱（redesign-blueprint.md）階段 2、3、4 合併提前，一次做完：全站約 74 個舊 Jinja 頁搬進 React 新殼，並同步完成廣告業界標準強化。分 6 批交付，細節以 `docs/ui-migration-contract.md` 為準。
2. 互動模型全站換成「任務流」：每個流程畫面中央只放目前該做的一件事，AI 預填＋推薦＋主按鈕（principles.md 第 20 條的版型化）。五條互動鐵則見契約總表第二節。
3. 三條雙軌收斂（使用者 2026-08-11 拍板）：
   - 素材生成以矩陣頁（theme_engine）為唯一路徑；合規掃描與採用關卡補進矩陣頁後，舊素材頁（ads_creatives.html）與舊引擎（app/ads/creative.py 生成路徑）退役。
   - 建品牌只留建檔精靈一條入口；陽春表單（brand_new.html 直建路徑）退役，精靈第一步支援只填名稱即往下。
   - 待辦聚合收斂為兩層：收件匣管跨品牌、駕駛艙指南卡管單品牌；舊首頁「今天要處理的事」獨立聚合退役。
4. 收斂點與所有搬家畫面一律重新設計互動，禁止舊頁換皮（使用者原話：跳脫舊有框架、完全現代化翻新）。

## 不可逆項目定案（code-rules 五項）

| 項目 | 定案 |
|---|---|
| 資料模型 | 不動。既有表與欄位照舊；強化項目（週報、QA 紀錄等）若需新表，該票動工前另行提請使用者批准 |
| 模組邊界 | 前端按 feature 資料夾：`frontend/src/components/<feature>/`；跨 feature 只准經 `components/layout/`、`lib/`。後端 API 掛在各自模組的 routes 檔，依賴方向沿用 A1 三層地界（brand_intelligence 不 import app.ads；ads 讀 orders 單向） |
| 對外契約 | JSON API 路徑規範 `/api/<module>/brands/{brand_id}/…`；欄位形狀由各畫面契約的假資料定案（screen-contract.md 第十二節），契約沒寫的欄位不得產出 |
| 同步/非同步 | AI 生成沿用後端既有背景執行緒＋冪等閘；前端輪詢狀態端點，不引入 websocket |
| 錯誤與交易邊界 | 寫入一律等後端確認才更新畫面（不做樂觀寫入）；失敗顯示人話＋可重試；後端交易邊界不動 |

## 理由

- 使用者決定將舊版介面搬家提前，且選「全搬＋順便強化」，避免廣告頁做兩次工。
- 盤點（105 塊積木、206 條路由）證實：117 條 HTML 路由幾乎零 JSON API，搬家的後端工作量＝補接口，不需重寫。
- 雙軌收斂依 workflow.md 第五節「同一能力禁止兩條代碼路徑」。

## 當時排除了什麼

- 重寫後端：零收益、高風險，總綱第二節本來就禁止。
- 一次性大爆炸生成整站：無中間檢查點，改為 6 批各自可驗收。
- 廣告頁照舊樣搬、強化後補：同一批頁面做兩次工。
- 維持素材新舊雙引擎、雙建檔入口、三處待辦聚合：違反單一路徑規範。
