# 下期建議補兩道守門：最小樣本數門檻＋檔期情境加權，不做硬性樣本分割

_Status: retired by ADR 0030 — the code it governed was deleted._

G4＋G13（2026-08-10 grill，GRILL-PENDING.md 已標記「同場 grill」，因為都動
`app/ads/nextcycle.py` 的同一段歷史資料比對邏輯）。

## 一、最小樣本數門檻＝50 次轉換（G13）

查證修正：GRILL-PENDING.md 原文提到的「F 段 50 轉換池」，查證後發現不是「切角資料可信度」
的門檻，是 `app/ads/target_cpa.py` 的 `WEEKLY_CONVERSIONS_PER_GROUP`，用途是算「一個廣告
組合的預算該抓多大」，跟「這批切角歷史資料信不信得過」是兩件事。`nextcycle.py` 目前完全
沒有樣本量守門——這是這輪要補的洞。

**沿用同一個 50 這個數字**（不是另外發明）：一是內部既有常數剛好也是 50；二是 web 查證
madgicx 的業界基準也是「50 次轉換才算可信」（見對話紀錄的查證結果）。內外部數字一致，
比自己隨便定一個數字更站得住腳。

## 二、樣本不足時：標「證據不足」，不排除（G13）

轉換數 < 50 的切角，`nextcycle.py` 的相似度／新穎度／同溫層比率計算仍然把它算進去，只是
在回傳結果多附一個 `evidence_sufficient: false` 旗標。**不排除的理由**：新品牌、新切角
天生樣本不足，直接排除等於系統永遠學不到新東西，也違背 ADR 0009「誠實狀態優先」的既有
原則——藏起來不算誠實，标出來讓使用者自己判斷才是。

## 三、花費達門檻仍零轉換：主動標記「表現差」（G13，新增）

跟「樣本不足」相反的情況：花了不少錢卻完全零轉換，這不是「還不知道」，是已經有足夠證據
判斷「這次沒打中」。沿用 `app/ads/budget.py` 的 `PAUSE_THRESHOLD_RATIO`（0.5）概念——單一
切角花費達到它分配預算的 50% 仍零轉換，`nextcycle.py` 主動標 `underperforming: true`，
下期建議不推薦重複使用。**注意**：這是沿用同一個「0.5 比例」判斷邏輯，不是直接呼叫
`budget.py` 的同一段程式碼（`budget.py` 的 `pause_threshold_spend` 是整個檔期層級的
「該考慮暫停」判斷，這裡是切角層級的「這切角這次沒打中」判斷，場景不同、公式概念相同）。

## 四、檔期情境標籤：自動比對日曆帶入，不必手動選（G4）

`campaign_cycle` 新增 `occasion` 欄位（新增，值為節日名稱或 `null`）。開檔期時，若檔期
時間窗口落在既有 `app/dashboard/campaign_calendar.py` 讀取的 `campaign_calendar_data.json`
某個節日的投放窗口內，自動帶入該節日名稱；沒對到任何節日則為 `null`（畫面顯示「常態檔期」）。

**欄位放在 `campaign_cycle`，不是 `experiment_cell`**：情境是整個檔期共有的屬性（同一檔期
底下所有切角都屬於同一個場合），不必每個切角格各自重複存一份。

**不需要使用者手動選**：直接重用已經存在、已經在用於備戰提醒的節日日曆資料，不必新增一套
使用者要自己判斷「這算不算母親節檔期」的介面。

## 五、情境標籤怎麼影響下期建議：加權混合，不做硬性樣本分割（G4，核心取捨）

`nextcycle.py` 的歷史資料比對（拒絕記憶指紋比對、新穎度、同溫層比率）改成：**樣本仍是
品牌全部歷史**（不因為場合不同就整批排除），只是計算相似度／權重時，`occasion` 跟這次檔期
相同的歷史資料權重加重，不同的權重較低但仍然參與計算。

**推翻了什麼**：GRILL-PENDING.md 原始構想是「依場合分開比較」（暗示樣本會被切開）。
grill 當下改成加權混合，理由：硬性分開比較，樣本量在場合層級會被切得更小，直接撞上第一節
剛定的 50 次門檻——新品牌很可能一整年只跑過一次某個節日，永遠沒有「同場合」歷史可比，
功能對新品牌等於沒用。加權混合則永遠有全部歷史當底，同場合只是把權重拉高，新舊品牌都能用，
也不會讓樣本量問題比現在更糟。

## 當時排除了什麼

- **依場合切開獨立比較的資料池**：見第五節，排除理由是會讓樣本量在場合層級碎片化，
  新品牌無法使用。
- **另開一套花費零轉換的判斷公式**：排除，沿用 `budget.py` 既有 `PAUSE_THRESHOLD_RATIO`
  概念，避免同一件事（「花費比例門檻」）在系統裡出現兩套不同數字。
- **樣本不足直接排除該切角**：排除，理由見第二節，牴觸誠實狀態優先原則（ADR 0009）。
- **檔期情境標籤由使用者手動選**：排除，改自動比對既有節日日曆資料，理由見第四節。
