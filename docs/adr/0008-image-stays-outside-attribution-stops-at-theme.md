# 圖片不進系統：只出提示詞，成效歸因收在主題層

_Status: retired by ADR 0030 — the code it governed was deleted._

舊規則：素材產出以「切角」為唯一分層，`app/ads/creative.py:40` 的 `VARIANTS_PER_CELL`
一格產 1 個 `image_prompt` ＋ 2 個 `hook` ＋ 1 個 `copy`；`creative.py:131` 的硬規則第 4 條
要求「同一個切角底下的幾則不要只是換句話說，要真的不一樣」，全域適用。圖片只以提示詞交付
（`app/templates/ads_creatives.html:77`「把這段貼進生圖工具就能做出這張圖」），生成後的圖
不回到系統。GRILL-PENDING C 段把生成單位改寫為「切角 × 廣告格式 → 一個平台素材包」。

推翻理由：使用者 2026-08-07 grill（G2）指出 Meta 彈性廣告格式的實際形狀——一則廣告最多
放 10 個圖或影片，這批媒體必須講同一件事，差異只服務於延緩廣告疲勞，不服務於比較優劣。
既有設計只有切角一層，把「要真的不一樣」套到所有素材上，因此永遠產不出這批同主題的媒體，
對應使用者的實測回饋「Meta 投放上一個都用不到」。

## 一、素材分三層，「素材包」一詞廢除

```
切角      為什麼買         → 比較優劣在這層，說法要真的不一樣
 └ 主題    這則廣告長什麼樣  → 一個主題＝一則廣告，有自己的一句話名稱
    └ 單張素材             → 只差配色、模特兒、拍攝角度
```

視覺風格（霓虹／賽博／科幻）屬主題層：換風格即為另一個主題、另一則廣告。切角層不管視覺，
單張素材層不得換視覺語言。定義見 `CONTEXT.md`。GRILL-PENDING C.2 的「素材包」與本 ADR 的
「主題」是同一個實體，統一用「主題」，程式命名 `theme`。

`creative.py:131` 那條規則保留不動（它管切角層），另外新增一條方向相反的主題層規則：同主題
底下的素材文案與圖上文字一律相同。兩條規則各自標明適用層級，不得只留一條。

主題有自己的 id 與一句話名稱（AI 產）。不得拿「第一個 image_prompt」當主題代表——刪掉第一則
會讓身分飄移，且提示詞是幾百字的畫面描述，在挑選畫面上無法當標題看。

## 二、圖不生、不逐張歸因；不進系統，但系統記得住在哪

系統不接圖片生成 API，不記錄單張素材的成效。成立的理由不是省磁碟，是**主題與一則廣告
一對一**：Meta 回來的廣告層成效本身就是主題成效，而廣告層歸因 `app/ads/reading.py:392`
的 `_asset_totals()` 走 `external_ad_mapping` 已經在做，不需要新建。

因此 Meta Insights 的 `image_asset` breakdown 不拉——這同時解掉「`image_asset` 不能在帳號層
拉、要下到活動或廣告層」那個限制。`body_asset`／`title_asset`／`description_asset` 三個要拉：
同一則廣告裡的 5 個主要文案是真的不一樣，廣告層成效分不出誰贏。

**圖檔本身不上傳進系統，改由系統指定一個固定位置讓使用者自己倒。** 一個主題一個資料夾，
按鈕放在該主題的「整組複製」旁邊，後端用 `os.startfile()`（Python 標準庫，Windows 內建）
叫出檔案總管。使用者從生圖工具下載完那一組就地貼上，檔名原封不動——資料夾路徑本身就是
分類，生圖工具給的亂序檔名不需要處理。

素材資料夾根目錄存 `app_setting` 的 `creative_asset_root`，預設 `data/creative`，設定頁可改
（圖檔量級一年約 2.5–4 GB，使用者可能指向雲端同步目錄或另一顆硬碟；路徑本來就是機器專屬，
先例見 `app/core/backup.py:22` 的 `BRAND_OS_BACKUP_DIR`）。結構：

```
<素材資料夾>/
  品牌_檔期_短碼/
    主題名_短碼/
      <生圖工具給的原始檔名>
```

人看得懂的名字在前，四碼短碼在後——名字可能重複也可能被使用者改掉，短碼是系統認回來的依據。

**系統永遠不自動刪圖**，只在檔期頁顯示「這期素材 XXX MB」＋一顆「開資料夾」。理由：同一個
提示詞再跑一次出來的圖不一樣，刪掉不可重現，屬 `code-rules.md` 第四節「防資料遺失」不得簡化
的範圍。**例外是刪品牌／刪檔期時連資料夾一起刪**——這兩個動作依決策 0015／0020 都要先封存
才做得到，是兩段式的刻意決定。刪除時只刪 `<素材資料夾>/<品牌_檔期_短碼>/` 這一層以下，且
先確認資料夾名帶得上系統的短碼（防止根目錄被指到 OneDrive 或磁碟機根目錄時遞迴刪錯）；
確認頁一併顯示「將刪掉 N 個資料夾、共 XXX MB」，照票 02 只說不擋。

日後要「重新利用這些實體圖片」的路是通的但尚未做：掃資料夾 → 丟給 Claude 讀圖 → 產描述與
指紋。系統已有金鑰，不需要新供應商。

## 三、交給生圖工具的形狀

圖片提示詞以主題為單位分組，一組上限 10 則（外部生圖工具單次上限），超過拆成 10＋N，組與組
之間互相隔離。每組一顆「整組複製」按鈕，複製內容 ＝ 使用者自訂開頭 ＋ 該組 N 則提示詞。

主要文案／標題／說明**不進整組複製**：Meta 後台只能一格一格貼，整包複製會逼使用者自己拆。
每一則各帶一顆純圖示的小複製鈕。

（2026-08-14 修訂，ADR 0019：本段的 `image_prompt_batch_header` 由品牌層「視覺風格偏好卡」
取代，現值遷移為各品牌預設；以下保留原文供歷史對照。）

自訂開頭存既有的 `app_setting`（`app/core/settings.py`），key `image_prompt_batch_header`，
**全站一份**，不分品牌——它描述的是「使用者用哪個生圖工具」，不是品牌事實。框裡只有使用者的
全域風格指令（例：圖上文字一律平面實填，不要浮雕、液態字、金屬字、粗糙紋理、磨砂感），沒有
任何佔位符。張數與尺寸由廣告模組算好、複製時自動接在使用者那段字上面。換生圖平台時使用者
自己在框裡加平台參數（例 Midjourney 的 `--ar 4:5`）。

## 四、生成量與格式選擇

沿用 GRILL-PENDING C.3：切角 × 格式全展開，生成量是候選上限不是預設值。切角層另外算出
「這個切角建議開幾則廣告、各用什麼格式」並預選；沒被選中的候選不消失，使用者隨時能取用。

敘事型輪播（步驟、前後對比、多商品各一卡）保留為獨立格式，不由彈性廣告的自動輪播取代——
自動輪播只是同一批圖換排法，做不出敘事。

## 五、查證到的 Meta 事實（2026-08-07）

- 彈性廣告格式：多個素材放進同一則廣告，投遞系統自己決定呈現形式；除了單圖與影片版本，
  Meta 另外從那批圖自動產一個輪播版本。它取代舊的動態素材（Dynamic Creative），且從廣告組
  層級下移到單一廣告層級。
- **只有 `OUTCOME_SALES` 與 `OUTCOME_APP_PROMOTION` 兩種行銷目標支援彈性廣告格式。**
- 每個 `text_type` 最多 5 則；每組至少 1 個圖或影片；素材總數上限 30。
- 2026 年 Meta 把彈性廣告從最上層格式選單移到「格式顯示選項」，行銷目標從 11 個併成 6 個，
  移除 Instagram Explore 版位。

來源：[Flexible Ad Format — Meta for Developers](https://developers.facebook.com/docs/marketing-api/flexible-ad-format/)、
[關於彈性廣告格式 — Meta 企業商家使用說明](https://www.facebook.com/business/help/835561738423867)、
[Asset Feed Spec](https://developers.facebook.com/documentation/ads-commerce/marketing-api/ad-creative/asset-feed-spec)。

## 六、跨平台

三層是骨架，「一個主題底下幾個素材」由平台插槽自己宣告，上限宣告為 1 的平台主題層自動消失、
畫面不顯示這一層。對照：Meta 彈性廣告 10；Google PMax 有資產群組，主題層成立；Google 搜尋
RSA 沒有圖只有 15 標題＋4 說明，沒有主題層；TikTok 一則廣告一支影片，主題層塌成 1；蝦皮商品
廣告直接吃商品圖與商品標題，三層都不成立。

## Consequences

- **`image_asset` 這條路封死**：日後若要看單張圖的成效，得先推翻「不存圖」與「主題以下不比
  優劣」兩條，不是加個參數就好。
- **交接時圖檔不在系統裡**：交接包只列提示詞與該主題的資料夾路徑，圖檔由使用者自己貼進去。
  使用者沒倒進資料夾時系統無從得知，也不擋——該主題的素材空間顯示 0 MB 就是唯一的線索。
- **備份不含圖檔**：`app/core/backup.py` 只複製 `data/app.db`。素材資料夾若指向 `data/` 以外，
  更完全在備份範圍外。硬碟故障時 DB 救得回來、圖救不回來。
- **前端會出現一顆按不下去的灰色「直接生圖（建置中）」按鈕**。這違反 `code-rules.md` 第三節
  「為了以後可能要用先搭骨架」的禁令，使用者 2026-08-07 明示要保留，理由是同時開發多個模組
  會忘記這件事還沒做。存圖功能與生圖功能一起做，在那之前這顆按鈕不接任何後端。
- **彈性廣告的行銷目標限制會擋掉一部分檔期**：開流量、互動、名單目標時這個格式不存在，主題層
  在那些檔期沒有作用。此限制尚未反映在任何畫面上。
- **G1 仍要決定尺寸與比例的實際值**，自訂開頭裡的尺寸那一行在 G1 定案前只接單圖 4:5 一種。
