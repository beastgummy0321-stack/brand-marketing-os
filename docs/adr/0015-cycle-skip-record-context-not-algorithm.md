# 「這期跳過」只留脈絡給提醒卡片，不進下期建議演算法

_Status: retired by ADR 0030 — the code it governed was deleted._

G8（2026-08-10 grill）。查證現況：系統裡沒有任何「跳過這次檔期」的機制；週報模組尚未
建置（`docs/redesign-blueprint.md` 列為「缺」，程式碼庫內查無相關檔案）——本輪「進不進
週報」問題留待週報動工時再處理，非本次決定範圍。

## 一、記一筆，明年照常提醒

新表（暫名 `campaign_skip`）：`brand_id` + `event_id`（對應 `campaign_calendar_data.json`
的節日 id）+ `year` + `reason`（選填）。跟 G7 的 `brand_dismissed_calendar_category`
（ADR 0014）是兩張獨立的表，語意不同：G7 是「這整類節日永遠跟我無關」，G8 是「今年這次
不投，不代表明年不投」——刻意不合併，合併會讓「今年不想投」被誤存成「以後都不提醒」。

## 二、附帶脈絡，不進 `nextcycle.py` 演算法

明年同一節日提醒再出現時，`prep_reminder()`／`creative_reminder()` 額外帶一句「去年
（理由）跳過」，純顯示用途。**不**寫進 `nextcycle.py` 的下期建議引擎（相似度／新穎度／
同溫層比率、規則卡）——那套管的是「哪個切角文案有效」，跟「要不要投這個節日檔期」是不同
層級的決定，混在同一套演算法會讓兩種完全不同性質的判斷互相干擾。

## 當時排除了什麼

- **跳過等同永久關閉提醒**：排除，理由見第一節，會跟 G7 的語意衝突。
- **跳過紀錄餵進 `nextcycle.py` 演算法**：排除，理由見第二節，layer 不同不該混。
- **本輪順便設計週報整合**：排除，週報還沒蓋，沒有東西可以整合，等它動工時再讀
  `campaign_skip` 這張表即可，不必現在預先設計介面。
