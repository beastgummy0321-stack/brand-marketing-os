# 0023 Meta 寫入走官方 MCP、整期一鍵建（暫停）、手填 ID 路徑保留為備案（2026-08-23）

承 ADR 0019 第 5 條（Meta 寫入＝官方 Ads MCP）。使用者於 M1 第①站裁決：

1. **第一片只做「建廣告（暫停）＋本系統發布」**；收件匣同意即執行、放手檔執行器各自另開票。
2. **整期一鍵全建**：交接頁一顆按鈕把所有 ready 的交接包建成 Meta 活動／廣告組合／廣告，
   一包失敗單獨顯示原因，其餘照建；發布也是整期一鍵。不做一包一包按。
3. **圖片由系統從素材資料夾自動上傳**；資料夾沒圖的包擋下不建。
4. **發布兩個出口都做**：上線授權關卡按過 → 系統呼叫 Meta 開啟；旁邊固定「到 Meta 後台看」連結，
   給不信任自動投放的人自己去看。
5. **手填 campaign ID 路徑保留**：Meta MCP 為限量 open beta（官方 2026-04-29 公告，逐步擴大），
   帳戶不一定連得上。兩條路寫同一張 `external_ad_mapping`，下游（成效歸因、P1 加權）不分來源。
6. `app/ads/meta_api.py` 檔頭「刻意不用官方 MCP」條文作廢，隨實作票改註解；唯讀 REST 客戶端本身保留。

## 當時排除了什麼
- 拿掉手填只留自動建——MCP 連不上時整個投放關卡卡死。
- 發布只能去 Meta 後台按——花錢的最後一下會脫離本系統的花費上限關卡（ADR 0019 第 7 條）。

## 後果
- 新增依賴 `mcp`（官方 Python SDK 2.0.0，MIT，2026-07-28）。
- Meta MCP transport／速率限制／台灣帳戶支援官方文件未寫明（查證記錄見 M1 票），實作時以實際連線為準，不得憑記憶補。
