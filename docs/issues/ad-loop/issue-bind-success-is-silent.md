# 配對失敗很吵，配對成功很安靜

Status: 2026-09-06 可用性演練量到（`docs/drills/`）。**三個角色全部撞到（3/3）**，
是本輪重現次數最多的畫面問題。純文案與回饋，沒有資料正確性風險。

成因：`bind_tree()` 回傳的是「這一批有哪些節點配對失敗、各自哪一種失敗」，空清單＝全部成功。
呼叫端只把失敗那份組成句子（`bind_failure_message()`）；**成功那份沒有任何人組句子**。
於是失敗是一整條紅字，成功是零個字。

使用者看到的：
- 失敗（阿明第一次按，還沒去 Meta 建）：「配對失敗：「Meta｜薑黃錠｜測試期｜廣泛開發＋新訴求」
  在 Meta 上找不到。名稱要一字不差（區分大小寫，前後空白也算）。上一層沒有配對成功時，
  它底下的節點這次不會比對。」——阿明：「一開始看到『失敗』兩個字有點嚇到，以為我哪裡做錯了。」
- 成功（三個人都一樣）：畫面上唯一的變化是活動標題旁多一個灰色小標籤「花費　累積中・ROAS 未追蹤」，
  外加核准區塊多一行預期／實際／差額。**沒有「配對成功」四個字，沒有幾個成功幾個失敗的計數，
  沒有逐節點的勾。**

三個人的反應剛好排成一條光譜：
- 阿明（新手）：8 分——他自己比對前後畫面差異推論出來了。
- Vivian（老手）：**3 分**——「我完全不知道剛剛那下按鈕做了什麼。是靜靜比對成功了沒講，
  還是根本沒抓到東西也沒講，兩種可能性都說得通。」
- 小杰（急性子）：5 分——**「失敗很吵、成功很安靜」**，「如果我是真小杰、沒逐張截圖比對，
  大概率會覺得按了沒反應，是不是壞了。」

同一個畫面上還有一個一致性的洞：**「配對」按鈕按下去不會鎖住**，小杰連按兩下兩次都真的送出去了；
同一頁的「開始排程」「產素材」一按就變狀態、第二下打不到。這次沒有造成重複資料（後端是冪等的），
但防護是靠前端反應快，不是靠後端——慢一點的網路擋不住。

`file:line`：`app/schedule/binding.py:23-45`（`bind_failure_message()`，只講失敗）、
`app/schedule/binding.py:73-140`（`bind_tree()` 的回傳形狀）、
`frontend/src/components/schedule/CampaignTree.tsx`（配對按鈕與結果呈現）。

做法（未裁決，但這條幾乎沒有裁決空間）：成功也要組一句話，講清楚「這次比對了幾個、成功幾個、
已經在追蹤花費了」。逐節點標「已配對」比一句總結更好，因為部分成功是常態
（上一層沒綁成，底下整批不比對——這件事現在只在失敗訊息裡提過一次）。route A／B 邊界，
半天以內。**順手把配對按鈕在送出期間鎖住**，跟同一頁其他按鈕一致。
