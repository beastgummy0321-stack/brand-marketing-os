# 把一張圖掛到某一個廣告節點上

Status: judged-no（2026-09-04 重判完畢，不開票）。下一個 session 不要再問一次。
關聯：憲法第 10 條（v1 不做生圖，但 schema 有位子）；ADR 0047（一個視覺方向，不是成品圖提示詞）。

## 重判的觸發條件到了，而且判的結果是不做

觸發條件成立：使用者 2026-09-04 手動建的那則廣告，圖是**他自己照提示詞生的、手動上傳到
Meta**（本人確認）。所以「生圖 → 找不到地方放 → 手動貼」這條路真的走過了。

判不做，三個理由都是查過的：

1. **判斷力零損失。** 診斷要的是「哪個視覺方向賺錢」，不是圖檔本身。而視覺方向已經逐則存著：
   `creative_candidate.visual_tone`（ADR 0047 兩個值）＋ `visual_concept`（一到兩句畫面概念）。
   2026-09-04 實查 `brd_bughunt` 最新五個候選，兩欄全部有值，例如
   「運動場館入口或健身包旁的產品特寫，使用紅色方向性邊光與局部水氣反光」。一則廣告＝一個候選，
   Meta 回來的 `ad_id` 沿深度 3 綁定指得回那個候選。
2. **叫代理每次排程讀懂圖片是純燒 token。** 它讀完吐出來的會是它自己上一步剛寫的那句
   `visual_concept`。
3. **未來接內部生圖時，門已經開著。** `creative_candidate` 建表當天（`20260901000002`）就留了
   `provider`／`provider_job_id`／`provider_status` 三欄，今天全是 `NULL`。那天要做的是把值填進去，
   不是改 schema。

## 真正缺的那一軸（不是這張票）

`visual_tone` **沒有**進 `performance.brand_creative_performance()` 的維度分組——七維裡沒有它。
所以「暖調 vs 暗調哪個賺」現在畫不出來，缺的是那一軸，不是那張圖。卡在同一份資料
（有座標的花費今天是 0 元），現在做等於盲做。等 `issue-t6c-three-agent-diagnosis.md` 的開票條件到了
一起判。
