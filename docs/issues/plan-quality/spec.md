# 目標：讓系統出得了「拿得出手」的方案與素材

Status: 2026-09-07 開行。前身是 `docs/issues/ad-loop/`（⑧⑨），那行已關——關的理由在下面〈廣告閉環為什麼可以關〉。
使用者的話：「目前這個程式給的方案和提示詞基本不能用，還有很多要細調。」

## 這一行要解決的事

閉環的管線是通的。**通的管線裡跑的是白開水。** 2026-09-07 真跑產出的方案長這樣：

> 「這是最穩健的基準方案，讓素材承擔大部分受眾溝通工作……優點是有機會擴大新客來源；
> 風險是廣泛受眾初期可能出現成本波動，因此不宜同時開太多廣告。」

沒有一個數字來自這個帳戶，沒有一句話是別的品牌不能照抄的。素材那一層同樣：五個版本的主要文字互相
之間只差詞序，證明欄七則全部是「無證明」。

## 兩個成因，都不是「還沒真投廣告」（2026-09-07 查證）

### 一、上下文是空的

`app/llm/context_compiler.py:87` 的 `compile()` 蒐集五類東西：品牌事實、人物誌、產品事實、規則卡、宣稱。
2026-09-07 真跑當下，資料庫裡這五類的列數是：

| 表 | 列數 |
|---|---|
| `brand_fact` | 0 |
| `persona` | 0 |
| `product_fact` | 0 |
| `rule` | 0 |
| `claim` | 0 |
| `customer_voice` | 0 |
| `product` | 1 |

也就是說，那三個方案是模型拿著「一個品牌名字＋一個產品＋方法論」寫出來的。它寫得空泛不是模型笨，
是**它手上真的沒有東西**。素材的證明欄七則全是「無證明」也是同一個原因：`claim` 是 0 列，沒有東西可引。

直接的解法是建檔精靈——但這正好連到 `docs/issues/ui/issue-intake-handoff-dead-end.md` 記的那件事：
建檔精靈本身難用到讓人填不完。**「叫使用者去填」不是解法，是把問題丟回去。**

### 二、出方案的時候看不到成效

`compile()` 的五類裡**沒有成效**。同一個帳戶當時已經有：

- 8 天真花費 14,577 TWD、31 筆購買、每筆購買成本約 470 元
- 保守 ROAS 1.74／樂觀 ROAS 2.75／追蹤覆蓋率 63%
- 8 則各自有 ROAS 的現役廣告

②出方案時**一個都看不到**。所以它每一次都用「第一次幫這個品牌做」的口吻寫，也沒辦法說
「你的 XX 廣告 CPA 是 470，這個方案要打的是把它壓到 400」。

這一條跟 `docs/issues/smart-loop/`（越用越聰明）貼著但不一樣：那一行管的是**跨期**帶著上一期的
記分與座標走；這一行管的是**單次**輸出就不夠好——即使沒有上一期，帳戶裡現成的數字也應該進 prompt。

## 廣告閉環（⑧⑨）為什麼可以關

那一行要證的是「這個環帶得動訊號」。逐段驗過：

| 段 | 證到哪 |
|---|---|
| ⑧ 花費回流 | **真錢**。2026-09-07 拉回 8 天 14,577 TWD，campaign／adset／ad 三層總額相等 |
| ⑦ 名稱比對綁定 | **真 Meta 物件**。11／11 三層全綁上，全形 `｜` 沒出問題 |
| ⑤ 座標落地 | 7／7 廣告 `coordinates_status='tagged'`，七維都有值 |
| 花費×座標的接合 | 真程式跑模擬花費驗過（`app/tools/simulate_meta_spend.py` 只假造最外層網路呼叫） |
| ⑨ 判讀 | 程式 2026-09-06 交件，演練在虛構數字上走過 |

只剩一件事沒證：**判讀判得準不準**。而那件事在輸入是白開水的時候量不出來——花兩週跟七千塊，
換到的是「模型對一批空泛素材的判讀」。所以瓶頸從「缺資料」移到「缺輸入品質」，這一行接手。

閉環那條 Meta 活動（`Beast Gummy｜一次補齊多盒更划算｜銷售`，11 個節點全綁好、暫停中）留著。
使用者哪天要開就開，開了資料自己會流進來，不擋任何一張票。

## 消融砍掉的，不要再提案一次（2026-09-04／09-07）

1. 「幫配對失敗訊息加一條 Playwright 斷言」——測試只收四類，「錯誤訊息措辭」不是。
2. 「開一支 `npm run e2e:real` 真跑驗收腳本」——它只驗得出「不是空的」，斷言比問題弱。
3. 「右邊一大片空白」——那是 `--width-form` 刻意的表單寬度上限。**先看 CSS 再喊版面 bug。**
4. 「把現有廣告改名，讓綁定回頭認領舊花費」——2026-09-07 使用者否決。機制真的會生效
   （`app/schedule/performance.py:87-97`，ADR 0064 §2），但那些廣告是使用者自己設計的，
   貼上系統替自己素材寫的座標會讓判讀學到錯的關聯。
5. 「再要求使用者實機投廣告才放行」——2026-09-07 使用者裁決：不要再拿真投放當任何一張票的前置。
