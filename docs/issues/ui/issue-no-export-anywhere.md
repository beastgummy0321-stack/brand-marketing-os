# 成效與判讀完全不能匯出，文案只能一則一則複製

Status: 2026-09-06 可用性演練量到（`docs/drills/`）。Vivian 給 **3 分**。
她要把東西帶去給老闆看，這是她評估導入的實際門檻之一。

成因：沒做。「本月 Meta 花費」表與「素材座標成效」判讀區沒有下載／CSV／列印／分享。
整個品牌底下唯一的匯出在「顧問分析報告」頁（列印／存成 PDF），那是品牌定位分析，
跟成效判讀是兩種東西——而且那份報告這個品牌還沒生成過。

素材文案有複製，但**是一則一則**：三層文案 × 5 個變體 × 每則廣告，Vivian 那棵樹是 9 則廣告，
45 組以上要一個一個點。（對照 `issue-tree-node-names-have-no-copy-button.md`：
文案有複製鍵、樹的名稱沒有，兩邊都缺「整批」。）

使用者看到的（Vivian）：
> 「要帶去給老闆看，目前只能自己截圖或用瀏覽器硬印這一頁。」

她的另一句更關鍵，因為它連到「排了下一期，上一期的座標接不回來」（`docs/issues/smart-loop/`「越排越好」第 1、2 刀）：
排了下一期之後，上一期的方案與判讀從畫面消失，**而她連截圖以外的方式都沒有留過底**。
沒有匯出＋沒有歷史，等於每一期的決策依據只活在那一期。

做法（未裁決）：
- 最小一刀：成效表與判讀區各一顆「複製成表格」（貼進試算表就成形），不做檔案下載。
  route A，一兩小時。
- 要裁決的：要不要做真正的 CSV 下載與「複製整棵樹的文案」。前者牽涉到「匯出的數字用哪個定義」
  （ROAS 一律保守／樂觀兩個值＋覆蓋率，見 `docs/contracts/schedule.md`「Diagnosis (T6c)」決定 5／11），
  匯出一份沒寫清楚定義的數字，比不匯出更危險。
