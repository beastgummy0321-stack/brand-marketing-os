# 前後端重設計總綱（2026-08-05 定案）

13 題訪談＋七路調查（程式碼盤點、persona 實測、外部開源範本、工作流地圖、過往決策、業界廣告流程、環境感知技術）後的完整共識。後續分票實作以本檔為唯一依據；與本檔衝突的舊慣例以本檔為準。

## 一、定位

**行銷駕駛艙**：打開先看見各品牌狀況（圖表為主、純文字為輔），系統主動告訴你下一步。功能多但藏在引導後面，使用者只管點下一步。

## 二、介面決策表

| 決策 | 結果 |
|---|---|
| 首頁 | 跨品牌總覽：每品牌一張卡（健康度、本月營收環比、檔期狀態、最重要的一件下一步），點卡進單品牌駕駛艙 |
| 駕駛艙第一屏 | ① 四張 KPI 卡（本月營收、廣告花費、ROAS、訂單數，各帶迷你趨勢線與環比）→ ② 主圖（營收 vs 廣告花費疊線）→ ③ 下一步指南卡＋異常警示區並排 → ④ 窄條：AI 油錢錶＋內容產線小計。細節一律收次頁 |
| 技術路線 | React（Vite）整站重寫，一次到位切換；開發期間舊 Jinja 介面照常可用，每完成一個模組給使用者預覽驗收 |
| 後端 | 資料庫與核心邏輯不動，新增儀表板資料彙整 API（JSON）；HTML 路由保留到切換日 |
| 選件 | ECharts（圖表）＋ shadcn/ui（組件）＋ Driver.js（首次導覽）；設計系統用 ui-ux-pro-max 技能包產生 |
| 螢幕 | 純桌機 1440px，不做響應式（沿用決策 0038 結果） |
| 引導 | 三層：空狀態改造（每頁沒資料時顯示「這頁幹嘛＋第一步按鈕」）＋首次進駕駛艙 30 秒導覽＋常駐指南卡 |
| 風格 | 淡色專業風，單一主題 |
| 圖表鐵則 | 首屏只做「一眼判斷好壞」；不用圓餅圖/儀表盤/3D 做精確比較；顏色只分類不表數值；最重要數字放左上 |

## 三、模組化藍圖與接口鐵則

- 未來模組：**內容產出與發布、SEO 搜尋佈局、顧客與口碑、訊息推播（EDM/LINE）**——大方向確定，功能細節不預設，各模組動工前必先訪談使用者定流程。
- **廣告優先**：廣告模組全部落地（見第四節驗收定義）之前，不動其他新模組。
- **接口鐵則**：模組之間只透過定義好的通用內部接口交換資料，禁止直接 import 對方內部或共用資料表寫入（前車之鑑：廣告↔訂單糾纏，2026-08 才拆完）。
- **平台插槽**：廣告模組做成插槽式——Meta 為第一個完整插槽（範本），Google Ads、蝦皮廣告、TikTok Ads、LINE LAP 預留插槽位置與接口，之後逐一實作不改架構。

## 四、廣告模組業界標準化

驗收定義：**下表全綠＝廣告模組完工**。「部分／大致合格」也要補到合格。

| 業界階段 | 現況 | 要補的 |
|---|---|---|
| 簡報與 KPI 對齊 | 缺 | 開檔時強制目標設定：KPI 對齊漏斗階段（曝光期看觸及/CPM，轉換期才看 ROAS/CPA） |
| 媒體企劃 | 部分 | 預算按漏斗拆層、排期策略三選一（連續/間歇/脈動）並記錄理由、保留彈性測試額度 |
| 計畫核准 | 合格 | 保留（去具名，見 ADR 0004） |
| 素材製作審核 | 合格 | 保留 |
| Trafficking | 大致合格 | 命名規範與 UTM 規則納入系統檢查 |
| 上線前 QA | 部分 | 升級到業界顆粒度：像素實測驗證、受眾排除名單、預算逐筆覆核、到達頁實點測試；**系統當「第二人」自動覆核**（單人無 four-eyes，用程式驗證代替） |
| 上線授權 | 合格 | 保留（去具名） |
| 監控與 pacing | 缺 | 成效每日自動同步（Meta/GA4 排程拉取，不再手動按）＋ pacing 警示（預算會提前燒完/花不完時進警示區） |
| 學習期紀律 | 合格（強項） | 保留判讀狀態機；補「學習期重置規則」進規則卡（預算單次調幅 >20% 會重置學習期等） |
| 週報 | 缺 | 六段式自動產出：執行摘要、各通路成效、目標 vs 實際、週對週、異常說明、建議行動 |
| 結案覆盤 | 大致合格 | 補固定格式（目標對照、落差歸因、學習兩層、具體建議），沉澱回饋下期 |
| 檔期日曆 | 缺 | 見第五節 |

## 五、環境感知顧問（採第一＋第二層）

- **第一層（免費，先做）**：內建台灣行銷檔期日曆資料檔（固定節日＋電商大檔）。提前期分級：大檔（雙11、母親節）90 天/8 週、中檔 45 天/6 週、小檔 30 天/3 週；素材一律提前 14 天完稿提醒。檔期內投放分預熱→高潮→衝刺三階段。提醒進駕駛艙指南卡。
- **第二層（AI 聯網）**：`app/llm/providers.py` 的 `AnthropicProvider.complete()` 加可選 `tools` 參數（預設不開），「下期建議」（nextcycle）與「打法/素材生成」（plan/creative）優先開通 web_search（`max_uses` 2–3、`user_location` TW）。詳見 ADR 0005。
- **第三層（Google Trends 等第三方數據源）**：不做。官方 API 未開放、替代方案花錢且有法律灰色地帶，第二層跑穩後再評估。

## 六、全站修繕清單（persona 實測痛點）

1. 「進單建檔」全面正名為「品牌建檔精靈」（詞彙表已收錄）。
2. 「累積智慧」等頁面的工程內部用語（野路子解禁、規則卡門檻等）全部翻白話。
3. 不可用的選單項目（未選品牌、即將推出）一律變灰＋提示，不得看起來可點。
4. 錯誤頁保留導覽與麵包屑，不得只剩一顆返回鈕。
5. 資料頁（品牌事實等）加摘要與分類，首屏不超過一屏文字。
6. 交接包手動搬運流程本次只優化操作指引（更手把手），自動化屬後端 agentic 工程，另案。

## 七、下一步指南卡（新建機制）

現況：建議都是「出事才跳」（打斷佇列）或「跑流程才出現」（方案生成）。新建常駐掃描：**判定用程式算，AI 只翻人話**（沿用系統鐵則）。貨源：待確認事實數、檔期卡在哪道關卡、判讀出爐未讀、下期草案已備好、檔期日曆備戰提醒、pacing 警示。與打斷佇列的分工見 CONTEXT.md 詞彙表。

## 八、分階段路線圖

| 階段 | 內容 |
|---|---|
| 0 基礎 | React 殼＋設計系統（ui-ux-pro-max 產出）＋儀表板 API 規範＋通用內部接口規範 |
| 1 駕駛艙 | 跨品牌總覽＋單品牌駕駛艙四件套＋檔期日曆第一層＋自動同步＋pacing 警示 |
| 2 廣告流程 | 企劃強化（KPI 對齊、預算拆層、排期策略）＋QA 升級＋關卡去具名＋三階段檔期投放 |
| 3 報告與聯網 | 週報六段式＋結案格式＋AI 聯網第二層 |
| 4 全站遷移 | 品牌智庫、品牌建檔精靈、訂單、設定頁搬進新前端＋白話化＋空狀態＋導覽 |
| 切換 | 體檢表全綠驗收 → 整站切到新前端，舊 UI 下線 |

每階段完成即給使用者預覽驗收；重整驗收標準沿用「純搬家＝斷言一行不改」原則。

## 九、明確不做／另案

- 手機/平板支援：不做。
- 深色模式：不做。
- 交接包自動化（agentic 後端）：另案。
- 內容/SEO/口碑/推播四模組：廣告全綠後，各自另開訪談。
- Google Trends 類第三方數據源：暫緩。
