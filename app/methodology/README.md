# 方法論檔索引

`app/methodology/` 放的是「AI 生成廣告計畫／文案／圖片 Prompt 時要吃的方法論規則」。
背景（決策 0024）：純模型裸生成的解方品質普通（0023 第 3 條承認的根因），解法是把專業行銷
skill 庫裡「已動工分支會實際消費」的規則萃取、在地化成台灣情境，寫成人話規則卡，餵進
context_compiler，比照品牌事實標準（有依據、可稽核、不捏造）。只按「消費拉動」萃取——沒有
對應分支在用的方法論檔不會出現在這裡；其餘 60+ 個 skill 等對應分支動工才萃取。

這份 README 有兩個讀者：一是 `context_compiler`（依下方對照表決定生成某類內容時要餵哪幾份
方法論檔），二是之後維護者（新增／更新方法論檔時，先看這裡確認索引與對照表要跟著改）。

## 維護規則

0. **每份方法論檔必須有複查到期日**（2026-08-03 決策 0034 新增）：
   寫在各檔 frontmatter 的 `複查到期日` 欄位，到期自動進收件匣提醒。
   **本批（2026-08-01 萃取）一律訂為 `2027-02-01`。**
   理由：這批檔自己就寫著「Meta 新演算法讓舊打法效果轉弱」，卻沒給自己配到期日
   ——外部世界（平台規則、法規）變得比文件快，而「需要時再重萃取」這件事沒有觸發點，
   實務上等於永遠不會發生。
1. **上游更新＝人工重萃取**：原始 skill／來源文件更新後，不會自動同步，必須人工重新讀一次
   來源、重新萃取，不做自動追蹤機制。
2. **每檔記來源版本**：每個方法論檔的 frontmatter 要記來源（庫、skill、萃取日期、來源版本），
   方便日後比對是否過時。
3. **新增檔必須同步更新本對照表**：任何新方法論檔上線，同一次改動要把它加進上方「檔案索引」
   與「任務型別對照表」，不能只加檔案不更新索引，避免對照表跟實際檔案脫鉤。
4. **只按消費拉動萃取**：不要為了「補齊」而預先萃取沒有分支在消費的方法論——沒有消費者的
   方法論檔是死文件，會增加維護負擔又沒人讀。

## 驗收標準（決策 0024 第 7 條）

方法論檔上線前後各過一關，兩關都要過才算完成：

1. **萃取忠實度**（每檔必過）：獨立驗證 Agent 對照原始 skill 逐條查——有依據、無捏造、
   無漏核心規則，比照品牌事實標準的嚴格度。
2. **效果盲測**（接上生成管線後才測）：同一開期輸入，接方法論前後各生成一次並排盲評，
   使用者分不出高下就要退回重萃。另加硬規則機檢：標注創意角度出處、有語料必引原話、
   Hook 橫跨多種切法。
