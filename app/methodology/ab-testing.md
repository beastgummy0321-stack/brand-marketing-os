# 廣告方法論：A/B 測試與統計紀律

本檔萃取自專業行銷 skill 庫，只收「可執行準則」，不收敘事案例。每條準則後方 `〔來源：檔名〕`
標出處，來源檔名一律相對 `skills/ab-testing/`。原文樣本數表為單位中立的次數／比例，非美元金額，
故不需在地化轉換，數字全部照原文搬入。

## 1. 核心原則

1. **先有假說，不是「先看看會怎樣」**：要有具體、可驗證的預期結果，且理由要基於觀察或數據。
2. **一次只測一個變數**：否則不知道到底是哪個改動造成差異。
3. **統計上要守紀律**：樣本數要**事先算好**，不能邊看邊停；一旦定案方法論就要走完，不能中途改。
4. **量對指標**：要有一個綁著商業價值的主指標；輔助指標用來解讀「為什麼」；另外要有護欄指標，
   防止優化主指標的同時傷到其他重要數字。

〔來源：ab-testing/SKILL.md〕

## 2. 假說結構模板

```
因為 [觀察／數據]，
我們相信 [改動]
會造成 [預期結果]
對 [受眾] 而言。
我們會用 [指標] 判斷這個假說是否成立。
```

**弱假說範例**：「換個按鈕顏色可能會提升點擊率。」

**強假說範例**：「因為使用者回饋與熱點圖顯示很難找到行動呼籲按鈕，我們相信把按鈕放大並改用對比色
會讓新訪客的行動呼籲點擊率提升 15% 以上。我們會用『瀏覽頁面到開始註冊』的點擊率來判斷。」

〔來源：ab-testing/SKILL.md〕

**多變體（A/B/n）要加樣本**：3 組（A/B/C）約需 1.5 倍樣本；4 組（A/B/C/D）約需 2 倍；5 組以上
建議考慮減少變體數。原因：比較組數增加，假陽性機率跟著增加，需用 Bonferroni 校正或支援自動校正
的工具。〔來源：ab-testing/sample-size-guide.md〕

**測試時長公式**：

```
測試天數 = （每變體所需樣本數 × 變體數）÷（每日流量 × 曝光佔比）
```

**最短測試天數的鐵則**：至少滿 1 週（涵蓋一週內的日別差異）；B2B 情境至少涵蓋 2 個營業週期
（平日 vs 週末）；電商情境要涵蓋發薪日前後（月初／月底消費模式）。**最長不建議超過 4–8 週**：
新鮮感效應會消退、外部因素會介入、也排擠其他測試的機會成本。〔來源：ab-testing/sample-size-guide.md〕

**樣本數不夠時的選項**（依序）：放寬要偵測的提升幅度（只抓 20% 以上的大效果）、降低信心水準（90%
代替 95%，有風險，需明文記錄）、減少變體數只測最有信心的一版、合併多個相似頁面的流量一起測、往
漏斗更上游測（流量更大的位置）、改用質化資料判斷不做定量測試、接受更長的測試天數。
〔來源：ab-testing/sample-size-guide.md〕

## 4. Peeking Problem 紀律（期中偷看的問題）

- **核心規則**：在還沒達到預先算好的樣本數之前就看結果、看到「還不錯」就提早喊停，會導致假陽性
  與錯誤決策。**要事先承諾樣本數，並信任這個流程走完**，不能中途改。〔來源：ab-testing/SKILL.md〕
- **測試進行中該做與不該做**：
  - 該做：監控技術問題是否正常、檢查各分群樣本品質是否正常、記錄外部干擾因素。
  - 不該做：偷看結果就提早喊停；測試途中更動任一變體內容；測試途中加入新的流量來源。
  〔來源：ab-testing/SKILL.md〕
- **若必須在達到樣本數前中途檢查**（高風險改動、需要提早喊停爛版本、時效性決策）：要改用
  「序貫檢定（Sequential Testing）」這種校正過多次檢視的統計方法，換來的代價是所需樣本數會
  略為增加、分析也更複雜——不是拿一般 A/B 檢定的門檻去做期中判讀。〔來源：ab-testing/sample-size-guide.md〕
- **判讀檢查清單（依序過）**：① 有沒有達到樣本數？沒有的話結果只能算初步。② 有沒有達到統計顯著
  （看信賴區間）？③ 效果量夠不夠有商業意義（對照 MDE，換算實際影響）？④ 輔助指標方向是否支持
  主指標？⑤ 護欄指標有沒有變差？⑥ 分群（裝置別、新舊訪客等）之間有沒有明顯差異？
  〔來源：ab-testing/SKILL.md〕

## 5. ICE 排序公式（實驗假說優先序）

對每個待測假說，依三個維度各打 1–10 分：

| 維度 | 問句 |
|---|---|
| Impact（影響力） | 如果這個假說成立，能把主指標拉動多少？ |
| Confidence（信心） | 有多確定這個假說會成立？（要基於數據，不是憑感覺） |
| Ease（容易度） | 多快、多便宜能把這個測試做出來並量到結果？ |

**ICE 分數 = （Impact ＋ Confidence ＋ Ease）÷ 3**。分數最高的先跑；每個月依最新情境重新打分一次。

〔來源：ab-testing/SKILL.md〕

**假說來源建議盤點**：成效數據（掉轉換點、轉換率偏低的頁面／廣告、表現差的分群）、顧客研究
（痛點、困惑、預期落差）、競品分析（對方在做而我們沒做的訊息或做法）、客服／留言（重複出現的
問題或抱怨）、熱點圖與畫面錄影（使用者猶豫、亂點、放棄的地方）、過去的「輸家」測試（輸的測試常常
藏著下一個該試的新角度）。〔來源：ab-testing/SKILL.md〕

**實驗速度參考指標**：每月上線測試數 4–8 個（多數團隊的合理節奏）；勝率 20–30%（成熟實驗計畫的
常態，持續明顯更高反而可能代表假說偏保守）；平均測試時長 2–4 週；假說待測清單深度維持 20+ 個。
〔來源：ab-testing/SKILL.md〕

## 6. 常見錯誤

**測試設計**：改動幅度太小（根本測不出差異）；一次測太多變數（無法歸因是哪個造成的）；沒有清楚
假說。

**執行**：提早喊停；測試途中更動內容；沒有檢查追蹤是否正確埋設。

**判讀**：忽略信賴區間；挑對自己有利的分群硬看；把「不顯著」的結果過度解讀成有意義的結論。

〔來源：ab-testing/SKILL.md〕

## 7. 本產品適用註記（對應決策 0024 第 3 條：財務線與統計線分離）

本產品把「判斷還能不能繼續花錢」與「判斷數據夠不夠格下科學結論」拆成兩條互不干擾的線：

- **財務線（維持既有，本檔不變動）**：打平／加碼／停損的判斷，一律用毛利反推計算，不受本檔統計
  規則影響——就算樣本數還沒到統計顯著門檻，只要毛利算下來還能繼續燒錢，仍可續投。
- **統計線（改查本檔）**：系統要判斷「Insufficient Data（樣本不足）」時，門檻改為查本檔第 3 節
  的樣本數速查表，不再用自訂的任意常數；要宣布贏家或要放大某個素材／版本前，必須先過這張表的
  樣本數門檻。
- **期中檢查點（第 3 天／第 7 天）禁止判勝負**：依 0023 第 16 條，這兩個時間點只做健康檢查
  （學習期是否正常、錢有沒有在花、素材是否已顯疲勞訊號），不得依此宣布任何版本贏或輸——這正是
  本檔第 4 節 Peeking Problem 紀律在產品裡的具體落地。
- **小預算誠實顯示「方向性判讀」**：當帳戶規模小、預算收不到本檔速查表要求的統計等級樣本數時，
  介面要如實顯示「這是方向性判讀，不是統計顯著的結論」，不得包裝成看似嚴謹的科學結果。
