# 部門任務：把活動樹的每個最深層節點各配一份文案（票 01）

任務代號：AD-CREATIVE-TASK-V1（本行是這份任務檔的識別行，請照樣保留，不要在回覆裡重複貼出）。

使用者已經在畫面上展開了一棵三層活動結構，現在要把「使用者接下來真的要在投放平台裡貼進去
的內容」寫出來——樹上每一個最深層的節點（沒有再往下一層的那一種），各配一份使用者可以
直接複製貼上的文案，再加一句可以拿去交給任何圖片工具的描述。這次要產文案的完整活動結構
（每一層、每個節點的名稱與已經有的欄位）接在這份任務說明之後的「這次要產文案的活動結構」
小節，原樣附上。品牌上下文接在結構之後，外殼不會改寫或摘要，你看到的就是全部。

## 節點名稱——一字不能差

「這次要產文案的活動結構」小節裡，找出每一個沒有 `children`（或 `children` 是空清單）的
節點，那就是最深層節點。你要交付的每一份文案的 `node` 欄位，必須跟該節點的 `name` **一字
不差**地相同——多一個字、少一個字、換個標點都算不同的名稱。每個最深層節點要有**剛好一份**
文案：少一個、多配一個、名稱對不上樹，外殼會把這次整批丟棄，使用者什麼都拿不到，錢也已經
花了。交付之前，自己把要交出去的節點名稱清單，逐一跟樹上的最深層節點核對一次。

## 交付內容

針對每一個最深層節點，給：

- **node**：見上一節，跟樹上的節點名稱完全相同的字串。
- **fields**：這則要交付的欄位，`[{"label": "欄位名", "value": "要填的值"}]`——欄位有哪些、
  叫什麼名字，由你自己判斷這個節點需要什麼，沒有固定清單。常見的例如「主要文字」「標題」
  「說明」，再加一則「圖片提示詞」（給任何圖片工具用的一段描述，不是真的去生圖，這個系統
  不生圖也不存圖）。這份任務檔往後會由使用者自己編輯調整要哪些欄位、要不要多加一個角度，
  跟外殼的程式無關——外殼只把你給的 `label`／`value` 原樣搬到畫面上。
- **warnings**：這則內容哪裡是你自己補的、還沒有事實根據的地方，每一條一句完整的中文話
  ——例如品牌上下文裡沒有已確認的價格或促銷事實，你先寫了一個看起來合理的折扣數字，就要
  在這裡老實講「這是佔位，投放前請自行核對」。誠實優先於好看，看不準就直說看不準。跟
  預設一致、沒有需要提醒的地方，給空清單。

## 篇幅上限

沿用 `campaign_tree.md` 已經量測過的教訓：輸出太長會在字串中間被截斷，整份因此作廢、錢
照花。所以：

- **`fields` 每個節點最多 6 個**，只給使用者真的要複製貼上的欄位；可有可無的欄位不要列。
- **每個 `value` 一句話或一小段講完**，不要寫成長篇；`warnings` 每條也是一句話。
- 「圖片提示詞」控制在一到兩句話，講清楚畫面裡有什麼、氛圍、角度即可，不必寫成分鏡腳本。
- 寧可少列一個可有可無的欄位，也不要讓整份輸出被截斷。**被切斷的內容一個字都不能用。**

寫完全部節點的內容之後，**在回覆的最後**附上一個 fenced json 區塊：

```json
{
  "creatives": [
    {
      "node": "……跟樹上最深層節點完全相同的名稱……",
      "fields": [
        {"label": "主要文字", "value": "……"},
        {"label": "標題", "value": "……"},
        {"label": "圖片提示詞", "value": "……"}
      ],
      "warnings": []
    }
  ]
}
```

`creatives` 的長度要剛好等於「這次要產文案的活動結構」裡最深層節點的數量，一個不多、一個
不少；`node` 逐一對應，不能有重複，也不能出現不在樹上的名稱。`label`／`value`／`warnings`
都是你自己的判斷，會原文照登在畫面上，不會被外殼改寫或翻譯。
