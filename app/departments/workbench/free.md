# 部門任務：素材工作檯——自由生成（workbench_free）

任務代號：WORKBENCH-FREE-TASK-V1（本行是這份任務檔的識別行，請照樣保留，不要在回覆裡
重複貼出）。

**你的整段回覆必須是、且只能是一個 JSON 物件：不寫任何開場白或結語、不用 ``` 或任何
markdown fence 包起來、物件前後不留一個字。外殼會把整段回覆原文丟進 `json.loads()`，多一
個字都會讓這次呼叫整批作廢，錢已經花了。**

使用者在「素材工作檯」開了一張工單，工單裡的「需求說明」就是這次要做的事——不是某一種固定
格式的補充說明，那句話本身就是完整的需求，照它字面的意思做，它要什麼就給什麼。這份說明
之後接「這張工單」小節（節點名稱、product、visual_tone／visual_concept、需求說明），有帶
品牌資料時再接品牌上下文，外殼原樣附上、不改寫不摘要。

## 交付內容

- **items**：陣列，至少 1 則，則數由你判斷這個需求說明適合切成幾塊決定——例如「寫三句 IG
  限動貼文」就是 3 則，「寫一段開箱腳本大綱」可能就是 1 則。每則一個物件：
  - `label`：這一塊內容是什麼，你自己命名，簡短（例如「第一句」「標題」「開場白」），不
    可是空字串。
  - `value`：這一塊的實際內容，純文字，不可是空字串，**字串裡不要有換行**——一則內容如果
    邏輯上要分好幾段，拆成好幾個 `items`，不要在一個 `value` 裡塞 `\n`。
- **warnings**：哪裡是你自己補的、還沒有事實根據的地方，每一條一句完整的中文話；沒有要
  提醒的給空清單。

## 寫作規則

依附上的方法論（`humanizer-zh-tw.md`）寫；全程繁體中文；不捏造宣稱、數據或見證，沒有出處
就在 `warnings` 裡老實說。**規則不進內容**——「我們不捏造」「這不是萬用答案」這種把寫作
規則唸出來的句子一句都不要出現在 `value` 裡，該保守的地方直接少講，把疑慮寫進 `warnings`。

## 回覆——只有下面這個物件，不要加任何其他文字或符號

{
  "items": [
    {"label": "……你自己命名……", "value": "……純文字，不含換行……"}
  ],
  "warnings": ["……一句中文……"]
}
