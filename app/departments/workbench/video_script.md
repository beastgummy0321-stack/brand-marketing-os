# 部門任務：素材工作檯——影片腳本（workbench_video_script）

任務代號：WORKBENCH-VIDEO-SCRIPT-TASK-V1（本行是這份任務檔的識別行，請照樣保留，不要在
回覆裡重複貼出）。

**你的整段回覆必須是、且只能是一個 JSON 物件：不寫任何開場白或結語、不用 ``` 或任何
markdown fence 包起來、物件前後不留一個字。外殼會把整段回覆原文丟進 `json.loads()`，多一
個字都會讓這次呼叫整批作廢，錢已經花了。**

使用者在「素材工作檯」開了一張工單，要幫這張工單寫可以直接拍的影片腳本。工單內容（節點
名稱、product、visual_tone／visual_concept、要求的支數）接在這份說明之後的「這張工單」
小節，其中一行逐字寫著這輪要幾支；方法論、品牌上下文依序接在工單之後，外殼原樣附上、不
改寫不摘要。

## 交付內容

- **scripts**：陣列，長度＝工單指定的支數，一支不多一支不少。每支物件：
  - `title`：這支腳本的一句話標題，方便使用者在清單上辨認。
  - `framework`：`creative-matrix.md` 第 5 節框架表裡的框架名稱原文，一字不差（例如
    「PAS」「UGC 見證流」）——不可自創框架名稱。支數 ≥2 時，同一批腳本至少橫跨 2 種框架
    （第 5 節「腳本輸出規則」第 3 條），不可全部同一套。
  - `hook`：這支腳本前 3 秒要說或要放的畫面／台詞，跟 `hook_pool` 裡收錄的那一則呼應但
    不必逐字相同（`hook_pool` 是共用池，這裡是這支腳本實際採用的那一個）。
  - `beats`：陣列，至少 3 個節拍，依所選框架的段落順序排——每個節拍一個物件：
    - `t`：這個節拍的時間區間（例如「0–3s」），依框架段落的時間軸切，實際長度可等比縮放。
    - `visual`：一句話畫面說明，不寫運鏡、不寫轉場。
    - `voice`：這個節拍的口播台詞。
    - `text`：畫面上要疊的字卡或字幕，跟口播不必逐字相同（字卡通常更短），沒有字卡就填
      空字串。
  - `cta`：這支腳本的行動呼籲，放在興趣最高點，不是硬等到片尾才出現。
- **hook_pool**：陣列，長度至少等於工單指定的支數——這批腳本共用的 Hook 池，至少橫跨 5
  種切法（第 4 節「Hook 切法」），不可全部同一種切法的換句話說；每支腳本的 `hook` 從這裡
  挑一則發展，不必逐字照搬。
- **warnings**：哪裡是你自己補的、還沒有事實根據的地方，每一條一句完整的中文話；沒有要
  提醒的給空清單。

## 寫作規則

依附上的方法論（`creative-matrix.md` 第 4／5 節、`copywriting.md`、`humanizer-zh-tw.md`）
寫；全程繁體中文；不捏造宣稱、數據或見證，沒有出處就在 `warnings` 裡老實說。段落標籤只能
從所選框架的段落名挑，不可自創；每 5–10 秒一個新資訊點或情緒點；三問檢查——開頭答「為什麼
要看」、中段答「為什麼要看完」、結尾答「為什麼要行動」；一支只講透一個核心賣點；價格與優惠
必上醒目字幕（放進對應節拍的 `text`）。

- **畫面說明只給拍攝用，不是文案腔**——`visual` 只描述鏡頭看到什麼，不重複 `voice` 已經
  講過的話。
- **規則不進台詞**——「我們不捏造」「這不是萬用答案」這種把寫作規則唸出來的句子一句都不
  要出現在 `voice`／`text`／`cta` 裡，該保守的地方直接少講，把疑慮寫進 `warnings`。
