# 部門任務：把方案展開成活動結構（票 09）

任務代號：CAMPAIGN-TREE-TASK-V1（本行是這份任務檔的識別行，請照樣保留，不要在回覆裡重複貼出）。

使用者已經在畫面上選定了一個檔期方案（怎麼分錢、為什麼這樣分），現在要把這個方案展開成
「使用者接下來真的要在投放平台裡打造的結構」——三層，每一層的每個節點都附上要打的名稱、
要填的欄位。這次的平台、選定方案的完整內容（摘要、理由、每個方向的比例與每日金額）接在
這份任務說明之後的「這次要展開的參數」小節，原樣附上。品牌上下文接在參數之後，外殼不會
改寫或摘要，你看到的就是全部。

## 平台的三層結構——用你的專業判斷，不要照抄下表

下表是幾個平台的**驗證過的**真實結構，供你判斷這次的平台該怎麼展開；平台改版是常態，
你的專業判斷永遠優先於這張表：

| 平台 | 第一層 | 第二層 | 第三層 | 預算在第幾層 |
| --- | --- | --- | --- | --- |
| Meta | 行銷活動（只放目標，不放預算） | 廣告組合 | 廣告 | 第 2 層 |
| Google | 行銷活動 | 廣告群組 | 廣告或關鍵字 | 第 1 層 |
| Google Performance Max | 行銷活動 | 素材群組（沒有關鍵字） | 素材 | 第 1 層 |
| TikTok | 行銷活動 | 廣告群組 | 廣告 | 第 1 層或第 2 層 |

`levels` 請用這個平台自己介面上的叫法（例如 Meta 是「行銷活動／廣告組合／廣告」）——
外殼不會把這幾個字翻譯成別的，你怎麼填畫面就怎麼顯示。

## 交付內容

針對每一層的每個節點，給：

- **name**：使用者要在平台介面上打的**確切名稱**。這個名稱之後系統會拿去比對使用者實際
  發佈出去的活動，取名要清楚、彼此不重複，讓使用者照抄就好，不必自己想。
- **fields**：這個節點要填的欄位，`[{"label": "欄位名", "value": "要填的值"}]`——例如
  Meta 的廣告組合要填「版位」「受眾」「每日預算」（若這層扛預算，見下）等，依你對這個平台
  介面的了解列出使用者實際會看到的欄位。
- **share**：只有「扛預算的那一層」的節點才填，介於 0（不含）到 1（含）之間的小數，
  同一層扛預算的節點全部加起來要等於 1.0——不扛預算的層，這個欄位不要出現（或填
  `null`）。不要自己算金額，外殼會拿這個比例乘以選定方案已經分給這個方向的每日金額、
  四捨五入到整數元。
- **warnings**：這個節點的設定跟平台預設值不一樣的地方，每一條都是一句完整的中文話
  （例如「只投 Facebook，沒有勾 Instagram」）。跟預設一致就給空清單——這是使用者事後
  發現「怎麼漏勾了」之前，最後一道防線，缺一條都可能讓使用者白花錢或漏放送。
- **children**：下一層的節點清單；第三層節點沒有下一層，`children` 給空清單。

寫完全部節點之後，**在回覆的最後**附上一個 fenced json 區塊：

```json
{
  "levels": ["行銷活動", "廣告組合", "廣告"],
  "budget_level": 2,
  "nodes": [
    {
      "name": "……使用者要打的第一層名稱……",
      "fields": [{"label": "目標", "value": "……"}],
      "share": null,
      "warnings": [],
      "children": [
        {
          "name": "……第二層名稱……",
          "fields": [{"label": "受眾", "value": "……"}, {"label": "版位", "value": "……"}],
          "share": 0.7,
          "warnings": ["只投 Facebook，沒有勾 Instagram"],
          "children": [
            {
              "name": "……第三層名稱……",
              "fields": [{"label": "素材", "value": "……"}],
              "share": null,
              "warnings": [],
              "children": []
            }
          ]
        }
      ]
    }
  ]
}
```

樹一定剛好三層深；扛預算的節點數量、名稱、`share`，跟選定方案裡「錢怎麼分」的方向數量、
理由要對得上——這是同一個決定的兩種呈現方式，不是兩個獨立的判斷。金額怎麼分、比例加總
合不合法由外殼的程式檢查，不是你的責任——你只要誠實給出你判斷下最合理的結構與理由
（看不準就直說看不準，誠實優先於好看）。
