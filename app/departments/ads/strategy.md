# 部門任務：投放中心——一個 Campaign 的推薦策略（ads_strategy）

任務代號：ADS-STRATEGY-TASK-V1（本行是這份任務檔的識別行，請照樣保留，不要在回覆裡重複貼出）。

下面會給你這次投放的目標句子、目標與成功條件、投放期間、這個品牌的起點（投放過沒、花費
歷史、平台讀回、像素）、程式列出的可用角色、品牌已知的事實、【這個賣法】（名稱、單品或組合、
事實、今天有效的價格）、【不能講】、這個賣法的顧客、【這期可用的優惠】、過去的學習記錄、
上幾期的排名、【上一期想學的】、【這期撐得起幾則】、以及程式已經算好的預算情境。你的工作是把
「錢要怎麼分配在可用角色之間」講清楚——不是幫他重新算預算金額，金額全部由程式計算，你只回
百分比。

**數字由程式印，你只寫連接的話。** 這期打哪幾群、可用哪些優惠、上限與上一期的成績、撐得起
幾則、讀了幾則留下／換掉——這些事實程式會自己印在策略上方。你寫的 `rationale`／`why`／
`unknowns`／`alternatives`／`learning_goals` 一個阿拉伯數字都不寫、不寫 `%`、不寫金額或
`NT$`：要提到某則廣告就寫它的名字，要提到某群人就寫那群是誰，要比大小就用「比較便宜」
「最多」這類字。帶數字的回覆會被整包退回。

**【不能講】列的字一個都不能出現**在你寫的任何一句話裡（理由、名稱、情境都一樣）。

**你的整段回覆必須是、且只能是一個 JSON 物件：不寫任何開場白或結語、不用 ``` 或任何
markdown fence 包起來、物件前後不留一個字。**

## 兩條不可違反的規則

- **不編數字。** 你回的每個 `pct` 都是你判斷出來的百分比，但金額、CPA、預算——任何
  「錢」的數字——一概不由你決定；`rationale`／`why`／`unknowns`／`learning_goals` 裡
  連下面給你的數字也不要抄，程式會印。看不出理由就照實講看不出來。
- **只給一個推薦方案。** `alternatives` 預設是空陣列；只有在真的存在一個站得住腳的
  取捨（例如「更保守但觸及少」）時才填一條，而且每一條都要講清楚它換到什麼、犧牲什麼。

## 先看起點再分配

【這個品牌的起點】是程式整理好的事實，分配要對得上它：從沒投放過的品牌沒有暖受眾可以
再行銷；購買人數少就撐不起一個回購組；寫「不知道」或「還沒讀過」的欄位就是不知道，不要
當成有。【投放期間內的行事曆】是程式列出的假日、考季與檔期，只在它真的會影響這個品牌的買家
時拿來安排時機與節奏，不必硬套節慶角度；寫「沒有資料」的年份就是沒查到，不是沒活動。

【上幾期的排名】是程式排好的：每則廣告的每筆成本（花費÷成交）、賣幾筆、花多少，以及程式判的
「留下」或「換掉」。留下／換掉是程式的判定，不要自己重判。有列時，
`rationale` 要點名這次建立在哪幾則「留下」的廣告上（寫廣告名，不寫它的成本），
以及這次不再用的「換掉」那一群＋角度；標「樣本少」的留下只賣了幾筆，值得再驗一次。
寫「還沒有結案過的廣告」就寫「還沒有結案成績」。

【這期可用的優惠】是這個賣法真的能給的優惠：投放結構至少要有一則廣告帶其中一個，分配時
把它算進去；寫「這期沒有可用的優惠」就不要寫優惠。【上一期想學的】是上一期打算弄清楚的事，
這期的 `learning_goals` 要接著它問下去，不要原封不動重複。【這期撐得起幾則】是程式用每天的
預算和上限算的：要分更多角色（每個角色至少一則廣告）時，在 `why` 裡說為什麼值得。

【這個賣法的顧客】有列顧客群時，每個角色的 `rationale` 要點名這個角色打的是哪一群（寫那群
是誰，不寫編號）；寫「還沒有建顧客群」就不用點名，也不要自己編一群。

**座標一律用中文名稱，不寫英文代碼。** 老闆會讀 `why`、`rationale`、`learning_goals`、
`unknowns` 的每一句：提到座標時寫排名括號前的中文名稱（例如「太麻煩」），不要寫括號裡的
`pain=effort` 這種代碼，也不要寫 `audience`、`offer` 這類維度英文字。

## 交付內容

- `allocation`：一個陣列，每一項是 `{"role", "pct", "rationale"}`：
  - `role`：只能用【可用角色】列出的角色，不能自己加（英文 key 照抄，程式要拿去對照；
    中文名稱由程式自己填，不用你回）。每個角色最多出現一次；不打算投的角色就不要列
    （列了 0% 也會被展開成一個投放組）。
  - `pct`：這個角色分到的百分比（0～100 的數字，全部項目加起來約等於 100）。
  - `rationale`：一句話說明為什麼這樣分，引用下面給的品牌事實／商品／學習依據。
- `why`：這個策略整體的理由，字串陣列，每條都要能指出用了下面哪一段資料。
- `unknowns`：這次策略還看不出來、需要投放後才知道的事，字串陣列，沒有就給 `[]`。
- `alternatives`：見上面規則，預設 `[]`。
- `learning_goals`：這一輪投放**想學到什麼**，字串陣列，**最多 3 條**，每條一句話。寫「哪些
  受眾／訊息組合帶來最多新客」這種下一輪用得上的問題，不要寫成預測、不要寫成對成效的保證，
  也不要重複 `unknowns`（`unknowns` 是現在還不知道的事，`learning_goals` 是這一輪打算去弄
  清楚的事）。沒有就給 `[]`。
