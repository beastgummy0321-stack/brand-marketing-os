# 部門任務：投放中心——一個 Campaign 的推薦策略（ads_strategy）

任務代號：ADS-STRATEGY-TASK-V1（本行是這份任務檔的識別行，請照樣保留，不要在回覆裡重複貼出）。

下面會給你這次投放的目標句子、目標與成功條件、投放期間、品牌已知的事實、
這次投放涉及的商品與今天有效的價格、過去的學習記錄、以及程式已經算好的預算情境。你的工作
是把「錢要怎麼分配在新客／再行銷／探索三種角色之間」講清楚——不是幫他重新算預算金額，
金額全部由程式計算，你只回百分比。

**你的整段回覆必須是、且只能是一個 JSON 物件：不寫任何開場白或結語、不用 ``` 或任何
markdown fence 包起來、物件前後不留一個字。**

## 兩條不可違反的規則

- **不編數字。** 你回的每個 `pct` 都是你判斷出來的百分比，但金額、CPA、預算——任何
  「錢」的數字——一概不由你決定，也不要在 `rationale`／`why`／`unknowns` 裡編出一個
  「精確」的錢或轉換率，只能引用下面給你的數字。看不出理由就照實講看不出來。
- **只給一個推薦方案。** `alternatives` 預設是空陣列；只有在真的存在一個站得住腳的
  取捨（例如「更保守但觸及少」）時才填一條，而且每一條都要講清楚它換到什麼、犧牲什麼。

## 交付內容

- `allocation`：一個陣列，每一項是 `{"role", "pct", "rationale"}`：
  - `role`：`new`／`retarget`／`explore` 三選一（英文，程式要拿去對照；中文名稱由程式自己填，
    不用你回）。
  - `pct`：這個角色分到的百分比（0～100 的數字，全部項目加起來約等於 100）。
  - `rationale`：一句話說明為什麼這樣分，引用下面給的品牌事實／商品／學習依據。
- `why`：這個策略整體的理由，字串陣列，每條都要能指出用了下面哪一段資料。
- `unknowns`：這次策略還看不出來、需要投放後才知道的事，字串陣列，沒有就給 `[]`。
- `alternatives`：見上面規則，預設 `[]`。

## 回覆——只有下面這個物件，不要加任何其他文字或符號

    {"role": "new", "pct": 50, "rationale": "……"},

  ],
  "why": ["……"],
  "unknowns": ["……"],
  "alternatives": []
}
