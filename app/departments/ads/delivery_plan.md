# 部門任務：投放中心——把策略角色展開成投放組與廣告（ads_delivery_plan）

任務代號：ADS-DELIVERY-PLAN-TASK-V1（本行是這份任務檔的識別行，請照樣保留，不要在回覆裡
重複貼出）。

下面會給你這次投放已經採用的角色分配（新客／再行銷／探索，每個角色的預算已經由程式算好，
你不用管金額），以及這個品牌可以用的座標詞彙表（dimension｜key｜label）。你的工作是把每個
角色展開成一個投放組，再幫每個投放組寫出 1～3 支廣告，每支廣告要指定七個座標維度
（audience／pain／angle／hook／proof／offer／format）。【投放期間內的行事曆】是程式列出的
假日、考季與檔期，只在它真的會影響這個品牌的買家時拿來挑情境與 hook，不必硬套節慶。
證明那一段列出的就是這個品牌**確認有**的證據；沒列的不能用。限時限量只在活動有結束日時出現，
截止日由工作檯帶給文案，這裡不寫日期。

**你的整段回覆必須是、且只能是一個 JSON 物件：不寫任何開場白或結語、不用 ``` 或任何
markdown fence 包起來、物件前後不留一個字。**

## 三條不可違反的規則

- **角色不能少也不能多。** 下面給你幾個角色，你就回幾個投放組，`role` 要跟給你的角色
  一字不差對上，不能自己加、不能漏掉。
- **座標只能從詞彙表裡挑。** 每個 `coordinates.<dimension>` 一定要填詞彙表裡那個維度的某個
  `key`（不是 `label`），七個維度一個都不能漏、不能編一個詞彙表沒有的 key。
- **名稱是要貼到平台後台的追蹤名稱。** 廣告名稱要能讓人一眼看出「這支廣告在打什麼」，不用
  emoji、不用平台自己的術語（例如不要出現「動態廣告」「A/B 測試」這種平台詞），同一個
  Campaign 裡每支廣告的名稱都要不一樣。

## 交付內容

- `groups`：一個陣列，最多 4 個（通常跟給你的角色數一樣多），每一項是
  `{"role", "name", "ads"}`：
  - `role`：`new`／`retarget`／`explore` 其中之一，對應下面給你的角色分配。
  - `name`：這個投放組的中文名稱，看得出角色跟這次投放的主題。
  - `ads`：這個投放組底下的廣告，1～3 支，每一項是 `{"name", "coordinates"}`：
    - `name`：追蹤名稱（見上面規則）。
    - `coordinates`：`{"audience", "pain", "angle", "hook", "proof", "offer", "format"}`
      七個鍵，每個值都是詞彙表裡對應維度的一個 `key`。
